# ROKEY 파이썬 스터디

ROKEY 11기 **파이썬 교과목 평가(10/16)** 를 스터디원 모두가 잘 보기 위한 문제 풀이 저장소입니다.
차시별 문제를 각자 풀고, 자동 채점으로 점수를 확인하고, PR 로 제출하며 서로 리뷰합니다. git 연습도 겸합니다.

- 설치할 것 없음: 파이썬만 있으면 됩니다(외부 패키지 불필요).
- 채점은 내 컴퓨터에서 바로, PR 을 올리면 GitHub Actions 가 한 번 더 자동 채점합니다.

## 평가 조건 요약

| 항목 | 내용 |
|---|---|
| 일시 | 10/16(금) 14:30 ~ 16:30, 프로그래머스 |
| 범위 | 강의 자료 + 주간 요약본 |
| 유형 | 빈칸 채우기, 반환값 문제, 출력 문제, 객관식 |
| 채점 | **부분 점수 없음**, 요구한 형식과 정확히 일치해야 정답 |
| 금지 | IDE·VSCode·파이썬 레퍼런스·메모·검색 (실행하기 버튼만 가능) |

그래서 이 저장소의 문제는 **코드를 눈으로 읽고 머리로 실행하기**, **형식을 정확히 맞추기**를 연습하도록 만들었습니다.

## 시작하기

```bash
git clone https://github.com/WaterMinCho/rokey-python-study.git
cd rokey-python-study
python study.py init <내 깃허브 ID>     # 내 풀이 폴더 만들기 (처음 한 번)
python study.py start 0                # 0차시(사용법 익히기) 문제 받기
python study.py grade 0                # 채점
```

> `python` 명령이 없으면 `python3` 로 실행하세요.

0차시는 도구와 제출 흐름을 익히는 연습 세트입니다. 여기까지 되면 준비 끝입니다.

## 매일 루틴 (16:40 스터디)

1. `git switch main && git pull` — 최신 문제 받기
2. `git switch -c <내ID>/s03` — 오늘 차시 브랜치 만들기
3. `python study.py start 3` — 문제 받기. `problems/s03/README.md`(개념 정리)부터 읽기
4. 퀴즈(`quiz.md`)는 **실행하지 않고** 풀어 `quiz.py` 에 답 적기 → 코드 문제 풀기
5. `python study.py grade 3` — 채점. 틀린 문제는 해설을 보기 전에 한 번 더 풀기
6. 커밋 → 푸시 → PR. 서로의 PR 에서 틀린 문제를 설명해 주기
7. 그래도 모르겠으면 `python study.py explain 3 Q5` 로 해설 확인

git 명령이 처음이면 [docs/GIT_GUIDE.md](docs/GIT_GUIDE.md) 를 그대로 따라 하면 됩니다.

## 명령어

| 명령 | 하는 일 |
|---|---|
| `python study.py list` | 세트(차시·모의고사) 목록 |
| `python study.py start 3` | 3차시 문제 받기 → `submissions/<ID>/s03/` |
| `python study.py grade 3` | 3차시 채점 (`grade` 만 쓰면 시작한 세트 전부) |
| `python study.py explain 3 Q5` | 해설·정답 보기 (코드 문제는 `p01` 처럼) |
| `python study.py reset 3 p02` | 코드 문제를 시작 코드로 되돌리기 |
| `python study.py status` | 내 진행 현황 |
| `python study.py board` | 전체 스터디원 현황판 |

세트는 차시 번호(`3`)나 ID(`s03`, `m1`, `c1`)로 지정합니다.

## 문제 유형과 채점 규칙

| 유형 | 답하는 곳 | 채점 |
|---|---|---|
| 객관식 | `quiz.py` 에 `Q1 = 3` (복수 정답은 `[1, 3]`) | 정답과 정확히 일치 |
| 출력 예측 | `quiz.py` 에 `Q2 = "출력 내용"` | 글자 단위로 일치 |
| 단답 | `quiz.py` 에 `Q3 = "답"` | 정확히 일치(대소문자 구분) |
| 빈칸 채우기 | `pNN.py` 의 `____` 자리 | 빈칸 외 수정 금지 + 테스트 전부 통과 |
| 반환값 | `pNN.py` 의 `solution` 함수 | 반환값과 **자료형**까지 일치 (3 ≠ 3.0) |
| 출력 | `pNN.py` 에 프로그램 작성 | 출력이 글자 단위로 일치 |

- 테스트를 **전부** 통과해야 점수를 받습니다(부분 점수 없음).
- 출력 비교에서 무시하는 것은 줄 끝 공백과 맨 끝 빈 줄뿐입니다.
- `input("안내 문구")` 의 안내 문구는 채점 출력에 포함되지 않습니다.
- 한 문제의 실행 제한은 5초입니다. 무한 루프는 시간 초과로 처리됩니다.
- 세트 득점률 80% 이상이면 통과(✅)로 표시합니다.

## 제출 규칙

- 내 폴더 `submissions/<내 ID>/` 안의 파일만 고칩니다. `problems/` 는 건드리지 않습니다.
- PR 하나에는 한 사람의 풀이만 담습니다. (둘 다 CI 가 검사합니다)
- 아직 풀지 않은 차시의 다른 사람 풀이·해설은 열어 보지 않습니다.
- 문제나 정답에 오류가 보이면 이슈로 알려 주세요.

## 저장소 구조

```
study.py                 문제 받기·채점·해설 도구
problems/<세트>/         문제 은행 (README.md 개념 정리, quiz.md, pNN/problem.md …)
submissions/<내 ID>/     내 풀이 (여기만 수정)
docs/GIT_GUIDE.md        git 흐름 가이드
docs/AUTHORING.md        출제 규격 (문제 추가·수정 방법)
tools/                   출제자·CI 용 도구
.github/workflows/ci.yml 자동 채점
```

정답·해설은 `problems/<세트>/sealed.json` 에 묶여 있습니다. 실수로 스포일러를 보지 않게 가려 둔 것이고
암호화는 아닙니다. 해설은 `explain` 명령으로 봅니다.

## 스터디장용

- 스터디원 초대: 저장소 **Settings → Collaborators** 에서 깃허브 ID 추가
- 문제 추가·수정: [docs/AUTHORING.md](docs/AUTHORING.md) (새 차시는 `problems/sNN/` 폴더만 추가하면 인식됩니다)
- 커밋 전 점검: `python tools/verify_bank.py` (모든 모범 답안·정답표 검증), `python tools/seal.py check`
