이번 작업은 기본 LSTM에 풀이 간격 정보를 추가하기 위한 **Time Gap 전처리 및 입력 검증 단계**이다.

공통 v8 데이터를 사용하여 개념별 시간 선택 로직을 수정하고, 숫자 특성 생성 함수와 실제 데이터 기반 테스트를 구현하였다.

현재는 전처리 검증까지 완료했으며, 모델 학습과 성능 평가는 진행하지 않았다.

## 예측할 값과 모델을 고른 이유

기본 LSTM은 학습자의 이전 문제 풀이 기록을 이용해 현재 문제의 정답 확률을 예측한다.

주요 입력은 이전 문제 ID, 개념, 정오답 기록과 현재 예측할 문제의 정보이다.

본인이 담당한 Time Gap 모델은 여기에 **특정 개념을 마지막으로 풀이한 이후의 경과 시간**을 추가하는 방식이다.

같은 개념이라도 마지막 풀이 이후 경과한 시간이 다르면 학습자의 이해 상태에 차이가 있을 가능성이 있으므로, 이를 추가 입력 특성으로 활용하고자 한다.

시간 정보는 다음 두 값으로 표현한다.

```python
[gap_log, gap_known]
```

- `gap_log`: 경과 시간을 일 단위로 변환한 뒤 로그 변환한 값
- `gap_known`: 경과 시간 확인 여부를 나타내는 값(0 또는 1)

실제 0초와 시간 미확인 상태를 구분하기 위해 두 값을 함께 사용한다.

Time Gap을 추가하는 것이 실제로 예측 성능을 개선하는지는 향후 기본 LSTM과 동일한 조건에서 비교할 예정이다.

### 2. 개념별 시간 선택 함수

`inspect_gaps.py`에 다음 함수를 구현하였다.

```python
select_query_gaps(concepts, seconds, known, names)
```

함수는 다음 순서로 동작한다.

1. 현재 문제의 개념을 나타내는 `concepts`에서 값이 1인 항목을 찾는다.
2. 패딩 인덱스 0은 제외한다.
3. 선택된 개념에 대응하는 경과 시간과 시간 확인 여부를 읽는다.
4. 확인된 시간이 있다면 그중 **가장 짧은 시간 하나**를 선택한다.
5. 확인된 시간이 없으면 시간 미확인 상태를 반환한다.
6. 현재 문제에 해당하는 개념이 없다면 빈 목록을 반환한다.

여러 개념 중 최단 시간을 선택하는 주요 코드는 다음과 같다.

```python
confirmed = [item for item in selected if item["known"]]

if confirmed:
    shortest = min(
        confirmed,
        key=lambda item: (
            item["gap_seconds"],
            item["concept_id"]
        )
    )
    return [shortest]

return [selected[0]]
```

확인된 시간이 여러 개라면 경과 시간이 가장 짧은 개념을 선택하며, 시간이 같으면 개념 인덱스가 작은 항목을 선택한다.

시간 미확인 상태의 0초를 실제로 경과한 0초로 오해하지 않도록 확인 여부를 먼저 검사한다.

### 3. 시간 단위 변환 및 숫자 특성 생성

시간이 확인된 경우 다음 변환을 적용한다.

```python
gap_seconds = float(seconds[j])
gap_days = gap_seconds / 86400.0
gap_log = math.log1p(gap_days)
```

86400초는 1일이며, `math.log1p(1)`의 결과는 약 `0.6931471805599453`이다.

선택한 시간 정보를 두 숫자로 반환하기 위해 다음 함수를 구현하였다.

```python
def build_time_feature(concepts, seconds, known, names):
    result = select_query_gaps(
        concepts,
        seconds,
        known,
        names
    )

    if not result:
        return [0.0, 0]

    return list(result[0]["time_feature"])
```

| 상황 | 모델 입력 |
|---|---|
| 시간 미확인 | `[0.0, 0]` |
| 실제 0초 경과 | `[0.0, 1]` |
| 1일 경과 | `[0.6931471805599453, 1]` |

확인된 시간값이 음수이거나 유한하지 않은 경우에는 `ValueError`가 발생하도록 처리하였다.

단, 해당 오류 사례에 대한 독립적인 실행 테스트는 아직 수행하지 않았다.

## 입력 처리부터 학습·예측까지 내 코드 설명

### 1. 공통 입력 생성

`learning_server.input_example`의 `load()`와 `batch()`를 사용하여 실제 v8 데이터를 읽는다.

```python
rows, vocabulary = load(
    str(DATASET_PATH),
    TRACK,
    SPLIT
)

HISTORY_LENGTH = 32
BATCH_SIZE = 4

example = batch(
    rows[:BATCH_SIZE],
    vocabulary,
    length=HISTORY_LENGTH
)

raw_inputs = example["inputs"]
```

### 2. 입력과 정답 분리

Time Gap 전처리에 사용하는 입력은 다음과 같다.

| 입력 | 의미 |
|---|---|
| `query_concepts` | 현재 문제의 개념 정보 |
| `query_gap_seconds` | 개념별 경과 시간 |
| `query_gap_known` | 시간 확인 여부 |
| `vocabulary["concepts"]` | 개념 번호표 |

현재 문제의 정답은 `example["targets"]`로 별도 관리된다.

본인의 시간 선택 함수는 현재 문제의 정답을 입력으로 사용하지 않으므로 정답 정보가 전처리 과정에 직접 포함되지 않는다.

### 3. 빈 이력과 패딩 구분

과거 풀이 이력이 32개보다 적으면 나머지 위치는 패딩으로 채워진다.

이때 다음 두 입력을 이용해 실제 기록과 패딩을 구분한다.

- `lengths`: 실제 과거 풀이 개수
- `mask`: 실제 기록이면 `True`, 패딩이면 `False`

과거 풀이 결과인 `results`에 0이 있더라도 실제 오답인지 패딩인지 구분해야 하므로 `mask`와 `lengths`를 함께 확인해야 한다.

### 4. Time Gap 입력 처리 흐름

실제 코드에서는 `build_time_feature()`가 내부에서 `select_query_gaps()`를 호출한다.

따라서 전체 입력 처리 과정은 다음과 같다.

```text
공통 v8 recorded 데이터
          |
          v
        load()
          |
          v
   batch(length=32)
          |
          v
   example["inputs"]
          |
          v
  query_concepts
  query_gap_seconds
  query_gap_known
          |
          v
  build_time_feature()
          |
          +-- select_query_gaps() 호출
          |        |
          |        +-- 현재 문제에 해당하는 개념 선택
          |        |
          |        +-- 확인된 경과 시간 중 최단 간격 선택
          |        |
          |        +-- 선택한 시간 정보 반환
          |
          v
  [gap_log, gap_known]
```

`select_query_gaps()`는 개념과 시간을 선택한 결과를 반환하고, `build_time_feature()`는 그 결과에서 모델 입력에 사용할 숫자 두 개를 추출한다.

여기까지가 이번에 직접 구현하고 테스트한 범위이다.

모델의 순전파, 손실 계산, 역전파, 파라미터 갱신, 저장 및 평가 과정은 아직 연결하지 않았다.

### 5. 현재 전처리의 한계

`<UNK>` 인덱스 1에는 여러 미등록 개념의 정보가 합쳐질 수 있다.

따라서 `<UNK>`에서 선택된 시간은 특정 미등록 개념 하나의 정확한 마지막 풀이 간격이 아닐 수 있다.

이번에는 `<PAD>` 인덱스 0만 제외하고 `<UNK>`를 유지하는 기존 동작을 사용하였다.

또한 입력 확인은 전체 데이터가 아닌 처음 4개 기록에 대해서만 수행하였으므로 전체 시간 확인 비율을 대표하지 않는다.
