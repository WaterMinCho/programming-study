# 출제 규격 (문제 은행 작성 가이드)

새 차시·모의고사를 추가하거나 기존 문제를 고칠 때 따르는 규격입니다.
세트 폴더 하나를 `problems/` 아래에 추가하면 도구가 자동으로 인식합니다(코드 수정 불필요).

## 1. 평가 조건 — 문제는 이것을 흉내 냅니다

- 실제 평가(프로그래머스) 유형: **빈칸 채우기, 반환값 문제, 출력 문제, 객관식**
- 범위: 강의 자료 + 주간 요약본
- **부분 점수 없음**, 문제가 요구한 형식과 정확히 일치해야 정답
- IDE·자동완성·레퍼런스·검색 금지 → 코드를 **눈으로 읽고 머리로 실행**하는 힘이 핵심

## 2. 세트 폴더 구조

```
problems/s03/                 세트 ID: 차시는 sNN, 모의고사 mN, 코딩테스트 cN
├── meta.json                 세트 정보
├── README.md                 개념 정리(자기 말로 요약) + 시험 함정 포인트
├── quiz.md                   퀴즈 문제지 (공개)
├── quiz_key.json             퀴즈 정답·해설 (비공개 — 봉인 대상)
├── p01/
│   ├── problem.md            문제 설명 (공개)
│   ├── problem.json          유형·배점·테스트 (공개)
│   ├── starter.py            시작 코드 (공개, 학생이 받아 가는 파일)
│   ├── solution.py           모범 답안 (비공개 — 봉인 대상)
│   └── explain.md            해설 (비공개 — 봉인 대상)
├── p02/ …                    p01 부터 번호 순서대로
└── sealed.json               비공개 파일 묶음 (seal 도구가 생성, 이것만 커밋)
```

비공개 3종(`quiz_key.json`, `solution.py`, `explain.md`)은 `.gitignore` 로 커밋이 막혀 있고,
`python tools/seal.py seal` 이 `sealed.json` 으로 묶습니다. (암호화가 아니라 스포일러 방지용)

### meta.json

```json
{
  "id": "s03",
  "title": "조건식과 제어문",
  "kind": "session",
  "week": 2
}
```

- `kind`: `session`(차시) · `codetest`(코딩테스트 트랙) · `mock`(모의고사)
- 모의고사는 `"time_limit_min": 120` 을 넣으면 `start` 시점부터 시간을 잽니다.

## 3. 퀴즈 (객관식 · 출력 예측 · 단답)

### quiz.md — 문항 제목은 반드시 `## Q번호` 로 시작

````markdown
# 3차시 퀴즈 — 조건식과 제어문

> 코드를 실행하지 말고 눈으로 풀어 보세요. 답은 `submissions/<내 ID>/s03/quiz.py` 에 적습니다.

## Q1 (객관식 · 2점)

다음 코드를 실행했을 때 출력되는 것은?

```python
print(1 + 2)
```

1. `12`
2. `3`
3. `1 + 2`
4. 오류가 발생한다

## Q2 (출력 예측 · 3점)

다음 코드의 출력 결과를 그대로 적으세요.

```python
print("Hello")
print("ROKEY")
```

## Q3 (단답 · 3점)

화면에 값을 출력할 때 사용하는 파이썬 내장 함수의 이름을 적으세요.
````

### quiz_key.json

```json
{
  "questions": [
    {
      "id": "Q1",
      "type": "choice",
      "answer": [2],
      "points": 2,
      "explain": "1 + 2 는 숫자끼리의 덧셈이라 3 이 출력됩니다. \"12\" 는 문자열 \"1\" + \"2\" 일 때의 결과입니다."
    },
    {
      "id": "Q2",
      "type": "output",
      "code": "print(\"Hello\")\nprint(\"ROKEY\")\n",
      "answer": "Hello\nROKEY",
      "points": 3,
      "explain": "print() 는 출력 뒤에 줄바꿈을 붙이므로 두 줄로 출력됩니다."
    },
    {
      "id": "Q3",
      "type": "short",
      "answer": ["print", "print()"],
      "points": 3,
      "explain": "값을 화면에 출력하는 내장 함수는 print 입니다. 대소문자를 구분합니다."
    }
  ]
}
```

| type | answer | 채점 |
|---|---|---|
| `choice` 객관식 | 보기 번호 리스트 `[2]`, 복수 정답은 `[1, 3]` | 집합이 정확히 같아야 정답. 복수 정답 문항은 문제에 "모두 고르세요" 명시 |
| `output` 출력 예측 | 출력 문자열 | 줄 끝 공백·앞뒤 빈 줄만 무시하고 정확히 비교. **`code` 필수** — 검증 도구가 실제로 실행해 정답과 대조함. 입력이 필요하면 `"stdin"` 추가 |
| `short` 단답 | 허용 답안 리스트 | 앞뒤 공백만 제거하고 정확히 비교. 옵션 `"ignore_case": true`, `"ignore_space": true` |

규칙

- 문항 ID 는 `Q1` 부터 순서대로. `quiz.md` 의 `## Q번호` 순서와 `quiz_key.json` 순서가 같아야 합니다.
- `output` 의 `code` 는 `quiz.md` 에 보여 준 코드와 **글자 그대로 동일**해야 합니다.
- 실행 환경에 따라 달라지는 출력 금지: `id()`, 메모리 주소, `set` 출력 순서, 난수, 현재 시각, 긴 소수 자릿수.
- "오류가 발생한다" 가 정답인 내용은 `output` 이 아니라 `choice` 로 냅니다.
- `short` 는 답이 하나의 토큰(이름·키워드·숫자·값)으로 떨어질 때만 씁니다. 표현이 여러 가지 가능한
  코드 조각(`i+1` / `i + 1`)은 단답이 아니라 **빈칸 채우기 코드 문제**로 냅니다.
- 해설(`explain`)에는 정답 근거와, 헷갈리기 쉬운 오답이 왜 틀렸는지를 1~3문장으로 씁니다.
- 배점: 객관식 2점, 출력 예측 3점, 단답 3점.

## 4. 코드 문제 (빈칸 채우기 · 반환값 · 출력)

### problem.json

```json
{
  "title": "두 수의 합",
  "type": "return",
  "level": 1,
  "points": 4,
  "mode": "call",
  "cases": [
    {"call": "solution(1, 2)", "expected": "3"},
    {"call": "solution(10, -3)", "expected": "7"},
    {"call": "solution(100, 200)", "expected": "300"}
  ]
}
```

- `type`: `fill`(빈칸 채우기) · `return`(반환값) · `print`(출력)
- `level`: 1 기본 · 2 응용 · 3 도전 — 세트 안에서 쉬운 것부터 배치
- `points`: level 1 → 4점, level 2 → 6점, level 3 → 8점
- `timeout`(선택): 문제 전체 제한 시간(초). 기본 5초
- `mode` 와 `cases`:

| mode | 테스트 한 건의 형태 | 용도 |
|---|---|---|
| `call` | `{"call": "solution([1, 2])", "expected": "3"}` | 함수 반환값 검사. `expected` 는 **파이썬 리터럴을 담은 문자열**(`"[1, 2]"`, `"'abc'"`, `"True"`, `"(1, 2)"`, `"{1: 'a'}"`). 자료형까지 같아야 정답(3 ≠ 3.0, True ≠ 1). 3건 이상 |
| `io` | `{"stdin": "5\n3\n", "stdout": "8\n"}` | 프로그램 전체를 실행해 표준 출력 비교. 입력이 없으면 `stdin` 생략 |
| `exec` | `{"code": "d = Dog('초코')\nd.bark()", "stdout": "초코: 멍멍\n"}` | 학생 파일을 먼저 불러온 뒤 `code` 를 실행해 출력 비교. 클래스·출력하는 함수·리스트를 제자리에서 바꾸는 함수 등 |

- 파일 처리 문제: 테스트에 `"files": {"data.txt": "내용"}`(실행 전에 만들어 줄 파일), `"expect_files": {"out.txt": "내용"}`(실행 후 있어야 할 파일)을 추가할 수 있습니다. 테스트마다 빈 임시 폴더에서 실행됩니다.
- 출력 비교는 **줄 끝 공백과 맨 끝 빈 줄만 무시**합니다. 그 밖의 띄어쓰기·대소문자·문장부호는 그대로 비교합니다.
- `input("안내 문구")` 의 안내 문구는 출력으로 치지 않습니다. `stdin` 은 `input()` 한 번에 한 줄씩 소비됩니다.
- `call`·`exec` 모드에서는 파일을 불러올 때 나온 출력은 버리고, `if __name__ == "__main__":` 블록은 실행되지 않습니다.

### starter.py 관례

반환값 문제 — 프로그래머스처럼 `solution` 함수 뼈대를 줍니다.

```python
def solution(a, b):
    answer = 0
    return answer
```

출력 문제 — 주어진 데이터가 있으면 적어 주고, 나머지는 학생이 작성합니다.

```python
# 여기에 코드를 작성하세요
```

빈칸 채우기 — 완성된 프로그램에서 핵심 부분만 `____`(밑줄 4개)로 비웁니다.

```python
name = input()
print("안녕하세요,", ____)
```

- 빈칸은 한 문제에 1~3개, 각 빈칸은 **한 줄 안에서** 채워집니다(여러 줄에 걸친 빈칸 불가).
- 채점은 "빈칸 외 줄을 건드리지 않았는가 + 테스트 통과"입니다. 동작이 맞으면 어떤 표현이든 정답입니다.
- 빈칸 채우기가 아닌 문제의 starter 에는 `____` 를 쓰지 않습니다.

### problem.md

```markdown
# p02. 두 수의 합 (반환값 · 4점)

정수 `a`, `b` 가 주어질 때, 두 수의 합을 **반환(return)** 하는 `solution` 함수를 완성하세요.

## 제한 사항
- -1000 ≤ a, b ≤ 1000

## 입출력 예

| a | b | 반환값 |
|---|---|---|
| 1 | 2 | 3 |
| 10 | -3 | 7 |
```

- 무엇을 반환/출력해야 하는지, **형식(자료형·띄어쓰기·줄바꿈)** 을 예시로 분명히 보여 줍니다.
- 출력 문제는 출력 예를 코드 블록으로 그대로 보여 줍니다.

### solution.py · explain.md

- `solution.py`: 그 차시까지 배운 문법만으로 쓴 모범 답안. 빈칸 채우기는 starter 에서 빈칸만 채운 형태.
- `explain.md`: 접근 방법 → 핵심 개념 → 흔한 실수 순으로 짧게.

## 5. 출제 원칙

1. **범위**: 해당 차시까지 강의에서 다룬 문법·개념만 사용합니다. 모범 답안도 마찬가지입니다.
2. **창작**: 강의 자료·과제의 문장이나 문제를 그대로 옮기지 않습니다. 같은 개념을 묻되 숫자·이름·상황을
   바꿔 새로 씁니다. (과제의 **문제 형식**은 실제 평가 형식의 힌트이므로 형식은 적극 참고)
3. **모호함 금지**: 정답이 하나로 정해져야 합니다. 출력 형식은 예시로 못 박습니다.
4. **테스트는 변별력 있게**: 그럴듯한 오답(경계값 실수, 초기값 실수, 형 변환 누락)이 통과하지 못하게
   경계·예외 케이스를 넣습니다. 시작 코드가 그대로 통과하면 안 됩니다.
5. **결정적**: 난수·시간·실행 환경에 따라 결과가 달라지는 문제는 내지 않습니다.
6. **분량(차시 세트 기준)**: 퀴즈 12문항 안팎(객관식 6 · 출력 예측 4 · 단답 2), 코드 9문제 안팎
   (빈칸 3 · 반환값 3 · 출력 3). 실습이 적은 차시는 퀴즈 비중을 늘립니다.
7. **문체**: 한국어 존댓말(~하세요 / ~입니다). 변수·함수 이름은 영어.

## 6. 작업 순서

```bash
python tools/seal.py unseal s03      # (기존 세트를 고칠 때) 정답·해설을 평문으로 풀기
#  … 문제 작성·수정 …
python tools/verify_bank.py s03      # 검증: 모범 답안 통과 / 시작 코드 불통과 / 출력 예측 실제 실행 대조
python tools/seal.py seal s03        # 다시 봉인 (평문 삭제)
python tools/seal.py check           # 커밋 전: 평문이 남아 있지 않은지 확인
```

직접 풀어 보며 점검할 때는 임의 폴더를 채점할 수 있습니다.

```bash
python study.py grade s03 --dir /tmp/my_try    # 폴더 안의 quiz.py, p01.py … 를 채점
```

## 7. 새 차시 추가 체크리스트

1. `problems/sNN/` 폴더를 만들고 `meta.json`, `README.md` 작성
2. `quiz.md` + `quiz_key.json` 작성
3. `p01/` … 코드 문제 작성
4. `python tools/verify_bank.py sNN` 통과 확인
5. `python tools/seal.py seal sNN` 후 커밋 → PR (CI 가 문제 은행 전체를 다시 검증)
