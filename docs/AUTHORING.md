# 운영 메모와 출제 규격 (스터디장용)

스터디장이 저장소를 운영하고 문제를 추가하거나 고칠 때 보는 문서입니다. 세트 폴더를 `problems/` 아래에 추가하면 프로그램이 자동으로 인식하고, 코드는 고치지 않아도 됩니다.

## 1. 운영 메모

- 스터디원 초대는 저장소 Settings → Collaborators 에서 합니다.
- main 은 PR 로만 바뀝니다. 머지 방식은 Squash 만 켜 뒀고, 머지되면 브랜치가 지워집니다. 머지 버튼은 검사 두 개(문제 은행 검증, 채점)가 통과한 뒤에 눌립니다.
- 풀이 PR 은 스터디 시간에 리뷰가 끝나면 스터디장이 머지합니다. 머지되면 현황판이 바뀝니다.
- 문항이 모자라면 Actions 가 "출제 요청" 이슈를 만들거나 고칩니다. 이슈의 표대로 문제를 추가해 머지하면 스터디원이 다음에 프로그램을 켤 때부터 회차에 들어갑니다.
- 전원의 학습 분석은 `python study.py analyze` 로 봅니다.
- 문제나 도구는 `main` 과 `study/<ID>` 가 아닌 새 브랜치에서 고칩니다. `main` 이나 `study/<ID>` 브랜치에서 풀이 폴더 밖의 파일을 고친 채 프로그램을 켜면, 문제 받기가 그 수정을 `.git/study-backup/` 에 복사하고 되돌립니다. 새 브랜치에서 고치는 중에 프로그램을 켜면 [문제 받기]를 건너뛰고 "지금 '<브랜치>' 에서 문제·도구 파일을 고치는 중이라 [문제 받기]는 하지 않았습니다."라고 알립니다.

저장소는 아래처럼 나뉘어 있습니다.

```
start.bat, start.command   더블클릭 실행
study.py                 실행기, 터미널 명령, 문제 은행 로딩과 채점
bootstrap.py             PyQt6 확인과 설치
gui/                     화면 (PyQt6)
session.py               화면과 터미널이 같이 쓰는 서비스 계층
adaptive.py              단원별 숙달도, 회차 구성, 준비도
gitflow.py               문제 받기와 제출
mdlite.py                문제 본문(마크다운)을 화면용으로 변환
problems/<세트>/         문제 은행
submissions/<ID>/        스터디원별 회차, 풀이, profile.json
docs/                    GIT_GUIDE(제출과 피드백), CRITERIA(판정 규칙), AUTHORING(이 문서)
tools/, tests/           출제와 CI 에 쓰는 도구, 테스트
```

## 2. 작업 순서

### 기존 세트를 고치거나 문항 더하기

모자란 단원, 레벨, 문항 수는 "출제 요청" 이슈의 표에 나옵니다. 문항을 더할 때와 고칠 때 모두 아래 순서로 합니다.

```bash
python tools/seal.py unseal s03      # 정답·해설을 평문으로 풀기
#  quiz.md 와 quiz_key.json, pNN/ 폴더에서 문항을 고치거나 더하기
python tools/verify_bank.py s03      # 검증: 모범 답안 통과, 시작 코드 불통과, 출력 예측을 실제로 실행해 대조
python tools/seal.py seal s03        # 다시 봉인 (평문 삭제)
python tools/seal.py check           # 커밋 전: 평문이 남아 있지 않은지 확인
```

커밋하고 PR 을 올리면 CI 가 문제 은행 전체를 다시 검증합니다.

### 새 세트 만들기

1. `problems/sNN/` 폴더를 만들고 `meta.json`, `README.md` 를 씁니다.
2. `quiz.md` 와 `quiz_key.json` 을 씁니다.
3. `p01/` 부터 코드 문제를 씁니다.
4. `python tools/verify_bank.py sNN` 이 통과하는지 확인합니다.
5. `python tools/seal.py seal sNN` 과 `python tools/seal.py check` 를 실행한 뒤 커밋하고 PR 을 올립니다.

직접 풀어 보며 점검할 때는 임의 폴더를 채점할 수 있습니다.

```bash
python study.py grade s03 --dir /tmp/my_try    # 폴더 안의 quiz.py, p01.py … 를 채점
```

## 3. 세트 폴더 구조

```
problems/s03/                 세트 ID: 차시는 sNN, 모의고사 mN, 코딩테스트 cN
├── meta.json                 세트 정보
├── README.md                 개념 정리(자기 말로 요약) + 시험 함정 포인트
├── quiz.md                   퀴즈 문제지 (공개)
├── quiz_key.json             퀴즈 정답·해설 (비공개, 봉인 대상)
├── p01/
│   ├── problem.md            문제 설명 (공개)
│   ├── problem.json          유형·배점·테스트 (공개)
│   ├── starter.py            시작 코드 (공개, 학생이 받아 가는 파일)
│   ├── solution.py           모범 답안 (비공개, 봉인 대상)
│   └── explain.md            해설 (비공개, 봉인 대상)
├── p02/ …                    p01 부터 번호 순서대로
└── sealed.json               비공개 파일 묶음 (seal 도구가 생성, 이것만 커밋)
```

비공개 파일(`quiz_key.json`, `solution.py`, `explain.md`)은 `.gitignore` 로 커밋이 막혀 있고, `python tools/seal.py seal` 이 `sealed.json` 으로 묶습니다. 실수로 미리 보지 않게 가린 것이고 암호화는 아닙니다.

### meta.json

```json
{
  "id": "s03",
  "title": "조건식과 제어문",
  "kind": "session",
  "week": 2
}
```

- `kind` 는 `session`(차시), `codetest`(코딩테스트 트랙), `mock`(모의고사) 중에서 고릅니다.
- `week`(선택)는 `list` 명령에 주차로 나옵니다.
- `priority`(선택)는 단원 중요도입니다. 기본 1.0 이고, 값이 클수록 회차에 자주 나오고 준비도 계산에서 크게 칩니다. 지금은 9·10·11·13·14차시가 1.5 입니다.
- 모의고사는 `"time_limit_min": 120` 을 넣으면 `start` 시점부터 시간을 잽니다.

## 4. 퀴즈 (객관식 · 출력 예측 · 단답)

### quiz.md

문항 제목은 `## Q번호` 로 시작합니다.

````markdown
# 3차시 퀴즈: 조건식과 제어문

> 코드를 실행하지 말고 눈으로 풀어 보세요. 답은 `submissions/<내 ID>/s03/quiz.py` 에 적습니다.

## Q1 (객관식 · 2점)

다음 코드를 실행했을 때 출력되는 것은?

```python
print(1 + 2)
```

1. `12`
2. `3`
3. `1 + 2`
4. 오류가 발생한다

## Q2 (출력 예측 · 3점)

다음 코드의 출력 결과를 그대로 적으세요.

```python
print("Hello")
print("ROKEY")
```

## Q3 (단답 · 3점)

화면에 값을 출력할 때 사용하는 파이썬 내장 함수의 이름을 적으세요.
````

### quiz_key.json

```json
{
  "questions": [
    {
      "id": "Q1",
      "type": "choice",
      "answer": [2],
      "points": 2,
      "level": 1,
      "tags": ["print 기초", "문자열과 숫자"],
      "explain": "1 + 2 는 숫자끼리의 덧셈이라 3 이 출력됩니다. \"12\" 는 문자열 \"1\" + \"2\" 일 때의 결과입니다."
    },
    {
      "id": "Q2",
      "type": "output",
      "code": "print(\"Hello\")\nprint(\"ROKEY\")\n",
      "answer": "Hello\nROKEY",
      "points": 3,
      "level": 2,
      "tags": ["print 줄바꿈"],
      "explain": "print() 는 출력 뒤에 줄바꿈을 붙이므로 두 줄로 출력됩니다."
    },
    {
      "id": "Q3",
      "type": "short",
      "answer": ["print", "print()"],
      "points": 3,
      "level": 1,
      "tags": ["print 함수"],
      "explain": "값을 화면에 출력하는 내장 함수는 print 입니다. 대소문자를 구분합니다."
    }
  ]
}
```

| type | answer | 채점 |
|---|---|---|
| `choice` 객관식 | 보기 번호 리스트 `[2]`, 복수 정답은 `[1, 3]` | 집합이 정확히 같아야 정답입니다. 복수 정답 문항은 문제에 "모두 고르세요"를 적습니다 |
| `output` 출력 예측 | 출력 문자열 | 줄 끝 공백과 앞뒤 빈 줄만 무시하고 정확히 비교합니다. `code` 가 있어야 하고, 검증 도구가 이 코드를 실제로 실행해 정답과 대조합니다. 입력이 필요하면 `"stdin"` 을 추가합니다 |
| `short` 단답 | 허용 답안 리스트 | 앞뒤 공백만 제거하고 정확히 비교합니다. `"ignore_case": true`, `"ignore_space": true` 를 넣으면 대소문자나 공백을 가리지 않습니다 |

### 퀴즈 규칙

- 객관식 보기는 본문 마지막의 번호 목록(`1.` `2.` …)으로 적습니다. 보기가 코드 블록이면 `**1번**` 문단 뒤에 코드 블록을 두어도 됩니다. 화면은 이 보기들을 답 칸의 카드로 옮기고 본문 칸에는 나머지(지문)만 보여 줍니다.
- 문항 ID 는 `Q1` 부터 순서대로 붙입니다. `quiz.md` 의 `## Q번호` 순서와 `quiz_key.json` 순서가 같아야 합니다.
- `output` 의 `code` 는 `quiz.md` 에 보여 준 코드와 글자 하나까지 같아야 합니다.
- 실행 환경에 따라 달라지는 출력은 내지 않습니다. `id()`, 메모리 주소, `set` 출력 순서, 난수, 현재 시각, 긴 소수 자릿수가 여기에 듭니다.
- 출력 예측 문항의 코드에는 `input("안내 문구")` 를 쓰지 않습니다(채점기는 안내 문구를 출력으로 치지 않아 실제 화면과 달라집니다). 입력이 필요하면 안내 문구 없는 `input()` 만 씁니다.
- 탭 문자(`\t`)가 들어가는 출력은 답안에 적기 모호하므로 출력 예측이 아니라 객관식으로 냅니다.
- "오류가 발생한다" 가 정답인 내용은 `output` 이 아니라 `choice` 로 냅니다.
- `short` 는 답이 토큰 한 개(이름, 키워드, 숫자, 값)로 떨어질 때만 씁니다. 표현이 둘 이상 가능한 코드 조각(`i+1` / `i + 1`)은 단답이 아니라 빈칸 채우기 코드 문제로 냅니다.
- 해설(`explain`)에는 정답 근거와, 헷갈리기 쉬운 오답이 왜 틀렸는지를 1~3문장으로 씁니다.
- 배점은 객관식 2점, 출력 예측 3점, 단답 3점입니다.
- `level`(필수)은 1 기본 개념 확인, 2 코드 읽기와 응용, 3 함정과 여러 개념 종합입니다. 프로그램이 이 값으로 문항을 고릅니다.
- `tags`(필수)에는 그 문항이 묻는 개념 1~3개를 짧은 한국어로 적습니다(예: `["elif 순서", "경계값"]`). 같은 세트 안에서는 같은 개념에 같은 표현을 씁니다. 약한 개념 분석에 이 글자가 그대로 나옵니다.

## 5. 코드 문제 (빈칸 채우기 · 반환값 · 출력)

### problem.json

```json
{
  "title": "두 수의 합",
  "type": "return",
  "level": 1,
  "points": 4,
  "mode": "call",
  "tags": ["return", "덧셈"],
  "examples": 2,
  "cases": [
    {"call": "solution(1, 2)", "expected": "3"},
    {"call": "solution(10, -3)", "expected": "7"},
    {"call": "solution(100, 200)", "expected": "300"}
  ]
}
```

- `type` 은 `fill`(빈칸 채우기), `return`(반환값), `print`(출력) 중에서 고릅니다.
- `level` 은 1 기본, 2 응용, 3 심화입니다. 세트 안에서 쉬운 것부터 배치합니다.
- `points` 는 level 1 이 4점, level 2 가 6점, level 3 이 8점입니다. 모의고사는 합계 100점에 맞춰 조정합니다.
- `timeout`(선택)은 문제 전체 제한 시간(초)이고 기본은 5초입니다.
- `tags`(필수)에는 묻는 개념 1~3개를 적습니다. 규칙은 퀴즈와 같습니다.
- `examples`(필수)는 문제 본문(problem.md)에 예시로 보여 준 앞쪽 테스트의 수이고 1 이상입니다. 화면의 '코드 실행'은 이만큼만 돌리고, 나머지 테스트는 '회차 제출' 때 채점합니다. 본문의 입출력 예와 `cases` 의 앞부분을 같은 순서로 맞춰 주세요.
- `mode` 와 `cases` 는 아래 표대로 적습니다.

| mode | 테스트 한 건의 형태 | 용도 |
|---|---|---|
| `call` | `{"call": "solution([1, 2])", "expected": "3"}` | 함수 반환값을 검사합니다. `expected` 는 파이썬 리터럴을 담은 문자열입니다(`"[1, 2]"`, `"'abc'"`, `"True"`, `"(1, 2)"`, `"{1: 'a'}"`). 자료형까지 같아야 정답입니다(3 ≠ 3.0, True ≠ 1). 테스트는 3건 이상 둡니다 |
| `io` | `{"stdin": "5\n3\n", "stdout": "8\n"}` | 프로그램 전체를 실행해 표준 출력을 비교합니다. 입력이 없으면 `stdin` 을 생략합니다 |
| `exec` | `{"code": "d = Dog('초코')\nd.bark()", "stdout": "초코: 멍멍\n"}` | 학생 파일을 불러온 뒤 `code` 를 실행해 출력을 비교합니다. 클래스, 출력하는 함수, 리스트를 제자리에서 바꾸는 함수에 씁니다 |

- 파일 처리 문제는 테스트에 `"files": {"data.txt": "내용"}`(실행 전에 만들어 줄 파일), `"expect_files": {"out.txt": "내용"}`(실행 후 있어야 할 파일)을 추가할 수 있습니다. 테스트마다 빈 임시 폴더에서 실행됩니다.
- 출력 비교는 줄 끝 공백과 맨 끝 빈 줄만 무시합니다. 그 밖의 띄어쓰기, 대소문자, 문장부호는 글자 단위로 비교합니다.
- `input("안내 문구")` 의 안내 문구는 출력으로 치지 않습니다. `stdin` 은 `input()` 한 번에 한 줄씩 소비됩니다.
- `call`·`exec` 모드에서는 파일을 불러올 때 나온 출력은 버리고, `if __name__ == "__main__":` 블록은 실행되지 않습니다.

### starter.py 관례

반환값 문제는 프로그래머스처럼 `solution` 함수 뼈대를 줍니다.

```python
def solution(a, b):
    answer = 0
    return answer
```

출력 문제는 주어진 데이터가 있으면 적어 주고, 나머지는 학생이 작성합니다.

```python
# 여기에 코드를 작성하세요
```

빈칸 채우기는 완성된 프로그램에서 묻고 싶은 부분만 `____`(밑줄 4개)로 비웁니다.

```python
name = input()
print("안녕하세요,", ____)
```

- 빈칸은 한 문제에 1~3개이고, 빈칸마다 한 줄 안에서 채워집니다. 여러 줄에 걸친 빈칸은 만들 수 없습니다.
- 채점은 빈칸 밖의 줄을 건드리지 않았는지와 테스트 통과 여부를 봅니다. 동작이 맞으면 어떤 표현이든 정답입니다.
- 빈칸 채우기가 아닌 문제의 starter 에는 `____` 를 쓰지 않습니다.
- 빈칸 채우기의 `problem.md` 에는 starter.py 내용을 코드 블록으로 싣습니다. 문제 설명만 읽어도 풀 수 있고 GitHub 에서 바로 보입니다.

### problem.md

```markdown
# p02. 두 수의 합 (반환값 · 4점)

정수 `a`, `b` 가 주어질 때, 두 수의 합을 **반환(return)** 하는 `solution` 함수를 완성하세요.

## 제한 사항
- -1000 ≤ a, b ≤ 1000

## 입출력 예

| a | b | 반환값 |
|---|---|---|
| 1 | 2 | 3 |
| 10 | -3 | 7 |
```

- 무엇을 반환하거나 출력해야 하는지, 형식(자료형, 띄어쓰기, 줄바꿈)을 예시로 분명히 보여 줍니다.
- 출력 문제는 출력 예를 코드 블록으로 보여 줍니다.

### solution.py · explain.md

- `solution.py` 는 그 차시까지 배운 문법만으로 쓴 모범 답안입니다. 빈칸 채우기는 starter 에서 빈칸만 채운 형태로 씁니다.
- `explain.md` 는 접근 방법, 묻는 개념, 흔한 실수 순으로 짧게 씁니다.

## 6. 출제 원칙

문제는 실제 평가 조건을 흉내 냅니다. 유형, 범위, 채점, 금지 항목은 [README 의 시험 정보](../README.md#시험-정보)에 있습니다. IDE, 자동완성, 레퍼런스, 검색을 쓸 수 없는 시험이라 코드를 눈으로 읽고 머리로 실행해야 풀리는 문제를 냅니다.

1. 해당 차시까지 강의에서 다룬 문법과 개념만 씁니다. 모범 답안도 마찬가지입니다.
2. 강의 연습문제와 과제 가운데 시험에 나올 만한 문제는 그대로 쓰거나 조금 바꿔 써도 됩니다. 새로 만들 때는 같은 개념을 숫자, 이름, 상황을 바꿔 묻습니다. 과제의 문제 형식은 실제 평가 형식의 힌트이므로 형식을 참고합니다.
3. 정답은 하나로 정해져야 합니다. 출력 형식은 예시로 못 박습니다.
4. 그럴듯한 오답(경계값 실수, 초기값 실수, 형 변환 누락)이 통과하지 못하게 경계와 예외 케이스를 테스트에 넣습니다. 시작 코드가 고치지 않은 채로 통과하면 안 됩니다.
5. 난수, 시간, 실행 환경에 따라 결과가 달라지는 문제는 내지 않습니다.
6. 차시 세트 하나의 분량은 퀴즈 20문항 안팎(객관식 10 · 출력 예측 7 · 단답 3), 코드 12문제 안팎(빈칸 4 · 반환값 4 · 출력 4)입니다. 실습이 적은 차시는 퀴즈 비중을 늘립니다. 회차는 단원과 레벨별로 안 푼 문항을 뽑고, 어느 레벨의 문항이 바닥나면 "출제 요청" 이슈에 그 단원과 레벨이 나옵니다.
7. 문제 글은 한국어 존댓말(~하세요, ~입니다)로 쓰고 변수와 함수 이름은 영어로 씁니다.
