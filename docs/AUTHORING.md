# 운영 메모와 출제 규격 (스터디장용)

스터디장이 저장소를 운영하고 문제를 추가하거나 고칠 때 보는 문서입니다. 세트 폴더를 `problems/` 아래에 추가하면 프로그램이 자동으로 인식하고, 코드는 고치지 않아도 됩니다. 알고리즘 여행의 던전 문제(`dungeons/`)는 규격과 검증 절차가 달라서 [JOURNEY_AUTHORING.md](JOURNEY_AUTHORING.md)에, 웹 면접 준비의 미션·사슬·학습 페이지(`web/`)는 [WEB_AUTHORING.md](WEB_AUTHORING.md)에 따로 적었습니다.

## 1. 운영 메모

- 일반 학습자는 저장소를 clone하고 start 파일로 실행합니다. 모델 개발 스터디원은 [본인 fork에서 개발 PR](LEARNING_WORKFLOW.md)을 보냅니다.
- main은 개발 PR로 갱신합니다. 해당 변경에 계획된 검사와 코드 검토를 마친 뒤 Squash로 머지합니다. [변경 파일별 검사 기준](PR_GUIDE.md#변경-파일별-자동-검사)을 따릅니다.
- 학습자는 동의한 뒤 [풀이 제출]을 누르거나 파일 자동 제출을 켜서 풀이 파일을 [비공개 서버](API_SUBMISSIONS.md)로 보낼 수 있습니다.
- 문항이 모자란 단원·레벨과 부족 수를 확인해 출제 요청 이슈에 적습니다. 문제를 추가해 머지하면 다음 프로그램 업데이트 때 함께 받습니다.
- 학습자 본인의 분석은 프로그램에서 확인합니다. 연구용 풀이 분석은 동의 후 수집한 비공개 자료로 진행하며 [수집 항목과 집계 기준](LEARNING_DATA.md)을 따릅니다.
- 문장 검사는 커밋할 때도 돌릴 수 있습니다. 저장소를 받은 컴퓨터에서 `python tools/check_style.py --install-hooks` 를 한 번 실행하면 커밋마다 스테이지에 올린 글과 커밋 메시지를 검사합니다. `.git/hooks` 에 같은 이름의 다른 훅이 이미 있으면 덮어쓰지 않고 그 경로를 알려 줍니다.
- 문제와 도구는 새 개발 브랜치에서 고치세요. 개발 브랜치에서 내 풀이 폴더 밖의 추적 파일을 수정하면 프로그램이 업데이트를 건너뜁니다. `main`이나 기존 `study/*` 브랜치에서 업데이트하면 그런 파일의 수정본을 Git 보관함(`study-backup/`)에 복사한 뒤 배포본을 적용합니다.

저장소는 아래처럼 나뉘어 있습니다.

## 2. 작업 순서

### 기존 세트를 고치거나 문항 더하기

문항을 더할 때는 출제 요청에 적힌 단원·레벨과 부족 수를 확인합니다. 문항을 더하거나 고칠 때는 아래 순서로 진행합니다.

```bash
python tools/seal.py unseal s03      # 정답·해설을 평문으로 풀기
#  quiz.md 와 quiz_key.json, pNN/ 폴더에서 문항을 고치거나 더하기
python tools/verify_bank.py s03      # 검증: 모범 답안 통과, 시작 코드 불통과, 출력 예측을 실제로 실행해 대조
python tools/seal.py seal s03        # 다시 봉인 (평문 삭제)
python tools/seal.py check           # 커밋 전: 평문이 남아 있지 않은지 확인
```

커밋하고 PR 을 올리면 CI 가 문제 은행 전체를 다시 검증합니다.

### 새 세트 만들기

1. `problems/sNN/` 폴더를 만들고 `meta.json`, `README.md` 를 씁니다. 퀴즈와 코드 문제 중 한 유형 이상을 넣습니다.
2. 퀴즈를 내면 `quiz.md`와 `quiz_key.json`을 함께 씁니다.
3. 코드 문제를 내면 `p01/`부터 번호 순서대로 만듭니다.
4. `python tools/verify_bank.py sNN` 이 통과하는지 확인합니다.
5. `python tools/seal.py seal sNN` 과 `python tools/seal.py check` 를 실행한 뒤 커밋하고 PR 을 올립니다.

직접 풀어 보며 점검할 때는 임의 폴더를 채점할 수 있습니다.

```bash
python study.py grade s03 --dir /tmp/my_try    # 폴더 안의 quiz.py, p01.py … 를 채점
```

### 학습 시각화 설계하기

파이썬·알고리즘 여행·AI 개론과 응용·웹 학습의 설명 그림, GIF, 그래프와 도식에 이 기준을 적용합니다. 학습 노트, 코딩 실습, 문항·힌트·해설에서 학습자가 그림으로 알아내야 할 내용을 한 문장으로 정합니다. 기존 그림은 핵심을 찾기 어렵거나 값·관계를 오해할 우려가 있는 것부터 이 기준으로 검토합니다.

[3Blue1Brown 신경망](https://www.3blue1brown.com/lessons/neural-networks/)과 [트랜스포머](https://www.3blue1brown.com/lessons/gpt/)는 하나의 설명 안에서도 구도와 표현을 바꿉니다. 입력 덩어리는 작은 단위로 나뉘고, 넓은 행렬에서는 선택한 열만 밝아집니다. 도식의 벡터와 식에는 같은 기호가 붙고, 여러 계산 결과는 한 눈금으로 옮겨 비교합니다. 참고 장면에서 실제로 보이는 것, 그 요소가 이해에 도움이 되는 이유, 지금 개념에 옮길 때의 한계를 구분해 적습니다. 캡처로는 보이지 않는 움직임과 재생 시간은 영상에서 확인한 경우에만 기록합니다.

| 학습자가 확인할 관계 | 써 볼 표현 | 결과를 점검하는 방법 |
| --- | --- | --- |
| 전체 안에서 한 부분 찾기 | 약한 명암으로 전체를 남기고 테두리·확대·괄호로 필요한 한 부분을 짚습니다. | 확대 뒤에도 원래 행·열·위치와 선택 범위를 찾을 수 있는지 봅니다. |
| 표현은 달라도 같은 값 알아보기 | 실제 예시에서 격자·표·벡터·수식으로 바꿉니다. 이름·기호·연결표시 중 맞는 것으로 대응하는 항을 잇습니다. | 표기 사이의 대응과 단위가 맞는지 확인하고, 예시 좌표·차원 축소·생략 구간은 표시합니다. |
| 익숙한 예와 새 개념 연결하기 | 무엇을 비교하는지 한쪽에 남겨 두거나, 장면을 바꾼 뒤에도 같은 라벨·기준 표시로 다시 찾게 합니다. | 두 예시에서 서로 대응하는 부분과 비유가 성립하는 범위가 드러나는지 확인합니다. |
| 어떤 동작이 상태를 바꾸는지 따라가기 | 바뀌는 칸·범위·연결과 남는 기준점을 또렷하게 보여 줍니다. 전후를 한눈에 비교해야 하면 나란히 놓습니다. | 각 장에서 바뀐 이유와 계산 순서가 읽히는지 확인합니다. 같은 상태를 장식 효과로 반복하지 않습니다. |
| 여러 경우의 차이 비교하기 | 공통 축·영점·눈금을 두고 부호·선 모양·라벨로 사례를 구분합니다. | 범위나 배율을 바꾸면 표시합니다. 강조를 없애도 값, 방향, 예외를 구분할 수 있어야 합니다. |
| 반복·겹침·공간 관계 알아보기 | 반복을 괄호와 생략점으로 묶거나, 가려진 면을 따로 보이게 합니다. 깊이가 관계를 설명할 때 원근이나 3D를 사용할 수 있습니다. | 화면에 실제로 그린 수와 전체 개수를 구분합니다. 보는 각도만 바뀌는 장면, 투영·단면을 보여 주는 장면, 값 자체가 바뀌는 장면을 구별해 표시합니다. 여러 각도에서 라벨이 겹치면 위치를 조정하거나 핵심 항목을 따로 보여 줍니다. |

#### Stitch에 시안 요청하기

아래 양식에서 대괄호를 채웁니다. 공개 출처와 제공할 수 있는 참고 장면, 학습에 필요한 자체 예제만 전달합니다. 학습자가 알아내야 할 답이 있는 화면은 힌트와 해설의 공개 범위를 함께 적습니다.

> [과목·화면·학습자 수준]에서 [학습 후 설명하거나 예측할 것]을 이해하도록 그림을 설계해 주세요. 먼저 [공개 자료 링크와 참고 장면]에서 직접 확인한 구도, 시선 순서, 크기, 명암, 여백, 글자·수식, 색, 선, 표식의 역할을 설명해 주세요. [제가 관찰한 점]도 대조하고, 빠트린 요소나 다르게 읽힌 부분과 그 근거를 적어 주세요. 확인하지 못한 화면이나 움직임은 따로 밝혀 주세요.
>
> 지켜야 할 사실은 [확인한 입력·출력·조건·단위·기호]이고, 화면 제약은 [기본 표시 크기·테마·형식·문제에서 가려야 할 정보]입니다. 정지 그림, 나란히 비교, 단계 애니메이션 중 필요한 형식을 골라 서로 다른 설명 구도를 비교한 뒤 시안과 추천 이유를 주세요. 색·배경·원근·장면의 개수와 배치는 학습 목적에 맞춰 제안해 주세요.
>
> 각 시안에서 장면마다 먼저 볼 대상, 바뀌는 것과 기준점, 표식이 가리키는 뜻, 읽을 핵심 문장, 검산할 결과를 적어 주세요. 작은 창에서 알아보기 어려운 부분이나 오해가 생길 수 있는 부분, 이를 다르게 표현한 방법도 알려 주세요.

처음 보는 사람이 그림으로 목표에 답할 수 있는지 확인한 뒤 안을 고릅니다. 시안에서 제안한 수치와 관계는 출처·실행·계산 결과와 대조합니다. 정답을 가리는 그림은 모든 장면과 반복 경계를 확인합니다. 최종 렌더링에서 캡션과 그림이 같은 상태를 설명하는지, 좁은 창과 큰 글자, 두 테마에서 중요한 부호·눈금·라벨을 읽을 수 있는지 확인합니다. 참고 장면, Stitch 시안, 실제 적용 검증의 결과를 기록합니다. 파일 크기·재생 시간·자료 등록과 서명은 각 과목의 제작 규격을 따릅니다.

## 3. 세트 폴더 구조

```
problems/s03/                 세트 ID: 차시는 sNN, 모의고사 mN, 코딩테스트 cN
├── meta.json                 세트 정보
├── README.md                 개념 정리(자기 말로 요약) + 시험 함정 포인트
├── quiz.md                   퀴즈 문제지 (공개)
├── quiz_key.json             퀴즈 정답·해설 (비공개, 봉인 대상)
├── p01/
│   ├── problem.md            문제 설명 (공개)
│   ├── problem.json          유형·배점·테스트 (공개)
│   ├── starter.py            시작 코드 (공개, 학생이 받아 가는 파일)
│   ├── solution.py           모범 답안 (비공개, 봉인 대상)
│   └── explain.md            해설 (비공개, 봉인 대상)
├── p02/ …                    p01 부터 번호 순서대로
└── sealed.json               비공개 파일 묶음 (seal 도구가 생성, 이것만 커밋)
```

비공개 파일(`quiz_key.json`, `solution.py`, `explain.md`)은 `.gitignore` 로 커밋이 막혀 있고, `python tools/seal.py seal` 이 `sealed.json` 으로 묶습니다. 실수로 미리 보지 않게 가린 것이고 암호화는 아닙니다.

### meta.json

```json
{
  "id": "s03",
  "title": "조건식과 제어문",
  "kind": "session",
  "week": 2
}
```

- `kind` 는 `session`(차시), `codetest`(코딩테스트 트랙), `mock`(모의고사) 중에서 고릅니다.
- `week`(선택)는 `list` 명령에 주차로 나옵니다.
- `priority`(선택)는 단원 중요도입니다. 기본 1.0이고 값이 클수록 회차에 자주 나옵니다. 지금은 9·10·11·13·14차시가 1.5입니다.
- 모의고사는 `"time_limit_min": 120` 을 넣으면 `start` 시점부터 시간을 잽니다.
- `exam`(선택)에 `false`를 넣으면 시험 범위 밖 세트로 보고 회차와 단원 띠에서 뺍니다. 지금은 21차시가 해당합니다. 문항 하나만 뺄 때는 `quiz_key.json`의 문항이나 `problem.json`에 `"exam": false`를 넣습니다. 20차시의 캐스케이드 분류기 이후 문항에 이 값을 씁니다. 이미 만든 회차에 든 문항은 건너뜁니다.

### 퀴즈 규칙

- 객관식 보기는 본문 마지막의 번호 목록(`1.` `2.` …)으로 적습니다. 보기가 코드 블록이면 `**1번**` 문단 뒤에 코드 블록을 두어도 됩니다. 화면은 이 보기들을 답 칸의 카드로 옮기고 본문 칸에는 나머지(지문)만 보여 줍니다.
- 문항 ID 는 `Q1` 부터 순서대로 붙입니다. `quiz.md` 의 `## Q번호` 순서와 `quiz_key.json` 순서가 같아야 합니다.
- `output` 의 `code` 는 `quiz.md` 에 보여 준 코드와 글자 하나까지 같아야 합니다.
- 실행 환경에 따라 달라지는 출력은 내지 않습니다. `id()`, 메모리 주소, `set` 출력 순서, 난수, 현재 시각, 긴 소수 자릿수가 여기에 듭니다.
- 출력 예측 문항의 코드에는 `input("안내 문구")` 를 쓰지 않습니다(채점기는 안내 문구를 출력으로 치지 않아 실제 화면과 달라집니다). 입력이 필요하면 안내 문구 없는 `input()` 만 씁니다.
- 탭 문자(`\t`)가 들어가는 출력은 답안에 적기 모호하므로 출력 예측이 아니라 객관식으로 냅니다.
- "오류가 발생한다" 가 정답인 내용은 `output` 이 아니라 `choice` 로 냅니다.
- `short` 는 답이 토큰 한 개(이름, 키워드, 숫자, 값)로 떨어질 때만 씁니다. 표현이 둘 이상 가능한 코드 조각(`i+1` / `i + 1`)은 단답이 아니라 빈칸 채우기 코드 문제로 냅니다.
- 해설(`explain`)에는 정답 근거와, 헷갈리기 쉬운 오답이 왜 틀렸는지를 1~3문장으로 씁니다.
- 배점은 객관식 2점, 출력 예측 3점, 단답 3점입니다. 회차(진단 포함)에서는 여기에 `level` − 1 을 더한 값을 가중치로 써서 100점을 나눕니다([CRITERIA](CRITERIA.md) 8절).
- `level`(필수)은 1 기본 개념 확인, 2 코드 읽기와 응용, 3 함정과 여러 개념 종합입니다. 프로그램이 이 값으로 문항을 고릅니다.
- `tags`(필수)에는 그 문항이 묻는 개념 1~3개를 짧은 한국어로 적습니다(예: `["elif 순서", "경계값"]`). 같은 세트 안에서는 같은 개념에 같은 표현을 씁니다. 약한 개념 분석에 이 글자가 그대로 나옵니다.
- `ref`(선택)에는 복습할 자료의 위치를 짧은 글의 리스트로 적습니다(예: `["강의 9차시 12쪽", "과제 9차시 3번", "4주차 요약본 9.2"]`). 오답 노트에서는 해설을 펴기 전에도 보이고, 정답과 해설 아래에도 나옵니다. 화면에는 " · " 로 이어 한 줄로 나오니 정답이 드러나는 글은 적지 않습니다.

## 5. 코드 문제 (빈칸 채우기 · 반환값 · 출력)

### problem.json

```json
{
  "title": "두 수의 합",
  "type": "return",
  "level": 1,
  "points": 4,
  "mode": "call",
  "tags": ["return", "덧셈"],
  "examples": 2,
  "cases": [
    {"call": "solution(1, 2)", "expected": "3"},
    {"call": "solution(10, -3)", "expected": "7"},
    {"call": "solution(100, 200)", "expected": "300"}
  ]
}
```

- `type` 은 `fill`(빈칸 채우기), `return`(반환값), `print`(출력) 중에서 고릅니다.
- `level` 은 1 기본, 2 응용, 3 심화입니다. 세트 안에서 쉬운 것부터 배치합니다.
- `points` 는 level 1 이 4점, level 2 가 6점, level 3 이 8점입니다. 모의고사는 합계 100점에 맞춰 조정합니다. 회차(진단 포함)에서는 이 값을 가중치로 그대로 써서 100점을 나눕니다.
- `timeout`(선택)은 문제 전체 제한 시간(초)이고 기본은 5초입니다.
- 문제 하나를 채점하는 동안 메모리를 512MB 넘게 쓰면 오답으로 처리합니다. 이 값은 문제마다 바꿀 수 없습니다.
- `tags`(필수)에는 묻는 개념 1~3개를 적습니다. 규칙은 퀴즈와 같습니다.
- `ref`(선택)는 퀴즈의 `ref` 와 같습니다.
- `examples`(필수)는 문제 본문(problem.md)에 예시로 보여 준 앞쪽 테스트의 수이고 1 이상입니다. 화면의 '코드 실행'은 이만큼만 돌리고, 나머지 테스트는 '회차 제출' 때 채점합니다. 본문의 입출력 예와 `cases` 의 앞부분을 같은 순서로 맞춰 주세요.
- `mode` 와 `cases` 는 아래 표대로 적습니다.

| mode | 테스트 한 건의 형태 | 용도 |
|---|---|---|
| `call` | `{"call": "solution([1, 2])", "expected": "3"}` | 함수 반환값을 검사합니다. `expected` 는 파이썬 리터럴을 담은 문자열입니다(`"[1, 2]"`, `"'abc'"`, `"True"`, `"(1, 2)"`, `"{1: 'a'}"`). 자료형까지 같아야 정답입니다(3 ≠ 3.0, True ≠ 1). 테스트는 3건 이상 둡니다 |
| `io` | `{"stdin": "5\n3\n", "stdout": "8\n"}` | 프로그램 전체를 실행해 표준 출력을 비교합니다. 입력이 없으면 `stdin` 을 생략합니다 |
| `exec` | `{"code": "d = Dog('초코')\nd.bark()", "stdout": "초코: 멍멍\n"}` | 학생 파일을 불러온 뒤 `code` 를 실행해 출력을 비교합니다. 클래스, 출력하는 함수, 리스트를 제자리에서 바꾸는 함수에 씁니다 |

- 파일 처리 문제는 테스트에 `"files": {"data.txt": "내용"}`(실행 전에 만들어 줄 파일), `"expect_files": {"out.txt": "내용"}`(실행 후 있어야 할 파일)을 추가할 수 있습니다. 테스트마다 빈 임시 폴더에서 실행됩니다.
- 출력 비교는 줄 끝 공백과 맨 끝 빈 줄만 무시합니다. 그 밖의 띄어쓰기, 대소문자, 문장부호는 글자 단위로 비교합니다.
- `input("안내 문구")` 의 안내 문구는 출력으로 치지 않습니다. `stdin` 은 `input()` 한 번에 한 줄씩 소비됩니다.
- `call`·`exec` 모드에서는 파일을 불러올 때 나온 출력은 버리고, `if __name__ == "__main__":` 블록은 실행되지 않습니다.

### starter.py 관례

반환값 문제는 프로그래머스처럼 `solution` 함수 뼈대를 줍니다.

```python
def solution(a, b):
    answer = 0
    return answer
```

출력 문제는 주어진 데이터가 있으면 적어 주고, 나머지는 학생이 작성합니다.

```python
# 여기에 코드를 작성하세요
```

빈칸 채우기는 완성된 프로그램에서 묻고 싶은 부분만 `____`(밑줄 4개)로 비웁니다.

```python
name = input()
print("안녕하세요,", ____)
```

- 빈칸은 한 문제에 1~3개이고, 빈칸마다 한 줄 안에서 채워집니다. 여러 줄에 걸친 빈칸은 만들 수 없습니다.
- 채점은 빈칸 밖의 줄을 건드리지 않았는지와 테스트 통과 여부를 봅니다. 동작이 맞으면 어떤 표현이든 정답입니다.
- 빈칸 채우기가 아닌 문제의 starter 에는 `____` 를 쓰지 않습니다.
- 빈칸 채우기의 `problem.md` 에는 starter.py 내용을 코드 블록으로 싣습니다. 문제 설명만 읽어도 풀 수 있고 GitHub 에서 바로 보입니다.

### problem.md

```markdown

정수 `a`, `b` 가 주어질 때, 두 수의 합을 **반환(return)** 하는 `solution` 함수를 완성하세요.

## 입출력 예
```

## 6. 출제 원칙

문제는 실제 평가 조건을 흉내 냅니다. 유형, 범위, 채점, 금지 항목은 [파이썬 시험 정보](../problems/README.md#시험-정보)에 있습니다. IDE, 자동완성, 레퍼런스, 검색을 쓸 수 없는 시험이라 코드를 눈으로 읽고 머리로 실행해야 풀리는 문제를 냅니다.

1. 해당 차시까지 강의에서 다룬 문법과 개념만 씁니다. 모범 답안도 마찬가지입니다.
2. 강의 연습문제와 과제 가운데 시험에 나올 만한 문제는 그대로 쓰거나 조금 바꿔 써도 됩니다. 새로 만들 때는 같은 개념을 숫자, 이름, 상황을 바꿔 묻습니다. 과제의 문제 형식은 실제 평가 형식의 힌트이므로 형식을 참고합니다.
3. 정답은 하나로 정해져야 합니다. 출력 형식은 예시로 못 박습니다.
4. 그럴듯한 오답(경계값 실수, 초기값 실수, 형 변환 누락)이 통과하지 못하게 경계와 예외 케이스를 테스트에 넣습니다. 시작 코드가 고치지 않은 채로 통과하면 안 됩니다.
5. 난수, 시간, 실행 환경에 따라 결과가 달라지는 문제는 내지 않습니다.
6. 차시 세트 하나의 분량은 퀴즈 20문항 안팎(객관식 10 · 출력 예측 7 · 단답 3), 코드 12문제 안팎(빈칸 4 · 반환값 4 · 출력 4)입니다. 실습이 적은 차시는 퀴즈 비중을 늘립니다. 회차는 단원과 레벨별로 안 푼 문항을 뽑고, 문항이 부족하면 회차에 단원·레벨과 부족 수를 기록합니다. 스터디장은 이 내용을 확인해 출제 요청 이슈에 적습니다.
7. 문제 글은 한국어 존댓말(~하세요, ~입니다)로 쓰고 변수와 함수 이름은 영어로 씁니다.
8. 코드 문제와 출력 예측은 파이썬 표준 라이브러리만으로 실행할 수 있게 냅니다. NumPy·pandas·openpyxl처럼 외부 패키지가 있어야 실행되는 예제는 객관식이나 단답으로 냅니다. 20차시의 좌표 계산처럼 표준 문법으로 옮길 수 있는 부분은 출력 예측으로 낼 수 있습니다. 검증 도구는 객관식과 단답의 정답을 실행해 보지 않으므로, 패키지를 설치한 환경에서 보기와 정답을 직접 실행해 확인합니다. 라이브러리 버전이나 운영체제에 따라 달라지는 표기(자료형 이름, 경로 구분자, 폴더 목록의 순서)는 정답으로 삼지 않습니다.
