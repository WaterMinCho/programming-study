# 모델 코드에 피드백을 남깁니다

팀원은 작은 PR로 직접 구현한 부분과 실행 결과, 궁금한 점을 공유합니다. WaterMinCho가 이 맥의 구독 Claude Code로 검토 초안을 만들고 파일·줄·주장을 확인한 뒤 PR에 게시합니다. 학생의 코드를 대신 완성하거나 팀원 PR을 자동으로 승인·머지하지 않습니다. PR 등록만으로 실행하는 서버나 예약 작업은 설정하지 않습니다.

## 공개 사례에서 가져온 기준입니다

2026년 11월 10일에 공식 기업 글·제품 문서·기업 연구자의 논문을 대조했습니다. 아래는 우리 팀이 적용할 기준입니다. 모든 기업의 내부 설정을 확인한 결과는 아닙니다. 제품이 제공하는 기능과 해당 기업이 실제로 운영한 사례를 구분했습니다.

## 이번 변경에 필요한 점만 확인합니다

| 바꾼 부분 | 확인할 내용 | 작성자가 설명해볼 질문 예시 |
|---|---|---|
| 자료·입력 | 예측 시점, 학습·검증·평가 구분, 전처리 기준을 구한 자료, 문항 판 | 이번 문제의 정답은 어느 칸에 있으며 모델 입력에서 어떻게 분리했나요? |
| 모델 | 배열 모양, 빈 자리와 실제 이력, 현재 문제 정보, 손실 함수의 입력 | 과거 이력이 없는 사람에게도 유효한 예측을 만들 수 있나요? |
| 학습 | 기울기 초기화·누적·갱신, 학습과 평가 모드 | 기울기를 초기화하지 않으면 이번 실험의 계산은 어떻게 달라지나요? |
| 평가·저장 | 같은 자료·설정의 기준 비교, 모델 불러오기, 재현 조건 | 학습 오차가 줄었는데 평가 오차가 커졌다면 무엇을 확인하겠나요? |
| 간격 | 같은 개념의 이전 공개 결과, 시각 미확인 값, 시간 단위와 변환 | 간격 0과 간격 미확인을 어떻게 구분했나요? |

이 목록을 모든 PR에 그대로 댓글로 붙이지 않습니다. 이번 변경과 관련된 항목만 봅니다. 과거 이력용 `mask`와 이번 예시의 정답표 `targets`를 구분합니다. 사용하는 함수마다 손실과 가림의 입력 조건도 대조합니다.

## 지적과 학습 질문을 구분합니다

확인한 결함에는 파일·줄·발생 입력, 현재 동작과 기대 동작, 영향, 직접 근거와 최소 수정 힌트를 붙입니다. 실행하지 않은 검사는 실행 확인이 필요하다고 적습니다. 근거가 부족하면 결함으로 단정하지 않고 확인 질문으로 남깁니다. 이름·문장 취향 같은 선택 제안은 결과를 바꾸는 오류보다 뒤에 둡니다.

주요 지적은 기본 3개를 먼저 보여주고 이해 확인 질문은 2개 이하로 둡니다. 확인한 중대 결함은 개수 제한 때문에 숨기지 않습니다. 잘 구현한 부분도 해당 코드의 근거가 있을 때 적습니다. 완성 모델이나 전체 패치를 대신 쓰지 않고 작은 입력과 수정 힌트를 먼저 제안합니다.

아래는 실제 PR의 지적이 아닌 작성 예시입니다.

> Q17을 예측하는 입력에 Q17의 정오답이 함께 들어가는 경로를 정적으로 확인했음. 답을 이미 알려준 예측이 되어 평가 조건을 바꿈. 정오답은 정답표에 남기고 입력에서 분리하는 방향으로 고쳐볼 수 있음. 이전 기록과 이번 정답을 각각 출력해 두 칸이 나뉘는지 확인해 주세요. 결과가 공개된 뒤 다음 회차에서는 이 기록을 어떤 조건으로 사용할 수 있는지도 설명해 주세요.

팀원은 `REVIEW_NOTES.md`에 댓글 링크, 채택·기각·보류 여부와 이유, 직접 실행한 결과를 남깁니다. 검토자와 모델의 의견이 같아도 실행이나 코드 근거 없이 확정하지 않습니다.

## 검토 자료를 먼저 고정합니다

저장소 루트에서 운영자가 실행합니다. `123`은 실제 검토할 PR 번호로 바꿉니다. 출력은 공개 저장소 밖의 새 비공개 폴더에 저장합니다. 같은 폴더를 덮어쓰지 않습니다.

```sh
python tools/learning_review.py prepare --pr 123 --out "$HOME/.rokey-collector/reviews/pr-123-v1"
```

이 명령은 PR의 base·head·분기점 SHA와 변경분, 관련 문맥을 고정합니다. SHA는 코드 판을 구분하는 값입니다. 변경분과 분기점은 같은 base·head 쌍의 비교에서 가져옵니다. 기본 문맥은 고정한 main 판의 담당 문서와 검토 판의 공통 입력 코드입니다. 필요한 호출부나 테스트는 `--context experiments/michae18/train.py`처럼 추가합니다. 기본 파일을 포함해 문맥은 5개 이하로 제한합니다.

전송 전에 `snapshot.json`을 직접 읽고 개인정보·원본 답안·인증 값이 없는지 확인합니다. 정적 검사는 개인 풀이 경로·데이터·모델 파일과 흔한 비밀 패턴을 막지만 모든 노출을 탐지한다고 보장하지 않습니다. 그림 파일은 경로만 포함하며 내용은 읽지 않습니다. 노트북은 출력과 메타데이터가 섞일 수 있어 이 도구의 입력에서 제외합니다. 필요한 코드를 텍스트 파일로 정리해 검토합니다.

## 초안은 게시와 별도로 만듭니다

```sh
python tools/learning_review.py review --from "$HOME/.rokey-collector/reviews/pr-123-v1"
```

구독 계정 로그인을 확인한 뒤 고정한 텍스트만 Claude Code에 전달합니다. 로컬 실행이라도 모델 제공자에게 텍스트가 전송됩니다. 사용자 지침·설치한 플러그인·hook을 읽지 않는 safe mode와 빈 설정 목록을 사용합니다. 내장 도구·추가 MCP 연결·자동 명령 확장도 끕니다. 관리자가 강제한 정책은 CLI에 계속 적용됩니다. PR의 코드나 주석 속 명령을 실행할 지시로 취급하지 않습니다. 검토 과정에서 모델 학습·프로그램 실행·코드 수정은 하지 않습니다. 이런 제한을 운영체제 전체의 통신 차단으로 설명하지 않습니다.

검토 프로세스에는 경로·언어·사용자 홈 등 실행에 필요한 환경값만 전달합니다. 인증 확인과 검토 호출에 같은 격리 옵션을 사용합니다. API 키와 별도 제공자 환경 설정은 전달하지 않습니다. 한도·만료·오류가 있으면 중단하며 유료 API로 자동 전환하지 않습니다. 계정의 추가 사용 과금과 데이터 보존 설정은 운영자가 별도로 확인합니다. `--no-session-persistence`는 로컬 세션 저장을 끄는 옵션이며 공급자의 보존까지 끄지 않습니다.

응답의 초기화 정보에서 도구·MCP·명령 확장이 비어 있고 API 키를 사용하지 않았는지 확인한 뒤 `feedback.md`를 저장합니다. 정보가 다르거나 빠졌다면 게시할 초안을 남기지 않습니다. `review.json`에는 CLI 버전과 실제 응답의 모델 이름·사용량·시간, 초기화 확인 결과를 기록합니다. 운영자는 파일·줄·근거·수정 힌트·문장을 직접 확인합니다. 검토 도구가 시험 코드를 실행했다고 해석하지 않습니다. 정적 검토로 확인할 수 없는 실행 결과는 작성자의 로그나 필요한 검사로 따로 확인합니다.

## 확인한 피드백만 PR에 게시합니다

```sh
python tools/learning_review.py post --from "$HOME/.rokey-collector/reviews/pr-123-v1"
```

이 명령을 직접 실행한 때만 댓글을 게시하고 저장된 본문을 다시 읽어 대조합니다. 게시 전 본문을 다듬을 수 있지만 맨 위의 검토 판 표시는 유지합니다. 이 도구는 `WaterMinCho/programming-study`의 팀원 개발 PR만 다루며 `study/<ID>` 풀이 PR은 제외합니다. 승인·머지 명령은 실행하지 않습니다.

게시 시작을 먼저 기록해 같은 폴더에서 중복 전송하지 않습니다. 댓글 번호를 받은 뒤 확인 읽기에 실패하면 다음 실행에서 그 댓글만 다시 확인합니다. 그사이 PR 판이 바뀌어 중단되면 `comment.json`의 번호로 기존 댓글부터 확인합니다. 전송 응답을 잃어 댓글 번호를 모르면 자동 재전송하지 않고 운영자에게 확인을 요청합니다.

준비·검토 완료·게시 전에 PR 판을 비교합니다. head나 base가 바뀌면 게시를 보류하고 새 폴더에서 자료를 다시 고정합니다. 기본 검토 뒤에는 수정한 부분과 미해결 지적을 중심으로 한 번 재검토합니다. 새 실패나 문맥 변경이 있으면 해당 범위만 더 확인합니다. 같은 코드·입력·환경에서 통과한 전체 검사를 반복하지 않습니다.
