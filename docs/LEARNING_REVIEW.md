# 모델 PR 코드 리뷰와 수정 요청

<a id="모델-pr의-코드-검토와-수정-요청을-확인합니다"></a>

팀원은 본인 fork의 `experiments/본인ID/`에서 코드를 만들고 공통 저장소로 PR을 보냅니다. 검토는 `michae18`, `wamangdoo`, `kimjs85529-a11y`가 만든 main 대상 개발 PR에 자동으로 시작합니다. 초안과 풀이 제출 PR은 제외합니다.

이 맥이 켜져 있고 구독 CLI와 GitHub 로그인이 유효할 때 동작합니다. Mac이 꺼져 있거나 구독 한도·인증 문제가 있으면 검토가 대기하거나 중단됩니다. 유료 API로 전환하지 않습니다. `스터디 코드 검토` 상태와 PR 리뷰에서 결과를 확인합니다.

| 결과 | 팀원이 할 일 |
|---|---|
| 승인 | 현재 커밋의 검토가 끝났습니다. CI 결과를 확인하고 운영자의 머지를 기다립니다. |
| 수정 요청 | 표시된 파일·줄과 작은 확인 입력을 보고 같은 브랜치에서 수정한 뒤 Push합니다. |
| 추가 확인 | 실행 명령·관측 결과·설계 이유를 PR 본문이나 댓글로 설명합니다. 설명이 부족하면 승인을 보류합니다. |
| 검토 중단 | 구독·인증·지원하지 않는 파일을 운영자가 확인합니다. 검토되지 않은 코드를 통과로 표시하지 않습니다. |

검토는 변경 코드와 제한한 문맥을 읽는 정적 검토입니다. 포크의 코드를 실행하거나 모델을 대신 만들지 않습니다. 검사를 통과해도 모델 성능과 실제 학습 효과가 검증됐다는 뜻은 아닙니다. 팀원 PR은 자동으로 머지하지 않습니다.

<a id="피드백에는-근거와-확인할-입력을-남깁니다"></a>

## 리뷰에서 확인할 입력과 오류 사례

정답 누출, 학습·평가 분리, mask와 데이터 모양, 손실 계산, 저장·불러오기처럼 결과를 바꾸는 문제를 우선합니다. 취향에 따른 포맷 변경을 늘리지 않습니다. 정답 코드를 대신 작성하지 않습니다.

피드백은 이번 변경의 결론과 확인 범위부터 짧게 적습니다. 수정할 항목은 행동 제목과 파일·줄 링크로 구분합니다. 현재 어떤 내용이 왜 문제인지, 어떤 조건에서 확인할지를 펼쳐 보여 줍니다. 코드 인용과 추가 수정 힌트는 필요할 때 열 수 있습니다. 낯선 용어는 실제 값이나 동작으로 풀어 설명합니다.

「수정 필요」는 지금 고칠 결함입니다. 승인 조건과 무관한 「선택 제안」은 접힌 영역에서 확인하고 반영할지 본인이 판단합니다. 수정 요청에는 같은 브랜치로 올리는 짧은 안내와 사용법 링크를 붙입니다. 확인 질문에는 댓글로 답합니다. 승인 리뷰는 별도의 질문이나 다음 모델 구현 과제를 기본으로 붙이지 않습니다. 파일을 고쳤다면 Commit으로 컴퓨터에 기록하고 Push로 본인 GitHub fork에 보냅니다. 같은 브랜치로 보내면 기존 PR에 추가되므로 새 PR을 만들지 않습니다. PR 설명글 수정은 GitHub의 Edit에서 처리합니다. [수정 커밋 올리는 순서](LEARNING_WORKFLOW.md#리뷰-질문에-답하고-수정한-커밋-남기기)를 따라 진행하세요.

프로그램·서버·공통 자료를 바꾸는 PR이나 큰 변경은 운영자가 직접 확인합니다. 자동 승인은 본인의 모델 폴더 안에서 제한한 텍스트 파일만 바꾼 작은 PR에 한정합니다. 검토 자료가 바뀌거나 실행 근거가 부족하면 승인을 보류합니다. [첫 PR 안내](LEARNING_WORKFLOW.md) · [담당별 미션](LEARNING_MISSIONS.md)

## 운영자용 검토기 설치와 실행

main을 최신으로 받은 뒤 저장소 루트에서 실행합니다. GitHub 쓰기 권한과 구독 계정 로그인이 필요합니다.

```sh
python3 tools/study_review_worker.py --once
python3 tools/study_review_worker.py --install
```

`--once`는 현재 대상 PR을 한 번 처리하며, 조건을 충족하면 GitHub에 검토 상태와 리뷰를 게시합니다. `--install`은 이 맥에 1분 간격의 실행기를 등록합니다. GitHub Actions의 실행기로 포크 코드를 내려받지 않습니다. 검토 자료·처리 상태·로그는 `~/.rokey-collector/review-worker/`에 비공개로 보관합니다. 게시 문장은 안내체로 작성하고 내부 판정·실행 기록은 별도로 남깁니다. 이전 형식으로 저장한 응답과 게시 확인 기록도 복구할 수 있게 유지합니다.

설치할 때 신뢰한 main의 검토 실행 코드만 `~/.rokey-collector/review-worker/runtime/<내용 SHA-256>/`에 복사합니다. 파일별 해시·크기를 `manifest.json`에 기록하고 원본과 저장한 바이트를 대조합니다. 실행기는 이 폴더를 작업 경로로 사용합니다. 풀이·계정 설정·Git 상태는 복사하지 않으며 macOS 보호 설정을 바꾸지 않습니다. 코드 폴더와 운영 폴더는 권한 700, 코드·설정·로그 파일은 600으로 보관합니다.

main을 갱신한 뒤에는 `--install`을 다시 실행해야 새 코드가 자동 실행에 반영됩니다. 내용이 같으면 기존 복사본을 검증해 사용하고 내용이 바뀌면 새 해시 폴더를 만듭니다. 기존 복사본을 덮어쓰지 않습니다. 다른 운영 폴더를 쓰려면 `--install --root /비공개/절대경로`로 지정합니다. 처리 상태·로그·실행 코드가 함께 그 경로를 사용하며 수동 실행에도 같은 `--root`를 지정합니다.

작업을 멈출 때는 다음 명령을 실행합니다. 다시 켜려면 위의 `--install`을 사용합니다.

```sh
launchctl bootout gui/$(id -u)/com.rokey.study-review
```

PR의 head·base·분기점을 고정하고 게시 직전에 다시 비교합니다. 같은 PR의 직전 리뷰는 과거 의견으로 함께 고정하되, 자체 리뷰 게시만으로 새 검토가 시작되지는 않습니다. 과거 리뷰를 현재 코드의 정답 근거로 취급하지 않습니다. 과거 리뷰에 공유할 수 없는 값이 있거나 자료 크기를 넘기면 해당 참고만 제외하고 자동 승인은 보류합니다. 이전 리뷰와 처리 상태를 대조해 중복 게시를 막습니다. 게시 응답을 잃고 원격 리뷰도 확인하지 못하면 자동 재게시하지 않습니다. 운영자는 해당 PR의 리뷰와 비공개 처리 상태를 먼저 대조합니다.

## 변경한 코드에 따른 검토 범위

설명·설정만 바꾸면 입력 이해와 설명의 정확성을 확인합니다. 모델 코드에서는 바뀐 배열·예측을, 학습·평가 코드에서는 해당 실행 근거를 확인합니다. 아직 제출하지 않은 다음 단계 구현이나 관련 없는 문제 은행·화면 검사를 요구하지 않습니다. 공통 구조를 바꿀 제안은 지금 발생하는 결함과 나누어 이유를 설명합니다. 프로그램 문서용 문장 패턴을 모델 설명의 승인 조건으로 사용하지 않습니다. 자동 검사의 구분은 [PR 검사 기준](PR_GUIDE.md#변경-파일별-자동-검사)을 따릅니다.


| 바꾼 부분 | 확인할 내용 | 작성자가 설명해볼 질문 예시 |
|---|---|---|
| 자료·입력 | 예측 시점, 학습·검증·평가 구분, 전처리 기준을 구한 자료, 문항 버전 | 이번 문제의 정답은 어느 칸에 있으며 모델 입력에서 어떻게 분리했나요? |
| 모델 | 배열 모양, 빈 자리와 실제 이력, 현재 문제 정보, 손실 함수의 입력 | 과거 이력이 없는 사람에게도 유효한 예측을 만들 수 있나요? |
| 학습 | 기울기 초기화·누적·갱신, 학습과 평가 모드 | 기울기를 초기화하지 않으면 이번 실험의 계산은 어떻게 달라지나요? |
| 평가·저장 | 같은 자료·설정의 기준 비교, 모델 불러오기, 재현 조건 | 학습 오차가 줄었는데 평가 오차가 커졌다면 무엇을 확인하겠나요? |
| 간격 | 같은 개념의 이전 공개 결과, 시각 미확인 값, 시간 단위와 변환 | 간격 0과 간격 미확인을 어떻게 구분했나요? |

이 목록을 모든 PR에 그대로 댓글로 붙이지 않습니다. 이번 변경과 관련된 항목만 봅니다. 과거 이력용 `mask`와 이번 예시의 정답표 `targets`를 구분합니다. 사용하는 함수마다 손실과 가림의 입력 조건도 대조합니다.

## 수정 요청과 학습 질문의 차이

확인한 결함에는 파일·줄·발생 입력, 현재 동작과 기대 동작, 영향, 직접 근거와 최소 수정 힌트를 붙입니다. 실행하지 않은 검사는 실행 확인이 필요하다고 적습니다. 근거가 부족하면 결함으로 단정하지 않고 확인 질문으로 남깁니다. 이름·문장 취향 같은 선택 제안은 결과를 바꾸는 오류보다 뒤에 둡니다.

결과를 바꾸는 결함부터 보여 줍니다. 선택 제안은 이번 변경에 필요한 경우만 짧게 적고, 확인 질문은 현재 PR의 판단에 필요한 내용으로 한정합니다. 확인한 결함을 글자 수에 맞춰 자르지 않습니다. 게시 상한을 넘으면 글을 잘라 올리지 않고 운영자가 범위를 확인합니다. 잘 구현한 부분은 코드 근거가 있을 때 적습니다. 완성 모델·전체 패치·교체할 문단을 대신 쓰지 않고 작은 확인 입력과 수정 방향을 남깁니다. 이전 리뷰의 선택 제안이나 해결된 내용을 새 근거 없이 반복하지 않습니다.

아래는 실제 PR의 지적이 아닌 작성 예시입니다.

> README의 입력 목록 한 곳을 실제 출력과 맞춰 주세요. mask와 정답표 설명은 코드와 맞습니다.
>
> 입력 확인 명령을 실행하면 15개 항목을 만드는데 문서에는 9개만 있다고 적혀 있습니다. 이 설명으로 입력을 준비하면 일부 항목을 빠뜨릴 수 있습니다.
>
> 확인: 같은 명령의 출력에서 입력 항목 이름을 문서와 비교해 주세요. 어떤 항목을 모델에 쓸지는 본인이 정하고 이유를 남겨 주세요.

팀원은 이번 수정과 관련된 판단·직접 실행한 결과를 `REVIEW_NOTES.md`에 남깁니다. 선택 제안은 필요할 때 검토하고 채택한 경우 이유를 함께 적습니다. 검토자와 모델의 의견이 같아도 실행이나 코드 근거 없이 확정하지 않습니다.

## 운영자의 수동 리뷰 절차

### 검토 자료를 먼저 고정합니다

저장소 루트에서 운영자가 실행합니다. `123`은 실제 검토할 PR 번호로 바꿉니다. 출력은 공개 저장소 밖의 새 비공개 폴더에 저장합니다. 같은 폴더를 덮어쓰지 않습니다.

```sh
python tools/learning_review.py prepare --pr 123 --out "$HOME/.rokey-collector/reviews/pr-123-v1"
```

이 명령은 PR의 base·head·분기점 SHA와 변경분, 관련 문맥을 고정합니다. SHA는 커밋을 구분하는 값입니다. 변경분과 분기점은 같은 base·head 쌍의 비교에서 가져옵니다. 기본 문맥은 고정한 main 커밋의 담당 문서와 검토 커밋의 공통 입력 코드입니다. 필요한 호출부나 테스트는 `--context experiments/michae18/train.py`처럼 추가합니다. 기본 파일을 포함해 문맥은 5개 이하로 제한합니다.

전송 전에 `snapshot.json`을 직접 읽고 개인정보·원본 답안·인증 값이 없는지 확인합니다. 정적 검사는 개인 풀이 경로·데이터·모델 파일과 흔한 비밀 패턴을 막지만 모든 노출을 탐지한다고 보장하지 않습니다. 그림 파일은 경로만 포함하며 내용은 읽지 않습니다. 노트북은 출력과 메타데이터가 섞일 수 있어 이 도구의 입력에서 제외합니다. 필요한 코드를 텍스트 파일로 정리해 검토합니다.

### 초안은 게시와 별도로 만듭니다

```sh
python tools/learning_review.py review --from "$HOME/.rokey-collector/reviews/pr-123-v1"
```

구독 계정 로그인을 확인한 뒤 고정한 텍스트만 Claude Code에 전달합니다. 로컬 실행이라도 모델 제공자에게 텍스트가 전송됩니다. 사용자 지침·설치한 플러그인·hook을 읽지 않는 safe mode와 빈 설정 목록을 사용합니다. 코드 실행 도구·추가 MCP 연결·자동 명령 확장도 끕니다. 구조화 응답에는 출력 형식만 맞추는 내부 도구를 허용합니다. 관리자가 강제한 정책은 CLI에 계속 적용됩니다. PR의 코드나 주석 속 명령을 실행할 지시로 취급하지 않습니다. 검토 과정에서 모델 학습·프로그램 실행·코드 수정은 하지 않습니다. 이런 제한을 운영체제 전체의 통신 차단으로 설명하지 않습니다.

검토 프로세스에는 경로·언어·사용자 홈 등 실행에 필요한 환경값만 전달합니다. 인증 확인과 검토 호출에 같은 격리 옵션을 사용합니다. API 키와 별도 제공자 환경 설정은 전달하지 않습니다. 한도·만료·오류가 있으면 중단하며 유료 API로 자동 전환하지 않습니다. 계정의 추가 사용 과금과 데이터 보존 설정은 운영자가 별도로 확인합니다. `--no-session-persistence`는 로컬 세션 저장을 끄는 옵션이며 공급자의 보존까지 끄지 않습니다.

응답의 초기화 정보에서 코드 실행 도구·MCP·명령 확장이 꺼져 있고 API 키를 사용하지 않았는지 확인한 뒤 `feedback.md`를 저장합니다. 정보가 다르거나 빠졌다면 게시할 초안을 남기지 않습니다. `review.json`에는 CLI 버전과 실제 응답의 모델 이름·사용량·시간, 초기화 확인 결과를 기록합니다. 운영자는 파일·줄·근거·수정 힌트·문장을 직접 확인합니다. 검토 도구가 시험 코드를 실행했다고 해석하지 않습니다. 정적 검토로 확인할 수 없는 실행 결과는 작성자의 로그나 필요한 검사로 따로 확인합니다.

### 확인한 피드백만 PR에 게시합니다

```sh
python tools/learning_review.py post --from "$HOME/.rokey-collector/reviews/pr-123-v1"
```

이 명령을 직접 실행한 때만 댓글을 게시하고 저장된 본문을 다시 읽어 대조합니다. 게시 전 본문을 다듬을 수 있지만 맨 위의 검토 커밋 표시는 유지합니다. 이 도구는 `WaterMinCho/programming-study`의 팀원 개발 PR만 다루며 `study/<ID>` 풀이 PR은 제외합니다. 승인·머지 명령은 실행하지 않습니다.

게시 시작을 먼저 기록해 같은 폴더에서 중복 전송하지 않습니다. 댓글 번호를 받은 뒤 확인 읽기에 실패하면 다음 실행에서 그 댓글만 다시 확인합니다. 그사이 PR 커밋이 바뀌어 중단되면 `comment.json`의 번호로 기존 댓글부터 확인합니다. 전송 응답을 잃어 댓글 번호를 모르면 자동 재전송하지 않고 운영자에게 확인을 요청합니다.

준비·검토 완료·게시 전에 PR 커밋을 비교합니다. head나 base가 바뀌면 게시를 보류하고 새 폴더에서 자료를 다시 고정합니다. 기본 검토 뒤에는 수정한 부분과 미해결 지적을 중심으로 한 번 재검토합니다. 새 실패나 문맥 변경이 있으면 해당 범위만 더 확인합니다. 같은 코드·입력·환경에서 통과한 전체 검사를 반복하지 않습니다.
