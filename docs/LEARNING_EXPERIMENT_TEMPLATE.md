# 모델 실험 기록 양식

<a id="모델-실험-기록을-시작합니다"></a>

본인 fork의 `experiments/본인GitHubID/`에 있는 기존 README나 실험 노트에 복사해 빈 항목을 채웁니다. 예상과 실행 결과를 구분하고 아직 측정하지 않은 값은 비워 둡니다.

<a id="무엇을-확인하나요"></a>

## 예측할 값과 모델을 고른 이유

어떤 입력으로 무엇을 예측하나요? 이 모델이나 설정을 고른 이유는 무엇인가요?

## 직접 구현한 부분

본인이 만든 코드와 참고한 코드를 구분합니다. 다른 팀원의 기본 모델을 사용하면 원본 코드 경로·전체 커밋 SHA와 바꾼 부분을 적습니다.

## 실행 조건

| 항목 | 실제 사용한 값 |
|---|---|
| 본인 fork·작업 브랜치·전체 커밋 SHA | |
| 자료 버전·전달 묶음 이름과 합성·실제 구분 | |
| 학습·검증·평가 구분 | |
| 샘플 구간·건수·시드·이력 길이 | |
| 모델 설정·난수 시드 | |
| 라이브러리·장비 | |

공개 기록에는 합성 자료의 재현 방법을 적습니다. 실제 자료의 상세 목록·해시·번호표·가중치는 비공개로 전달합니다.

## 다른 사람이 실행할 방법

설치, 입력 준비, 학습, 저장, 새 프로세스에서 불러오기, 예측 순서로 실제 사용한 명령을 적습니다. 입력 파일 확인·샘플 테스트와 실제 모델 예측·학습을 구분합니다. 실행하지 않은 단계는 미실행으로 적습니다.

## 결과와 오류 사례

관측한 수치와 실패 입력을 적습니다. 비교 대상과 조건이 같았나요? 원인으로 확인한 사실과 아직 추정하는 설명은 무엇인가요?

<a id="코드를-설명해-봅니다"></a>

## 입력 처리부터 학습·예측까지 내 코드 설명

입력과 이번 정답은 어떻게 나눴나요? 빈 이력과 빈 자리는 어떻게 처리했나요? 손실·역전파·갱신·평가·저장 후 예측이 어느 코드에서 이어지나요?

## 질문을 받고 바꾼 부분

이슈·PR 링크, 받은 질문, 반영 여부와 이유, 수정 커밋, 다시 실행한 결과를 적습니다. 배운 점은 실제로 바꾼 코드나 확인한 동작과 연결합니다.
