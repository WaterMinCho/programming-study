# 모델 실험 기록 양식

<a id="모델-실험-기록을-시작합니다"></a>

본인 fork의 `experiments/본인GitHubID/`에 있는 기존 README나 실험 노트에 복사해 빈 항목을 채웁니다. 예상과 실행 결과를 구분하고 아직 측정하지 않은 값은 비워 둡니다.

<a id="무엇을-확인하나요"></a>

## 예측할 값과 모델을 고른 이유

어떤 입력으로 무엇을 예측하나요? 이 모델이나 설정을 고른 이유는 무엇인가요?

## 직접 구현한 부분

본인이 만든 코드와 참고한 코드를 구분합니다. 다른 팀원의 기본 모델을 사용하면 원본 코드 경로·전체 커밋 SHA와 바꾼 부분을 적습니다.

## 실행 조건

| 항목 | 실제 사용한 값 |
|---|---|
| 본인 fork·작업 브랜치·전체 커밋 SHA | |
| 맞춰 받은 공통 `main` 전체 커밋 SHA | |
| 묶음 `manifest.json` SHA-256 | |
| `features_version`, 번호표 `question_min_count`, 끼운 변형 행을 뺐는지 | |
| 자료 전달 묶음 이름과 합성·실제 구분 | |
| 과목과 학습·검증·평가 구분 | |
| 샘플 구간·건수·시드·이력 길이 | |
| 모델 설정(`hidden_size`, 임베딩 차원, 파라미터 수)과 초기화 시드 | |
| Python 버전과 PyTorch 버전(`torch.__version__` 출력값) | |
| OS와 장비(CPU·GPU) | |

공개 기록에는 합성 자료의 재현 방법을 적습니다. 실제 자료의 상세 목록·해시·번호표·가중치는 비공개로 전달합니다.

## 다른 사람이 실행할 방법

설치, 입력 준비, 학습, 저장, 새 프로세스에서 불러오기, 예측 순서로 실제 사용한 명령을 적습니다. 입력 파일 확인·샘플 테스트와 실제 모델 예측·학습을 구분합니다. 실행하지 않은 단계는 미실행으로 적습니다.

## 결과와 오류 사례

관측한 수치와 실패 입력을 적습니다. 비교 대상과 조건이 같았나요? 원인으로 확인한 사실과 아직 추정하는 설명은 무엇인가요?

수치는 [채점 명령](LEARNING_STARTER.md#예측-파일-채점)이 낸 표를 그대로 붙입니다. 모델 값만 따로 적지 않습니다.

| 항목 | 적을 값 |
|---|---|
| 채점한 구간과 명령 | 예: `--track ai --split validation` |
| 구간의 행 수·오답 수·가명 수 | |
| 모델과 기준선 여섯 개의 로그 손실·Brier·ROC-AUC·정확도 | 표를 붙입니다 |
| 각 값의 행 독립 표준오차와 가명 묶음 표준오차 | 표에 함께 나옵니다 |
| 로그 손실이 가장 낮은 기준선의 이름 | |
| 모델 로그 손실에서 그 기준선 로그 손실을 뺀 값. 음수면 모델이 낫습니다. | |
| 경고 문구 | 나왔으면 지우지 않고 그대로 둡니다 |

경고가 나온 구간의 결과는 "실행 확인"으로 적고 모델 우열의 근거로 쓰지 않습니다. 실제 자료는 푼 사람이 몇 명뿐이라서 평가 구간의 결과를 새 학습자에게도 맞는다는 근거로 쓰지 않습니다. 실제 자료에서 가명이 3개보다 적은 구간은 가명 수를 적지 않고 "3개보다 적음"으로 적습니다. 합성 자료로 낸 수치는 합성 자료라고 함께 적습니다. 자료 버전이 다른 결과는 다른 표에 적습니다.

<a id="코드를-설명해-봅니다"></a>

## 입력 처리부터 학습·예측까지 내 코드 설명

입력과 이번 정답은 어떻게 나눴나요? 빈 이력과 빈 자리는 어떻게 처리했나요? 손실·역전파·갱신·평가·저장 후 예측이 어느 코드에서 이어지나요?

## 질문을 받고 바꾼 부분

이슈·PR 링크, 받은 질문, 반영 여부와 이유, 수정 커밋, 다시 실행한 결과를 적습니다. 배운 점은 실제로 바꾼 코드나 확인한 동작과 연결합니다.
