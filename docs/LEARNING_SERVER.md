# 수집 서버를 운영합니다

이 서버는 동의한 참가자의 풀이를 비공개로 모읍니다. 모델 학습과 추천은 실행하지 않습니다. 앱에서 파이썬·AI 비전 개론을 연결하며 과목 값은 `ai`, `python`입니다. 실제 운영 주소와 수강생 계정은 이 저장소에 등록하지 않습니다.

네 명의 첫 운영은 [무료 호스팅 후보와 시범 운영 절차](LEARNING_PILOT.md)를 따릅니다. 개인 초대 파일 발급, 상태 확인, DB·키 백업과 새 폴더 복구를 제공합니다. 배포와 합성 전송 검증 결과는 시범 운영 안내에 기록했습니다. 실제 접속 주소와 초대 코드는 개인별로 전달합니다.

## 개발 서버를 확인합니다

Python 표준 라이브러리로 실행할 수 있습니다. 데이터 파일은 저장소 밖에 둡니다.

```sh
python -m learning_server --db /비공개경로/learning.sqlite3 invite --count 4
python -m learning_server --db /비공개경로/learning.sqlite3 serve
```

첫 명령은 서로 다른 초대 코드 네 개를 출력합니다. 한 과목만 시험할 때 각자 한 개씩 사용합니다. 두 과목을 모두 쓰는 네 명에게는 `pilot` 명령으로 코드 8개를 개인별 파일에 나눠 발급합니다. 코드는 기본 7일 동안 유효하며 다른 가명 계정이 재사용할 수 없습니다. 저장 응답을 놓쳤을 때는 같은 가명 계정이 같은 코드로 등록을 다시 시도할 수 있습니다. 데이터베이스에는 원래 코드와 인증 토큰을 보관하지 않고 해시만 보관합니다. 데이터 파일 옆의 `.key` 파일은 초대 재시도의 인증 생성에 필요합니다. 백업·복구할 때 함께 보호합니다.

두 번째 명령은 `127.0.0.1:8765`에서 개발용 서버를 엽니다. 이 기기의 앱에서만 `http://127.0.0.1:8765`로 접속할 수 있습니다. 다른 기기에서 HTTP로 답안을 보내지 않습니다.

| 경로 | 용도 |
|---|---|
| `GET /health` | 실제 DB 연결과 형식 판 확인. DB를 열지 못하면 503 반환 |
| `POST /v1/enroll` | 초대 코드·가명 구분값·전송 동의로 참가자 등록 |
| `POST /v1/events` | 개인 인증으로 최대 100건·1MiB씩 저장 |
| `DELETE /v1/me` | 본인 풀이 삭제·업로드 인증 폐기 |

다른 참가자의 데이터를 읽는 공개 API는 없습니다. 요청 묶음은 한 트랜잭션으로 저장합니다. 재전송은 중복 삽입하지 않으며 고유번호·순서 충돌은 묶음 전체를 취소합니다. 삭제와 업로드가 겹쳐도 철회한 참가자가 새로 업로드하지 못하도록 저장 직전 다시 확인합니다.

## 운영 서버에 배포합니다

개발용 `wsgiref` 서버는 운영용으로 사용하지 않습니다. [Python 공식 설명](https://docs.python.org/3/library/wsgiref.html)과 [Waitress 실행 안내](https://docs.pylonsproject.org/projects/waitress/en/stable/runner.html)를 따릅니다.

```sh
python -m pip install -r learning_server/requirements.txt
```

`STUDY_DATA_DB`를 저장소 밖의 실제 비공개 경로로 설정한 뒤 실행합니다.

```sh
waitress-serve --listen=127.0.0.1:8765 --threads=4 --max-request-body-size=1048576 --channel-timeout=30 --no-expose-tracebacks learning_server.wsgi:application
```

컨테이너를 쓰는 경우 `docker build -f learning_server/Dockerfile -t study-learning-data .`로 빌드합니다. `/data`에는 비공개 영구 볼륨을 연결합니다. 컨테이너 사용자는 UID 10001이며 이 사용자가 볼륨에 쓸 수 있어야 합니다. 서버 외부에는 HTTPS를 처리하는 프록시를 두고, 프록시의 요청 크기도 1MiB로 제한합니다. 인증 헤더·요청 본문·답안을 접근 로그에 기록하지 않습니다. 데이터베이스·키·백업을 정적 파일로 제공하지 않습니다.

PythonAnywhere 배포의 HTTPS와 합성 계정 전송은 확인했습니다. 위 Waitress·컨테이너 구성은 별도 장비용 예시입니다. 컨테이너 빌드·실제 수강생 기기 접속·100명 동시 사용 성능은 아직 확인하지 않았습니다.

## 모델 개발용 파일을 전달합니다

```sh
python -m learning_server --db /비공개경로/learning.sqlite3 export --out /공유할비공개경로/events.jsonl
```

기본은 입력 답안을 제외합니다. 입력 답안을 포함한 연구가 따로 승인됐을 때만 `--include-answers`를 붙입니다. 파일을 다시 읽어 SHA-256을 확인한 뒤 결과를 출력하며 기존 파일을 덮어쓰지 않습니다. 이 파일과 이후 모델·실험 결과는 공개 저장소에 커밋하지 않습니다. 공개 예제는 실제 기록과 구분한 가상 자료로 만듭니다.

서버 삭제 뒤에는 이후 내보내기에 해당 풀이가 나오지 않습니다. 이미 전달한 학습용 사본·모델·백업은 자동으로 회수되지 않습니다. 운영자가 파일 판과 전달 대상을 기록하고, 삭제 요청이 오면 사본 삭제와 재학습 필요 여부를 함께 처리합니다.

내보낸 파일을 과목별 학습·검증·평가 자료로 나눌 수 있습니다.

```sh
python -m learning_server.dataset --input /비공개경로/events.jsonl --out /비공개경로/dataset-v1
python -m learning_server.dataset --synthetic --out /비공개경로/synthetic-v1
```

출력 폴더는 새로 만듭니다. 실제 입력 파일의 해시와 각 결과 파일의 행 수·해시를 `manifest.json`에 기록하고 다시 읽어 확인합니다. 가상 자료에는 `synthetic: true`를 표시합니다. 실제 자료는 3일 이상의 관찰이 있어야 나눕니다. 날짜 경계를 가로지르는 풀이 묶음은 평가용 분리에서 제외하고, 이미 사용자 정정이 붙은 답과 묶음 안 재시도도 제외합니다. 정정 답을 객관적인 정답으로 바꾸지 않습니다. 과거에 관찰한 판정은 그 시점의 입력 이력으로 남기며 정정 이력은 정정한 시점 이후에만 반영합니다. 같은 모의고사의 문항들은 시험 시작 또는 처음 관찰한 문제 반환 시점의 이력을 함께 사용합니다. 제출 뒤 한꺼번에 공개한 판정을 같은 시험의 다음 문항 입력에 섞지 않습니다. 시험 전 이력을 확인할 기록이 없으면 해당 모의고사의 학습 행을 만들지 않습니다.

각 행은 문항·개념·과거 관찰 이력·현재 정오답을 구분합니다. `features`에는 현재 답을 넣지 않고 `target`으로 분리합니다. 모의고사 빈 답안은 오답 학습 행으로 만들지 않습니다. 수집 이전의 학습량은 알 수 없으므로 관찰된 이력만 표시합니다. 같은 사람이 이미 본 문제의 미래 답을 예측하는 기본 분리이며, 새 학습자·새 문항 일반화 검사는 별도로 준비합니다.

입력 이벤트의 `synthetic`이 참이면 학습용 행과 목록에도 합성 자료로 보존합니다. 거짓이면 `recorded`, 표시가 없으면 `unmarked`로 남깁니다. 출처가 없는 값을 실제 기록으로 채우지 않으며 합성·기록·미표시 입력이 섞이면 파일을 만들기 전에 거절합니다. `--synthetic`으로 생성하는 기존 연습 자료도 같은 출처를 유지합니다.

모의고사 문항별 목표는 답을 마지막으로 바꿨을 때의 목표와 로드맵 판입니다. 그때의 동의 차수와 `observed_at`을 초안에 함께 보관하고 같은 값의 재저장으로 바꾸지 않습니다. 제출 뒤의 `source_at`은 제출 기록 시각이고 이벤트의 `at`은 추가 DB 저장 시각입니다. 이전 초안에 관찰 문맥이 없으면 목표와 관찰 시각을 null로 남겨 `unrecorded`로 구분합니다. 동의 차수가 달라진 입력은 기존처럼 수집에서 제외합니다.

## 희망 직무별 풀이 경향을 집계합니다

기존 파이썬 기록의 변환, 풀이 순서와 간격 입력, 공통 비교 자료는 [공통 학습 자료 준비](LEARNING_STARTER.md)를 참고하세요.

```sh
python -m learning_server cohorts --input /비공개원본/events.jsonl --out /비공개결과/cohorts-v1
python -m learning_server --db /비공개원본/learning.sqlite3 cohorts --out /비공개결과/cohorts-v2
```

JSONL 내보내기 파일이나 로컬·서버 수집 DB를 읽습니다. DB는 읽기 전용으로 열며 새 수집 DB를 만들지 않습니다. 결과는 원본 폴더와 저장소 밖의 새 폴더에만 씁니다. 폴더 권한은 700, 파일 권한은 600으로 만들고 `cohorts.jsonl`과 `manifest.json`을 다시 읽어 확인합니다. 기존 경로는 덮어쓰지 않습니다.

과목·목표 ID·로드맵 SHA-256·풀이 종류·태그·자료 출처별로 참가자, 답, 최초답, 재시도, 원래 맞힌 답, 정답 수정, 미선택 답을 셉니다. 연습 최초답은 묶음 안 첫 답, 모의고사 최초답은 첫 응시의 문항별 제출 답, 회상 최초답은 내보낸 기록에서 같은 물음·칸·수준을 처음 답한 기록입니다. 모의고사 재응시와 이후 회상은 재시도로 셉니다. 회상 이전의 학습 여부는 알 수 없습니다. 첫 시도 여부가 없으면 `unknown_attempts`로 셉니다. 정답 수정은 별도 횟수이며 원래 채점을 덮지 않습니다. 여러 태그가 붙은 답은 태그별로 각각 세므로 행의 참가자 수나 답 수를 모두 더하면 중복됩니다. 태그가 없으면 `tag`는 null입니다.

모의고사의 빈 답과 수집 동의 전에 입력해 제외한 답은 답 횟수와 오답 횟수에 넣지 않습니다. 문항 반환이나 읽기 기록도 답 횟수로 세지 않습니다.

목표 스냅샷이 없는 옛 기록은 `unrecorded`, 명시한 미선택은 `unselected`, 알 수 없는 목표 ID는 `unknown`으로 구분합니다. 뒤의 `goal_changed`로 앞의 답을 분류하지 않습니다. 선택 번호와 갱신일은 원본 이벤트에 보존하고 집계에서는 같은 로드맵 SHA-256끼리 묶습니다. 수집 이후의 목표 변경은 과거 답을 바꾸지 않습니다.

합성 자료는 이벤트나 내보내기 머리의 `synthetic: true`로 표시합니다. 표시가 없는 연습용 입력은 `--synthetic`으로 지정할 수 있습니다. 출처 표시가 없는 JSONL은 `unmarked`로 남기며 실제 수강생 기록으로 확정하지 않습니다. 수집 DB와 앱·서버 내보내기는 기록 자료인 `recorded`로 구분합니다. 시각과 문항별 소요 시간이 없으면 각각 누락 횟수로 세고 값을 채우지 않습니다. 이 집계는 실력 순위, 직무 적합도, 진로 선택의 효과나 학습 원인을 설명하지 않습니다.

## 네 명에서 다른 수강생으로 확대합니다

| 순서 | 프로그램 담당이 준비할 내용 | 다음 단계로 넘어갈 조건 |
|---|---|---|
| 네 명 시범 운영 | 개인 초대, 저장·재전송·삭제, 분석용 사본 | 각자 동의한 자료가 중복·누락 없이 왕복하며 중단·삭제가 작동함 |
| 두 과목 연결 | 연결한 파이썬·AI 개론에서 별도 동의와 과목별 초대 사용 | AI·파이썬 기록과 모델 평가를 별도로 구분함 |
| 소규모 외부 수강생 | 운영자 연락처·이용 목적·보관 기간·삭제 요청 경로를 담은 고지, HTTPS 서버, 설치 안내 | 실제 Windows 기기에서 설치·등록·오프라인 후 재전송·삭제를 확인함 |
| 수강생 확대 | 초대 발급, 설치·업데이트, 저장 공간·실패율 관찰, 백업 복구 | 예상 요청량으로 동시 전송·복구를 측정하고 운영자가 대응할 수 있음 |

다른 수강생에게 저장소 협업자 권한을 주지 않습니다. 데이터 공유에 참여하지 않는 수강생도 문제를 풀 수 있어야 합니다. 앱 설치와 문제 업데이트는 기존 배포 방식에서 이어가되, 공개 풀이 PR과 비공개 연구 데이터 전송을 나눕니다. 과거에 동의한 공개 풀이 제출을 새 연구 목적의 자동 수집 동의로 간주하지 않습니다.

서버·설치·수집 연결·데이터 정리·학습용 분리·운영 점검은 프로그램 담당이 맡습니다. 팀원에게는 다음 문서의 딥러닝 미션만 배정합니다.
