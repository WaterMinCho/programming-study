# 개발 PR 제목과 검사 결과를 확인합니다

[스터디 개발 시작](STUDY_START.md) · [fork에서 첫 PR까지](LEARNING_WORKFLOW.md)

## 제목은 변경한 내용을 씁니다

`종류(범위): 변경 내용` 형식으로 씁니다. 범위는 생략할 수 있고 콜론 뒤에는 한 칸을 띄웁니다.

| 변경 | 제목 예시 |
|---|---|
| 첫 입력 실습 기록 | `docs(model): 공통 입력과 정답 모양 기록` |
| 모델 코드 추가 | `feat(model): LSTM 학습과 평가 추가` |
| 잘못된 동작 수정 | `fix(model): 빈 이력의 손실 계산 수정` |
| 검사 추가 | `test(model): 미래 풀이를 가리는 조건 확인` |

종류는 `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `style`, `perf`, `build`, `ci` 중에서 고릅니다. 제목 형식이 틀리면 [Edit]로 제목을 고칩니다. 새 커밋을 만들지 않아도 제목·본문 변경 시 검사가 다시 실행됩니다.

PR 본문에는 무엇을 바꿨는지, 어떤 입력으로 확인했는지와 실행하지 못한 조건을 적습니다. 기록은 `~함`, `~음`, `~했음`으로 씁니다. 긴 완료 목록 대신 한두 문단으로 설명합니다.

```text
feat(model): LSTM 학습과 평가 추가

공통 입력 판4의 합성 자료로 학습·평가·저장 코드를 추가했음. 빈 이력과 mask를 확인했으며 실제 수강생 자료의 학습은 실행하지 않았음.
```

## 검사와 코드 검토를 구분합니다

문장·제목 검사는 글의 형식을 확인합니다. 프로그램 검사는 바꾼 기능의 동작을 확인하고, 문항 검사는 정답·출처·그림 연결을 확인합니다. 문서만 바꾸었다고 문항·화면 전체를 매번 검사하지 않으며 코드가 바뀌면 해당 동작 검사가 필요합니다. 기존 검사를 삭제하지 않고 변경 파일에 맞춰 실행합니다.

팀원 모델 PR은 코드와 실험 설명을 검토받습니다. 수정 요청이 있으면 같은 브랜치에서 고치고 Push합니다. 검사 통과와 코드 검토 완료를 확인한 뒤 운영자가 머지하며, 스터디원의 PR을 자동 머지하지 않습니다.

## 변경 파일에 맞춰 검사합니다

| 바꾼 부분 | 자동 확인 범위 |
|---|---|
| 사용 안내 README | 문장·제목·검사 계획의 완료 |
| 본인 모델 폴더의 설명 | 문장·제목·코드 검토 |
| 본인 모델 폴더의 Python 코드 | 구문·문장·제목·코드 검토 |
| 서버 코드 | 기능 검사와 해당 운영 경로 |
| 화면·공통 학습 코드 | 관련 기능·문항·화면 검사 |

Python 구문 검사만으로 모델 학습과 평가가 검증되지는 않습니다. 팀원은 사용한 입력 판·실행 명령·결과를 PR에 남깁니다. 비교할 파일을 알 수 없으면 제품 검사를 실행합니다. 필수 상태인 `필수 검사`는 계획한 검사가 끝났는지 확인합니다. `문장 검사`와 `PR 제목`도 통과해야 합니다.

검사와 현재 코드 판의 검토가 끝나면 [Slack 결과 카드](SLACK_NOTIFICATIONS.md)를 확인합니다.
