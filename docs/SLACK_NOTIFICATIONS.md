# Slack에서 PR 소식을 확인합니다

PR은 GitHub에서 만들고 검토합니다. Slack에는 바뀐 상태와 바로가기만 알립니다. 알림을 눌러 해당 PR이나 검사 결과를 열 수 있습니다. 댓글 본문·풀이·학습 기록은 보내지 않습니다.

| 소식 | 카드에 보이는 내용 | 바로가기 |
|---|---|---|
| PR 등록·다시 열기 | PR 제목, 작성자, 브랜치, 초안 여부 | PR 보기 |
| 초안의 검토 준비 완료 | 검토를 시작할 수 있다는 안내 | PR 보기 |
| CI 종료 | 이번 실행의 검사별 통과·실패 | 검사 결과, PR 보기 |
| 리뷰 제출 | 검토자, 승인 의견·수정 요청·검토 의견 | 리뷰 보기, PR 보기 |
| 코드 리뷰의 답글 | 답글 작성자, 대화 안내 | 답글 보기, PR 보기 |
| PR 댓글 | 댓글 작성자, 새 피드백 안내 | 댓글 보기, PR 보기 |
| PR 머지·닫기 | 공통 저장소 반영 여부 | PR 보기 |

모델·프로그램 개발 PR을 대상으로 합니다. `study/<ID>` 브랜치와 `submissions/`만 바꾼 풀이 제출 PR은 제외합니다. 자동 채점 봇 댓글도 제외합니다. 코드 검토는 기존처럼 PR을 공유했을 때 진행하며 알림이 검토·승인·머지를 대신하지 않습니다.

CI는 작업 묶음 하나가 끝날 때 한 번 알립니다. `CI`, 문장 검사, 수집 서버 운영 검사, 알고리즘 여행 검증을 대상으로 합니다. 취소·생략한 실행과 이전 코드 판의 뒤늦은 결과는 제외합니다. 한 작업 묶음이 통과했다고 전체 머지 조건이 충족됐다고 표시하지 않습니다. 재실행하면 새 결과를 알립니다.

GitHub는 충돌이 있는 PR의 `pull_request` 작업을 실행하지 않습니다. 이때 PR 등록 알림도 빠질 수 있습니다. 충돌을 해결한 뒤 PR을 다시 열거나 검토 준비 상태로 바꾸면 알림을 받을 수 있습니다. 이미 받은 알림은 수정하거나 삭제하지 않으며 같은 이벤트의 알림 작업을 손으로 재실행하면 다시 전송합니다.

## 운영자가 채널을 연결합니다

Slack 앱의 Incoming Webhooks와 GitHub Actions를 사용합니다. 별도 서버나 유료 알림 서비스를 두지 않습니다. 2026년 11월 12일 확인한 공식 설정은 [Slack 웹훅 안내][webhook]와 [GitHub 이벤트 안내][events]를 따릅니다.

1. [Slack 앱 설정][apps]에서 알림용 앱을 만듭니다. Incoming Webhooks를 켭니다.
2. **Add New Webhook to Workspace**에서 스터디 채널을 선택합니다. 앱 권한은 해당 채널에 메시지를 보내는 `incoming-webhook`만 사용합니다.
3. 발급한 웹훅 주소를 저장소 **Settings → Secrets and variables → Actions → New repository secret**에 넣습니다. 이름은 `SLACK_STUDY_WEBHOOK_URL`입니다. 주소를 코드·이슈·채팅에 붙이지 않습니다.
4. 알림 코드가 main에 반영되면 **Actions → Slack 스터디 알림 → Run workflow**에서 main을 선택해 실행합니다.
5. 채널에서 **스터디 알림 연결을 확인합니다** 카드를 확인합니다. 이 카드는 실제 PR이나 CI 결과가 아닌 연결 확인용입니다. 이후 새 개발 PR의 알림을 확인합니다.

웹훅이 없으면 전송을 보류했다는 실행 기록을 남깁니다. 전송 실패는 별도 알림 작업에서 확인하며 프로그램의 CI 판정을 바꾸지 않습니다. 주소가 노출되면 Slack에서 해당 웹훅을 폐기한 뒤 새 주소로 비밀 값을 바꿉니다. 알림을 중단하려면 저장소의 비밀 값을 삭제합니다.

## 포크 PR에도 비밀 값을 전달하지 않습니다

`스터디 알림 전달`은 PR 번호·이벤트 종류·리뷰 번호만 하루 보관합니다. 저장소 체크아웃과 비밀 값 접근은 하지 않습니다. `Slack 스터디 알림`은 기본 브랜치의 도구로 GitHub에 저장된 실행·PR·리뷰를 다시 조회합니다. 전달 파일은 크기와 구성을 제한해 읽으며 실행하거나 디스크에 풀지 않습니다.

GitHub 조회 권한은 코드·실행·PR 읽기로 제한합니다. 포크의 코드나 아티팩트 안의 명령을 실행하지 않습니다. 포크 PR의 실행에 승인 대기가 걸리면 운영자가 GitHub에서 확인할 때까지 알림도 늦어질 수 있습니다. `pull_request_target`과 포크에 비밀 값을 허용하는 설정은 사용하지 않습니다.
