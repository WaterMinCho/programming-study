# 세 모델의 공통 학습 자료와 입력 예제

<a id="기존-풀이-기록으로-모델-개발을-시작합니다"></a>

새 데이터가 쌓일 때까지 기다릴 필요는 없습니다. 기존 파이썬 풀이 기록과 현재 문제의 개념 정보를 공통 형식으로 바꿉니다. 이후 파이썬·AI 개론·응용의 새 수집 자료도 같은 도구로 준비합니다. WaterMinCho가 자료를 준비하고 세 팀원은 같은 파일로 모델을 비교합니다.

팀원은 [실제 자료 받기·샘플링 안내](LEARNING_DATA_ACCESS.md)부터 따라 합니다. 아래 변환 명령은 WaterMinCho가 원본에서 공통 자료를 준비할 때 사용합니다. 팀원마다 원본을 다시 변환하지 않습니다.

## 팀원이 함께 쓸 자료 버전

새로 만드는 공통 입력 버전은 `features_version: 6`입니다. 버전 4·5와 현재 공유 폴더의 `common-input-f4-20261112` 자료도 계속 읽을 수 있습니다. 합성 자료는 파이썬·AI를 각각 학습 8건·검증 2건·평가 2건으로 준비했습니다. 사용 범위를 확인한 기존 파이썬 기록은 학습 84건·검증 29건·평가 18건입니다. 실제 AI 기록과 수강생 전원의 자료가 준비됐다는 뜻은 아닙니다.

세 팀원은 Drive의 **ROKEY 모델 스터디 · 공통 학습 자료** 폴더에서 번호표가 포함된 같은 ZIP을 내려받습니다. 묶음 SHA-256은 `b5dd2a5daa4af4ec05de7ee1ac91a93ac485d93003f10ca3b6bbabc718c00bff`입니다. 아래 명령으로 새로 만드는 합성 예제는 버전 5입니다. 실험에는 사용한 폴더의 `manifest.json`에서 `features_version`을 확인해 적습니다. 담당 이슈에는 자료를 열었는지만 적습니다.

기존 실제 자료는 한 사람의 기록이며 과거 문항 버전과 일부 시각을 확인할 수 없습니다. 새 학습자에 대한 성능이나 추천 효과로 해석하지 않습니다. 검증·평가에 번호표에 없는 문항이 있으므로 UNK와 개념 입력도 확인합니다.

## 기존 파이썬 풀이를 학습 자료로 변환하기

WaterMinCho가 저장소 루트에서 실행합니다. `--profile`에는 비공개로 보관한 실제 원본 경로를 지정합니다. 다른 사람의 기록은 연구 사용 동의를 받은 뒤 지정합니다. 아래 시간대는 한국 시간으로 해석한다는 가정이며 원래 시각도 따로 남깁니다.

```sh
python -m learning_server.starter --profile ../legacy-profiles/participant/profile.json --agree --timezone +09:00 --out ../learning-profile-v1
```

기존 파일은 수정하지 않습니다. 결과는 공개 저장소 밖의 새 폴더에 저장하고 다시 읽어 확인합니다. 같은 폴더를 덮어쓰지 않으므로 다시 만들 때는 다른 이름을 지정합니다. 원본 답안·GitHub ID·이름은 복사하지 않으며 새 가명 구분값을 만듭니다.

기존 기록에는 채점 시각과 결과가 있습니다. 실제로 문제를 읽은 시각과 답을 입력한 시각, 당시 문제 버전은 알 수 없습니다. 과거 문항 버전은 `null`로 남기고 개념은 현재 문제 목록에서 연결했다는 출처를 보존합니다. 예전 풀이에 나중에 고른 희망 직무를 붙이지 않습니다.

예측 기준 시각은 기록에 남은 회차 생성 시각입니다. 그보다 먼저 공개된 채점 결과만 입력에 넣습니다. 같은 시각의 결과는 보수적으로 제외합니다. 회차 생성 시각이 없으면 풀이 간격은 미확인으로 남깁니다. 사용하지 못한 문항·시각·건너뛰기는 `legacy-provenance.json`에서 확인합니다. 이 자료만으로 새 학습자에게도 잘 맞는다고 판단하지 않습니다.

## 새 풀이 기록과 합성 예제 준비

WaterMinCho가 이미 내보낸 수집 JSONL 파일을 다음과 같이 준비합니다.

```sh
python -m learning_server.starter --input ../learning-events.jsonl --out ../learning-recorded-v1
```

실제 기록을 전달받기 전에는 기존 합성 예제로 입력 모양을 확인합니다. 이 작은 예제의 점수를 실제 학습자 성능으로 쓰지 않습니다.

```sh
python -m learning_server.starter --synthetic --out ../learning-demo-f5
python -m learning_server.input_example --dataset ../learning-demo-f5 --track python --batch-size 4 --length 32
python -m learning_server.input_example --dataset ../learning-demo-f5 --track ai --batch-size 4 --length 32
```

추가 라이브러리 설치나 모델 학습 없이 실행할 수 있습니다. 자료에 있는 과목만 선택합니다. 기존 파이썬 프로필로 만든 자료에는 파이썬만 들어 있습니다.

`input_example`은 실제 배열도 출력합니다. 공개 실행 예시는 합성 자료로 만들고 실제 자료는 [요약만 출력하는 확인 도구](LEARNING_DATA_ACCESS.md#자료-파일-검증-명령과-정상-결과)를 사용합니다.

## 세 모델의 공통 입력 형식

```python
from learning_server.input_example import load, batch

rows, vocabulary = load("../study-data/common-input-f4-20261112/recorded-python", "python", "train")
example = batch(rows[:4], vocabulary, length=32)
inputs = example["inputs"]
targets = example["targets"]
```

| 항목 | 모델에 전달하는 값 |
|---|---|
| `questions`, `results` | 이전 문제 번호와 정오답입니다. 모양은 `[묶음 크기, 이력 길이]`입니다. |
| `concepts` | 이전 문제의 개념을 표시합니다. 모양은 `[묶음 크기, 이력 길이, 개념 수]`입니다. |
| `mask`, `lengths` | 실제 풀이가 있는 자리와 개수입니다. 이력이 없는 학습자는 길이가 0입니다. |
| `query_question`, `query_concepts` | 앞으로 예측할 문제와 개념입니다. 현재 정답은 포함하지 않습니다. |
| `query_gap_seconds`, `query_gap_known` | 같은 개념의 마지막 채점 이후 지난 시간과 시각 확인 여부입니다. 모양은 `[묶음 크기, 개념 수]`입니다. |
| `difficulties`, `difficulty_known` | 이전 문제의 출제 난이도와 확인 여부입니다. 모양은 `[묶음 크기, 이력 길이]`입니다. |
| `query_difficulty`, `query_difficulty_known` | 예측할 문제의 출제 난이도와 확인 여부입니다. 모양은 `[묶음 크기]`입니다. |
| `courses`, `query_course` | 이전 풀이의 과정 번호와 이번 문제의 과정 번호입니다. 학습 때 보지 못했거나 기록되지 않은 과정은 UNK입니다. |

이번 정오답은 `example["targets"]`에 예시마다 하나씩 들어 있습니다. 1은 정답, 0은 오답입니다. 모델에는 위 표의 `inputs`만 전달합니다.

문제·개념 번호는 학습 자료만으로 정합니다. 이후 처음 등장한 값은 1번인 미확인 값으로 처리하고 0번은 빈 자리로 씁니다. 정오답의 0은 오답이므로 빈 자리 구분에는 반드시 `mask`를 사용합니다. 풀이 이력은 최근 128개까지 보관합니다.

순서 입력의 길이와 기준 방법의 개념 집계 범위는 구분합니다. 개념별 시도 수·정답 수·마지막 시각은 이번 문제에 붙은 각 개념에 대해 예측 전에 공개된 전체 기록으로 계산합니다. 묶음의 답은 묶음 전체가 공개된 뒤 사용합니다. 간격은 그 개념의 답 이벤트 중 가장 늦은 시각부터 예측 시각까지로 계산합니다. 공개 여부를 판단하는 시각과 구분합니다.

공통 입력 버전 5부터 문제를 제시할 때의 출제 난이도 1~3을 담습니다. 값이 없으면 숫자는 0, 확인 여부는 False입니다. 0을 가장 쉬운 문제로 해석하지 않습니다. 문항 번호가 학습 때 없던 UNK여도 출제 난이도가 확인됐다면 사용할 수 있습니다.

버전 6은 변형 문항의 생성 조건도 보존합니다. `input_example.batch()`의 `question_provenance`에서 현재 문제의 `query`와 이전 문제의 `history`를 확인할 수 있습니다. 기록에 조건이 없으면 `None`이며 과거 값을 추정해 채우지 않습니다. 기존 모델용 숫자 배열의 크기는 유지합니다. 생성 조건을 추가 입력으로 쓸 때는 세 팀원이 같은 항목과 평가 분할을 사용하도록 먼저 맞춥니다. 공유 폴더의 기존 자료는 새 버전 생성만으로 바뀌지 않습니다.

버전 4 자료는 같은 이력 집계 규칙을 쓰므로 계속 읽습니다. 과거 기록에 없던 난이도를 현재 문항 목록에서 가져와 채우지 않습니다. 버전 3 이하의 자료는 예측 시각과 이력 집계를 다시 확인하도록 거절합니다. 새 자료는 별도 폴더에 준비합니다.

시각을 알 수 없는 항목은 `query_gap_known=False`로 표시합니다. 함께 들어 있는 숫자 0을 당일 복습으로 해석하지 않습니다. 새 파이썬 수집에서는 실제 화면에 선택한 문항의 표시 시각을 사용합니다. 외부 편집기나 터미널에서 풀어 표시 시각을 모르면 간격을 추정하지 않습니다.

michae18과 wamangdoo는 간격 입력을 제외한 같은 자료로 LSTM과 Transformer를 비교합니다. kimjs85529-a11y는 같은 LSTM에 간격과 확인 여부를 추가합니다. 입력을 비우는 처리와 미래 기록을 가리는 처리는 [담당별 미션](LEARNING_MISSIONS.md)을 따릅니다.

AI 자료는 같은 과정·문항 버전·풀이 위치의 반환 기록이 하나로 연결될 때 그 시각을 사용합니다. `prediction_source`와 `prediction_event`로 연결 근거를 확인합니다. 연결되지 않은 시각은 미확인으로 남기며 채점·업로드 시각으로 채우지 않습니다. 간격 담당은 파이썬과 연결 가능한 AI 자료의 시각 확인 비율과 미확인 문항 번호 비율을 살핀 뒤 비교 범위를 정합니다.

## 학습·검증·평가 파일과 비교 결과

`records/`에는 과목별 `train`·`validation`·`test` 파일과 목록이 있습니다. 같은 풀이 묶음을 서로 다른 구간에 나누지 않습니다. 평가할 예측 시점이 앞 구간의 채점 결과보다 이르면 해당 묶음을 제외합니다. 제외한 행 수는 자료 목록의 `excluded_split_rows`에 남깁니다. `vocabulary.json`은 학습 자료의 번호표이고 `manifest.json`은 원본과 결과 파일의 해시를 기록합니다. 입력 예제는 해시가 달라진 파일을 읽지 않습니다.

`baseline.json`에는 과거 개념별 정답 비율로 예측한 결과가 있습니다. 정오답 구분 점수인 ROC-AUC와 확률 오차인 Brier·로그 손실을 같은 자료에서 비교합니다. 맞힌 답이나 틀린 답 한쪽만 있으면 ROC-AUC는 `null`로 남깁니다. 딥러닝 모델의 설정은 검증 자료로 고른 뒤 마지막 평가 자료로 비교합니다.

공통 평가 함수 `learning_server.starter.metrics()`에는 정답과 예측 확률을 같은 개수로 전달합니다. 정답은 숫자 `0`·`1`, 확률은 `0` 이상 `1` 이하의 유한한 숫자로 적습니다. `NaN`처럼 계산하지 못한 값이나 빠진 예측을 넣으면 점수를 계산하지 않고 오류를 알려줍니다. 양쪽 목록이 모두 비어 있으면 행 수는 0이고 점수는 `null`입니다.

실제 기록과 모델 파일은 비공개로 전달합니다. 새로 고른 기록을 다시 변환하면 가명 구분값도 바뀌므로, 비교 실험에서는 WaterMinCho가 한 번 준비한 같은 자료와 파일 해시를 사용합니다. 이 도구는 모델을 학습하거나 앱의 추천을 바꾸지 않습니다.

## AI 개론·응용별 결과 비교

AI 개론·응용은 같은 `ai` 자료에서 함께 준비합니다. 원자료의 `course`가 관측값이고 예전 기록의 추정은 `course_inferred`로 나눕니다. 모델 입력의 `courses`는 과거 각 풀이의 과정 번호, `query_course`는 현재 문제의 과정 번호입니다. 번호표는 학습 구간에만 맞추며 없는 값은 UNK로 처리합니다. `baseline.json`의 `by_course`에서 과정별 결과를 따로 봅니다.

이전 공통 자료와 ZIP은 덮어쓰지 않습니다. 현재 도구가 이전 버전을 알리면 같은 허락받은 원본을 새 출력 폴더로 다시 준비합니다. 모델의 자료 버전·번호표·가중치도 함께 맞춥니다.
