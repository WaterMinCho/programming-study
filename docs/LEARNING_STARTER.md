# 세 모델의 공통 학습 자료와 입력 예제

<a id="기존-풀이-기록으로-모델-개발을-시작합니다"></a>

새 데이터가 쌓일 때까지 기다릴 필요는 없습니다. 기존 파이썬 풀이 기록과 현재 문제의 개념 정보를 공통 형식으로 바꿉니다. 이후 파이썬·AI 개론·응용의 새 수집 자료도 같은 도구로 준비합니다. WaterMinCho가 자료를 준비하고 세 팀원은 같은 파일로 모델을 비교합니다.

팀원은 [실제 자료 받기·샘플링 안내](LEARNING_DATA_ACCESS.md)부터 따라 합니다. 아래 변환 명령은 WaterMinCho가 원본에서 공통 자료를 준비할 때 사용합니다. 팀원마다 원본을 다시 변환하지 않습니다.

<a id="세-팀원이-사용할-자료-버전을-맞춥니다"></a>

## 팀원이 함께 쓸 자료 버전

자료를 만든 코드에 따라 공통 입력 버전이 다릅니다.

| 자료 | `features_version` |
|---|---|
| 최신 `main`에서 새로 만드는 자료 | 8 |
| 공유 ZIP `common-input-f8-20261118` | 8 |
| 이전 공유 ZIP `common-input-f4-20261112` | 4 |
| 고정 커밋 `cc87ec96`의 [Colab 합성 예제](LEARNING_DATA_ACCESS.md) | 5 |

최신 `main`의 입력 읽기·자료 검사 도구는 버전 4·5·6·7·8을 지원합니다. [지원 버전 선언][supported-versions]과 [입력 읽기 조건][input-load]에서 버전과 파일 해시를 확인합니다. 공유 ZIP은 최신 `main`으로 읽고 [자료 검사 명령](LEARNING_DATA_ACCESS.md#자료-파일-검증-명령과-정상-결과)으로 본인이 받은 파일을 확인합니다.

합성 자료는 파이썬·AI를 각각 학습 8건·검증 2건·평가 2건으로 준비했습니다. 버전 8 묶음의 실제 기록은 AI가 학습 953건·검증 299건·평가 260건, 파이썬이 학습 223건·검증 109건·평가 48건입니다. 사용 범위를 확인한 기록만 넣었습니다. 수강생 전원의 기록이 들어 있지는 않습니다.

세 팀원은 Drive의 **ROKEY 모델 스터디 · 공통 학습 자료** 폴더에서 번호표가 포함된 같은 ZIP을 내려받습니다. 버전 8 묶음 `common-input-f8-20261118.zip`의 SHA-256은 `458ba3aa6f312a8bf99414e5afd10ad39be8dfebbab1b375ca3d4afbb2236cfc`입니다. 이 묶음은 커밋 `a16b247`의 코드로 만들었습니다. `recorded/manifest.json`의 SHA-256은 `40141519fa79d1f7050d8f5c65b7b7e38e41d9c86b6a98f01063a70b2a1d5be5`입니다. 이전 묶음 `common-input-f4-20261112.zip`의 SHA-256은 `b5dd2a5daa4af4ec05de7ee1ac91a93ac485d93003f10ca3b6bbabc718c00bff`입니다. 폴더 이름만으로 버전을 정하지 않고, `manifest.json`의 `features_version`과 생성에 쓴 코드 커밋을 실험 기록에 적습니다. 자료 수신·입력 검사 성공 여부는 본인 담당 이슈 #119·#120·#121에 적습니다.

가명은 서버가 학습자마다 붙인 구분값(`participant`)입니다. 버전 8 묶음의 실제 자료는 파이썬 평가 구간을 빼면 구간마다 가명이 3~4개이고, 파이썬 평가 구간은 3개보다 적습니다. 새 학습자에 대한 성능이나 추천 효과로 해석하지 않습니다. 검증·평가에 번호표에 없는 문항이 있으므로 UNK와 개념 입력도 확인합니다. 번호표와 UNK는 [버전 8 설명](#버전-8-문항-번호표와-드문-문항)에 있습니다.

### 자료 버전을 하나로 맞추는 순서

1. WaterMinCho가 새 묶음의 `manifest.json` SHA-256과 그 묶음을 만든 코드 커밋을 담당 이슈에 알립니다.
2. fork의 `main`을 그 커밋 이후로 갱신합니다. 갱신하지 않은 코드로 버전 8 자료를 읽으면 `input_example.load()`는 "이전 이력 집계로 만든 자료입니다. 원본을 보존하고 새 폴더에 공통 자료를 다시 준비해 주세요."를, `sample check`는 "지원하는 공통 입력 버전의 자료를 지정해 주세요."를 냅니다. 이 문구가 나오면 자료를 다시 만들지 말고 저장소를 갱신합니다.
3. `python -m learning_server.sample check --dataset <받은 폴더>`로 해시와 `features_version`을 확인합니다.
4. 실험 기록에 묶음 SHA-256, 공통 저장소 커밋, `features_version`을 적습니다.
5. 버전 4·5로 낸 결과는 "이전 자료" 제목 아래에 그대로 두고, 버전 8 결과와 한 표에 섞지 않습니다.

도구가 "더 새 도구로 만든 자료입니다"라고 알리면 2번부터 다시 합니다.

## 기존 파이썬 풀이를 학습 자료로 변환하기

WaterMinCho가 저장소 루트에서 실행합니다. `--profile`에는 비공개로 보관한 실제 원본 경로를 지정합니다. 다른 사람의 기록은 연구 사용 동의를 받은 뒤 지정합니다. 아래 시간대는 한국 시간으로 해석한다는 가정이며 원래 시각도 따로 남깁니다.

```sh
python -m learning_server.starter --profile ../legacy-profiles/participant/profile.json --agree --timezone +09:00 --out ../learning-profile-v1
```

기존 파일은 수정하지 않습니다. 결과는 공개 저장소 밖의 새 폴더에 저장하고 다시 읽어 확인합니다. 같은 폴더를 덮어쓰지 않으므로 다시 만들 때는 다른 이름을 지정합니다. 원본 답안·GitHub ID·이름은 복사하지 않으며 새 가명 구분값을 만듭니다.

기존 기록에는 채점 시각과 결과가 있습니다. 실제로 문제를 읽은 시각과 답을 입력한 시각, 당시 문제 버전은 알 수 없습니다. 과거 문항 버전은 `null`로 남기고 개념은 현재 문제 목록에서 연결했다는 출처를 보존합니다. 예전 풀이에 나중에 고른 희망 직무를 붙이지 않습니다.

예측 기준 시각은 기록에 남은 회차 생성 시각입니다. 그보다 먼저 공개된 채점 결과만 입력에 넣습니다. 같은 시각의 결과는 보수적으로 제외합니다. 회차 생성 시각이 없으면 새 학습·검증·평가 자료에서 해당 답을 제외합니다. 사용하지 못한 문항·시각·건너뛰기는 `legacy-provenance.json`에서 확인합니다. 이 자료만으로 새 학습자에게도 잘 맞는다고 판단하지 않습니다.

## 새 풀이 기록과 합성 예제 준비

WaterMinCho가 이미 내보낸 수집 JSONL 파일을 다음과 같이 준비합니다.

```sh
python -m learning_server.starter --input ../learning-events.jsonl --out ../learning-recorded-v1
```

실제 기록을 전달받기 전에는 기존 합성 예제로 입력 모양을 확인합니다. 이 작은 예제의 점수를 실제 학습자 성능으로 쓰지 않습니다.

```sh
python -m learning_server.starter --synthetic --out ../learning-demo-f8
python -m learning_server.input_example --dataset ../learning-demo-f8 --track python --batch-size 4 --length 32
python -m learning_server.input_example --dataset ../learning-demo-f8 --track ai --batch-size 4 --length 32
```

추가 라이브러리 설치나 모델 학습 없이 실행할 수 있습니다. 합성 자료는 코드가 끝까지 돌아가는지 확인하는 용도입니다. 합성 자료로 낸 점수를 적을 때는 합성 자료라고 함께 씁니다. 자료에 있는 과목만 선택합니다. 기존 파이썬 프로필로 만든 자료에는 파이썬만 들어 있습니다.

`input_example`은 실제 배열도 출력합니다. 공개 실행 예시는 합성 자료로 만들고 실제 자료는 [요약만 출력하는 확인 도구](LEARNING_DATA_ACCESS.md#자료-파일-검증-명령과-정상-결과)를 사용합니다.

## 세 모델의 공통 입력 형식

```python
from learning_server.input_example import load, batch

rows, vocabulary = load("../study-data/common-input-f8-20261118/recorded", "python", "train")
example = batch(rows[:4], vocabulary, length=32)
inputs = example["inputs"]
targets = example["targets"]
```

| 항목 | 모델에 전달하는 값 |
|---|---|
| `questions`, `results` | 이전 문제 번호와 정오답입니다. 모양은 `[묶음 크기, 이력 길이]`입니다. |
| `concepts` | 이전 문제의 개념을 표시합니다. 모양은 `[묶음 크기, 이력 길이, 개념 수]`입니다. |
| `mask`, `lengths` | 실제 풀이가 있는 자리와 개수입니다. 이력이 없는 학습자는 길이가 0입니다. |
| `query_question`, `query_concepts` | 앞으로 예측할 문제와 개념입니다. 현재 정답은 포함하지 않습니다. |
| `query_gap_seconds`, `query_gap_known` | 같은 개념의 마지막 채점 이후 지난 시간과 시각 확인 여부입니다. 모양은 `[묶음 크기, 개념 수]`입니다. |
| `difficulties`, `difficulty_known` | 이전 문제의 출제 난이도와 확인 여부입니다. 모양은 `[묶음 크기, 이력 길이]`입니다. |
| `query_difficulty`, `query_difficulty_known` | 예측할 문제의 출제 난이도와 확인 여부입니다. 모양은 `[묶음 크기]`입니다. |
| `courses`, `query_course` | 이전 풀이의 과정 번호와 이번 문제의 과정 번호입니다. 학습 때 보지 못했거나 기록되지 않은 과정은 UNK입니다. |

이번 정오답은 `example["targets"]`에 예시마다 하나씩 들어 있습니다. 1은 정답, 0은 오답입니다. 모델에는 위 표의 `inputs`만 전달합니다.

문제·개념 번호는 학습 자료만으로 정합니다. 이후 처음 등장한 값은 1번인 미확인 값으로 처리하고 0번은 빈 자리로 씁니다. 정오답의 0은 오답이므로 빈 자리 구분에는 반드시 `mask`를 사용합니다. 풀이 이력은 최근 128개까지 보관합니다.

순서 입력의 길이와 기준 방법의 개념 집계 범위는 구분합니다. 개념별 시도 수·정답 수·마지막 시각은 이번 문제에 붙은 각 개념에 대해 예측 전에 공개된 전체 기록으로 계산합니다. 묶음의 답은 묶음 전체가 공개된 뒤 사용합니다. 간격은 그 개념의 답 이벤트 중 가장 늦은 시각부터 예측 시각까지로 계산합니다. 공개 여부를 판단하는 시각과 구분합니다.

공통 입력 버전 5부터 문제를 제시할 때의 출제 난이도 1~3을 담습니다. 값이 없으면 숫자는 0, 확인 여부는 False입니다. 0을 가장 쉬운 문제로 해석하지 않습니다. 문항 번호가 학습 때 없던 UNK여도 출제 난이도가 확인됐다면 사용할 수 있습니다.

버전 6부터 변형 문항의 생성 조건도 보존합니다. `input_example.batch()`의 `question_provenance`에서 현재 문제의 `query`와 이전 문제의 `history`를 확인할 수 있습니다. 기록에 조건이 없으면 `None`이며 과거 값을 추정해 채우지 않습니다. 기존 모델용 숫자 배열의 크기는 유지합니다. 생성 조건을 추가 입력으로 쓸 때는 세 팀원이 같은 항목과 평가 분할을 사용하도록 먼저 맞춥니다. 공유 폴더의 기존 자료는 새 버전 생성만으로 바뀌지 않습니다.

이전 버전 4·5·6 자료도 실험을 재현할 수 있도록 계속 읽습니다. 읽기 성공만으로 버전 7의 이력 검사를 통과했다고 판단하지 않습니다. 과거 기록에 없던 난이도를 현재 문항 목록에서 가져와 채우지 않습니다. 버전 3 이하의 자료는 예측 시각과 이력 집계를 다시 확인하도록 거절합니다. 새 자료는 별도 폴더에 준비합니다.

<a id="버전-8-문항-번호표와-드문-문항"></a>

### 버전 8: 문항 번호표와 드문 문항

번호표는 문항마다 모델 입력용 정수를 붙인 목록입니다. 번호표는 `vocabulary.json`의 `questions`에 들어 있습니다. 0번 `<PAD>`는 빈 자리에 붙는 번호입니다. 1번 `<UNK>`는 번호표에 없는 문항에 붙는 번호입니다. 모델은 번호마다 숫자 벡터를 하나씩 학습합니다. 이 벡터를 임베딩이라고 합니다.

버전 7까지는 문항 번호표를 (문항 id, 문항 버전) 쌍으로 만들었습니다. AI 문항 버전 해시에는 시드·보기 순서·앱 코드 해시가 들어가서 같은 문항도 화면에 낼 때마다 값이 바뀝니다. 그래서 11월 16일 서버 사본(이벤트 5,867건)으로 실제 AI 자료를 만들면 학습 구간 690행이 번호 690개가 되고, 검증 263행과 평가 283행의 `query_question`이 모두 UNK가 됐습니다. 파이썬도 앱을 갱신하면 같은 문항의 버전이 갈립니다.

버전 8은 번호표를 문항 id 하나로 만듭니다. 같은 사본에서 드문 문항을 하나도 빼지 않고 다시 세면, `query_question`이 UNK인 행은 AI 검증 263행 중 6행, AI 평가 283행 중 36행으로 줄어듭니다. `vocabulary.json`의 `question_unit`에 이 규칙(`question_id`)이 적혀 있고 `input_example.batch()`가 그 값을 읽어 번호를 붙입니다. 팀원 코드는 `batch()`를 지금처럼 부르면 되고 배열 이름과 모양도 바뀌지 않습니다.

버전 8은 드문 문항도 번호표에서 뺍니다. 학습 구간에서 예측할 문제(`query_question`)로 나온 횟수가 기준 횟수보다 적은 문항은 번호표에 넣지 않고 학습·검증·평가 모두 UNK로 보냅니다. 기준 횟수는 `vocabulary.json`의 `question_min_count`에 적혀 있고 기본값은 2입니다. 기준이 2 이상이면 학습 구간의 과거 이력에만 나오고 예측할 문제로는 나오지 않은 문항도 UNK로 갑니다. 기준이 1이면 학습 구간의 문항을 모두 남깁니다. 횟수는 학습 구간에서만 세므로 검증·평가 구간의 문항과 정답은 번호표를 바꾸지 않습니다. 번호표에서 뺀 문항 수는 `rare_questions`에 적혀 있습니다. 개념 번호표에는 이 기준을 적용하지 않습니다.

드문 문항을 빼야 학습 중에도 1번이 나오고 1번의 임베딩이 학습됩니다. 학습 구간의 문항을 모두 번호표에 넣으면 학습 중에는 1번이 한 번도 나오지 않아 1번의 임베딩이 처음 값에서 바뀌지 않습니다. 그러면 평가 때 UNK로 간 문항은 학습되지 않은 임베딩으로 예측합니다.

기본값 2는 모델을 학습해 비교해 보고 고른 값이 아닙니다. 같은 사본으로 기준 1과 2의 UNK 수를 세면 아래와 같습니다. 예측할 문제 열은 `query_question`이 UNK인 행 수입니다. 이력 열은 각 행의 이전 풀이 최대 128개를 모두 더한 자리 가운데 UNK인 자리 수입니다.

| 과목·구간 | 예측할 문제 UNK 행, 기준 1 → 2 | 이력 UNK 자리, 기준 1 → 2 |
|---|---|---|
| AI 학습 | 0/690 → 180/690 | 0/68,403 → 17,063/68,403 |
| AI 검증 | 6/263 → 44/263 | 712/33,278 → 3,639/33,278 |
| AI 평가 | 36/283 → 108/283 | 3,022/34,493 → 10,631/34,493 |
| 파이썬 학습 | 0/223 → 106/223 | 0/1,936 → 660/1,936 |
| 파이썬 검증 | 74/109 → 97/109 | 1,070/6,229 → 3,511/6,229 |
| 파이썬 평가 | 27/48 → 43/48 | 112/1,024 → 512/1,024 |

기준을 1에서 2로 바꾸면 `<PAD>`·`<UNK>`를 포함한 번호표 크기는 AI가 306개에서 126개로, 파이썬이 159개에서 53개로 줄어듭니다. AI 평가 구간에서 예측할 문제가 UNK인 행은 72행 늘어납니다. 이 72행의 문항은 학습 구간에서 예측할 문제로 한 번 나왔거나 과거 이력에만 나왔습니다. 기준 1에서는 이 문항의 임베딩이 학습 구간의 그 한 번과 이력 속 풀이로 학습됩니다. 기준 2에서는 이 문항이 예측할 문제와 이력 모두에서 UNK로 바뀌어 이 정보가 입력에서 빠집니다. 파이썬은 평가 구간 48행 중 43행의 예측할 문제와 평가 이력 1,024자리 중 512자리가 UNK가 됩니다. 그래서 문항 번호로 얻는 정보가 AI보다 더 크게 줄어듭니다.

기본값은 WaterMinCho가 비교 실험 결과를 보고 정합니다. 과목마다 기준을 다르게 두는 방법과, 기준 1로 두고 학습할 때만 일부 문항을 무작위로 UNK로 바꾸는 방법도 후보입니다. 모든 문항을 남긴 자료가 필요하면 WaterMinCho가 `--min-count 1`로 따로 만들고, 실험 기록에 그 값을 적습니다.

버전 8에서는 번호를 붙이는 문자열이 바뀌어 같은 문항도 번호 순서가 달라질 수 있습니다. 버전 7 이전 번호표로 학습한 가중치를 버전 8 번호표에 그대로 불러오지 않습니다.

이미 받은 버전 4·5 자료는 지금 도구에서도 이전처럼 (문항 id, 문항 버전) 쌍으로 번호를 붙여 읽습니다. 이전 공유 ZIP `common-input-f4-20261112`를 최신 도구로 읽은 배열은 이전 도구로 읽은 배열과 같습니다. 이 ZIP의 실제 파이썬 기록은 모든 행의 문항 버전이 비어 있고 합성 자료는 과목마다 문항이 하나라서, 쌍으로 번호를 붙여도 같은 문항끼리 같은 번호를 받았습니다. 그래서 버전 4·5로 낸 입력 확인과 순전파 결과는 문항 버전 해시 때문에 UNK가 늘어나는 문제의 영향을 받지 않았습니다.

버전 8 자료인데 번호표에 `question_unit`이 없거나 모르는 값이면 읽지 않습니다. 버전 9 이상은 "더 새 도구로 만든 자료입니다" 오류로 알립니다.

버전 8의 각 행에 붙는 `selection`은 AI 연습 묶음의 선정 규칙 이름(`policy`), 묶음 안에서 다시 내는 규칙 이름(`retry_policy`), 그 문항이 들어온 후보(`pool`), 틀린 문항 뒤에 끼운 변형이면 원래 틀린 문항 id(`queued_for`)를 담습니다. `pool`이 `linked`이면 끼운 변형, `done`이면 오늘 이미 마친 문항을 채운 행입니다. 기록에 없는 값은 `null`이고 추정해 채우지 않습니다. 이 필드는 모델 입력 배열에 넣지 않습니다. 끼운 변형은 앞 문항을 틀린 뒤에만 나오므로 입력으로 쓰면 출제 규칙이 예측에 섞입니다. 끼운 변형 행을 예측 대상에서 뺀 자료는 `--exclude-linked`로 만들고, 뺀 수는 `records/manifest.json`의 `excluded_rows.linked_variant`에 남습니다. 뺀 행도 뒤 문제의 과거 이력에는 그대로 들어갑니다.

버전 7은 예측 기준 시각을 확인한 답만 학습·검증·평가 자료로 만듭니다. 확인할 수 없는 답의 수는 `records/manifest.json`의 `excluded_rows.missing_prediction_time`에 남깁니다. 제외한 답도 채점 결과가 공개된 시각을 알면 이후 문제의 과거 이력에는 사용할 수 있습니다. 원본 기록은 바꾸지 않습니다.

‘내 답도 맞음’으로 정정한 답은 학습 정답에서 제외합니다. 정정 전에 예측한 문제의 이력에는 당시 판정을 남기고, 정정 뒤에 예측한 문제에서는 그 답을 정오답 이력과 개념별 집계에서 뺍니다. 정답으로 뒤집어 넣지 않습니다. 같은 시각의 정정은 예측 뒤에 알려진 것으로 처리합니다. 모의고사와 한 번에 채점하는 풀이 묶음은 시작 이력을 고정합니다. 진행 중 생긴 정정을 그 시작 이력에 소급하지 않습니다. 정정 대상을 하나로 구분할 수 없으면 자료 생성을 멈추고 원본 확인을 요청합니다.

같은 개념의 이전 풀이가 없거나 이전 자료에서 시각을 확인할 수 없으면 `query_gap_known=False`로 표시합니다. 함께 들어 있는 숫자 0을 당일 복습으로 해석하지 않습니다. 새 파이썬 수집에서는 실제 화면에 선택한 문항의 표시 시각을 사용합니다. 외부 편집기나 터미널에서 풀어 표시 시각을 모르면 새 학습 자료에서 해당 답을 제외합니다.

michae18과 wamangdoo는 간격 입력을 제외한 같은 자료로 LSTM과 Transformer를 비교합니다. kimjs85529-a11y는 같은 LSTM에 간격과 확인 여부를 추가합니다. 입력을 비우는 처리와 미래 기록을 가리는 처리는 [담당별 미션](LEARNING_MISSIONS.md)을 따릅니다.

AI 자료는 같은 과정·문항 버전·풀이 위치의 반환 기록이 하나로 연결될 때 그 시각을 사용합니다. `prediction_source`와 `prediction_event`로 연결 근거를 확인합니다. 연결되지 않은 답은 원본에 남기고 새 학습 자료에서는 제외합니다. 채점·업로드 시각을 예측 시각으로 대신 쓰지 않습니다. 간격 담당은 파이썬과 연결 가능한 AI 자료의 시각 확인 비율과 미확인 문항 번호 비율을 살핀 뒤 비교 범위를 정합니다.

<a id="비교-결과와-파일-버전을-확인합니다"></a>

## 학습·검증·평가 파일과 비교 결과

`records/`에는 과목별 `train`·`validation`·`test` 파일과 목록이 있습니다. 같은 풀이 묶음을 서로 다른 구간에 나누지 않습니다. 평가할 예측 시점이 앞 구간의 채점 결과보다 이르면 해당 묶음을 제외합니다. 제외한 행 수는 자료 목록의 `excluded_split_rows`에 남깁니다. `vocabulary.json`은 학습 자료의 번호표이고 `manifest.json`은 원본과 결과 파일의 해시를 기록합니다. 입력 예제는 해시가 달라진 파일을 읽지 않습니다.

<a id="예측-파일-채점"></a>

### 예측 파일 채점

모델이 낸 예측은 첫 줄이 `event_id,probability,model_version`인 CSV나, 줄마다 같은 세 키를 담은 JSONL로 저장합니다. 예측 파일은 저장소 밖에 둡니다. 채점 명령은 묶음 해시를 확인한 뒤 모델 점수를 같은 구간의 기준선과 한 표로 보여 줍니다. 기준선은 모델 없이 정답 비율만으로 낸 예측입니다. 모델 점수가 기준선보다 나아야 학습한 효과가 있다고 볼 수 있습니다.

```sh
python -m learning_server.score --dataset ../learning-demo-f8 --track ai --predictions ../preds/lstm-validation.csv
```

`--split`을 적지 않으면 검증 구간을 채점합니다. 평가 구간은 설정을 모두 정한 뒤 `--split test`로 한 번만 채점합니다. `--out ../preds/lstm-score.json`을 붙이면 같은 결과를 JSON 파일로도 저장합니다. 저장소 밖의 새 파일만 받고 이미 있는 파일은 덮어쓰지 않습니다.

채점할 구간의 `event_id`가 예측 파일에 빠졌거나, 구간에 없는 `event_id`가 들어 있거나, 같은 `event_id`가 두 번 나오면 채점하지 않습니다. 확률이 0 이상 1 이하가 아니거나 한 파일에 `model_version`이 둘 이상이어도 채점하지 않습니다.

표에는 모델과 함께 기준선 여섯 개가 나옵니다. 다섯 개는 학습 구간의 기록으로 계산하고, `past-concept-ratio-v1`은 각 행 앞에 있는 같은 사람의 과거 풀이로 계산합니다. 가명은 서버가 학습자마다 붙인 구분값(`participant`)입니다. 문항·개념·가명별 비율은 `(맞힌 수 + 2 × 전체 정답 비율) / (푼 수 + 2)`로 계산합니다. 전체 정답 비율은 학습 구간 모든 행의 정답 비율이고, 한두 번만 푼 문항의 비율이 0이나 1로 치우치지 않게 두 건 몫으로 섞습니다. 학습 구간에 없는 문항·개념·가명은 전체 정답 비율을 씁니다.

| 이름 | 확률 |
|---|---|
| `majority` | 학습 구간에서 더 많이 나온 답(0 또는 1). 로그 손실과 ROC-AUC는 `-`로 나옵니다. |
| `overall-mean` | 학습 구간 전체 정답 비율 |
| `per-question` | 같은 문항 id의 학습 구간 정답 비율 |
| `per-concept` | 행에 붙은 개념마다 구한 학습 구간 정답 비율의 평균 |
| `per-participant` | 같은 가명의 학습 구간 정답 비율 |
| `past-concept-ratio-v1` | `baseline.json`에 저장된 개념별 과거 정답 비율 |

합성 자료에 모든 행을 0.7로 예측한 파일을 채점하면 다음처럼 나옵니다.

```text
ai validation 구간: 2행, 오답 1행, 가명 2개, 끼운 변형 0행 (자료 버전 8, 묶음 b00f5cfd0a1b)
합성 자료입니다. 실행 확인용이며 모델 비교 근거로 쓰지 않습니다.
표의 값: 값 ± 행 독립 표준오차 / 가명 묶음 표준오차
이름 | 로그 손실 | Brier | ROC-AUC | 정확도
lstm-a | 0.7803 ± 0.4236 / 0.4236 | 0.2900 ± 0.2000 / 0.2000 | 0.5000 ± 0.5000 / 계산할 수 없음 | 0.5000 ± 0.3536 / 0.5000
majority | - | 0.5000 ± 0.5000 / 0.5000 | - | 0.5000 ± 0.3536 / 0.5000
overall-mean | 0.8370 ± 0.5493 / 0.5493 | 0.3125 ± 0.2500 / 0.2500 | 0.5000 ± 0.5000 / 계산할 수 없음 | 0.5000 ± 0.3536 / 0.5000
(per-question, per-concept, per-participant, past-concept-ratio-v1 줄은 줄임)
이 구간은 오답 1행, 가명 2개라 모델 비교 근거로 쓰기 어렵습니다.
```

첫 줄에는 과목과 구간, 행 수, 오답 수, 가명 수, 끼운 변형 행 수, 자료 버전, 묶음 `manifest.json` SHA-256 앞 12자리가 나옵니다. 첫 열의 `lstm-a`는 예측 파일의 `model_version`입니다.

표의 각 값은 `값 ± 행 독립 표준오차 / 가명 묶음 표준오차` 꼴입니다. 표준오차는 같은 방식으로 기록을 다시 모았을 때 그 값이 얼마나 달라질 수 있는지 나타내는 크기입니다. 행 독립 표준오차는 모든 행을 서로 독립으로 보고 계산합니다. 가명 묶음 표준오차는 가명을 하나씩 빼고 다시 계산한 값이 서로 얼마나 퍼지는지로 구합니다. 같은 사람의 행은 서로 닮아서 행 독립 값이 실제보다 작게 나올 수 있습니다. 가명이 둘 미만이면 가명 묶음 값은 "계산할 수 없음"으로 나옵니다. ROC-AUC는 가명 하나를 뺐을 때 정답이나 오답 한쪽만 남아도 "계산할 수 없음"으로 나옵니다. 오답이 50행 미만이거나 가명이 5개 미만이면 표 아래에 "모델 비교 근거로 쓰기 어렵습니다" 경고가 붙습니다. 경고가 붙은 결과는 비교 결론이 아니라 실행 확인으로 적습니다.

공유 ZIP `common-input-f8-20261118`의 실제 자료는 AI 검증이 오답 37행·가명 3개, AI 평가가 오답 35행·가명 3개, 파이썬 검증이 오답 12행·가명 3개입니다. 파이썬 평가는 오답 14행이고 가명이 3개보다 적습니다. 네 구간 모두 경고가 붙습니다.

지금 실제 자료의 검증·평가 구간은 학습 구간보다 뒤 날짜에 푼 기록입니다. 푼 사람이 몇 명뿐이라서 이 점수를 새 학습자에게도 맞는다는 근거로 쓰지 않습니다. AI는 첫 시도 정답 비율이 학습 0.92, 검증 0.88, 평가 0.87이라 늘 맞힘으로 예측해도 정확도가 높습니다. 모델끼리는 로그 손실과 Brier로 견주고 정확도는 참고로 적습니다.

`baseline.json`에는 과거 개념별 정답 비율로 예측한 결과가 있습니다. 정오답 구분 점수인 ROC-AUC와 확률 오차인 Brier·로그 손실을 같은 자료에서 비교합니다. 맞힌 답이나 틀린 답 한쪽만 있으면 ROC-AUC는 `null`로 남깁니다. 딥러닝 모델의 설정은 검증 자료로 고른 뒤 마지막 평가 자료로 비교합니다.

공통 평가 함수 `learning_server.starter.metrics()`에는 정답과 예측 확률을 같은 개수로 전달합니다. 정답은 숫자 `0`·`1`, 확률은 `0` 이상 `1` 이하의 유한한 숫자로 적습니다. `NaN`처럼 계산하지 못한 값이나 빠진 예측을 넣으면 점수를 계산하지 않고 오류를 알려줍니다. 양쪽 목록이 모두 비어 있으면 행 수는 0이고 점수는 `null`입니다.

실제 기록과 모델 파일은 비공개로 전달합니다. 새로 고른 기록을 다시 변환하면 가명 구분값도 바뀌므로, 비교 실험에서는 WaterMinCho가 한 번 준비한 같은 자료와 파일 해시를 사용합니다. 이 도구는 모델을 학습하거나 앱의 추천을 바꾸지 않습니다.

## AI 개론·응용별 결과 비교

AI 개론·응용은 같은 `ai` 자료에서 함께 준비합니다. 원자료의 `course`가 관측값이고 예전 기록의 추정은 `course_inferred`로 나눕니다. 모델 입력의 `courses`는 과거 각 풀이의 과정 번호, `query_course`는 현재 문제의 과정 번호입니다. 번호표는 학습 구간에만 맞추며 없는 값은 UNK로 처리합니다. `baseline.json`의 `by_course`에서 과정별 결과를 따로 봅니다.

이전 공통 자료와 ZIP은 덮어쓰지 않습니다. 현재 도구가 이전 버전을 알리면 같은 허락받은 원본을 새 출력 폴더로 다시 준비합니다. 모델의 자료 버전·번호표·가중치도 함께 맞춥니다.
