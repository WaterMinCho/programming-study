# 제출과 피드백

[사용준비](../gui/README.md) · [풀이 제출 안내](../submissions/README.md)

풀이는 프로그램의 [**풀이 제출**]로 올립니다. [회차 제출] 등으로 채점한 뒤 학습 현황·과목 현황 또는 파이썬 결과 화면에서 하단 알림 카드를 확인하세요. 제출할 변경이 있을 때 버튼이 나타납니다.

## 처음 한 번 로그인

프로그램에서 사용하는 ID와 같은 GitHub 계정에 **이 저장소의 쓰기 권한**이 있어야 합니다. 스터디장이 보낸 저장소 초대를 수락하세요. 공개 저장소는 누구나 받을 수 있지만 여기에 풀이를 올리려면 쓰기 권한이 필요합니다. 초대를 받지 않은 수강생도 학습과 로컬 채점은 계속 할 수 있습니다.

### Windows

[Git for Windows](https://git-scm.com/install/windows)를 설치한 뒤 프로그램에서 [풀이 제출]을 누릅니다. Git 인증 창이나 브라우저 로그인이 나타나면 초대를 받은 GitHub 계정으로 로그인합니다. 이미 인증된 PC에서는 창이 생략될 수 있습니다. SourceTree에 로그인했더라도 프로그램이 실행하는 Git에서 인증을 다시 요구할 수 있습니다.

### macOS

터미널에서 GitHub CLI를 사용할 수 있다면 아래를 실행합니다.

```bash
gh auth login
```

질문에 `GitHub.com`, `HTTPS`, `Yes`(Git 인증에 사용), `Login with a web browser` 순서로 답합니다. `gh`가 없으면 [GitHub CLI 설치 안내](https://cli.github.com/)를 따릅니다. Homebrew가 이미 있다면 `brew install gh`로 설치할 수도 있습니다. 설정 뒤 프로그램에서 다시 [풀이 제출]을 누릅니다.

## 제출하면 일어나는 일

1. 프로그램이 `submissions/<내 ID>/`만 묶습니다. 다른 사람의 풀이와 프로그램·문제 파일은 담지 않습니다.
2. 내 기록을 원격 저장소의 `study/<내 ID>` 브랜치로 올립니다. 브랜치는 내 풀이를 따로 모아 두는 공간입니다.
3. 저장소의 자동 작업이 PR을 만들고 제출 기록을 분석한 댓글을 남깁니다. 브라우저에 열린 페이지에서 PR과 검사 결과를 확인합니다.
4. 팀원이 질문과 피드백을 남기면 프로그램에서 답을 고치고 다시 제출합니다. 열려 있는 PR에 수정분이 추가됩니다.
5. 검토한 풀이는 스터디장이 main에 합칩니다. 이미 합쳐진 뒤 새 풀이를 제출하면 새 PR을 만듭니다.

제출은 내 컴퓨터의 풀이를 지우지 않습니다. 프로그램이 다른 기록으로 바꿔야 할 때는 `.git/study-backup/`에 사본을 남깁니다. GitHub 제출은 [비공개 학습 데이터의 서버 전송](../learning_server/README.md#풀이-데이터-수집)과 별개입니다.

다른 PC에서 제출한 풀이와 이 PC의 기록이 이어지지 않으면 어느 기록을 쓸지 묻는 창이 나올 수 있습니다. 선택 전에 두 PC 중 마지막으로 푼 곳을 확인하세요. AI 학습 위치와 추가 수집 기록 등 GitHub에 올리지 않는 값은 [기록 보관 안내](../gui/README.md#컴퓨터를-바꾸거나-사본을-보관합니다)를 따릅니다.

## 제출이 안 될 때

오류 문구에 맞는 항목부터 확인합니다. 제출에 실패해도 로컬에 저장한 답은 남습니다.

- **로그인이 필요하다고 나오면** 위의 인증 과정을 마치고 다시 제출합니다. 브라우저에 로그인 창이 남아 있는지도 확인합니다.
- **저장소에 접근할 권한이 없다고 나오면** 초대 수락 여부와 Git이 사용하는 계정을 확인합니다. Windows는 제어판 → 사용자 계정 → 자격 증명 관리자에서 GitHub 관련 항목의 계정을 확인합니다. 다른 계정이 저장됐다면 해당 GitHub 항목만 제거한 뒤 다시 제출해 로그인합니다. [GitHub 공식 인증 안내][github-credentials]를 참고하세요. 초대받은 계정으로도 실패하면 스터디장에게 권한을 확인해 달라고 요청합니다.
- **Git이 없다고 나오면** Git을 설치한 뒤 프로그램을 다시 엽니다. 터미널의 `git --version`도 확인합니다.
- **인터넷 연결이나 응답 시간 오류가 나오면** 연결을 확인한 뒤 다시 제출합니다.
- **clone한 폴더가 아니라고 나오면** ZIP으로 받았는지 확인합니다. [실행·기록 복구 안내](../gui/README.md#예전-버전을-받아-뒀거나-문제-받기가-계속-오류로-끝날-때)에 따라 새 폴더로 복제하고 내 풀이 폴더를 복사합니다. 기존 폴더도 보관합니다.
- **다른 컴퓨터의 풀이를 고르는 창이 나오면** 더 최근에 푼 PC와 각 과목의 기록을 확인합니다. 선택이 어렵다면 창의 안내를 복사해 문의합니다.
- **‘올렸습니다. PR은 잠시 뒤 자동으로 만들어집니다’가 나오면** 잠시 뒤 저장소의 [Pull requests](https://github.com/WaterMinCho/programming-study/pulls)를 확인합니다. 열린 페이지에 [View pull request]가 있으면 그 PR을 엽니다.

계속 실패하면 안내 창의 [자세히]나 [오류 내용 복사]로 내용을 확인하고 [오류 제보](../gui/README.md#그-밖에-불편하거나-이상할-때)에 적습니다. 개인 초대 코드와 인증 정보는 제외합니다.

## PR 에서 피드백하기

1. 저장소의 **Pull requests**에서 제목이 `<ID> 풀이`인 PR을 엽니다. 자동으로 만든 PR은 작성자가 `github-actions`로 표시될 수 있습니다.
2. **Files changed**에서 코드 줄 옆의 `+`로 질문을 씁니다. 왜 이렇게 풀었는지, 다른 입력에서도 동작하는지 확인합니다. 한 줄 질문은 [Add single comment]로 게시할 수 있습니다.
3. 여러 줄의 리뷰를 모았다면 **Review changes**에서 Comment나 Approve를 고르고 [Submit review]로 게시합니다.
4. 스터디장이 검사와 피드백을 확인한 뒤 **Squash and merge**로 공통 main에 합칩니다. 참가자가 올린 풀이 PR을 임의로 합치거나 닫지 않습니다.

다른 사람의 답을 보기 전에는 자신의 회차부터 채점해 두세요. PR에는 아직 풀지 않은 문제의 답과 `profile.json`의 채점 결과가 보일 수 있습니다. 코드 풀이와 설명할 부분을 중심으로 피드백합니다.

## 학습용 폴더에서는 프로그램으로 제출합니다

- 학습용 폴더에서는 직접 Commit·Push하거나 [Publish Branch]를 누르지 않아도 됩니다. 프로그램의 [풀이 제출]을 사용합니다.
- GitHub의 연필 버튼이나 **Commit suggestion**으로만 고치면 프로그램의 로컬 답안과 어긋날 수 있습니다. 답은 프로그램에서 고친 뒤 다시 제출합니다.
- 현재 학습용 폴더는 `WaterMinCho/programming-study`를 직접 clone합니다. 내 fork를 clone하면 [풀이 제출]도 그 fork를 대상으로 동작하므로 공통 풀이 PR과 현황판에 연결되지 않습니다. **모델 개발은 fork를 사용**하며 [모델 개발 안내](LEARNING_WORKFLOW.md)에 따라 별도 폴더에서 진행합니다.

## 참고: 제출 버튼이 git 으로 하는 일

<details>
<summary>Git 명령과 제출 기록 확인 방법 펼쳐보기</summary>

아래는 Git을 직접 확인하고 싶은 사람을 위한 참고입니다. 평소 제출할 때 입력할 필요는 없습니다.

| 프로그램 동작 | Git에서 하는 일 |
|---|---|
| 새 자료 받기 | `git fetch`로 원격 main을 받아 파일을 맞춥니다. |
| 내 풀이 묶기 | `submissions/<내 ID>/`만 담은 커밋을 만듭니다. |
| 올리기 | 원격 `study/<내 ID>` 브랜치로 `git push`합니다. |
| PR 만들기 | 저장소의 자동 작업이 PR을 엽니다. |

현재 상태는 `git status`, 최근 커밋은 `git log --oneline -5`로 읽습니다. `제출한 풀이 반영(이 컴퓨터에만 둠)` 커밋은 로컬 기록을 맞추기 위한 것으로 원격에 올리지 않습니다.

</details>
