# 공통 부품과 화면 설계

전체 학습앱 리디자인은 채택한 시안의 색·표면·글자 위계·카드 배치·탐색·팝업 구성을 기존 `theme → kit → pattern → screens`에 적용합니다. 기능·정책·저장 형식·신호 연결은 기존 계약을 따릅니다. 화면별 적용 상태는 [적용 계획](UI_LAYOUT_PLAN.md), 기능과 검사 범위는 [변경 영향](CHANGE_IMPACT.md)에서 확인합니다.

## 값과 기본 부품, 반복 배치의 책임 구분하기

| 계층 | 현재 구현과 책임 | 다른 계층에 남길 책임 |
| --- | --- | --- |
| `theme` | `gui/theme.py`의 색 역할, `TYPE`, `GAP`, `LEARN_GAP`, `CONTROL`과 두 테마·글자 3단계 | 단원 선택·채점·저장·통신을 결정하지 않습니다. 기존 값을 새 토큰 목록에 복제하지 않습니다. |
| `kit` | `gui/kit.py`의 글·버튼·입력 표시·카드·스크롤·제목 묶음과 초점 표시 | 화면의 자료 키나 제출 조건을 알지 않습니다. 같은 역할의 글자와 상태 표현을 제공합니다. |
| `pattern` | `TopBar`, `BottomBar`, `NavigationTabs`, `SectionBrowser`, `DialogLayout`처럼 부품을 묶는 배치와 키보드 규칙 | 서로 다른 업무를 이름이 같다는 이유로 합치지 않습니다. 이 계층은 책임 구분이며 새 폴더나 기반 클래스를 요구하지 않습니다. |
| `screens` | 첫 화면·과목 홈·학습·시험·복습·커리어가 자료와 기존 컨트롤러를 연결 | 공통 배치의 색·간격·줄바꿈 계산을 화면마다 새로 만들지 않습니다. |

디자인 공통은 배치·외형·표시 상태·키보드 조작이 같은 경우에 적용합니다. 기능 공통은 같은 자료와 처리 규칙을 공유하는 기존 서비스에 둡니다. 학습과 시험의 [다음] 버튼은 같은 모양을 사용해도 저장·채점·시간 정책은 호출 화면이 결정합니다. 실제 사용처에서 같은 규칙을 확인한 부분만 추출하며 화면 종류를 검사하는 분기가 늘어나면 작은 부품을 공유하고 조합은 화면에 남깁니다.

2026년 11월 16일 [Fluent의 토큰 구분][fluent-tokens]과 [Carbon의 패턴 설명][carbon-patterns]을 대조했습니다. 값과 사용 목적을 분리하고 필요한 부품을 조합하는 구조를 참고합니다. 기존 `kit` 안에 있는 배치 부품을 계층 이름에 맞추기 위해 이동하지 않습니다.

## 시안과 실제 화면 대조하기

시안의 버튼·수치·설명은 현재 기능과 하나씩 대조합니다. 보기 좋은 배치라도 없는 기능이나 바뀐 기본값을 그대로 가져오지 않습니다. 동의·전송·파일 저장의 범위와 과목별 진도 계산은 기존 코드가 결정합니다.

AI 홈의 과정 선택은 같은 폭의 둥근 테두리와 배경으로 표시합니다. 하위 분류는 아이콘·이름·설명을 담은 카드로 구분합니다. 분류 영역 너비가 1100px 이상이고 창 높이가 700px 이상일 때 카드를 펼칩니다. 둘 중 하나라도 부족하면 설명을 접습니다. 접은 단추에는 아이콘과 이름을 한 묶음으로 가운데에 둡니다. 아이콘 때문에 단추가 모두 한 줄에 놓이지 않거나 이름이 한 줄 더 접히면 아이콘을 뺍니다. 고른 분류는 파란 바탕에 흰 글자와 아이콘으로 칠하고, 키보드 초점은 점선으로 구별합니다. 긴 차시 제목은 줄바꿈하며 학습 안내 이미지와 강조 좌표도 변경한 배치에 맞춰 확인합니다.

`NextCard`는 이어서 할 일을 먼저 찾도록 파랑에서 청록으로 이어지는 배경과 테두리로 강조합니다. 머리말은 청록색 보조 글자, 제목은 `title` 역할을 사용합니다. 기존 여백과 버튼 폭으로 가로 배치 여부를 계산하며 다음 행동의 선택·클릭 신호는 호출부가 유지합니다.

촘촘한 화면의 이어서 할 일은 `NextCard(compact=True)`로 만듭니다. 바탕은 `emphasis_bg` 한 색이고 테두리는 `hero_edge`입니다. 학습 현황 카드만 `plain_next` 속성을 주어 흰 표면과 `line` 테두리로 그립니다. 꼬리표와 제목 사이, 제목과 설명 사이는 4px입니다. 보통 글자에서 설명이 한 줄이면 카드가 최소 높이 108px 안에 듭니다.

제목 오른쪽에는 `set_side()`로 보조 글 한 줄을 둘 수 있습니다. 알고리즘 지도는 "던전 1 「향신료 시장」 · 중급" 같은 던전·역할 줄을 이 자리에 둡니다. AI 홈은 「단원 이름」 줄을 이 자리에 두고 나머지 줄을 설명으로 씁니다. 제목과 보조 글이 한 줄에 들어가지 않으면 보조 글을 제목 아래로 내립니다. 보조 글이 비어 있으면 숨깁니다. 학습 현황은 보조 글 대신 '이어서 할 일' 꼬리표 오른쪽에 과목 이름을 둡니다. 과목 이름은 설명 줄에서 첫 ` · ` 앞에 있는 글입니다.

학습 현황은 넓은 창에서 왼쪽 열에 과목 카드를 두고 오른쪽 열에 오답 노트와 최근 7일 학습 카드를 차례로 둡니다. `DashboardRow`가 두 열을 66:34 폭으로 나누고 열 사이를 20px 띄우며 위쪽을 맞춥니다. 왼쪽 열은 본문 글자 크기의 32배, 오른쪽 열은 그 폭에 34:66 비율을 곱한 값과 두 카드의 최소 폭 가운데 큰 값이 필요합니다. 이 합보다 좁으면 과목, 오답 노트, 최근 7일 학습 순서로 쌓습니다. 과목 카드는 본문 글자 크기를 기준으로 3열·2열·1열로 전환하고, 마지막 줄에 카드가 하나만 남으면 그 카드가 줄 전체 폭을 씁니다. 과목별 진도·오답·최근 채점의 집계와 이동 대상은 기존 기능을 따릅니다.

팀 수집 현황은 기간별 그래프를 전체 누적보다 앞에 둡니다. 지표 제목은 `caption`, 숫자는 `title` 역할로 표시하고 조회 권한·기간 선택·지표 설명을 유지합니다. 학습 기록 설정은 상태와 기록 수를 먼저 보여주고 전송·파일 저장·희망 직무를 따로 펼칩니다.

## 색과 글자 역할 적용하기

2026년 11월 17일의 시각 변경은 `gui/theme.py`에 모읍니다. 밝은 화면은 옅은 청회색 바탕과 흰 표면, 어두운 화면은 짙은 남색 바탕과 한 단계 밝은 표면을 사용합니다. 일반 카드에는 1px 선과 16px 모서리를 적용합니다. 학습 현황·파이썬 홈·회차 풀이·결과·오답 노트, 알고리즘 지도·문제 화면, AI 홈·차시 목록·단원 학습·연습·모의고사는 촘촘한 배치를 씁니다. 여기서는 카드 모서리가 8px, 버튼과 입력칸은 6px, 꼬리표는 4px입니다. 위 막대는 56px, 아래 막대는 64px이고 본문과 막대의 좌우 여백은 24px입니다. 화면은 `kit.dense()`로 묶음에 `density="dense"` 속성을 주고, 막대는 `TopBar(dense=True)`·`BottomBar(dense=True)`를 씁니다. AI 단원 학습의 단계 표시줄은 `Stepper(dense=True)`로 48px입니다. 웹 학습·커리어처럼 이 목록에 없는 화면은 64px 위 막대, 80px 아래 막대, 32px 여백을 씁니다.

학습 현황의 위 막대는 흰 바탕에 아랫선을 둡니다. 알고리즘 지도와 AI 홈의 위 막대는 창 바탕색 위에 둡니다. 알고리즘 지도와 AI 홈·차시 목록이 위 막대에 붙이는 [설정]은 테두리 단추로 그립니다.

## 번호 칩과 꼬리표 쓰기

꼬리표는 `kit.badge()`로 만들고 색은 tone 으로 고릅니다. tone 이 없으면 회색입니다. `accent`는 선택 색 바탕을 씁니다. `success`·`warning`·`danger`는 정답·재도전·오답과 같은 약한 바탕과 글자색을 씁니다. 촘촘한 화면에서 꼬리표 모서리는 4px입니다. 숫자만 든 꼬리표는 새 화면 문구로 보지 않습니다. 이미 화면이나 같은 함수에 있는 개수만 꼬리표로 옮깁니다.

| 자리 | 꼬리표 | 숨기는 때 |
| --- | --- | --- |
| 학습 현황 과목별 학습 머리 | 보이는 과목 칸 수 | 숨기지 않습니다. |
| 파이썬 홈 [오답 노트] 단추 안 | 파이썬 틀린 문항 수, `danger`. 학습 현황 오답 줄의 '틀린 문항 N개'와 같은 수입니다. | 0개일 때 |
| 파이썬 홈 지난 회차 머리 | 지난 회차 수 | 0개일 때 |
| 회차 풀이 문항 목록 카드 | 'N문항' | 숨기지 않습니다. |
| 회차 풀이 지문 제목 위 | 유형 `accent`, 단원과 배점은 회색, '지난번에 틀린 문항' `warning` | 다시 푸는 문항이 아니면 마지막 꼬리표를 숨깁니다. |
| 알고리즘 목록 머리 | 고른 던전의 지도 상태. 클리어는 `success`, 진행 중은 `accent`, 시작 전과 준비 중은 회색입니다. | 숨기지 않습니다. |
| 알고리즘 던전 카드 | 주제·보스 난이도 줄을 ` · `로 나눈 조각마다 회색 꼬리표 | 숨기지 않습니다. |
| 알고리즘 문제 줄 | 준비 문제, 회색 | 제목과 한 줄에 들어가지 않으면 꼬리표를 숨기고 같은 글을 둘째 줄 끝에 씁니다. |
| 알고리즘 힌트 탭 | '힌트 1/3'의 '1/3', 회색 | 탭 글에 숫자가 없을 때 |
| AI 차시 목록 단원 줄 | '코드 읽기'·'심화 있음', `accent` | 해당하지 않는 단원 |
| 오답 노트 갈래 머리 | 갈래의 문항 수. 틀린 문항은 오답 색, 미응답은 회색, 다시 맞힌 문항은 정답 색입니다. | 숨기지 않습니다. |
| 오답 노트 문항 줄 끝 | 틀린 문항은 '오답' `danger`, 미응답 문항은 '미응답' 회색 | 다시 맞힌 문항 |
| 오답 노트 문항 제목 위 | 첫 시도 결과, 회차, 'N개 회차에서 틀림' | 공급자가 꼬리표를 주지 않는 AI 문항 |

회차 지문의 꼬리표가 칸보다 길면 줄임표로 줄이고 전체 글은 툴팁에 둡니다. 꼬리표 줄은 폭이 모자라면 다음 줄로 넘깁니다. 꼬리표 때문에 칸의 최소 폭이 늘어나지 않게 합니다.

번호 칩은 `kit.number_chip()`으로 만듭니다. 칩에는 이미 있는 순번 글을 넣습니다. AI 차시·단원 번호와 파이썬 회차 번호는 '01'처럼 두 자리로 씁니다. 칩 높이는 꼬리표와 같고 모서리는 4px입니다. 칩 폭은 두 자리 숫자 폭에 16px를 더한 값 이상입니다. 그래서 한 자리 번호와 두 자리 번호가 같은 폭으로 줄을 맞춥니다. 목록 줄에서는 `kit.Row(lead=칩)`으로 상태 점 다음, 제목 앞에 둡니다.

번호 칩의 색은 자리마다 정합니다. 알고리즘 일반 문제 줄, AI 단원 줄, 알고리즘 문제 화면 머리는 회색입니다. 알고리즘 보스 줄과 AI 홈 차시 줄은 `accent`입니다. 알고리즘 목록에서 이어서 할 문제 줄만 `solid`를 씁니다. `solid`는 `primary` 바탕에 흰 글자입니다. 알고리즘 문제 목록은 모든 칩을 가장 넓은 칩의 폭에 맞춥니다. 그래서 제목이 같은 세로선에서 시작합니다.

AI 홈 차시 줄은 `tile=True`를 주어 정사각 칩을 씁니다. 한 변은 `theme.number_tile()`입니다. 보통 글자에서는 36px이고, 큰 글자에서는 caption 줄 높이에 12px를 더한 값으로 늘어납니다. 정사각 칩의 테두리는 1px `hero_edge`입니다.

서로 바꿔 고르는 칩은 `kit.segmented()`로 붙인 칩 묶음을 만듭니다. 묶음이 바깥 1px `line` 테두리와 6px 모서리를 그리고 칩은 사이 간격 없이 붙습니다. 양 끝 칩만 바깥쪽 모서리가 둥급니다. 묶음 높이는 칩 높이에 2px를 더한 값입니다. `soft` 묶음에서 고른 칩은 `emphasis_bg` 바탕에 `link` 글자입니다. 알고리즘 문제 화면의 풀이 언어가 `soft`를 씁니다. `solid` 묶음에서 고른 칩은 `primary` 바탕에 흰 글자입니다. 오답 노트의 과목 선택이 `solid`를 씁니다. 키보드 초점은 칩의 2px `focus` 테두리로 보입니다. `solid`로 고른 칩의 초점 테두리는 `surface` 색입니다. 팀 수집 현황·웹 홈·직무 추천이 쓰는 기본 `kit.chip()`은 붙은 칩 묶음 규칙을 받지 않습니다.

## 목록 줄과 결과 표시 맞추기

촘촘한 화면에서 `RowList(separate=True)`는 줄 사이 선 대신 줄마다 흰 상자를 그립니다. 상자 사이는 8px입니다. 알고리즘 던전의 문제 목록과 AI 차시 목록의 단원 줄이 이 모양을 씁니다. `least`를 주면 줄 최소 높이와 글 위아래 여백을 따로 정합니다. 큰 글자에서는 글 높이만큼 줄이 늘어납니다.

알고리즘 목록에서 이어서 할 문제 줄은 `next_row` 속성을 주고 `emphasis_bg` 바탕으로 칠합니다. 마우스를 올리거나 누른 바탕은 다른 줄과 같게 바뀝니다. 모의고사 결과의 차시별 표는 열마다 `RowList(striped=True)`를 씁니다. 줄 사이 선을 긋지 않고 열마다 두 번째, 네 번째 줄처럼 짝수 번째 줄에 `surface_alt` 바탕을 칠합니다. 이 표의 줄 높이는 48px입니다. 줄은 개론 차시 다음에 응용 차시를 번호 순서로 놓습니다. 한 열 폭은 'N차시' 칸, 가장 긴 차시 이름, 막대(결과 화면만), 끝 글('n문항'이나 '맞은 수 / 문항 수')을 한 줄에 놓는 폭입니다. 표 폭이 한 열 폭의 두 배 이상이면 두 열로 나눕니다. 그래서 두 열에서 차시 이름이 줄임표로 줄지 않습니다. 이때 왼쪽 열에 앞 차시를, 오른쪽 열에 뒤 차시를 두고 두 열 사이에 1px 세로선을 긋습니다. 표 폭이 한 열 폭의 두 배보다 좁으면 한 열로 둡니다. 'N차시' 칸 폭은 열마다 그 열에서 가장 긴 글에 맞춥니다. 하나도 맞히지 못한 차시는 'N차시' 칸, 이름, '0 / n'을 `danger` 글자로 씁니다. 그 차시의 문항이 모두 이 기기에서 채점하지 못한 문항이면 `danger` 글자로 쓰지 않습니다. 숫자가 같은 줄에 있어 색만으로 상태를 나누지 않습니다. 표 위에는 빈칸, 객관식, 코드 작성 가운데 문항이 있는 유형마다 작은 카드를 하나씩 두고 '맞은 수 / 문항 수 맞음'과 얇은 막대를 씁니다. 이 기기에서 채점하지 못한 코드 작성 문항이 있으면 코드 작성 카드 안의 '맞은 수 / 문항 수 맞음' 줄 아래에 '채점하지 못한 문항 n개'를 씁니다. 카드마다 240px(큰 글자에서는 글자 비율만큼 넓힘)을 줄 만큼 폭이 넓지 않으면 카드를 세로로 쌓습니다.

모의고사 시작 전 화면도 요약 카드 아래에 같은 유형 카드와 차시별 표를 둡니다. 유형 카드에는 '빈칸 n문항'과 한 줄 설명을, 차시별 표에는 차시마다 'n문항'을 쓰고 막대는 두지 않습니다. 회차 목록과 시작 전 요약 카드의 설명을 같은 형식으로 표시합니다. 개론 회차는 문항 수와 시간 뒤에 '개론 1~17차시'처럼 과정 이름을 붙입니다. 모든 차시 회차는 차시 범위를 개론과 응용으로 나눠 쓰고, 32문항 혼합 회차는 차시 범위 대신 과정별 문항 수를 씁니다. 시계가 멈추지 않는다는 안내는 `warning` 띠 하나에 넣어 요약 카드와 유형 카드 사이에 둡니다. 모든 차시 회차와 32문항 혼합 회차는 이 띠의 첫 문장으로 120분이 연습 기본값이라는 문장을 넣습니다.

모의고사 시험 화면의 번호 칸은 모두 같은 폭입니다. 시험 중에는 답한 문항 번호 뒤에 체크 표시를, 나중에 보기로 표시한 문항 번호 뒤에 별표를 붙입니다. 제출한 뒤에는 맞음 ○, 틀림 ×, 비움 −, 이 기기에서 채점하지 못함 ? 를 붙입니다. 칸 폭은 가장 큰 번호에 이 기호를 하나씩 붙여 굵은 글자와 보통 글자로 재고, 그 가운데 가장 넓은 폭으로 정합니다. 그래서 제출 전후에 칸 폭과 줄 수가 같습니다. 툴팁과 접근성 이름에는 기호 대신 '10번 · 답함 · 나중에 보기'처럼 말로 씁니다. 채점하지 못한 문항이 있으면 요약 카드에 그 수와, 그 문항이 전체 문항 수에는 들어가지만 맞은 문항과 복습에는 들어가지 않는다는 문장을 더합니다. 제출한 뒤 위 막대의 시계 자리에는 '제출 완료'만 쓰고 '남은 시간' 글은 숨깁니다. 번호 칸 묶음 위에는 '문항 번호 · 지금 번호 / 전체 수' 접는 줄을 둡니다. 펼친 번호 칸 묶음의 높이가 스크롤 영역 높이의 1/3 을 넘으면 접은 채로 엽니다. 창 크기가 바뀌면 같은 기준으로 다시 접거나 펼칩니다. 학습자가 직접 접거나 펼치면 그 회차 화면이 열려 있는 동안 고른 상태를 지킵니다. Tab 키는 접는 줄에서 첫 번호 칸으로 갑니다. 문항 카드 머리에는 'n / 전체 수' 옆에 차시 `accent` 꼬리표를 둡니다. 첫 빈칸에 초점이 가면서 화면이 내려가도 카드 머리는 화면 안에 남습니다. 빈칸 입력 칸 아래에는 입력 형식 한 줄을 caption `secondary` 로 두고, 문항 자료에 `hint` 가 있으면 칸 위에 이름표로 씁니다. 코드 속 빈칸은 코드 상자 아래에 칸마다 형식 줄을 둡니다. 빈칸 입력 칸의 접근성 이름은 번호와 이름표(이름표가 없으면 입력 종류)이고, 접근성 설명은 형식 줄과 같은 글입니다.

모의고사의 코드 작성 문항은 창 크기와 상관없이 지문, 코드, 실행 결과를 차례로 한 열에 둡니다. 지문 아래에는 공개 예시를 `>>>` 호출 줄과 돌려준 값으로 보입니다. 코드 상자는 빈칸 문항과 같은 `CodeSlots` 를 쓰고 시작 코드의 `____` 줄마다 한 줄 칸을 둡니다. 다른 줄은 고칠 수 없고 칸 사이는 Tab 으로 옮겨 갑니다. 칸의 접근성 이름은 '채울 줄 n' 입니다. [코드 실행]은 아래 막대 왼쪽의 [나중에 보기] 옆에 두고 시험 중인 코드 작성 문항에서만 보입니다. 실행 결과 상자는 파이썬 회차 화면과 같은 표로 그리고 높이를 내용에 맞춥니다. 채점과 [코드 실행]이 도는 동안에는 문항 카드 위 안내 띠에 하는 일을 적습니다. 다른 작업이 아직 돌고 있어 [코드 실행]이나 제출을 시작하지 못하면 오류 띠가 아니라 같은 안내 띠에 잠시 뒤 같은 단추를 다시 누르라고 적습니다. 제출한 뒤에는 칸을 읽기 전용으로 두고, 이 기기의 초안에 통과 수가 있으면 '채점에 쓴 숨은 테스트 n개 중 m개 통과'를 보인 다음 시작 코드에 모범 답안 줄을 넣은 코드를 보입니다.

AI 홈 차시 줄은 꺾쇠 왼쪽에 폭 120px의 얇은 막대와 '읽은 수 / 단원 수'를 둡니다. AI 차시 목록의 단원 카드 머리에도 같은 폭의 막대를 둡니다. 단원을 다 읽으면 두 막대를 `success` 색으로 칠합니다.

학습 현황 과목 칸의 진도 줄은 왼쪽에 이름, 오른쪽에 굵은 숫자를 둡니다. 설명과 진도 줄 사이에는 8px, 1px 선, 8px를 차례로 둡니다. 파이썬 홈 단원 칸은 '01' 번호 아래에 caption 크기의 단원 이름 한 줄을 둡니다. 칸 폭에 이름 세 글자가 들어가지 않으면 이름을 빼고 번호만 가운데에 둡니다.

파이썬 홈의 지난 회차 줄은 목록 항목을 직접 나눠 그립니다. 왼쪽에 회차 번호 칩, 가운데에 제목, 오른쪽에 굵은 점수와 파란 꺾쇠 '›'를 둡니다. 진단 테스트처럼 회차 번호가 없는 줄은 칩 자리만 비웁니다. 줄마다 `surface_alt` 바탕에 모서리 6px이고 줄 사이는 8px입니다. 목록 높이는 줄 수에 맞추고 줄이 없으면 목록을 숨깁니다.

파이썬 결과 화면은 점수 옆에 득점률을 `accent` 꼬리표로 보입니다. 숙달한 단원 줄은 왼쪽에 이름, 오른쪽에 굵은 '숙달 수 / 전체 수'를 두고 숫자 끝을 막대 끝에 맞춥니다. 요약 문단의 정답·오답·미응답 수 앞에는 각 결과 색의 점을 둡니다.

결과 화면의 단원별 판정 표에는 `table.verdict` 클래스를 주어 세로선 없이 줄 아래 가로선만 긋습니다. 머리 줄은 `surface_alt` 바탕입니다. 판정 칸은 `span.tag-verdict-<판정>` 꼬리표로 칠합니다. 진급은 선택 색, 숙달은 정답 색, 유지는 회색, 재도전은 재도전 색입니다. 단원 번호는 흐린 글자로 씁니다. 내용 칸에서 '→' 뒤의 다음 할 일은 `link` 색으로 씁니다. 문항 목록의 글자는 본문 색으로 두고 판정은 줄 앞 꼬리표로 알립니다.

Qt 문서는 표 폭을 CSS 로 받지 않습니다. 꽉 찬 표에는 `width="100%"` 속성을 줍니다. 칸 아랫선은 `border-bottom: 1px solid …` 처럼 한 줄로 몰아 쓴 표기를 읽지 않으므로 `border-bottom-width`·`border-bottom-style`·`border-bottom-color`로 나눠 씁니다. 문서 안 꼬리표는 `span.tag-ok`·`span.tag-wrong`·`span.tag-blank`처럼 약한 바탕 글자로 씁니다.

회차 실행 결과는 요약 문단을 `td.callout` 칸에 둡니다. 예시마다 통과와 실패를 `span.tag-ok`·`span.tag-wrong` 꼬리표로 씁니다. 요약 아래에는 통과한 예시의 비율 막대를 숫자 없이 둡니다. 실행 결과 칸은 1px `line` 테두리와 8px 모서리로 그립니다. 회차 지문의 코드 상자는 위아래 안 여백만 16px로 늘립니다. 좌우 여백을 늘리면 760×480 가장 큰 글자에서 지문에 가로 스크롤이 생깁니다.

오답 노트의 객관식 보기는 번호 칸과 보기 칸 두 칸 표로 그립니다. 고른 보기 줄에는 약한 오답 바탕과 '내 답' 꼬리표를 붙입니다. '정답' 꼬리표는 해설을 편 뒤에만 정답 보기 줄에 붙입니다. 꼬리표가 붙은 줄만 보기 칸 안에 작은 표를 넣어 꼬리표를 오른쪽에 둡니다. 그래서 꼬리표가 없는 줄의 보기 글은 줄 끝까지 씁니다.

AI 연습에서 채점한 뒤 보이는 정답 줄은 판정 문장보다 한 단계 낮은 `learn_caption`으로 씁니다. 채점한 뒤 읽기 전용으로 바꾼 입력칸에만 정답이나 오답의 약한 바탕을 칠합니다. 알고리즘 테스트 추가 창처럼 아직 고칠 수 있는 칸은 테두리 색만 바뀝니다. 연습 문항 카드의 최대 폭은 976px이고 넓은 창에서는 가운데에 둡니다. 976px는 1024 창에서 카드가 차지하던 폭이라 그 창의 코드 줄 접힘이 바뀌지 않습니다.

AI 연습 완료 화면은 첫 답에 맞힌 수를 `display` 숫자로 보이고 복습 일정과 이번 연습의 세부 수치를 따로 놓습니다. 넓은 창은 두 묶음의 위를 맞춰 나란히 두고, 글자 크기에 비해 폭이 부족하면 복습 일정을 먼저 보여 줍니다. 묶음 사이는 24px, 항목 줄 사이는 8px, 설명 문단 사이는 16px를 씁니다. 항목 이름은 왼쪽, 같은 묶음의 날짜와 수치는 오른쪽에 맞춥니다. 작은 창에서도 아래 행동 단추는 본문과 함께 스크롤하지 않습니다.

AI 단원 학습의 아래 막대에는 [다음] 왼쪽에 '지금 단계 / 단계 수'를 둡니다. 이 글은 초점을 받지 않습니다. AI 학습 위치 상자는 `emphasis_bg` 바탕과 `hero_edge` 테두리로 그립니다. 모의고사 결과의 '처음 점수'는 이름을 본문 글자로, 점수 숫자를 파란 굵은 글자로 씁니다. 알고리즘 결과 카드는 결과가 없을 때만 머리 글 두 줄을 회색 칸 가운데에 둡니다. 회색 칸의 안 여백은 16px입니다.

### 시안과 다르게 둔 곳

- 회차 아래 막대의 자동 저장 안내는 폭이 모자라면 줄임표로 줄고 전체 글은 툴팁에 둡니다. 안내에 남는 폭을 주면 760×480에서 아래 막대를 한 줄로 두는 계산이 바뀝니다.
- 알고리즘 문제 줄의 흰 상자와 이어서 할 일 카드의 테두리는 다른 화면과 같은 공통 모양을 씁니다. 공통 규칙을 바꾸면 다른 화면에도 번집니다.
- 알고리즘 지도 카드는 지도 최소 폭 390px 때문에 1280 창에서 목록 카드보다 좁습니다. 지도 폭을 줄이면 던전 이름 줄임표가 늘어납니다.
- 지도 본체는 원과 뱀 모양 길을 씁니다. 시안의 4열 격자로 바꾸면 던전 이름 대부분이 줄임표가 되고 권장 순서와 화살표 이동 순서가 바뀝니다.
- AI 홈 차시 제목 앞의 'N차시' 글은 따로 떼지 않습니다. 떼려면 차시 줄의 줄바꿈 높이 계산을 다시 짜야 합니다. 760×480 가장 큰 글자에서는 차시 제목이 두 줄로 접히지만 줄임표나 겹침은 없습니다.
- AI 단원 학습 글에 들어간 코드 블록의 안 여백은 16px로 둡니다. 20px로 늘리면 1024×700 가장 큰 글자에서 코드 줄이 새로 접힙니다.
- 모의고사 결과의 [이전]·[다음]은 시험 중과 같은 오른쪽 묶음에 둡니다. 제출한 뒤에만 자리를 옮기면 아래 막대의 줄 쌓기와 760 폭 배치가 상태마다 달라집니다.
- 문서 안 꼬리표는 모서리가 각지고 높이가 글줄과 같습니다. Qt 문서는 span 의 높이와 둥근 모서리를 그리지 않고, 한 칸 표로 바꾸면 글줄 안에 놓을 수 없습니다.

설정의 표시 위치와 기능 허용 조건은 함께 적용합니다. 공통 메뉴가 생겨도 본인 확인·동의·제출·업데이트의 기존 정책을 넓히지 않습니다.

## 행동 줄의 배치 계산 공유하기

`gui/action_layout.py`의 `ActionLayout`을 `DialogLayout`·`BottomBar`·`SubmissionBar`와 로드맵 확대창이 공유합니다. 표시 중인 항목 측정·좌우 묶음·줄바꿈 계산을 재사용하며 기존 `gui.dialog_layout`의 가져오기 경로도 유지합니다. 대화상자는 좁을 때 주 행동을 먼저 쌓고 학습·제출 하단은 원래 행동 순서를 유지합니다.

행동 줄은 버튼의 표시 여부와 실제 필요 크기를 받고 배치만 결정합니다. 제출 가능 여부·동의·작업 중 상태·채점·타이머는 기존 호출부가 결정합니다. 같은 위젯과 신호 연결을 유지하며 재배치 때문에 버튼을 다시 만들거나 작업을 중복 연결하지 않습니다. 숨은 항목의 자리는 남기지 않고 비활성 항목은 필요한 안내와 함께 유지합니다.

대화상자·학습 하단·제출 안내의 바깥 여백과 도구 간격은 각각 기존 값을 사용합니다. 계산 공유를 이유로 모든 영역의 간격을 같은 숫자로 바꾸지 않습니다. 주 행동의 위치와 읽는 순서, 긴 한국어 버튼, 한 줄에서 여러 줄로 바뀌는 높이를 확인합니다. 제출 안내는 상태가 바뀌어도 읽던 위치를 밀지 않도록 기존 끝 여백과 초점 노출을 함께 검증합니다.

## 표시 변경 중 기능 상태 보존하기

글자·테마·창 크기를 바꾸면 배치를 다시 계산하되 답안·커서·선택 범위·현재 문항·펼친 설명을 유지합니다. 읽던 항목과 스크롤 위치는 레이아웃이 안정된 뒤 복원하며 사용자가 직접 이동한 새 위치를 우선합니다. 팝업을 닫으면 호출한 버튼으로 초점을 돌리고 그 버튼이 사라졌을 때만 다음 행동으로 옮깁니다.

비동기 결과는 현재 학습자·과정·문항·요청과 맞는지 확인한 뒤 적용합니다. 닫기·취소·권한 철회 뒤 도착한 응답은 화면을 다시 열거나 오래된 선택을 덮어쓰지 않습니다. 같은 대기 상태를 반복 조회할 때는 버튼 활성화·초점·선택·스크롤을 바꾸지 않습니다. 알림은 입력 초점을 가져오지 않고 중복 제출도 시작하지 않습니다.

창 전체 작업 잠금, 학습 기록의 배경 전송, 영상 준비는 소유자가 다릅니다. 같은 `busy`라는 이름만으로 모두 같은 행동을 막거나 같은 취소 절차를 적용하지 않습니다. 탐색 허용 목록과 제출 안내 허용 목록도 별도로 유지합니다.

시험의 시간 계산과 표시 갱신은 구분합니다. 창이나 설정을 왕복해도 원래 시작·마감과 기존 일시 정지 정책을 유지합니다. 움직임 줄이기는 진행 중 효과와 예약된 자동 재생에도 적용하고 학습 그림의 정지·수동 넘김은 남깁니다. 상태 보존 검사는 [변경별 검사 선택](CHANGE_IMPACT.md#변경별-검사-선택하기)을 따릅니다.

## 화면 목적에 필요한 차이 유지하기

AI 학습·연습·시험·결과는 기존 본문 카드와 지문·입력·단계별 행동 구획에 공통 테마를 적용합니다. 파이썬 결과의 점수·문항 목록·해설도 기존 구획을 유지합니다. 대표 캡처에서 구분되는 영역을 다시 상자로 감싸지 않으며 문항·채점·시험 시간·저장 정책은 각 화면에 남깁니다.

파이썬 Round는 목록·지문·답안의 분할 구조를 유지하며 작은 창에서 목록 폭과 패널 여백을 줄입니다. 넓은 창으로 돌아오면 보관한 분할 크기를 복원합니다. 목록 폭·여백과 분할 복원 조건은 [문제 화면 배치](UI_LAYOUT_PLAN.md#문제-종류에-맞춰-지문과-답안-놓기)를 따릅니다. 캡처의 구획 확인과 창 왕복·입력·저장 검사의 완료를 구분합니다.

| 서로 다른 조건 | 유지할 차이 |
| --- | --- |
| 일반 화면과 학습 본문 | 아래의 일반 글자·간격과 학습용 글자·간격을 각각 사용합니다. |
| 학습 하단과 제출 안내 | 학습 하단은 본문과 나눈 고정 행을 사용하고 제출 안내는 조건부 표시와 기존 스크롤 여백을 유지합니다. |
| 코드·행렬·로드맵·영상 | 공간 관계가 필요한 내용에는 별도 스크롤·확대·전용 조작을 허용합니다. 화면 전체의 버튼이나 설명을 함께 잘라내지 않습니다. |
| 운영체제별 대화상자 | Windows/macOS의 키보드와 버튼 역할을 확인합니다. 삭제·철회를 Enter 기본 행동으로 만들지 않습니다. |
| 좁은 창과 넓은 창 | 글자를 줄이는 대신 행·열·보조 영역을 바꾸며 현재 선택과 읽던 위치를 유지합니다. |

채택한 시안의 색·표면과 정보 위계를 실제 화면에 적용합니다. 실제 제품에 없는 구독 등급·학기·기능은 도입하지 않습니다. 시각 변경의 코드 반영과 Qt의 실제 조작 검증을 구분합니다.

## 제목과 설명 사이 띄우기

제목과 소제목은 ‘화면 설정하기’, ‘출력 모양 비교하기’처럼 할 일을 짧게 씁니다. 이미 뜻이 분명한 ‘수집 통계’ 같은 제목은 유지합니다. 설명 문장은 본문에 두고, 제목에 쓰인 부정·수치·조건은 줄이는 과정에서 뜻이 달라지지 않게 확인합니다.

세로 간격은 `gui/theme.py`의 `GAP`에서 고릅니다. 같은 제목과 설명은 `kit.heading()`으로 묶습니다. 설명을 숨기면 그 자리에 간격도 남기지 않습니다.

| 이어지는 요소 | 간격 | 적용 위치 |
|---|---:|---|
| 목록 제목과 짧은 보조 설명 | 8px | 단원·문항 목록, 다음 행동 카드의 분류 이름 |
| 제목과 그 제목을 설명하는 글 | 12px | 과목 소개, 구역 소개, 카드, 대화상자, 노트 제목 |
| 본문 문단 | 16px | 노트와 해설의 문단 |
| 설명과 다음 목록·입력 영역 | 24px | 과목 홈의 목록, 대화상자의 입력 영역 |
| 카드 안의 내용 묶음 | 24px | 지표, 소개 글, 기술 목록 |
| 서로 다른 구역 | 48px | 과목 홈과 학습 현황 |

보통 글자에서 제목은 30px에 줄 높이 40px, 본문은 17px에 줄 높이 28px입니다. 가장 큰 글자는 본문 21px에 줄 높이 36px입니다. 제목과 설명 사이는 12px를 유지합니다. 줄바꿈한 글의 높이를 먼저 확보하고 다음 내용을 24px 띄웁니다. 두 줄 목록은 최소 80px를 확보합니다. 설명이 여러 줄이면 목록 높이도 늘어납니다.

화면 설정의 글자 크기 선택 단추 셋은 같은 글꼴·크기·굵기·높이로 표시합니다. 폭은 가장 긴 단추 글자에 맞춥니다. 크기를 줄였다가 키우거나 설정을 다시 열어도 같은 기준을 적용합니다. 선택한 항목은 배경색으로 구분합니다.

기본 목록·체크박스에도 공통 글꼴 역할을 지정합니다. 화면 설정을 바꾸면 목록의 선택과 입력을 유지하며 같은 역할의 글자가 함께 커지고 작아집니다. 긴 목록 제목은 툴팁에서도 전체 내용을 확인할 수 있게 합니다.

학습 본문의 복사 허용과 답안 칸의 입력 제한은 따로 적용합니다. 나중에 펼친 확인 물음과 새로 만든 코드 빈칸에도 같은 제한을 적용합니다. 제한 안내는 입력·선택 범위·초점·읽던 위치를 바꾸지 않으며 한글 입력·되돌리기·저장 답안 복원은 유지합니다. 인증 코드 복사와 학습 설명의 복사도 함께 확인합니다.

행간을 대조할 때는 같은 글꼴·크기·아이콘을 쓴 기본 목록과 비교합니다. 실제 캡처에서도 두 글줄 사이의 간격을 확인합니다.

가로 도구 모음과 선택지 사이에는 내용에 맞는 간격을 씁니다. 제목·설명 규칙을 모든 배치 숫자에 적용하지 않습니다. 오답 결과처럼 한 문단이 표의 한 줄을 대신하는 곳은 기존 문단 간격을 유지합니다.

모의고사 목록 설명과 회차 목록 사이는 24px, 회차 이름과 문항 수 사이는 8px입니다. 응시와 결과 화면은 요약·문항 유형·차시별 표·문항 번호·지문처럼 다른 묶음 사이를 24px 띄웁니다. 유형 카드의 제목과 설명 사이는 12px입니다. 문항 번호를 펼치면 위 제목 줄과 번호 칸 사이에 8px를 둡니다.

그림 넘김 단추는 글자에 필요한 폭을 유지합니다. 한 줄에 들어가지 않으면 다음 줄로 넘깁니다. 카운터는 가장 긴 장 번호의 폭을 확보합니다. 재생과 일시 정지는 같은 정사각형 아이콘 단추에서 전환합니다. 크게 보기는 넘김 줄에 자리가 있을 때 함께 놓고, 공간이 부족하면 그림 설명 아래에 놓습니다. 장을 바꿔도 넘김 단추의 위치는 유지합니다.

화면을 바꾸면 offscreen에서 실제 창 크기 760×480, 1024×700, 1280×800을 확인합니다. 가장 큰 글자와 밝은·어두운 테마에서 제목·설명 간격, 줄바꿈, 단추의 글자 폭을 확인합니다. 제출 안내를 갱신할 때 입력 내용·선택 영역·초점·스크롤 위치도 대조합니다.

Windows 창 검사는 `QT_QPA_PLATFORM=windows`에서 별도로 수행합니다. 요청한 창 크기와 실제 크기, 화면의 작업 영역, 글자 크기와 배율을 기록합니다. 실행 환경의 화면이 작아 창 크기를 줄인 결과를 프로그램의 배치 실패로 판정하지 않습니다. 배율을 바꿔 확인할 때 `QT_SCALE_FACTOR`로 시험한 값과 Windows의 표시 설정을 구분합니다.

창이 작은 경우에는 스크롤로 각 단추를 보이게 한 뒤 글자와 클릭 영역 전체가 들어오는지 확인합니다. Windows가 그린 창의 캡처와 위젯 캡처도 대조합니다. 운영체제·Qt 버전·테마·실제 창 크기를 함께 남기며 호스팅 실행 환경의 확인 결과를 사용자 기기의 검증으로 확대하지 않습니다.

빈 화면과 기록이 쌓인 화면을 모두 확인합니다. 그래프의 권장 너비를 작은 창의 최소 너비로 강제하지 않습니다. 나란한 카드가 들어가지 않으면 세로로 배치하고, 창을 넓히면 다시 나란히 놓습니다. 화면 첫 진입과 왕복, 글자 확대 뒤 축소에서도 가용 폭을 다시 계산합니다.

## 수집 통계의 요약과 조회 기간 구분하기

## 팝업의 하단 동작 고정하기

확인·오류·풀이 ID·GitHub 본인 확인·동의·제출·학습 데이터 팝업은 `gui/dialog_layout.py`의 공통 배치를 사용합니다. 제목과 하단 동작은 `surface_raised`, 스크롤 본문은 `bg`로 면을 나눕니다. 제목 아래와 하단 위에 1px 선을 표시합니다. 제목과 하단 동작은 고정하고 긴 본문만 스크롤합니다.

제목·본문·버튼의 좌우 여백은 32px로 맞춥니다. 제목 위는 24px, 제목 아래는 설명이 있으면 16px·없으면 12px로 둡니다. 본문 위는 16px, 아래는 24px를 확보합니다. 본문에는 기존 글자 역할을 사용하며 글자 확대에 따라 함께 커집니다. 부모 창과 작업 영역에 맞추는 크기 계산과 호출부의 확인·닫기·저장 동작을 유지합니다.

주 행동 하나를 오른쪽에 강조하고 복사·자세히 같은 보조 동작은 왼쪽에 둡니다. 표시 중인 버튼의 실제 글자 폭과 8px 간격으로 줄바꿈을 정합니다. 창 폭만으로 글자를 압축하거나 숨긴 버튼의 자리를 남기지 않습니다. 삭제·철회 버튼의 역할과 Enter로 실행하지 않는 규칙은 유지합니다.

간단한 알림의 기본 너비는 560px입니다. 확인·닫기 버튼을 세로로 배치할 때는 주 행동을 먼저 둡니다. 창 높이를 계산할 때는 스크롤 영역의 최소 높이와 하단의 실제 줄 수, 별도로 고정한 선택 항목을 함께 반영합니다. 짧은 설명을 제목에 붙일 때도 `kit.heading()`의 12px 간격을 유지합니다.

GitHub 확인 코드는 본문 앞쪽에 충분히 크게 표시합니다. 보관 항목은 같은 창에서 펼쳐 읽을 수 있게 하고, 확인 코드를 복사하는 버튼은 유효한 코드가 있을 때만 하단에 표시합니다. 복사 후에는 같은 코드 영역에서 완료를 알리며 새 팝업을 띄우지 않습니다. 코드 만료나 인증 시도 무효화 뒤에는 예전 코드를 숨깁니다. 초점이 있던 복사 버튼이 사라지면 새 확인을 시작하는 버튼으로 옮깁니다.

승인 대기의 반복 조회는 버튼 활성 상태·문구·초점·선택·스크롤·배치를 바꾸지 않습니다. 새 코드 준비·오류·만료·종료처럼 다음 행동이 바뀔 때만 표시를 바꿉니다. 첫 본인 확인의 종료와 기존 기기의 재확인 취소는 실제 동작에 맞는 이름을 사용합니다.

## 학습 본문의 글자와 간격 넓히기

AI 비전 개론의 설명·보기·입력에는 메뉴보다 큰 읽기용 글자를 씁니다. 보통은 22px·줄 높이 40px, 기본 설정인 크게는 24px·44px, 더 크게는 26px·48px입니다. 학습 제목은 30~34px, 활동 제목은 24~28px입니다. 코드도 20~24px와 줄 높이 32~40px로 키웁니다. 그림 캡션은 18~22px이며 그림 속 글자도 본문 크기에 맞춰 함께 확대합니다.

학습 본문과 연습 문항의 읽기 너비는 1200px에서 시작하고 큰 창에서는 1600px까지 넓어집니다. 작은 창에서는 실제 가용 폭을 따릅니다. 카드 안쪽은 32px, 문단 사이는 24px, 단계 안의 서로 다른 글·그림·물음 묶음 사이는 48px를 둡니다. 제목과 바로 아래 설명 사이는 학습 화면에서 16px입니다. 이 학습 범위의 값은 위의 일반 화면 간격과 구분합니다.

단원 처음과 마지막의 전체 흐름은 펼쳐 둡니다. 중간 단계에서는 현재 위치와 [전체 흐름 보기]를 표시하고, 단원별 보충 문장과 흐름 그림은 펼쳤을 때 함께 보입니다. 760×480의 가장 큰 글자에서 현재 단계 제목과 핵심 문장에 닿는지 확인합니다.

전체 노트·노트 보기·세 수준 설명에도 같은 글자와 문단 기준을 적용합니다. 그림이 커져 한 화면에 다 들어오지 않으면 스크롤로 그림과 조작부에 각각 접근할 수 있게 합니다. 그림 비율과 코드 글자 크기는 유지하고, 긴 코드는 줄바꿈이나 가로 스크롤로 끝까지 볼 수 있게 합니다. 글 안의 코드 상자에서 긴 줄을 접으면 접힌 뒷부분은 그 줄의 들여쓰기보다 공백 네 칸 더 들인 자리에서 시작합니다. 맨 앞 칸에서 시작하면 함수 밖의 새 줄처럼 읽히기 때문입니다.

<a id="창의-가로-공간을-사용합니다"></a>

## 창의 가로 공간 사용하기

왼쪽 과목 메뉴의 아이콘은 같은 크기와 열에 놓고, 메뉴 이름과 구역 이름은 같은 세로선에서 시작합니다. 고른 메뉴는 옅은 파란 배경과 파란 글자로 표시합니다. 글자와 아이콘을 따로 가운데 정렬하되 단추의 클릭 영역은 한 덩어리로 유지합니다. 좁은 창의 과목 선택란은 같은 순서와 현재 선택을 유지합니다.

첫 화면과 과목 홈은 1600px까지 넓어집니다. 웹 학습과 연습 카드도 창의 남는 폭을 사용합니다. 편집기 옆의 설명은 편집기와 나란히 놓인 칸의 가용 폭을 따르며 본문 글자가 커지면 읽기 폭의 상한도 늘어납니다. 작은 창에서 이 수치를 최소 폭으로 강제하지 않습니다.

여러 열 표의 항목을 온전히 읽을 폭이 부족하면 열별 설명으로 바꿉니다. 열 제목 아래에 원래 첫 열의 항목 이름과 해당 값을 함께 표시합니다. 창을 넓히면 원래 비교 표로 돌아옵니다. 글자 크기와 값의 관계는 유지합니다.

## 학습 활동과 그림 조작 구분하기

학습 그림은 장면마다 먼저 볼 대상을 크기·명암·여백으로 드러냅니다. 축·기호·수식 항에는 가리키는 대상 가까이에 이름을 붙입니다. 장면 구도가 달라져도 같은 대상임을 표시합니다. 배경과 글자 대비를 두 테마에서 보고 작은 창의 기본 크기에서도 핵심 숫자와 부호를 읽을 수 있는지 확인합니다. 제작 순서는 [그림과 GIF 만들기](AI_AUTHORING.md#관찰-순서에-맞춰-그림과-gif-만들기)를 따릅니다.

떠올리기와 왜일까요는 32px 안쪽 여백과 24px 간격을 가진 활동 영역으로 묶습니다. 제목은 `learn_activity`로 표시합니다. 라벨·라디오 버튼·체크박스는 본문의 전체 높이 대신 첫 글줄의 중심에 맞춥니다. 인라인 강조는 글꼴 크기·줄 높이·기준선을 바꾸지 않습니다.

같은 줄에 놓인 숫자와 설명은 글자 기준선을 맞춥니다. 체크 항목 오른쪽의 시간·메모도 첫 글줄을 따릅니다. 제목과 설명을 함께 표시하는 목록의 상태 점은 두 줄 묶음의 가운데에 둡니다. 이 배치는 첫 글줄에 맞추는 문항 표시와 구분합니다.

그림 넘김 줄과 하단 도구는 각 줄 안에서 세로 가운데를 맞춥니다. 줄이 바뀌면 새 줄의 높이를 따로 계산합니다. 입력 칸은 초점·정답·오답 테두리가 두꺼워져도 바깥 높이를 유지합니다. 글자 크기를 바꾼 뒤에도 같은 기준으로 다시 배치합니다.

정렬 검사는 위젯 상자의 좌표와 캡처에 그려진 첫 글줄을 함께 대조합니다. 짧은 글과 여러 줄 글, 표시가 숨겨진 상태, 글자 크기 전환을 확인합니다. 가는 숫자 획을 빈 줄로 오인하지 않는지도 대조합니다. 숨겨진 입력부의 배치가 다른 화면의 최소 크기를 늘리지 않게 합니다.

의심되는 부분은 같은 조건의 수정 전후 캡처에서 부모 영역, 같은 줄의 형제 요소, 글자와 아이콘 확대본을 함께 확인합니다. 숫자가 있는 상태와 `–`처럼 미측정 표시만 있는 상태를 나눕니다. 글꼴의 계산 경계와 실제 획이 다를 수 있으므로 화면에 그려진 화소도 비교합니다. 캡처를 저장하거나 요소가 창 안에 들어오는지만 검사한 것으로 정렬 검토를 대신하지 않습니다.

그림 넘김은 별도 테두리 영역에 두고 재생은 강조 테두리와 글자색으로 구분합니다. 학습 단계의 다음·채점 행동을 화면의 주 버튼으로 유지합니다. 한 장 그림에는 재생 조작을 보이지 않습니다. 학습 그림은 가로세로 비율을 유지하며 글자 설정에 따라 커집니다. 가장 큰 글자에서 본문 폭까지 넓히되 원본 폭의 1.5배를 상한으로 둡니다. 원본보다 크게 그린 결과의 글자도 확인합니다.

GIF는 마지막 장 다음에 첫 장으로 돌아가 반복 재생합니다. 화면 밖으로 나가면 타이머를 멈추고, 다시 보일 때 재생 중이던 그림만 이어갑니다. 직접 일시 정지하거나 장을 넘겼다면 그 장면을 유지합니다. 움직임 줄이기를 켜면 자동 재생을 멈춥니다.

그림 바로 아래에 재생·장 넘김·장 번호·크게 보기를 한 영역으로 모으고 설명은 그 아래에 둡니다. 좁은 창에서도 크게 보기는 같은 조작부 안에서 줄바꿈합니다. 조작부의 제목·버튼·장 번호·크게 보기는 줄마다 가운데에 모아 그림·설명과 좌우 가운데를 맞춥니다. GIF 조작부의 제목·장 번호·이전 장·다음 장·크게 보기는 같은 글자 크기를 씁니다. 같은 줄의 버튼 높이도 맞추고 줄이 바뀌면 그 줄 안에서 정렬합니다. 조작부 높이는 실제 줄 수에 맞춥니다.

크게 보기 창은 화면 폭이 충분하면 조작부가 한 줄로 들어가는 폭으로 열고, 높이는 창 폭에서 다시 잰 그림과 조작부 높이로 정합니다. 제목, 그림, 조작부, 닫기 버튼이 화면 작업 영역보다 크면 그림을 같은 비율로 줄여 스크롤 없이 보이게 합니다. 본문 칸이 넓으면 크게 보기 그림이 본문 그림보다 작을 수 있습니다. 재생은 삼각형, 일시 정지는 두 막대 아이콘으로 표시합니다. 아이콘 버튼에는 지금 누르면 할 동작을 툴팁과 접근성 이름으로 붙입니다. 키보드 조작과 두 테마의 색도 확인합니다.

제출할 풀이가 확인되면 상단의 [풀이 제출]은 `link` 글자색으로 강조하고 하단의 같은 행동은 파란 채움 버튼으로 표시합니다. 상단과 하단에 같은 이름을 사용하며 확인 중·빈 기록·조회 실패·동의가 필요한 상태는 강조하지 않습니다. 완료·실패 안내는 기존 하단 알림 안에 남기고 새 작업을 시작하거나 새 미제출 풀이를 확인하면 갱신합니다. 알림을 자동으로 깜빡이거나 초점·읽던 위치를 옮기지 않습니다. 2026년 11월 13일 [Carbon 버튼 지침][carbon-button]의 행동명과 위계를 참고했습니다.

하단 알림은 제출할 변경·받을 자료·제출 결과가 있을 때 띄웁니다. 내용 끝에는 상태와 무관한 스크롤 여백을 두어 알림의 출현·소멸로 읽던 위치가 바뀌지 않게 합니다. 키보드로 내용 안의 동작에 초점을 옮기면 알림 위까지 보이게 합니다.

알림의 줄바꿈은 실제 문장과 단추에 필요한 폭으로 정합니다. 한 줄에 들어가는 알림을 창 너비만으로 두 줄로 나누지 않습니다. 배경 전송 상태를 갱신할 때는 편집 중인 희망 직무·입력·선택 항목을 다시 채우지 않습니다.

Windows에서 학습 그림을 확인할 때는 본문과 확대창을 따로 봅니다. 확대창의 가로·세로 스크롤을 양끝까지 옮겨 원본 끝부분에 닿는지 확인하고, 크게 보기·닫기·단계 이동 단추를 실제로 누릅니다. 원본 그림의 비율과 적용된 최대 글자 크기, 실제 창 크기를 함께 기록합니다.

AI 홈의 상단에는 돌아가기와 `AI` 제목을 표시합니다. [AI 개론]·[AI 응용]·[모의고사]는 그 아래에서 본문 폭을 똑같이 나눠 사용합니다. 매거진과 같은 `NavigationTabs`를 사용하며 선택한 탭은 큰 글자·배경·둥근 테두리로 구분합니다. [모의고사] 탭은 개론·응용 회차를 한 목록에 보여 줍니다. 이 목록은 개론 세션으로 만듭니다. 마지막으로 고른 탭은 사용자별 `ai/tab` 설정에 남기고 `ai/course`에는 과정 탭을 고를 때만 씁니다. 학습 현황의 AI 줄, 복습 확인 수, 이어서 할 일은 [모의고사] 탭을 골라 두었어도 `ai/course`의 과정으로 그립니다. 응용을 공부하던 학습자가 [모의고사] 탭을 골라 둔 채 학습 현황에서 이어서 할 일을 누르면 [AI 응용] 탭으로 돌아가고 `ai/tab`도 과정 탭으로 바뀝니다. 개론을 공부하던 학습자는 학습 화면만 열리고 `ai/tab`은 [모의고사] 탭으로 남습니다. 하위 학습 메뉴는 별도 카드로 표시합니다. 과정 전환이 끝난 뒤 선택 표시를 바꾸며 과정 탭·학습 메뉴·본문의 양끝과 스크롤바 여백을 맞춥니다.

학습 코드에는 현재 예제에서 하는 일을 짧게 설명하고, 앞서 배운 내용은 [설명 다시 보기] 보조 버튼으로 연결합니다. 이미 있는 코드를 다시 상자로 감싸지 않습니다. 참고 창은 현재 화면 위에서 열고 제목·닫기 버튼을 고정하며 본문만 스크롤합니다. 현재 차시와 참고한 차시를 구분하고 다른 과정의 설명을 열어도 풀던 답안과 읽던 위치를 유지합니다.

AI 홈은 개론·응용 탭 아래에 [학습 단원]·[문제집]·[코딩으로 실전학습하기]를 고정합니다. [모의고사] 탭에서는 이 분류 줄을 숨기고 회차 목록만 표시합니다. 예전 회차와 숨긴 회차는 제출한 사람에게만 '이전에 푼 회차 n개' 접는 줄 아래에 표시합니다. 예전 회차를 풀다 만 사람에게는 새 회차로 다시 시작하라는 안내 띠를 표시합니다. 분류 선택과 목록 스크롤은 `gui/section_browser.py`의 `SectionBrowser`를 재사용하며 선택한 분류의 내용만 표시합니다. 과정 설명·이어서 할 일과 [학습·사용 안내]·[학습 기록 설정] 버튼은 [학습 단원]에만 둡니다. 다른 분류는 제목·설명·목록 순으로 바로 이어 작은 창에서도 목록 공간을 확보합니다. 같은 차시 번호에는 과정 이름을 붙이고 마지막으로 선택한 과정을 보존합니다.

학습 메뉴는 분류 영역 너비 1100px 이상·창 높이 700px 이상에서 아이콘과 설명을 펼칩니다. 작은 화면에서는 설명을 접고, 아이콘 때문에 줄 수가 늘지 않을 때만 이름 앞에 아이콘을 둡니다. 각 표시 방식에서 실제 글자 폭과 가장 긴 단어가 들어가는 폭으로 한 줄 배치 여부를 정합니다. 버튼은 같은 폭으로 나누고 세 항목이 들어가지 않으면 두 열로 배치합니다. 이름을 줄이거나 메뉴를 숨기지 않으며 긴 이름은 줄바꿈하고 단추 높이를 맞춥니다. 선택 배경과 키보드 초점 점선을 구분하고 위아래 방향키는 실제 행 배치를 따릅니다. 작은 창·가장 큰 글자·두 테마에서 본문 공간과 전체 메뉴를 함께 확인합니다.

선택한 분류는 `primary` 바탕에 흰 글자와 아이콘으로 구분하고 키보드 초점은 점선 테두리로 표시합니다. 고른 분류에 초점이 있으면 점선을 흰색으로 그립니다. 비활성 상태에서도 선택 배경을 유지합니다. 프로그램을 켜 둔 동안 학습자·과정별 분류 선택과 분류별 스크롤 위치를 메모리에 보관하며 목록 배치가 끝난 뒤 복원합니다. 자료가 없어도 분류 단추는 유지하고 준비 안내를 표시합니다. 자료·기록 읽기 실패는 준비 중과 구분해 원인과 확인 방법을 알립니다.

과정의 내용을 준비하는 동안 기존 탭의 선택 표시를 유지합니다. 제목·목록·버튼을 채운 뒤 선택 표시와 본문을 함께 그립니다. 이미 읽은 과정의 자료는 재사용하고 새 기록·연습 위치·모의고사 마감은 다시 확인합니다. 자료 파일이 바뀌거나 학습자 기록을 새로 열면 이전 자료를 재사용하지 않습니다. 전환 성능은 처리 시간과 실제 화면 표시까지의 시간을 구분해 측정하며 고정 대기를 넣은 검사의 시간을 화면 응답 속도로 쓰지 않습니다.

심화 팝업은 화면 안에 들어오는 크기로 열고 긴 내용은 내부에서 스크롤합니다. 닫기는 본문 밖에 두어 항상 도달할 수 있게 합니다. 원래 단계와 읽던 위치·입력은 유지합니다. 새 부품은 부모 레이아웃에 붙인 뒤 표시 상태를 반영해 별도 창이나 초점 이동이 생기지 않게 합니다.

팝업을 다시 열 때도 현재 부모 창과 모니터의 작업 영역에 크기·위치를 맞춥니다. Esc로 닫은 뒤 열었던 단추로 초점을 돌립니다. GIF의 재생을 예약한 뒤 화면 밖으로 나가면 실제로 보일 때까지 기다립니다. 예약 이후 움직임 줄이기를 켜도 재생을 시작하지 않습니다.

선택형 연구 참여는 사용 목적을 설명하고 프로그램 이용에 필수인 약관처럼 부르지 않습니다. 서버 명칭은 ‘비공개 서버’로 통일합니다. 전송 항목·사용 목적·보관 기간·철회 방법은 본문에서 확인할 수 있게 합니다.

첫 화면의 AI 활동 그래프와 최근 채점에는 개론·응용 기록을 함께 표시합니다. 진도·복습·오답과 이어갈 위치는 선택한 과정으로 유지하고 과정 이름을 붙입니다. 단원 읽기도 포함한 합계는 `기록된 활동`으로 표시합니다.

2026년 11월 11일 [W3C의 모달 대화상자 지침](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)과 [Qt QDialog 문서](https://doc.qt.io/qt-6/qdialog.html)를 대조했습니다. 열기·닫기·키보드 초점의 기대 동작을 네이티브 창에서 확인하며, 웹용 속성을 Qt 위젯에 그대로 적용하지 않습니다. 자동 재생의 멈춤·수동 조작은 [W3C의 움직이는 내용 제어 설명](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)을 참고합니다.

[Mayer의 멀티미디어 학습 연구 요약][mayer]을 참고해 관련 그림과 설명을 가까이 두고 학습자가 장면을 멈추거나 다시 보는 길을 유지합니다. 빠르고 복잡한 설명과 학습자의 사전 지식에 따라 적용 조건이 달라집니다. 현재 그림의 속도나 배치만으로 이해·기억 향상을 확인했다고 쓰지 않습니다.

[mayer]: https://www.cambridge.org/core/books/multimedia-learning/7A62F072A71289E1E262980CB026A3F9/listing

화면 문구는 [토스의 라이팅 운영 사례](https://toss.tech/article/1st_uxwriter)와 [NHS의 글쓰기 지침](https://service-manual.nhs.uk/content/how-we-write)을 참고합니다. 반복해서 쓸 기준을 문서·검사기에 반영하고, 추상적인 평가 대신 실제 동작과 집계 대상을 씁니다. 낯선 용어는 먼저 설명하며 한국어 문맥은 별도로 읽어 확인합니다.

[carbon-button]: https://www.carbondesignsystem.com/building-blocks/core/components/button/guidelines

설정 메뉴는 누른 버튼 아래에 붙여 표시합니다. 화면 끝에서는 위쪽으로 옮기고 글자 크기·테마·창 크기가 바뀌면 위치를 다시 맞춥니다. 글자 크기와 테마는 각각 현재 선택을 보여 주는 선택 버튼으로 묶습니다. 본인 확인·첫 화면과 커리어 튜토리얼 다시 보기·업데이트 확인·불편 접수는 그 아래에 둡니다. Esc와 바깥 클릭으로 닫고 키보드로 연 경우 원래 버튼으로 돌아옵니다. 등장 효과는 ease-in, 닫기 효과는 ease-out을 적용하며 움직임을 끈 상태에서는 즉시 처리합니다.

통계의 전체 수집 기록과 열어 본 문항·열린 문제·입력한 답·채점은 서로 합산하지 않습니다. 숫자 옆 정보 버튼에는 그 숫자의 단위·반복 처리·미확인 범위를 적고 마우스·키보드로 열 수 있게 합니다. 알 수 없는 과거 값과 아직 계측하지 않은 값은 0으로 표시하지 않습니다. 프로그램 업데이트와 풀이 제출 버튼은 확인된 작업이 있을 때만 표시하고 강조합니다. 조회 실패를 완료로 표시하지 않습니다.

같은 레이아웃의 글자·수치·아이콘은 의도한 기준선과 중심, 첫 글줄을 함께 확인합니다. 버튼 이름은 누른 뒤 생기는 결과를 드러내며 뜻이 모호한 동작에는 짧은 툴팁이나 첫 진입 안내를 둡니다. 가려진 답을 펼치는 동작, 마지막 복습 질문으로 이동하는 동작, 채점하는 동작은 구분합니다. 이름을 바꾸면 화면 제목·관련 메뉴·사용 안내도 함께 맞춥니다.


## 본문 펼치기와 접기

답·부연 설명·출처를 펼치는 줄에는 `DisclosureButton`을 사용합니다. 이름은 본문의 글자 시작점에 맞추고 화살표는 오른쪽 끝에서 첫 글줄의 가운데에 맞춥니다. 줄 전체를 누를 수 있으며 버튼은 펼칠 내용 바로 위에 둡니다. 여러 줄인 제목도 본문 폭 안에서 줄바꿈합니다.

버튼의 최소 높이는 48px, 위아래 여백은 12px입니다. 질문과 답 버튼 사이는 24px, 버튼과 답 사이는 16px로 맞춥니다. 하단 구분선으로 조작 영역을 표시하고 키보드 초점은 같은 선의 색과 두께로 구분합니다. 펼칠 때 이름이 짧아져도 버튼 높이가 줄지 않게 합니다.

Enter·Space로 펼치고 접습니다. 기존 학습 질문 목록의 좌우 방향키는 유지하며 다른 펼치기 버튼에 방향키 동작을 추가하지 않습니다. 접힌 영역에 초점이 있었다면 버튼으로 돌립니다. 작은 창·최대 글자·두 테마에서 첫 글줄과 화살표를 실제 그림으로 대조하고, 반복해서 펼친 뒤에도 답안·읽던 위치가 유지되는지 확인합니다.

## 커리어의 단계와 논문 그림

개발자 로드맵의 소개·직무 제목·업무 장면·팀과 담당 업무·출처·관련 영상은 내용별 카드로 묶습니다. 목록 소개의 추천과 조직 설명 버튼은 같은 행동 줄에 둡니다. 상세의 [업무·결과]·[학습 로드맵]은 `NavigationTabs`로 표시합니다. 학습 순서 제목과 확대 버튼은 한 묶음으로 두고 단계 카드에는 예시 배경과 파란 연결선을 사용합니다. 기존 직무·수업 범위·관심 저장·목록 복귀 동작은 유지합니다.

개발자 로드맵과 매거진의 페이지 제목은 보통 글자에서 36px인 `display` 역할을 사용합니다. 영상 검색·출처 필터는 카드에 묶고 논문은 대표 그림에 테두리를 둡니다. 논문 설명 바깥 카드의 선은 생략하며 [그림 설명 보기]를 대표 그림 바로 아래에 둡니다. 긴 설명과 출처 펼침, 원문 열기·영상 재생의 기존 연결을 유지합니다.

매거진의 [영상]과 [논문 해설]은 제목 아래에서 같은 폭·글자 크기·높이로 표시합니다. 선택한 탭은 배경과 둥근 테두리로 구분하고 본문을 스크롤해도 두 탭은 화면 위에 남습니다. 탐색 줄의 좌우 끝은 본문과 맞추며 검색 조건과 탭별 읽던 위치를 유지합니다.

2026년 11월 15일 [Carbon의 탭 지침][carbon-tabs]에서 짧은 항목 이름과 동일 폭 배치를 참고했습니다. 색과 글꼴은 기존 프로그램의 테마를 사용합니다.

[carbon-tabs]: https://www.carbondesignsystem.com/building-blocks/core/components/tabs/guidelines

직무 탐색은 업무 장면·직무 이름·산출물을 함께 보여 줍니다. 목록에서 선택하는 동작과 관심 직무를 저장하는 동작을 구분합니다. 상세에서는 업무와 학습 순서를 탭으로 나누고 선택한 직무 이름을 유지합니다. [직무 바꾸기]는 돌아가기 버튼 옆에 두고 전체 직무 중 현재 선택을 표시합니다. 직무를 바꿔도 보고 있던 탭은 유지하며 새 직무의 내용을 위에서부터 보여 줍니다. [직무 목록]은 상세 방문 순서와 관계없이 처음 들어온 목록의 필터·읽던 위치·카드 초점을 복원합니다. 창 높이가 커져도 제목과 그림 사이 간격은 유지하고 남는 높이는 본문 끝에 둡니다. 작은 창뿐 아니라 QHD 큰 창에서 두 테마와 글자 크기를 바꿔 확인합니다.

2026년 11월 14일 [roadmap.sh의 직무별 탐색](https://roadmap.sh/), [Codecademy의 목록과 분류](https://www.codecademy.com/catalog), [Duolingo의 화면 위계 개편](https://blog.duolingo.com/core-tabs-redesign/)을 참고했습니다. 그림·글자의 배치와 탐색 방식을 비교했으며 외부 디자인 자산은 사용하지 않았습니다.

학습 순서는 단계마다 주제와 연결되는 작은 그림을 먼저 두고 수업 범위를 함께 표시합니다. 실제 글자 폭으로 열 수를 정하며, 줄을 바꿀 때도 원래 순서로 읽을 수 있게 연결합니다. 수업 범위와 학습자의 진도는 구분합니다.

논문 목록은 검증한 계산 그림과 입력 모양·조건을 함께 보여줍니다. 긴 해설과 출처는 펼쳐 읽고, 그림을 누르면 같은 논문의 단계별 설명으로 이어집니다. 도식의 글자도 본문의 글자 설정과 테마를 따릅니다.

논문 해설에도 학습용 글자 기준을 적용합니다. 본문은 22~26px, 보조 설명은 18~22px로 표시하고 제목·본문·펼침 버튼의 글자 시작점을 맞춥니다. 그림의 행 이름은 숫자 칸의 글자 중심에 맞추며, 행렬 칸에는 가장 긴 기호의 폭과 좌우 여백을 확보합니다. 나란히 놓을 폭이 부족하면 글자를 줄이지 않고 세로로 연결합니다. 설명 상자와 화살표 위치는 줄바꿈한 글의 높이를 기준으로 정합니다. 하단의 이전·단계 번호·다음은 한 묶음으로 두고 단계를 바꿔도 버튼 위치가 움직이지 않게 합니다.

확대 로드맵은 가운데 번호와 직선으로 단계 순서를 표시합니다. 세부 주제는 얇은 선으로 해당 단계에 연결하고 색과 글자로 수업 범위를 함께 표시합니다. 표시 방식만 바꿀 때는 기존 관심 직무와 자료 버전을 유지합니다.

### 커리어 사용법 안내

직무 목록·직무 상세·매거진은 각각 처음 방문할 때 [화면별 두 단계 안내](career/README.md#화면-사용법-보기)를 표시합니다. 현재 화면에 보이는 대상에 설명을 붙이고 직무 선택과 관심 저장, 영상 재생과 논문 해설 열기를 구분합니다. 툴팁에는 버튼 이름보다 누른 뒤의 결과나 저장 범위, 조작법을 짧게 적습니다.

상단 [사용법]은 현재 화면의 안내만 다시 엽니다. 설정의 [커리어 튜토리얼 다시 보기]는 직무 목록부터 시작하고 상세·매거진 안내도 다음 진입에 표시합니다. 안내를 끝까지 보거나 [건너뛰기]·Esc로 닫으면 완료 기록을 로컬 기기에 보관합니다. 페이지 이탈만으로는 완료 기록을 남기지 않습니다.


### 기록 설정의 정보 순서

학습 홈의 [학습 기록 설정]은 작은 보조 버튼으로 두고 학습 시작 버튼과 구분합니다. 팝업 첫 화면에는 현재 수집 상태와 중단·재개 동작을 표시합니다. 전송 확인·컴퓨터에 파일 저장·선택형 희망 직무는 각각 펼쳐서 사용합니다. 구역을 펼치거나 접으면 팝업 높이를 화면 안에서 다시 맞추고, 초점이 없는 희망 직무 선택 상자는 휠을 본문 스크롤로 넘깁니다. 파일에 답안을 포함하는 선택은 파일 저장 구역에 두며 서버 전송 버튼과 섞지 않습니다. 저장 결과와 오류도 해당 구역에서 표시합니다. 배경 전송으로 상태가 바뀌어도 편집 중인 선택·펼친 구역·읽던 위치는 유지합니다. 사용자가 직접 스크롤하거나 Tab으로 이동하면 새 위치를 따릅니다. 동의 변경·삭제는 고정 하단 버튼에서 공통 화면으로 연결합니다.
