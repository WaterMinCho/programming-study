# AI 개론·응용 출제 안내

AI 개론·응용에 학습 노트, 연습 문항, 생성기, 상황별 코드 뼈대, 그림을 넣는 사람이 보는 문서입니다. 파일 규격, 봉인·검증·서명 명령, 출제·재풀이·대조·검토를 나눠 맡는 교차 검증 순서, 쓰는 사람과 검토하는 사람이 같이 쓰는 체크 목록을 적었습니다. 학습 노트의 기본 꼴과 서명은 웹 면접 준비의 학습 페이지와 같아서 [WEB_AUTHORING.md](WEB_AUTHORING.md) 의 학습 페이지 절도 함께 읽습니다.

학습자가 적은 코드는 실행하지 않습니다. 앱에서 빈칸 채우기와 객관식 문제로 코드 지식을 확인합니다. 객관식에는 줄 순서 맞추기와 고칠 줄 찾기도 포함합니다. 강의 자료가 맞다고 가정하지 않습니다. 문항은 사실 확인을 마친 사실(`facts.json`)로만 만듭니다. 자료 오류의 대조는 사실 목록과 검토 기록에 보존하고, 학습 본문과 해설에는 확인한 원리와 조건을 바로 설명합니다. 외부 교재의 파일 이름이나 셀 번호를 몰라도 이해할 수 있게 씁니다.

## 2. 학습 노트(page.md)

### 먼저 가르칠 개념 고르기

강의와 과제의 목표를 기준으로, 앞뒤 차시에서 반복해서 쓰는 원리와 다음 실습에 필요한 선수 개념을 고릅니다. 원논문·공식 문서·실무 예제로 현재도 쓰이는 원리인지 확인합니다. 공인·민간 시험은 공개 출제 범위와 예제에 나타난 개념을 근거로 씁니다. 기술 글과 풀이 피드백에서 반복되는 혼동은 비교 예제와 오답 해설에 반영합니다. 같은 원문을 다시 인용한 글은 각각의 근거로 세지 않습니다. 선택한 개념마다 근거와 학생이 할 수 있어야 할 판단을 검토 기록에 남깁니다. 기술 설명의 조건과 값은 공식 문서·원논문·계산 또는 실행 결과로 대조합니다. 학생 풀이를 참고한 경우 저장·제출된 범위를 밝히고, 학습 목표와 실제로 확인한 결과를 나누어 기록합니다.

### 그림과 설명 이어 놓기

단원 첫 단계에서 배우는 목적과 전체 흐름에서의 위치를 보여 줍니다. 개념 단계에서는 짧은 결론 뒤에 그림을 두고, 표시한 입력·변화·출력을 가까운 설명이나 계산 예에서 짚습니다. 역할이 다른 설명은 짧은 소제목으로 나누고, 조건을 비교할 때는 표나 같은 순서의 목록을 씁니다. 한 문단은 한 생각을 담고, 화면에서 여러 줄 이어지는 문단은 예나 그림 앞뒤로 나눕니다. 단원 마지막에도 현재 위치를 보여 주고, 같은 흐름에서 조건 하나를 바꿔 결과를 떠올리게 합니다. [학습 본문의 글자와 간격](UI_DESIGN.md#학습-본문의-글자와-간격-넓히기)을 실제로 적용된 화면에서 확인합니다.

깊이·채널 축·카메라 방향처럼 공간 관계를 배울 때는 입체 도식을 검토합니다. 입력과 출력의 차이, 수치 대조, 단계 순서는 읽기 쉬운 형식으로 고릅니다. 과정의 변화를 봐야 할 때는 장을 넘기거나 멈출 수 있는 그림을 씁니다. 대학원 교안은 실제 쪽을 열어 축·레이블·분기·화살표의 배치를 참고하고, 수치와 조건을 검증해 학습 수준에 맞춰 그립니다. 내부 검토 기록에 참고한 쪽과 그림의 제작 근거를 적습니다.


제목은 ‘출력 모양 비교하기’, ‘기울기 구하기’처럼 짧게 씁니다. 원리를 설명하는 제목은 ‘기울기가 줄어드는 이유’처럼 무엇을 배울지 드러냅니다. 제목을 바꿀 때는 목차와 `meta.json`의 이름, 단계 분류, 링크, 검토 서명을 함께 확인합니다. 본문의 조건·수식·정답은 제목과 구분해 검토합니다.

`#` 은 노트 제목, `##` 는 단원, `###` 는 단계입니다. 단원 제목은 `meta.json` 의 `sections` 값과 같아야 하고, 단원 키는 `<차시 번호><a~i>`(5c), 응용은 `a1a`처럼 앞에 a를 붙이고, 상황별 코드는 무리 노트 번호를 따라 개론 `18a`~`18z`, 응용 `a18a`~`a18z`입니다. `sections` 에 없는 `##`(그림 출처 등)는 단원으로 세지 않습니다. `##` 바로 밑에는 글을 두지 않고 첫 `###` 안에 씁니다.

단계 제목 바로 밑 줄에 그 단계가 설명하는 사실 id 를 적습니다. 이 줄은 화면에 넘기기 전에 지워지고 verify_ai 가 카드의 `step` 과 맞춰 봅니다.

```
### 시그모이드를 여러 번 지날 때 기울기 변화 확인하기
<!-- facts: F05-12 F05-13 -->
```

단계의 종류는 제목 앞머리로 정합니다. 「심화」로 시작하면 대학원 강의안 단계, 「보충 설명」은 시험 범위 안의 보충, 「더 알아보기」는 시험 범위 밖, 「외울 것」은 단원 마지막 단계입니다. 그 밖은 강의 단계입니다. 단원 단계는 먼저 풀어 보기와 외울 것을 넣어 4~7개이고, 마지막은 꼭 「외울 것」입니다.

울타리 블록은 JSON 한 덩이로 씁니다.

| 블록 | 필드 | 화면 |
|---|---|---|
| `ai-guess` | `id`, `q`, `options`(2~4), `answer`(0부터), `reveal_step`(답을 보일 뒤 단계 번호), `cards` | 먼저 풀어 보기. 채점하지 않음 |
| `ai-reveal` | `guess`(먼저 풀어 보기 id) | 처음 고른 답과 정답 한 줄 |
| `ai-recall` | `id`, `q`(`____` 하나), `answer`, `mode`, 선택 `why` | 떠올리기. 바로 채점, 상자는 움직이지 않음 |
| `ai-why` | `q`, `a` | 왜일까요. 답은 접어 둠 |
| `ai-memo` | `[{"q", "a", "cards"}]` | 외울 것. 질문을 누르면 답이 펴짐 |
| `ai-trend` | `title`, `text` | 2026 흐름. 단계 수에 넣지 않음 |
| `ai-diff` | `skel`, `left`, `right`(코드 예제 이름) | 뼈대 두 코드 예제 나란히 보기. 다른 줄에 바탕색을 칠함 |
| `ai-rotate` | `id`, `skel`, `variant`, 선택 `slots`(자리 id 목록). 뼈대에 `note_only` 자리가 있으면 `slots` 를 꼭 적고 `note_only` 자리만 넣음 | 돌려 가며 빈칸. 자리를 하나씩 가리고 틀린 자리는 세 자리 뒤에 다시 냄. 상자는 움직이지 않음 |
| `ai-levels` | `id`, `concept`, `levels`(수준 7·15·20 의 객체 셋) | 세 단계로 다시 보기. 단계 끝에 접혀 있고 펴면 수준마다 그림, 글, 확인 물음이 나옴. 상자는 움직이지 않음 |
| `ai-formula` | `id`, `title`, `input`, `terms`, `operation`, `output`, `figure`, `q`, `a` | 수식 자세히 보기. 그림과 계산을 별도 창에서 읽고 확인 물음의 답을 펼칩니다. 기록하지 않습니다. |
| `ai-code-help` | `title`, `explanation`, `reference`, 선택 `code` | 코드의 뜻을 본문에서 설명하고 앞서 배운 단계의 그림·설명을 별도 창으로 엽니다. |

`ai-guess`마다 같은 단원의 `ai-reveal`을 연결합니다. `reveal_step`은 그 해설이 실제로 나타나는 단계 번호와 맞춥니다.

`ai-rotate`·`ai-levels` 의 `id` 는 먼저 풀어 보기·떠올리기 id 와 같은 단원 안에서 겹치지 않게 씁니다. 뼈대 코드 예제를 코드 울타리로 보일 때는 울타리 바로 위 줄에 `<!-- skel: S1 표준형 -->` 를 적습니다. verify_ai 가 줄 끝 `#` 주석과 빈 줄을 뗀 울타리 줄이 그 코드 예제 `lines` 와 같은지 봅니다. 이 줄도 화면에 넘기기 전에 지워집니다.

외울 것의 `cards` 는 그 단원의 핵심 카드를 모두 덮어야 합니다. 자료의 오류는 확인한 원리와 성립 조건을 본문에 바로 반영합니다. 학습자에게 별도 정정 상자를 보이지 않습니다. 비교한 원문과 위치는 내부 검토 기록에 보존합니다. 필요한 배경 설명에는 `> **[보충 설명]** …`을 쓸 수 있습니다.

짧은 핵심어는 `<mark>기울기</mark>`처럼 형광펜과 볼드로 표시하고, 긴 핵심 원리는 `<u>역전파는 기울기를 계산하며 매개변수를 갱신하지 않습니다.</u>`처럼 밑줄로 표시합니다. 강의·과제의 목표, 앞뒤 단원의 연결, 공식 자료와 공개 시험·반복 오해 근거를 대조해 강조할 곳을 고릅니다. 문단 전체를 강조하지 않으며 코드 울타리 안에는 강조 태그를 넣지 않습니다.

`terms.json` 의 낱말은 정의한 노트를 `page` 로 둡니다. 앞 차시가 그 낱말을 먼저 쓰면 그 차시를 `intro` 로 두고, 그 차시 `meta.json` 의 `defines` 에 넣고, 처음 쓰는 문장 앞에 "…을 오차라고 부릅니다" 꼴 정의 한 문장을 둡니다. 1차시가 어림값의 오차를 먼저 쓰고 4차시가 예측의 오차를 정의하는 경우처럼 쓰임이 조금 달라도 이렇게 소개합니다. `also` 에 적은 꼴은 한 낱말에만 두고, 다른 낱말에서도 받을 꼴은 `accept` 에 둡니다. 4차시의 오차와 손실처럼 서로 다른 낱말로 가르치는 두 말은 서로의 `accept` 에 넣지 않습니다.

그림 블록은 웹과 같은 꼴이고 GIF 의 `프레임:` 줄 수는 GIF 장 수와 같아야 합니다. 프레임 줄은 그림 아래 장 설명으로 보이는 글이라 말투 검사를 받습니다.

### 앞에서 배운 코드 설명 연결하기(ai-code-help)

처음 쓰는 함수는 하는 일과 입력·출력, 필요한 인수의 뜻을 본문에 설명합니다. 이미 배운 코드라면 지금 쓰는 이유를 짧게 적고 해당 단계에 연결합니다. 버튼을 누르지 않아도 현재 예제를 이해할 수 있어야 합니다. 바로 위에 같은 코드가 있으면 `code`는 생략합니다.

````
```ai-code-help
{
  "title": "DataLoader",
  "explanation": "shuffle은 자료 순서를, batch_size는 한 묶음의 최대 크기를 정합니다.",
  "reference": {
    "course": "intro",
    "lesson": "l10",
    "unit": "10c",
    "step": 3,
    "title": "섞는 순서와 배치 크기 따로 고르기"
  }
}
```
````

`reference`의 과정은 `intro` 또는 `applied`입니다. 학습 페이지 ID, 단원, 단계 번호와 실제 제목을 함께 대조합니다. 같은 함수 이름이 나온다는 이유만으로 연결하지 않고, 현재 예제의 자료형·축·실행 모드까지 설명하는 단계인지 읽어 확인합니다. 단계를 옮기거나 제목을 고치면 이 연결도 갱신합니다.

참고 창은 학습 화면을 이동하지 않고 공개된 설명을 읽습니다. 확인 물음과 그 정답은 빼고 글·코드·그림을 보여줍니다. 참고 창 안에서는 이전 설명 버튼을 다시 만들지 않습니다. 열거나 닫아도 과정·단원·답안·진도·수집 기록을 바꾸지 않습니다. 닫기와 Esc 뒤에는 읽던 위치와 입력 선택을 유지합니다. 작은 창·최대 글자·두 테마에서 제목, 그림, 닫기 버튼을 확인합니다.

### 수식 자세히 보기(ai-formula)

수식 상세 설명은 `ai-formula`로 구분합니다. `input`에는 입력 모양과 값을, `terms`에는 각 항의 뜻을, `operation`에는 한 연산을, `output`에는 출력 모양과 적용 조건을 적습니다. 이 필드와 `id`·`title`·`q`·`a`는 비어 있지 않은 글이며 코드 울타리를 넣지 않습니다. 모르는 필드는 오류로 처리합니다. 핵심 조건은 단계 본문에도 남깁니다.

`figure`는 `file`, `caption`, `content`, `frames` 객체입니다. `file`은 `assets/` 아래 PNG 또는 GIF입니다. PNG의 `frames`는 빈 목록이며 GIF는 `{"text": "장 설명", "ms": 2200}` 형태의 목록을 씁니다. 기존 그림의 크기·이름·시간·장 수·manifest 검사를 따릅니다. 수식 본문과 그림은 학습 페이지의 기존 서명 대상에 포함됩니다.

수식 창은 그림을 크게 보여 준 뒤 입력·항·계산·출력과 확인 물음을 차례로 설명합니다. `q`의 답은 `a`에 쓰며 답 보기 전의 글과 그림에는 같은 답을 미리 쓰지 않습니다. 답을 펼치거나 창을 닫아도 채점·진도·동의·수집 기록을 쓰지 않습니다. 닫기·Esc 뒤 원래 단계·스크롤·답안·선택 영역을 유지하고 열었던 단추로 초점을 돌립니다. GIF는 화면에 보이는 동안 반복 재생하며 일시 정지·수동 넘김·움직임 줄이기를 지원합니다.

### 세 단계로 다시 보기(ai-levels)

어려운 개념을 처음 숫자로 다루는 단계의 맨 끝(떠올리기·왜일까요 뒤)에 블록 하나를 둡니다. 차시마다 3~5개이고 먼저 풀어 보기·외울 것·2026 흐름 단계에는 두지 않습니다. `concept` 는 20자 이하의 개념 이름이고 접힌 줄 제목 뒤에 붙습니다. terms.json 낱말이면 이름을 그대로 쓰고, 그 낱말의 `intro` 나 `page` 노트에 둡니다.

````
```ai-levels
{"id": "v1", "concept": "기울기",
 "levels": [
  {"level": 7, "text": "…", "figure": {"file": "assets/4b-31.png", "caption": "…", "content": "…"},
   "q": "… ____ 입니다.", "answer": ["2"], "mode": "number", "why": "…"},
  {"level": 15, "text": "…", "figure": {…}, "q": "…", "answer": ["…"], "mode": "number", "why": "…"},
  {"level": 20, "text": "…", "code": "…\n…", "mistake": "…",
   "figure": {…}, "q": "…", "answer": ["…"], "mode": "number", "why": "…"}
 ]}
```
````

`levels` 는 7·15·20 순서의 객체 셋입니다. `q`·`answer`·`mode`·`places`·`unit`·`why` 는 떠올리기와 같고, `code`(2~8줄)·`mistake`(자주 하는 착각 하나와 바른 문장)는 심화에만 씁니다. `where`는 어느 수준에도 쓰지 않습니다. 표에 없는 키, 모르는 `mode`, 초급·중급의 `code`·`mistake`, 글 안의 ``` 와 ~~~ 는 은행이 읽지 못하고 화면에 깨진 블록으로 보입니다. 코드는 `code` 에만 둡니다.

| 수준 | 쓰는 것 | 쓰지 않는 것 |
|---|---|---|
| 초급 | 단계 숫자 가운데 작은 수 하나둘, 상자와 화살표 그림, 짧은 문장 | terms.json 낱말(`known` 은 됨), 식 기호(= × ÷ + / ^ √ ∂ Σ ² * < >, 숫자 사이의 − 와 -), 인라인 코드, 낱말을 대신할 새 이름. `answer` 에도 쓰지 않음 |
| 중급 | 사칙연산, 그래프나 표, 식 한 줄과 그 식에 단계 숫자를 한 단계씩 넣은 계산. 2차원 값은 괄호 없는 숫자 칸 표 | 편미분 기호, `[[`, `@`, 라이브러리 이름(torch, numpy, np, nn), 인라인 코드 |
| 심화 | 정의 한 문장, 식, 코드 2~8줄, 자주 하는 착각 하나, 단계 그림에 없는 코드 결과나 모양을 보이는 그림 | 앞 수준 설명 되풀이, 단계 그림이나 표를 다시 그린 그림 |

- 비유를 쓰지 않습니다. 초급도 실제 숫자와 그림으로 쓰고, 낱말을 피하려고 "틀린 정도" 같은 이름을 짓지 않습니다. 숫자 앞에 붙은 −(−4)는 됩니다.
- 수준마다 그 단계의 숫자 예를 이어 쓰고 뒤 수준은 앞 수준의 숫자를 이어받습니다. 블록 글은 그 자리까지 정의된 낱말만 씁니다. 뒤 단계나 뒤 차시의 낱말은 미리 설명하지 않습니다.
- 블록에는 새 사실을 더하지 않습니다. 단계 facts 줄의 사실, 그 단계 숫자로 다시 계산한 값, 공식 문서·원논문으로 확인해 meta.json `sources` 에 적은 사실만 씁니다. 본문에 빠진 내용이나 뒤 단계 내용은 블록에 넣지 않고 본문에 씁니다. 접힌 블록을 펴지 않는 사람에게는 보이지 않기 때문입니다.
- 확인 물음은 그 수준의 글과 그림만 보고 풀리고 답은 숫자나 짧은 말로 정해집니다. 초급·중급은 되도록 `number` 로 내고, `word` 면 받는 답을 둘 이상 둡니다. 그 단계의 떠올리기·왜일까요와 같은 물음이나 같은 답을 쓰지 않습니다. 세 수준이 한 화면에 같이 펴지므로 낮은 수준 물음의 답을 높은 수준의 글, 캡션, 코드에 그대로 쓰지 않습니다.
- `answer` 는 모두 자기 `mode` 로 채점해 맞음이 되는 꼴로 적습니다. `number` 칸의 답을 "약 2.4" 로 적으면 화면에서 2.4 도 약 2.4 도 틀림이 됩니다. 0.10536 처럼 끝나지 않는 소수는 `places` 를 두고 물음에 "소수 셋째 자리까지"처럼 몇 자리로 쓸지 적습니다.
- 블록 글도 본문처럼 영어 낱말이나 코드 뒤의 조사를 "W가", "`x[0]`은" 처럼 붙여 씁니다. web_lint 가 울타리 안을 보지 않아서 verify_ai 가 text, caption, q, why, mistake를 봅니다.
- 확인 물음 결과는 떠올리기처럼 `record.json` 에 `level` 과 함께 남고 복습 날짜와 외울 것에 들어가지 않습니다.
- 단원 첫 단계의 읽는 시간과 meta.json `minutes` 는 접힌 블록을 넣지 않고 셉니다.

## 3. 문항

카드 id 는 `i05-b07`(빈칸), `i05-c03`(객관식), `i05-s21`(문장), `i05-g02`(생성기), 주제는 `i05-t03` 입니다. 모든 카드에 `unit`, `step`(`5c/3`), `facts`, `core`, `prio`(1~3), `level`(1~3), `tags`(1~3개), `ref` 를 둡니다. 선택 필드는 `family`(같은 계산·같은 사실 묶음), `confuse`(헷갈리는 짝 태그, `confuse:axis-0-1` 꼴), `deep`(대학원 근거), `errata`(걸린 강의 자료 오류 id), `alt`(같은 사실을 바꿔 쓴 문항)입니다. `step` 단계의 `<!-- facts -->` 줄과 카드 `facts` 가 하나 이상 겹쳐야 합니다. 단원마다 핵심 카드(`core`)는 3~4개입니다.

빈칸 문항은 지문의 `____` 수와 `blanks` 수가 같아야 합니다. 칸마다 `answer`(첫째가 화면 정답), `mode`, 선택 `hint`·`places`·`unit`·`term` 을 둡니다.

| mode | 쓰는 곳 | 받는 차이 |
|---|---|---|
| `word` | 개념 낱말 | 공백·붙임표·가운뎃점·밑줄, 끝 조사 하나나 "입니다", terms.json 의 also·accept |
| `code` | 코드 토큰 | 공백, 따옴표 모양, 빈칸 좌우 문맥을 같이 쓴 답, 정답에 없는 끝 `()` 와 앞 `.` |
| `number` | 계산 값 | 천 단위 쉼표, 빼기표(U+2212), 분수, `unit` 꼬리, `places` 반올림 |
| `shape` | 텐서 모양 | 대괄호·소괄호·x·×, `torch.Size(...)` |
| `values` | 배열 값 | `tensor(...)`·`array(...)` 껍데기, `dtype=`, 원소 반올림. True·False 는 1·0 과 다르게 봄 |
| `exact` | 서식 문자열 | 앞뒤 공백만 |

빈칸 바로 뒤에 받침에 따라 갈리는 조사를 두지 않고 "____ 입니다" 꼴로 씁니다. 칸이 둘 이상이면 칸끼리 정답이 겹치지 않게 지문에 칸마다 무엇인지 적습니다. `register_full_backward_hook` 처럼 긴 API 이름은 객관식으로만 냅니다.

객관식 문항은 보기 4개이고 `options[].ok` 는 그 보기 글이 참인지입니다. `pick: "right"` 면 참인 보기가, `"wrong"` 이면 거짓인 보기가 답입니다. 복수 정답 객관식(`multi: true`)은 답 2~3개이고 지문에 "모두" 를 씁니다. 답이 아닌 보기의 `why` 는 바른 문장 한 줄이고, 옳은 것 고르기의 거짓 보기에는 노리는 착각을 짧게 적은 `aim` 을 둡니다(화면에 나오지 않음). "모두 옳다" 처럼 다른 보기를 가리키는 보기는 쓰지 않습니다.

문장 묶음(`statements.json`)은 주제마다 참 4·거짓 4 이상입니다. 참 문장에는 상자 2 부터 나오는 빈칸판 `cloze`(`____` 하나와 `answer`)를 둡니다. 상자는 문장마다 따로 셉니다.

같은 보기 묶음 안의 문장을 다른 단원에서 배운다면 그 문장에 `unit`과 `step`을 함께 적습니다. 주제의 `unit`을 따르는 다른 문장은 그대로 둡니다. `facts`와 `ref`, `meta.json`의 단원별 `stmt` 수도 실제 학습 위치와 맞춥니다. 보기 묶음을 유지하더라도 읽기 기록과 복습 노트는 문장이 지정한 단원을 따릅니다.

변형 문항을 추가한 뒤에는 단원 연습에서 실제로 선택되는지 확인합니다. 핵심 문항·예정된 복습·같은 문항군의 중복·새 문항 상한을 함께 대조합니다. 단원에서는 조건을 충족한 생성기 하나를 새 비핵심 고정 문항보다 먼저 고를 수 있습니다. 이미 다시 풀 생성기가 있으면 기존 순서를 유지합니다. 복습과 시험 전 훑기는 이미 푼 문항을 먼저 고르고 아래 변형 연결 규칙을 적용합니다. 이 선택 정책은 기록의 `policy=rules-v2`와 실행 코드 해시로 구분합니다. 모의고사 오답과 관련 연습을 한 쌍으로 고르는 경로는 `rules-v3`로 남깁니다.

일반 오답에서 같은 단원·근거의 기존 생성기를 연결한 묶음은 `rules-v4`로 남깁니다. 열린 문항이나 새 문항 조건을 충족한 후보만 쓰며 심화 비교 짝은 바꾸지 않습니다. 생성기가 없으면 `ai/review_variants.json`에서 내용 대조를 마친 고정 문항을 연결하고 `rules-v5`로 남깁니다. 검토 목록에서 명시적으로 연결한 생성기도 `rules-v5`와 목록 버전을 기록합니다. 두 후보 모두 없으면 원래 오답 구성과 `rules-v2`를 유지합니다. 선택 후보와 실제 선택을 구분하고 원문항·변형의 ID와 생성 시드·표시 조건은 각 문항에 따로 남깁니다. 아직 표시 조건을 선언하지 않은 기존 생성기는 `undeclared`를 유지하며 값을 추정해서 채우지 않습니다.

자동 복습과 시험 전 훑기에서는 선택된 미해결 오답·예정 복습 문항에 변형을 최대 세 장 연결합니다. 같은 단원과 열림 조건을 지키고 오늘 완료한 문항과 이미 복습할 후보는 새 짝에서 제외합니다. 생성기는 근거가 겹치는 후보를 고릅니다. 근거 항목이 다르거나 정정 출처가 붙은 생성기는 지문·계산을 대조한 명시적 연결에서만 사용합니다. 고정 문항은 지문·조건을 직접 대조한 검토 목록의 연결만 씁니다. 같은 단원에서 서로 다른 근거 항목을 연결할 때도 같은 개념을 다른 조건에 적용하는지 확인합니다. 보기 순서나 문장 부정만 바꾼 쌍은 등록하지 않습니다. 새 비핵심 문항 상한은 묶음 전체에서 합산합니다.

총 20문항 안에서 보충 문항부터 교체합니다. 아직 들어오지 못한 복습 문항이 있는 경우에만 마지막 예정 문항을 다음 묶음으로 미룰 수 있습니다. 미해결 오답·심화 비교 짝·연결 원문항은 미루지 않습니다. 예정 문항이 정확히 20개이고 보충 문항이 없으면 변형을 넣으려고 새 묶음을 만들지 않습니다. 선택된 짝은 원문항 다음에 배치하고 `rules-v5`, 후보·선택한 짝·미룬 문항을 기록합니다. 각 답은 실제 문항 ID에만 반영하며 기존 초안은 다시 편성하지 않습니다.

푸는 도중 다시 내도 지문이 같은 문항을 틀리면 같은 연결 규칙으로 고른 변형을 묶음 안에 끼웁니다. 끼운 변형은 묶음을 만들 때의 선택 기록에 없고, 답은 변형 문항 ID 로만 기록합니다. 어느 원문항 때문에 끼웠는지는 진행 중 묶음 저장의 `queue` 항목(`for`)에만 두고 수집하지 않습니다. 차시 문제집·단원 연습·섞어 풀기의 선택 기록에는 오늘 마친 문항을 모은 넘침 후보 `done` 이 들어가고, 그 후보에서 고른 문항은 `selected_pools` 값이 `done` 입니다. 정책 값은 바꾸지 않았으며 실행 코드 해시로 구분합니다.


고정 문항을 추가할 때는 해당 `meta.json`의 `card_order`에 기존 카드 ID 순서를 먼저 기록하고 새 ID를 뒤에 붙입니다. 문장·생성기 카드를 포함한 전체 목록을 사용합니다. 새 문항 때문에 기존 카드의 순서가 밀려 저장된 복습 묶음을 잇지 못하는 일을 막습니다. 실제 지문·답이 바뀐 경우의 복원 차단은 유지합니다.

생성기를 생략한 조회에서도 카드 순서 번호는 전체 목록을 따릅니다. 이때는 `meta.json`의 단원별 생성기 목록에 있는 ID만 생략할 수 있습니다. 고정 문항 누락이나 중복은 계속 오류로 처리합니다.

생성기는 `gens.py` 에 씁니다. 표준 라이브러리만 쓰고 `basis` 는 `lecture-example` 이나 `lecture-formula` 입니다.

```python
from aiprep.gen import blank, gen, num

@gen("i05-g02", unit="5b", level=2, tags=["Linear 파라미터 수"], ref=["5차시 과제 5번"], facts=["F05-20"],
     basis="lecture-formula", step="5b/3")
def linear_params(r):
    """입력 a, 출력 c 인 Linear 층의 학습 파라미터 수."""
    a, c = r.pick([8, 16, 32]), r.int(1, 10)
    return blank(stem="`nn.Linear(%d, %d)` 의 학습 파라미터는 ____ 개입니다." % (a, c),
                 blanks=[{"answer": [str(a * c + c)], "mode": "number", "unit": "개"}],
                 explain="입력 × 출력 + 출력(편향)입니다. %d×%d+%d = %s 입니다." % (a, c, c, num(a * c + c)),
                 params={"a": a, "c": c})
```

`oracle.py` 에는 생성기 id 의 붙임표를 밑줄로 바꾼 함수(`def i05_g02(params)`)를 둡니다. 빈칸이면 칸마다 정답 글의 목록, 객관식이면 답 보기의 글을 돌려줍니다. 300 시드에서 생성기와 oracle 이 같아야 하고 서로 다른 지문이 20개 이상이어야 합니다. 반올림 경계는 `fixed(x, k)` 가 `Retry` 로 피합니다.

생성 조건을 수집할 문항은 `gen_spec.meta`의 `template_revision`에 `"affine-translation-1"`처럼 템플릿 버전을 문자열로 적고, `display_params`에 지문에 공개한 입력 조건의 키만 나열합니다. 정답·풀이 결과·해설이나 답을 구분하는 내부 표시는 넣지 않습니다. 선언하지 않은 생성기의 `params`는 전송하지 않습니다. 원래 문항군은 `family`로 연결하고 숫자가 바뀔 때마다 새 개념으로 등록하지 않습니다.

새 기록에는 생성기·템플릿 ID, 버전, 실행에 사용한 소스 해시, 시드와 선언한 조건이 남습니다. 지문·보기 순서와 함께 만든 `instance_id`는 실제로 제시한 문제를 구분합니다. 같은 문제를 다시 푼 시도는 기존 기록 고유번호로 구분합니다. 이전에 저장한 답안이나 생성 조건이 없는 초안을 현재 생성기로 다시 해석해 채우지 않습니다. 공개 전에 수집·서버 저장·공통 입력에서 같은 조건이 유지되는지 확인합니다.

`ref`에 쓸 수 있는 표기의 예입니다. `5차시 슬 p21`, `5차시 노트북 02 [7]`, `5차시 과제 4번`, `10차시 강의노트 [3]`, `요약 1주차 p14`, `대학원 05 p15`, `공식 13차시`, `PyTorch 문서 CrossEntropyLoss`. 첫 근거는 해당 과정과 차시의 강의 자료입니다. 응용은 `응용 1차시 슬 p3`처럼 과정 이름을 붙입니다. 개론은 해당 주차 요약본도 첫 근거로 쓸 수 있습니다. 심화 자료는 강의 근거 뒤에 적습니다.

강의 자료 위치는 문항의 `ref`, facts.json의 `where`, meta.json의 `sources`에 남깁니다. 본문·블록·캡션·문항·보기·해설·생성기 견본에는 붙이지 않습니다. 앞에서 소개하지 않은 파일 별칭이나 셀 번호를 설명의 전제로 삼지 않습니다. 필요한 데이터·코드·계산 조건을 같은 화면에서 설명합니다. 더 볼 곳은 "5차시 여섯째 단원 3단계"처럼 학습 화면으로 안내합니다. 공식 문서 이름과 외부 그림의 출처 표시는 유지합니다.

새 차시를 준비할 때는 강의와 과제의 원본에 이어 공유 폴더의 보충교안·실습, `data`, 대학원 참고 교안도 살핍니다. 해당 단원과 이어지는 자료는 실제 쪽이나 셀을 읽고 어느 그림·설명·문항에 쓰였는지 출처 검토 기록에 적습니다.

## 4. 상황별 코드 뼈대

### 차시를 갱신할 때 코딩 실습 확인하기

개론·응용 차시를 새로 공개하거나 기존 설명·예제·과제를 바꿀 때마다 [코딩으로 실전학습하기]도 함께 확인합니다. 실제 강의와 과제의 코드에서 달라진 입력·출력, 호출 순서, 자주 틀리는 조건을 찾아 기존 실습 노트(`l18`, `al18`)와 대조합니다. 개론에서 배운 코드를 응용에서 쓰는 경우 두 곳의 정확한 학습 단계를 연결합니다.

이미 다루는 상황이면 관련 실습 코드·문항·해설을 보완합니다. 새로운 입력이나 판단을 연습할 자리가 필요하면 독립된 실습 단원을 추가하고, 같은 과정에서 먼저 배울 차시를 `after`에 지정합니다. 그대로 사용할 수 있는 경우에는 작업 기록에 대조한 단원과 판단 근거를 남깁니다. 읽기 자료와 실습 공개 시점이 다르면 남은 대상과 이유를 적습니다.

실습을 바꾸면 노트·코드 뼈대·문항·해설·출처를 함께 검사합니다. 같은 입력에서 예제와 채점이 맞는지 대조하고, 해당 과정의 목록과 차시 문제집에 표시되는지 확인합니다. 기존 문항 ID와 저장된 풀이를 보존하고, 학습 중인 묶음이 업데이트 뒤 이어지는지 확인합니다.

상황별 코드 단원의 카드는 뼈대 파일에서 엔진이 만듭니다. 과정마다 무리를 하나씩 두고 `index.json` 의 `patterns` 에 적습니다. 개론 무리 `pc` 는 노트 `l18`, 뼈대 `ai/patterns/S1.json`~, 문항 폴더 `ai/items/pc/` 를 씁니다. 응용 무리 `apc` 는 노트 `al18`, 뼈대 `ai/patterns/apc/S101.json`~, 문항 폴더 `ai/items/apc/` 를 씁니다. 문항 폴더에는 단원별 카드 수를 적은 `meta.json`, 계산 문항의 `gens.py`와 독립 정답 함수 `oracle.py`를 둡니다. `facts.json`과 `review.json`은 `sealed.json`에 묶습니다. 사실 id 는 개론 `F18-01`, 응용 `FA18-01` 이고 강의 자료 오류는 `X18-01`, `XA18-01` 입니다. 차시 사실을 옮긴 것은 `from` 에 원래 id 를 적습니다.

`patterns` 항목에는 `course` 와 `folder` 를 적을 수 있습니다. `course` 를 적지 않으면 무리 id 로 정하고(a 로 시작하면 응용), 적은 값이 id 와 다르면 목록을 읽지 못합니다. `folder` 를 적지 않으면 뼈대를 `ai/patterns` 맨 위에서 찾습니다. pc 항목은 두 키 없이 지금 글자 그대로 둡니다. 키를 더하거나 단원 `name` 을 바꾸면 개론 카드의 문항 버전이 바뀔 수 있어서입니다. 응용 무리는 `{"id": "apc", "course": "app", "folder": "apc", "page": "al18", ...}` 처럼 둘 다 적습니다.

- 세션은 고른 과정의 무리만 읽고 그 무리 폴더의 뼈대만 씁니다. 응용 뼈대 파일이 깨져도 개론 코딩 실습은 열립니다.
- 뼈대 id 는 은행 전체에서 하나씩입니다. 같은 id 가 두 폴더에 있으면 하위 폴더 무리를 읽지 못하고 `verify_ai.py` 가 실패합니다. 응용 뼈대는 `S101` 부터 씁니다.
- 카드 id 는 무리 id 를 앞에 붙입니다(`pc-k01`, `apc-k01`). 단원의 `after` 는 같은 과정의 차시여야 합니다.
- 응용 무리를 넣을 때 `terms.json` 을 고치지 않습니다. 용어를 하나만 더해도 두 과정의 미완료 묶음이 복원되지 않습니다. 동의어는 slot 의 `answer` 와 `line_answer` 에 직접 적습니다.
- 뼈대를 추가한 뒤에는 저장한 뼈대 목록으로 미완료 묶음의 해시를 다시 대조합니다. 목록을 저장하기 전에 만든 묶음은 문항 폴더 `meta.json`의 `resume_skeletons`에 기록된 공개 뼈대 목록을 사용합니다. 기존 뼈대와 출제된 문항이 일치하면 이어풉니다. 기존 뼈대를 고치는 경우에는 미완료 묶음의 전환 결과를 PR에 적습니다.
- 응용 코딩 실습 카드(`apc-…`)는 `review_variants.json` 에 넣지 않습니다. 엔진의 카드 번호 규칙이 apc 를 받지 않아 한 장만 넣어도 두 과정의 변형 연결이 모두 꺼집니다. `verify_ai.py` 는 이 카드만 막고 pc 카드는 막지 않습니다.
- `patterns` 항목 하나라도 형식이 틀리면(id 와 다른 `course`, `..` 이 든 `folder` 등) `index.json` 을 읽지 못해 개론과 응용이 모두 열리지 않습니다. 뼈대 파일과 달리 과정끼리 갈라 두지 않으니 `verify_ai.py` 를 통과한 뒤에 올립니다.
- 응용 차시가 늘어 차시 노트 번호가 무리 노트(`al18`)와 같아지면 `verify_ai.py` 가 실패합니다. 그때는 무리 노트를 다른 번호로 옮깁니다.

새 무리는 아래 순서로 출제합니다.

1. `index.json` 의 `pages`, `order` 에 무리 노트를, `patterns` 에 무리 항목을 넣습니다.
2. 노트 `ai/learn/<노트 id>/meta.json`(`lesson` 은 무리 id, 단원 `kind` 는 `pattern`)과 `page.md` 를 씁니다. `ai/learning-map.json` 에도 단원을 등록합니다.
3. 뼈대를 `ai/patterns/<folder>/` 에 쓰고, 문항 폴더 `ai/items/<무리 id>/` 에 `meta.json`, `work/facts.json` 을 둡니다.
4. `verify_ai.py <무리 id>`, `verify_web.py --bank ai --total-mb 32 <노트 id>`, `ai_overlap.py --lecture "<그 과정 강의 폴더>" <무리 id>` 를 통과시킵니다.
5. `ai_seal.py brief <무리 id>` 로 재풀이를 받고, 노트와 카드를 서명한 뒤 봉인합니다(7절).

뼈대는 강의의 입력 조건과 호출 순서를 확인한 뒤 이 트랙의 예제로 씁니다. 변수 이름만 바꾼 것을 새 설명이나 독립 계산으로 세지 않습니다. 겹침 검사에서 같은 줄이 나오면 원문과 문맥을 직접 대조합니다. `loss.backward()`, `optimizer.step()`, `model.eval()`, `with torch.no_grad():`만으로 이뤄진 세 줄은 공통 호출 순서로 봅니다. 이 경우에도 코드 120자 전체 일치와 직접 쓴 계산이 포함된 세 줄, 산문 검사는 유지합니다. 예제의 변수 이름이 원문과 다르면 학습 노트에서 한 문장으로 밝힙니다.

```json
{"format": 1, "id": "S1", "title": "미니배치 학습 한 에폭", "tags": ["학습 루프"], "prio": 3,
 "variants": {"표준형": {"situation": "미니배치마다 파라미터를 한 번 갱신하며 한 에폭을 학습합니다.",
                         "lines": ["model.train()", "for x, y in loader:", "    optimizer.zero_grad()", "..."]}},
 "slots": [{"id": "pc-k01", "variant": "표준형", "line": 0, "token": "train", "answer": ["train"], "mode": "code",
            "hint": "메서드 이름", "line_answer": ["model.train()"], "facts": ["F18-03"], "step": "18a/2", "core": true,
            "level": 1, "ref": ["5차시 노트북 03 [23]"], "explain": "..."}],
 "orders": [{"id": "pc-o01", "variant": "표준형", "lines": [5, 6, 7, 8, 9], "valid": [[0, 1, 2, 3, 4], [1, 0, 2, 3, 4]], "...": "..."}],
 "picks": [{"id": "pc-p01", "variant": "표준형", "line": 10, "stem": "...",
            "wrong": [{"text": "loss_sum += loss.item()", "aim": "배치 평균을 그대로 더함", "why": "..."}], "...": "..."}],
 "changes": [{"id": "pc-x01", "from": "1차시 fit", "to": "표준형", "stem": "...", "back": null, "...": "..."}]}
```

- 코드 예제마다 `situation` 과 `lines` 를 둡니다. `situation` 은 가이드 말투 한두 문장이고 그 코드 예제로 만든 카드 지문의 첫 줄이 됩니다. `lines` 는 들여쓰기 4칸이고 주석, 탭, `____` 를 넣지 않습니다. 줄 번호는 0부터 셉니다.
- 아래 id 는 개론 무리 예이고 응용 무리는 `apc-k01` 처럼 씁니다. slot(`pc-k01`)은 코드 예제 전체를 보이고 그 자리를 가린 코드 빈칸, order(`pc-o01`)는 줄 순서 고르기, pick(`pc-p01`)은 그 자리에 맞는 줄 고르기, change(`pc-x01`)는 from 코드 예제를 to 코드 예제로 바꿀 때 고칠 줄을 모두 고르는 문항입니다.
- 모든 카드에 `facts`, `step`, `level`, `ref`, `explain` 을 적습니다. `level` 과 `ref` 는 머리에서 물려받지 않고, `tags` 와 `prio` 는 적지 않으면 머리 값을 씁니다. 첫 ref 는 그 줄을 가르친 강의 슬라이드·노트북·과제·강의노트나 요약본입니다.
- slots 항목에 `"note_only": true` 를 적으면 그 자리는 카드가 되지 않고 학습 노트의 돌려 가며 빈칸(`ai-rotate`)에서만 쓰입니다. id 는 `apc-n101` 처럼 무리 id 뒤에 `n` 과 번호를 붙여 카드 id(k·o·p·x)와 구분합니다. `variant`, `line`, `token`, `answer`, `mode`, `hint`, `explain` 은 slot 과 같게 적습니다. `level`, `ref` 는 적지 않아도 되고, `facts`, `step` 을 적으면 쓰는 곳이 없으므로 `verify_ai.py` 가 실패합니다. 엔진은 이 자리를 slot 카드의 점차 지우기에서 가리지 않고, `meta.json` 의 slot 수와 복습·오답 노트·재풀이 채점 키에도 넣지 않습니다. `hint` 와 `explain` 은 화면에 보이므로 `verify_ai.py` 가 말투를 봅니다.
- slot 의 `token` 은 그 코드 예제 전체에서 한 번만 나와야 합니다. slot 문항은 코드 예제 전체를 보여서 같은 토큰이 다른 줄에 있으면 그 줄에서 답을 옮겨 쓸 수 있습니다. 두 번 나오는 토큰(`to`, `item`, `size`)은 pick 으로 묻습니다. `answer` 첫째는 `token` 과 같고, `line_answer` 첫째는 들여쓰기를 뺀 그 줄입니다. 같은 코드 예제 자리끼리 답이 겹치면 함께 가렸을 때 칸을 구별할 수 없어 실패입니다.
- 코드 예제에 `figures` 로 입력·결과 그림을 적을 수 있습니다(`{"input": "learn/al18/assets/a18a-1.png", "output": "..."}`). 엔진은 이 값을 연습 화면 값에만 넘기고 카드에는 넣지 않습니다. 파일이 없으면 `verify_ai.py` 가 실패합니다.
- order 의 `valid` 는 `lines` 안 위치의 순열 목록이고 코드 예제 순서(`[0, 1, 2, 3, 4]`)를 꼭 넣습니다. 오답 보기는 엔진이 valid 하나에서 이웃 두 줄을 바꾸거나 한 줄을 옮겨 만듭니다.
- pick 의 `wrong` 에는 오답 보기 세 개를 적고 보기마다 `text`, `aim`(노리는 착각), `why`(바른 설명)를 둡니다.
- change 의 정답은 두 코드 예제를 difflib 로 견줬을 때 다른 줄이라 두 코드 예제는 다른 줄이 둘 이상이어야 합니다. `back` 에 반대 방향 지문을 적으면 묶음 안에서 다시 낼 때 반대 방향으로 냅니다.
- 같은 줄이나 같은 사실을 묻는 카드는 `family` 를 같이 줍니다. 한 묶음에 family 하나만 나오고, 엔진은 같은 코드 예제 카드를 order·pick, change, slot 순서로 냅니다. change 의 같은 줄 보기에는 pick 의 답 줄이 나올 수 있고, slot 은 코드 예제 전체를 보여서 앞 카드의 답이 됩니다.

응용 단원은 돌려 가며 빈칸으로 가린 자리와 같은 자리의 빈칸 카드를 두지 않습니다. 노트에서 채운 자리가 연습에서 같은 지문으로 다시 나오기 때문입니다. 돌려 가며 빈칸에 쓸 자리는 `note_only` 자리로 따로 적고 slot 카드의 `line`·`token` 과 겹치지 않게 고릅니다. 같은 코드 예제에서 slot 카드와 `line`·`token` 이 모두 같으면 `verify_ai.py` 가 실패합니다. 같은 줄의 다른 토큰은 막지 않습니다. `note_only` 자리가 하나라도 있는 뼈대를 쓰는 `ai-rotate` 는 `slots` 에 `note_only` 자리만 적어야 하고, 어느 `ai-rotate` 도 가리키지 않는 `note_only` 자리가 있으면 `verify_ai.py` 가 실패합니다. `note_only` 자리가 없는 개론 뼈대(S1~S9)는 지금처럼 `slots` 를 적지 않으면 모든 자리를 돌립니다. `note_only` 자리를 지울 때는 `retired.json` 에 적지 않습니다.

slot 카드가 나올 때 엔진은 같은 코드 예제의 열린 자리 상자 평균으로 함께 가릴 자리 수(0~3)를 정하고, 상자가 낮은 자리부터 함께 가립니다. 함께 가린 칸을 틀리면 그 자리 카드가 다음 학습일 복습에 나옵니다. 함께 가릴 자리 수가 3 이고 주 자리 상자가 4 이상이면 `line_answer` 가 있는 줄은 줄 전체를 가립니다. 그래서 `line_answer` 에는 같은 동작을 하는 다른 꼴을 모두 적습니다.

CNN의 특징 수처럼 숫자를 바꿔 계산하는 문항은 무리 문항 폴더의 `gens.py`(개론 `items/pc/gens.py`)에 `pc-g01` 같은 ID로 등록합니다. 차시 생성기와 같은 필드를 쓰고 `unit`과 `step`은 해당 상황별 단원에 연결합니다. `meta.json`의 단원별 `gen` 목록에도 넣습니다. 코드 자리의 답을 숫자로 바꾸어 만들지 않습니다. 독립 계산 함수는 `oracle.py`에 두고 공개 지문 재풀이와 300개 시드 대조를 거칩니다. 이 문항도 단원을 읽은 뒤 열리며 권장 차시의 문제집과 상황별 오답 노트에 함께 나옵니다.

## 5. 사실 확인(facts.json)

`facts` 의 사실마다 `id`, `from`(factcheck 의 위치), `text`(확인 기록을 바꿔 쓴 한 문장), `verdict`, `where`, `checked` 를 둡니다. `verdict` 가 틀림·확인 못 함인 사실은 문항에 쓰지 않습니다. 단순화·부분적으로 맞음이면 `ask_as` 의 표현으로만 묻습니다. `concept_only` 사실은 number·exact·values 빈칸으로 묻지 않습니다. `errata` 를 다루는 기존 카드의 내부 해설에는 검증용 "정정:" 표기를 보존하며 화면에서는 이 표기를 빼고 바른 설명을 바로 보여 줍니다. 해당 문항은 모의고사에 넣지 않습니다. `sources` 에는 강의 폴더 기준 경로와 sha256 을 적습니다. 경로는 실제 폴더 이름을 그대로 써서 `강의_11기_AI개론_2차시_…/강의_11기_AI개론_2차시_01_numpy.ipynb` 꼴이고, 요약본은 맨 위 파일 이름만 씁니다. `verify_ai.py --sources` 가 이 경로로 파일을 찾습니다.

## 6. 그림

학습 노트 그림은 `tools/ai_art/lNN.py` 를 출제자 파이썬(numpy·matplotlib·Pillow)으로 돌려 직접 그리고, matplotlib 는 Agg 로만 씁니다. 파일은 폭 1120px·높이 600px 이하, GIF 는 10장 이하·장마다 1,600~2,500ms·250KB 이하, PNG 는 150KB 이하입니다. 그림에 찍는 숫자는 스크립트 안에서 assert 로 확인합니다.

GIF의 장 수는 보여 줄 계산 단계로 정합니다. 3~5장으로 변화 과정과 마지막 요약을 모두 보여 줄 수 있으면 같은 장을 늘리지 않습니다. 첫 입력, 바뀌는 값, 마지막 결과가 이어지는지 모든 장을 열어 확인합니다. μ·γ·√와 음수 부호는 실제 화면 폭으로 줄여서도 구분되는 글꼴이나 mathtext로 그립니다.

저장할 때는 `tools/ai_art` 의 `quantize()` 로 64색 팔레트를 만듭니다. `FIXED` 에 적힌 색은 팔레트에 먼저 들어가서 옅은 회색과 옅은 보라처럼 가까운 두 색도 서로 합쳐지지 않습니다. 스크립트에 새 색을 쓰면 `FIXED` 에도 넣어야 tests/test_ai_tools.py 가 통과합니다.

텐서, 특징 맵, 채널처럼 여러 겹이 쌓인 모양을 보여 줘야 하는 그림은 `tools/ai_art/iso.py` 로 그립니다. 이 파일로 비스듬히 내려다본 타일, 입체 상자, 겹친 판을 그릴 수 있습니다. 빛은 왼쪽 위에서 온다고 보고 윗면·왼쪽 면·오른쪽 면을 세 밝기로 칠합니다. 겹친 판은 뒤 판을 그림 파일 픽셀로 오른쪽 16px, 위 12px씩 비껴 놓습니다. 이번 장에서 새로 나온 부분은 파랑 면에 진한 파랑 테두리(`new`), 앞 장에서 나온 부분은 옅은 파랑(`seen`), 아직 나오지 않은 부분은 회색 점선 윤곽(`todo`)으로 그립니다. 새로 나온 부분을 더 진하게 보여 줘야 하면 진한 파랑 면(`strong`)을 씁니다. 그래프·표·흐름 그림은 평면으로 두고 같은 색과 선 굵기를 씁니다.

있던 그림을 다시 그릴 때는 장 수, 장마다 보이는 시간, 그림 속 숫자와 글자를 바꾸지 않습니다. 캡션과 장 설명이 말하는 색과 위치가 새 그림에서도 맞는지 장마다 대조합니다. 그림 파일이 한 바이트라도 바뀌면 그 노트의 서명을 다시 합니다.

```
python3 -m tools.ai_art l05 5a-2  # 5a-2 그림을 그리고 manifest에 기록합니다.
python3 tools/ai_art/l02.py l02-1  # l02 스크립트로 l02-1 그림을 그립니다.
python3 -m tools.ai_art l02 --record  # l02의 기존 그림을 manifest에 기록합니다.
```

직접 그린 그림은 manifest에 등록합니다. 가져온 그림은 `meta.credits`에 출처를 적습니다. 이번에 확인한 3Blue1Brown 공식 글의 MP4 두 개는 원작자 FAQ의 짧은 인용 허락으로 사용합니다. 허락 이름은 `3Blue1Brown FAQ clip permission (under 60 seconds)`이며 author는 `3Blue1Brown · Grant Sanderson`, permission_url은 `https://www.3blue1brown.com/about/`, url은 해당 공식 MP4 주소로 적습니다. source_seconds에는 사용한 원본 구간의 초수를 적으며 전체 해당 credits의 합도 60초 미만으로 둡니다. 직접 그린 그림의 manifest나 CC 라이선스로 등록하지 않습니다. 화면마다 저작자와 공식 글 링크를 읽을 수 있게 두고 원본 장면과 추가 한글 설명을 구별합니다. 캡션과 주변 본문에는 대표 장면 발췌와 느린 표시임을 밝힙니다. 표시 시간과 원본 사용 시간을 구별하고 시그모이드의 입력 0·출력 0.5와 출력 범위를 다른 활성화 함수로 넓히지 않습니다. 검증기는 확인한 원작자·허락 URL·공식 자산 URL·기재한 시간 조건을 검사하며 주변 설명과 실제 원본 사용 범위는 별도로 대조합니다. 가져온 GIF에도 기존 크기·장 수·색 수·용량 한도를 적용합니다.

세 수준 블록 그림은 수준마다 새 PNG 하나이고 이름은 `<단원>-<단계 번호><수준 번호>`(초급 1, 중급 2, 심화 3)입니다. 4b 셋째 단계 블록이면 `4b-31`, `4b-32`, `4b-33` 입니다. 화면 520×280(파일 1040×560)이고 글자는 matplotlib 22 이상, 30KB 안팎으로 둡니다. 캡션은 "그림 N." 으로 시작하지 않는 문장 하나이고 `content` 에 그림에 무엇이 있는지 적습니다. `tools/ai_art/levels.py` 의 `chain`(초급 상자와 화살표), `grid`(괄호 없는 숫자 칸 표), `graph`(좌표 그래프)가 크기와 글자를 맞춘 Figure 를 돌려주고, 글이 칸을 넘으면 ValueError 를 냅니다. 블록마다 함수 하나가 수준을 인자로 받아 그리게 그 차시 스크립트에 둡니다.

그리는 명령에는 그림 이름을 꼭 붙입니다. 이름 없이 돌리면 서명된 그림을 모두 다시 그려 해시가 바뀝니다.

Qt로 만든 학습 패턴·조건 그림은 PyQt6와 Pillow가 있는 작성 환경에서 필요한 파일만 다시 만듭니다. 모델 코드는 실행하지 않습니다.

```
python -m tools.ai_art.l01_training_qt --only 1b-6 1b-7 1b-8
python -m tools.ai_art.conditions_qt --only 7f-4
python -m tools.ai_art.lesson_bridges_qt --only 10 11
python -m tools.ai_art.level_repairs_qt --only 13b-32 13c-33
```

차시를 잇는 그림은 같은 예의 배치 수·클래스 수·입출력 모양을 이어 씁니다. 입력 크기나 모델을 바꾸면 그 지점의 이유와 새 조건을 적습니다. 정답이 모델 입력으로 보이는 화살표를 쓰지 않으며, 축의 수·축의 크기·원소 수·갱신하는 파라미터를 구분합니다. 실제 실행 결과와 설명용 도식도 구분합니다. 같은 그림을 초급·중급·심화에 반복하지 않고 수준마다 계산이나 결과를 보탭니다.

단계와 사실은 실제 설명 내용으로 연결합니다. 같은 사실을 여러 단계에서 사용하거나 한 단계가 여러 사실을 설명할 수 있습니다. 그림의 연속 처리·조건 분기·방법 비교를 화살표로 구분하고 장별 설명에는 바뀐 값과 조건을 적습니다. 회전은 길이와 직각, 좌표 그림은 축 방향과 축척을 계산으로 확인합니다. 축척이 없는 도식은 그 점을 표시합니다. 확인 물음의 답을 같은 수준 그림에 미리 적지 않으며 심화에서는 입력이나 실패 조건을 바꿔 원리를 적용하게 합니다.

서명은 글 파일(.py, .json, .md)을 줄 끝 LF 로 읽어 해시를 세므로 Windows 에서 받아도 맞습니다. 봉인은 내용을 바꾸지 않아 봉인 앞뒤로 서명이 맞습니다. 서명 뒤에 한 글자라도 고치면 `--require-review` 가 떨어지고, 바뀐 카드를 다시 재풀이·대조·검토한 뒤 다시 서명합니다.

첫 재풀이 뒤 문장만 고쳐 다시 서명할 때는 `--keep-first-pass`로 이전 기록을 보존합니다. 이 옵션은 맞힌 수, 틀린 문항, 시간과 나머지 기록을 함께 보존합니다. `--first-pass`나 `--minutes`와 함께 쓰지 않습니다. 이전 기록을 읽을 수 없으면 서명하지 않습니다.

## 모의고사 검증하기

`python3 tools/verify_ai.py m1 m2 m3`는 실제 회차의 30문항·60분 구성과 차시별 배분을 검사합니다. m1·m2·m3는 문항 수를 작게 적어도 이 검사를 받습니다. m90 같은 작은 검증용 회차에는 기존 문항 꼴·빈칸·보기·정정 제외·deep 수 검사를 적용합니다.

모의고사 폴더의 meta.json에는 format=1, id, count=30, minutes=60과 blueprint를 적습니다. blueprint는 `{"i01": 1, "i02": 2, ...}`처럼 차시별 문항 수를 담습니다. 0개인 차시는 생략할 수 있습니다. index.json의 count·minutes·range도 함께 대조합니다. m1의 range는 `[1, 12]`이고 m2·m3는 `[1, 17]`입니다. meta에 range를 쓰면 같은 값을 적습니다.

| 차시 | m1 | m2 | m3 |
|---|---:|---:|---:|
| i01 | 1 | 1 | 2 |
| i02 | 2 | 2 | 1 |
| i03 | 2 | 2 | 2 |
| i04 | 4 | 3 | 2 |
| i05 | 2 | 2 | 2 |
| i06 | 2 | 2 | 2 |
| i07 | 2 | 1 | 2 |
| i08 | 3 | 2 | 2 |
| i09 | 2 | 2 | 1 |
| i10 | 4 | 2 | 2 |
| i11 | 3 | 2 | 2 |
| i12 | 3 | 2 | 1 |
| i13 | 0 | 2 | 2 |
| i14 | 0 | 2 | 2 |
| i15 | 0 | 1 | 2 |
| i16 | 0 | 2 | 2 |
| i17 | 0 | 0 | 1 |
| 합계 | 30 | 30 | 30 |

실제 문항의 lesson을 세어 표와 대조합니다. meta의 blueprint만 맞추고 실제 문항 배분을 바꾸면 실패합니다. 두 차시에서 다룬 주제에는 처음 다룬 차시를 적습니다. 어느 차시에서 처음 소개했는지는 대조자가 원강의에서 확인합니다.

문항은 id, lesson, unit, step, facts, ref, level, topic, kind, stem, explain을 사용합니다. lesson에는 iNN을 적고 topic에는 실제 개념명을 적습니다. 같은 topic은 한 회에 두 문항까지이며 공백·구분 기호·대소문자를 정규화해 셉니다. 같은 개념에 다른 이름을 붙인 경우는 대조자가 확인합니다. facts는 해당 차시의 사실 ID를 사용합니다. unit·step은 해당 학습 페이지에 존재하고 그 단계의 사실 줄과 facts가 겹쳐야 합니다. 첫 ref에는 집계 차시의 강의·과제·요약 근거를 적습니다.

kind=blank는 blanks를 사용하며 한 문항의 칸은 1~2개입니다. kind=choice는 options·pick을 사용합니다. multi를 생략하면 false이고 값을 적으면 bool을 사용합니다. 보기는 네 개이며 multi=true의 정답은 정확히 두 개입니다. 구성은 빈칸 14개와 객관식 16개입니다. 객관식은 right 단일 답 7개, wrong 단일 답 6개, multi 3개입니다. level 1/2/3은 8/15/7개입니다.

빈칸 문항은 범주 하나에만 넣습니다. 숫자·shape·values 칸이나 숫자만 답하는 칸이 하나라도 있으면 계산·모양 문항으로 셉니다. 숫자 상수·숫자 배열·숫자끼리의 산술식을 code 모드로 적어도 코드 수에 넣지 않습니다. 남은 문항에 word·exact 칸이 섞이면 낱말 문항으로 셉니다. 모든 칸이 실제 코드 토큰을 묻는 code 모드일 때만 코드 문항으로 셉니다. True·False·None은 코드 토큰으로 다룹니다. 코드 문항은 6개 이상, 계산·모양은 5개 이상, 낱말은 3개 이하입니다.

실제 과제형 코드 빈칸에는 assignment=true를 적습니다. 생략하면 false이고 값을 적으면 bool을 사용합니다. 이 표시는 코드 문항이며 Python 코드 울타리 안에 빈칸이 있을 때만 과제형 수에 포함합니다. 한 회에 과제형 코드 빈칸을 5개 이상 넣습니다. 상황별 코드 문항에는 pattern에 존재하는 S1 같은 뼈대 ID를 적고 해당하지 않으면 생략합니다. pattern 문항은 3개 이상이며 상황별 코드의 학습 단계와 사실 ID도 사용할 수 있습니다. assignment·pattern 표시와 수는 실제 과제·뼈대와의 대응을 증명하지 않습니다. 대조자가 지문과 원자료를 읽어 확인합니다.

errata가 붙은 문항과 기존 연습에서 정정 근거로 함께 쓴 사실 ID를 제외합니다. 사실 자체에 errata 표시가 있어도 제외합니다. deep은 bool이며 한 회에 두 문항까지입니다. concept_only 사실은 숫자·모양 빈칸과 숫자 보기로 묻지 않습니다. 등록 답이나 보기 하나라도 숫자·숫자 배열·산술식 형태를 쓰면 값으로 묻는 문항으로 봅니다. 긴 문장 안의 계산 요구나 기록에 연결하지 않은 정정 주제는 대조자가 확인합니다.

같은 사실은 세 회 중 두 회까지만 사용합니다. 같은 회에서 그 사실을 여러 번 써도 회차 사용은 한 번으로 셉니다. 다른 ID로 같은 사실을 새로 등록해 제한을 피하지 않도록 원래 사실 ID를 사용합니다. 다른 회차의 파일이 있으면 m1만 선택해도 회차 간 중복과 사실 사용을 함께 검사합니다. ID나 화면 지문·보기가 같은 문항을 여러 회에 넣으면 실패합니다. 보기 순서와 답·해설·근거만 바꾼 문항도 같은 문항으로 봅니다.

연습 지문은 정적 지문·대체 지문·참거짓·cloze·생성기 견본과 상황별 코드 공개 견본을 비교합니다. 생성기 견본은 --seeds 수만큼 시드 0부터 만듭니다. NFKC·casefold로 정규화한 어절·식별자·숫자의 집합을 만들고 빈칸 표시는 뺍니다. 교집합 크기를 합집합 크기로 나눈 자카드 값이 0.6 이상이면 실패합니다. 이 검사는 가능한 생성기 출력 전체를 대조하지 않습니다.

학습자에게 보이는 문장의 말투와 코드 울타리의 짝도 검사합니다. 빈칸에는 첫 등록 답을 채워 Python 코드 구문을 분석합니다. 코드의 실행 결과와 정답 사실은 대조자가 확인합니다. 객관식에 의도적으로 넣은 오류 코드는 구문 분석을 강제하지 않습니다. 검사를 통과한 회차는 기존 --answers·--first-pass·--keep-first-pass·--require-review 경로로 채점·기록·서명을 확인합니다. 첫 재풀이 파일을 읽지 못하면 서명을 중단하고 이전 기록을 보존합니다.

서명한 회차의 문항이나 `ai/index.json` 회차 줄의 배분 버전(blueprint_revision)을 고칠 때는 `python3 tools/ai_seal.py unseal m4`처럼 먼저 풉니다. 학습자 기록에는 응시한 문항의 회차 버전 해시(fingerprint)가 남습니다. unseal은 서명한 문항을 이 해시 이름의 폴더 `work/versions/<fingerprint>/`에 items.json과 spec.json으로 남깁니다. 문항을 고쳐 seal하면 이 예전 문항도 함께 봉인됩니다. 그 버전으로 제출한 학습자는 결과·해설·오답 복습을 예전 문항으로 엽니다. 제출하지 않고 풀던 초안은 새 응시로 다시 시작합니다. `--sign`은 review.json에 그때의 fingerprint와 회차 줄 값을 적습니다. unseal은 이 회차 줄 값으로 fingerprint를 다시 계산해 예전 문항의 폴더 이름을 정합니다. 이 값이 없는 예전 서명은 지금 회차 줄로 계산하므로 회차 줄을 unseal한 뒤에 고칩니다. 서명한 뒤 fingerprint가 바뀌게 문항이나 회차 줄을 고치고 unseal을 건너뛰면 seal이 멈추고 unseal을 먼저 하라고 안내합니다. `verify_ai.py`는 남긴 예전 문항의 fingerprint를 다시 계산해 폴더 이름과 같은지 보고, 직전 커밋의 봉인에 있던 예전 문항이 빠지거나 바뀌면 실패합니다. 예전 문항에 있던 ID를 지금 문항이 쓰면 두 문항의 차시(lesson)가 같아야 하고, 다르면 실패합니다. 뺀 문항의 ID는 meta.json의 retired_items에 적고 새 문항에는 가장 큰 번호 다음 번호를 줍니다. 직전 커밋과 견주는 검사는 커밋하기 전의 작업 폴더에서만 차이를 찾습니다. `--sign`은 이전 서명에 있던 예전 문항이 빠졌거나, 서명한 버전의 예전 문항을 남기지 않은 채 fingerprint가 바뀌었으면 서명하지 않습니다.

서명한 회차의 `ai/index.json` 회차 줄에 `"hidden": true`를 두면 그 회차는 학습자 목록에 나오지 않습니다. 그 회차를 제출한 기록이 있는 사람에게만 [이전에 푼 회차] 아래에 보입니다. 회차를 공개할 때는 이 값을 지우고 `ai/README.md`의 회차 안내와 `docs/GUIDE_INDEX.md`의 링크를 함께 고칩니다. `hidden`은 fingerprint와 검토 서명에 들지 않으므로 지워도 다시 서명하지 않습니다.

예전 회차를 목록에서 내릴 때는 회차 줄에 `"legacy": true`를 두고 제목을 '이전 모의고사 N회'로 바꿉니다. m1\~m6은 이렇게 내렸습니다. `legacy` 회차는 그 회차를 제출한 기록이 있는 사람에게만 [이전에 푼 회차] 아래에 보입니다. 시작했지만 제출하지 않았고 시간이 남은 사람에게는 목록에서 빠지고, 풀던 초안 파일은 지우지 않습니다. 시간이 이미 끝난 시도는 예전처럼 자동 제출합니다. 개론 전용 회차는 응시 기간 `window`에 [시작, 끝] 날짜가 있어야 `verify_ai.py`를 통과하지만, `legacy` 회차는 빈 목록이어도 통과합니다. `legacy`와 회차 제목도 fingerprint와 검토 서명에 들지 않으므로 바꿔도 다시 서명하지 않습니다.

## 혼합 회차 m4·m5·m6 검증하기

`python3 tools/verify_ai.py m4 m5 m6`는 회차별 32문항을 검사합니다. 회차마다 개론 16문항과 응용 16문항을 사용합니다. 개론은 1~17차시의 누적 내용을 다룹니다. 응용은 m4·m5에서 1~3차시, m6에서 1~4차시를 다룹니다. 연습 기본값은 120분입니다. 약 2시간 연습을 참고한 값이며 공식 평가 시간은 아닙니다. 기존 timed 경로를 사용하고 시간 제한 없는 분기를 추가하지 않습니다.

index.json과 meta.json에 `scope=mixed`, `courses=["intro", "app"]`, `course_counts={"intro": 16, "app": 16}`, `blueprint`, `blueprint_revision`을 함께 적습니다. 문항에는 course·lesson·concept·family·level·format·sourcefacts·conditions·allowed_answers·explain·transferaxis를 보존합니다. allowed_answers는 빈칸의 허용 답을 담으며 객관식의 정답은 options의 ok로 기록합니다. level_reason에는 난도를 나눈 출제 근거를 적습니다. 이 분류를 실제 학습자의 난도나 능력 측정값으로 사용하지 않습니다.

실제 문항은 빈칸 16개·객관식 16개이며 level 1/2/3은 8/16/8개입니다. 주 차시 배분은 i01~i09와 i11~i17에 한 문항씩이며 m4·m5는 a01/a02/a03에 5/6/5문항, m6는 a01/a02/a03/a04에 4문항씩입니다. `mixed32-blueprint-v1`·`mixed32-transfer-v1`은 기존 배분, `mixed32-applied04-v1`은 4차시 포함 배분으로 검사합니다.

새 배분을 쓰는 회차는 아래 순서로 등록합니다.

1. `tools/verify_ai.py`의 `MIXED_BLUEPRINTS`에 배분 버전을 등록합니다. 등록하지 않은 `blueprint_revision`은 검사에서 실패합니다.
2. `aiprep/mixed_mock.py`의 `PUBLISHED_IDS`에 회차 ID를 추가합니다.
3. 그 회차가 학습자 목록에 보이게 하려면 같은 배분 버전의 문항 수·시간·과정별 문항 수를 `aiprep/mixed_mock.py`의 `CONTRACTS`에도 넣습니다.

i10에는 주 문항이 없으므로 i10의 내용은 i09 문항의 related_sources에 연결합니다. sourcefacts는 주 차시 facts와 보조 차시 related_sources의 사실 목록을 순서대로 합칩니다. 보조 차시는 개론 1~17차시와 그 회차 배분에 있는 응용 차시만 받습니다. 각 사실이 해당 과정·차시의 사실 목록과 공개 학습 단계에 있는지 대조하며 정정 근거·미확인 사실은 제외합니다.

문서로 보충한 사실의 첫 ref는 해당 사실의 where에 기록한 문서나 HTTPS 주소도 받습니다. 실제 내용의 지지는 별도 출처 검토 기록에서 확인합니다. 연습과의 어휘 겹침 검사는 풀이 원리의 독립성을 증명하지 않습니다. 혼합 회차는 서로와 기존 회차의 지문·보기 중복을 비교하며 m1~m3의 세 회 중 두 회 사실 사용 제한은 기존 회차에 적용합니다.

새 조건을 묻는 회차는 기존 문항을 덮어쓰지 않고 새 회차 ID로 추가합니다. 새 문항은 같은 차시의 단원 문항·문장, 생성기 출력, 학습 노트의 짐작·떠올리기·세 단계 블록, 앞선 혼합 회차의 같은 차시 문항과 대조합니다. 숫자와 조건이 같은 물음은 조건이나 묻는 방향을 바꿔 다시 씁니다. m5·m6는 조건 변형·개념 응용·코드 분석·개념 비교를 두 과정에 모두 넣습니다. meta.json의 `variation_types`는 `condition`, `application`, `code_analysis`, `comparison` 순서이며 각 문항의 `transferaxis`에 해당 유형을 적습니다. `tools/verify_ai.py`는 배분 버전이 `mixed32-transfer-v1`·`mixed32-applied04-v1`이거나 meta.json에 `variation_types`를 적은 회차에서 과정마다 네 유형이 모두 있는지 검사합니다. 새 배분 버전을 이 검사에 넣으려면 `VARIATION_REVISIONS`에 추가합니다. 각 문항의 근거와 연결할 연습을 대조하고, 다른 과정이나 아직 제출하지 않은 시험 문항을 복습 후보로 넣지 않습니다. 생성기와 연결할 때는 같은 개념인지 지문까지 읽어 확인합니다. 한 묶음에 원문항과 관련 연습을 함께 낼 때는 생성기 비율·같은 문항군 제한 뒤에도 두 문항이 남는지 검사합니다.

meta.json의 draft=true에서는 구조 검사를 실행할 수 있습니다. 두 과정의 시작 목록에서는 숨기며 `--sign`과 `--require-review`는 실패합니다. 최종 검토 뒤 draft를 해제하고 기존 첫 재풀이 기록을 연결해 서명합니다. 서명은 meta.json과 문항 파일을 함께 덮습니다. 초안 원본·출처 해시·첫 답안은 비공개 검토 경로에 보존합니다. 봉인 뒤에도 같은 `--require-review`로 확인합니다. 검토 전 작업 파일을 봉인하거나 공개 준비 완료로 기록하지 않습니다.

## 모든 차시 회차 검증하기

### 새 회차의 문항 수와 범위 정하기

짧게 점검할 회차와 시간을 두고 풀 회차를 섞어 냅니다. 짧은 회차는 핵심 개념과 자주 헷갈리는 조건을 빠르게 확인할 수 있게 구성합니다. 긴 회차에는 같은 개념을 새 조건에 적용하거나 코드의 결과와 오류 원인을 설명하는 문항을 더합니다. 예를 들어 30문항대 점검과 50문항대 실전 연습을 둘 수 있습니다. 문항 수와 시간은 코드 작성 등 오래 걸리는 문항까지 다시 풀어 본 뒤 정합니다.

개론과 응용의 문항 수는 먼저 확인할 개념을 고른 뒤 셉니다. 공개한 범위의 모든 차시가 들어갔는지, 선행 개념을 실제 응용에 써 볼 수 있는지, 빠진 핵심 개념이 있는지를 대조합니다. 강사가 출제 범위를 안내한 경우 그 내용을 함께 참고합니다. 개론·응용 비율과 문항 유형별 수는 쏠림을 찾는 데 씁니다.

새 회차는 새 ID와 배분 버전을 씁니다. `aiprep/mixed_mock.py`의 `CONTRACTS`에 총 문항 수, 시간, 개론·응용 문항 수와 `app_through`를 적습니다. `tools/ai_mock_rules.py`의 `PINNED_BLUEPRINTS`에 차시별 문항 수를 적고, `tools/verify_ai.py`의 `ALL_LESSON_RULES`에는 문항 유형과 난이도별 수를 등록합니다. 검사기는 이 배분과 실제 문항을 대조합니다. 공개한 회차를 다시 열 때는 그 회차에 저장한 범위·배분과 보존본을 사용합니다.

### 등록한 배분과 실제 문항 대조하기

배분 버전이 `all44-v1`인 회차는 개론 1~17차시와 응용 1~5차시를 모두 담습니다. 문항은 44개, 시간은 120분이고 개론 31문항과 응용 13문항을 씁니다. 이 세 값은 `aiprep/mixed_mock.py`의 `CONTRACTS`에 적은 값이 기준이고, `tools/verify_ai.py`는 그 표를 읽어 index.json과 meta.json을 검사합니다. 두 파일에는 혼합 회차처럼 `scope=mixed`, `courses=["intro", "app"]`, `range=[1, 17]`, `blueprint`, `blueprint_revision`을 적고, `count`, `minutes`, `course_counts`도 `CONTRACTS`와 같은 값으로 적습니다. meta.json에는 회차 묶음 번호 `round_set`도 1 이상 정수로 적습니다. 공개된 1·2회는 1, 3·4회는 2, 5회는 3입니다.

모의고사 1~4회는 응용 1~9차시를 범위로 하는 `all52-v1`을 사용합니다. 회차마다 개론 36문항과 응용 16문항이 나오고 연습 시간은 120분입니다. format별 문항 수는 choice 18, bug 6, order 3, blank 10, predict 11, code 4이고, level 1/2/3은 13/26/13개입니다. 코드 작성 4문항은 level 2와 level 3에 두 개씩 있습니다.

5회는 응용 1~10차시를 범위로 하는 `all54-v1`을 사용합니다. 개론 38문항·응용 16문항에 120분입니다. format별로 choice 19, bug 6, order 3, blank 10, predict 12, code 4이며 level 1/2/3은 14/27/13개입니다. 코드 작성의 수준별 수는 1~4회와 같습니다.

6회는 `all33-v1`의 33문항·60분입니다. CNN과 YOLO를 보강합니다. 7회는 `all42-v1`의 42문항·90분입니다. 기존 개념을 새 조건에 적용하고 결과를 검산하는 문제를 늘립니다. 두 회차 모두 응용 10차시까지 다룹니다.

제출 후 해설에서 관련 학습을 열려면 문항의 `learning_reference`에 과정·페이지·단원·단계 번호와 제목을 적습니다. 단계 안의 설명만 열려면 `section`에 그 설명의 제목을 적습니다. 본문에서 이 제목은 별도 텍스트 블록의 첫 줄에 `####` 제목으로 씁니다.

`PINNED_BLUEPRINTS`에 등록한 배분은 차시별 문항 수와 합계를 그대로 대조합니다. `all52-v1`이 처음 공개한 배분도 이 표에 있습니다. 이 표에 없는 기존 회차는 `exam_size`로 총 문항 수를 계산하고 `allocate`로 차시별 문항을 나눕니다. `allocate`는 응용에 약 30%를 배정하고, 각 차시에 한 문항씩 배정한 뒤 남은 문항을 차시 점수에 따라 나눕니다. `LESSON_SCORES`는 카드 수, 단원 수, 시험 근거, 현직자 근거, 뒤 차시 의존으로 차시 점수를 정합니다.

`python3 tools/verify_ai.py m11`은 혼합 회차와 같은 근거, 중복, 연습 겹침 검사에 더해 아래 항목을 봅니다.

- `all44-v1`의 format별 문항 수는 choice 16, bug 5, order 3, blank 8, predict 8, code 4입니다. choice·bug·order는 kind=choice, blank·predict는 kind=blank, code는 kind=code로 적으므로 객관식 24, 빈칸 16, 코드 작성 4문항이 됩니다.
- `all44-v1`의 level 1/2/3은 11/22/11개입니다. 이 가운데 코드 작성 4문항은 level 2 2개, level 3 2개입니다.
- `CONTRACTS`의 문항 수는 `PINNED_BLUEPRINTS`에 등록한 차시별 문항 수를 더한 값과 같아야 합니다. 기존 자동 배분은 `exam_size`의 값과 대조합니다.
- 문항 ID는 회차 ID 뒤에 두 자리 번호를 붙여 씁니다. meta.json에 `retired_items`가 없는 회차는 -01부터 문항 수까지 한 번씩 씁니다. m12이면 m12-01부터 m12-44까지입니다. 처음 낸 회차에는 `retired_items`를 적지 않습니다. 검사는 처음 낸 회차인지 알지 못해서, 번호를 잘못 써 생긴 빈 번호를 `retired_items`에 적어도 통과시킵니다. 이때는 `retired_items`를 적지 말고 번호를 고칩니다.
- 배분 버전이 바뀌어 문항을 넣거나 빼도 남는 문항의 ID는 바꾸지 않습니다. 뺀 문항의 ID는 meta.json의 `retired_items` 목록에 적고 다시 쓰지 않습니다. 새 문항은 그 회차에서 가장 큰 번호 다음 번호부터 씁니다. 예를 들어 m11에서 m11-10을 빼고 두 문항을 더하면 `retired_items`에 m11-10을 적고 새 문항에 m11-45와 m11-46을 줍니다. 쓰는 ID와 `retired_items`를 합쳐 -01부터 가장 큰 번호까지 빈 번호가 있으면 `retired_items` 없이 사라진 ID로 보고 실패합니다. `retired_items`에 있는 ID를 문항에 다시 써도 실패합니다. 이 규칙은 32문항 회차(m4·m5·m6)에도 똑같이 걸립니다.
- 그 배분 버전에 속한 공개 개론·응용 차시가 blueprint에 하나라도 빠지면 실패합니다. 학습 노트 meta.json, 문항 meta.json, 봉인이나 작업본이 모두 있는 차시를 공개된 차시로 봅니다.
- round_set이 같은 모든 차시 회차끼리 facts에 같은 사실 ID를 쓰면 실패합니다. round_set이 다르면 경고만 냅니다. 경고가 난 사실은 다른 단계나 조건으로 냈는지 회차 기록에 적습니다. related_sources의 보조 사실은 세지 않습니다. meta.json이 draft=true인 모든 차시 회차도 대조하므로, 두 회차를 모두 초안으로 쓰는 동안에도 같은 사실을 쓰면 실패합니다. 회차 사이의 같은 지문·보기 검사도 초안인 모든 차시 회차와 대조합니다. 32문항 회차를 검사할 때도 초안인 모든 차시 회차와 대조합니다.

빠진 차시 검사는 모든 차시를 다루는 배분 버전에 적용합니다. 새 차시를 공개하면 그 차시의 값을 `LESSON_SCORES`에 넣고 앞 차시의 의존 값을 고칩니다. 차시나 배점이 바뀔 때는 기존 회차의 차시별 문항 수를 `PINNED_BLUEPRINTS`에 보존하고 `app_through`에 그 회차의 응용 범위를 적습니다. 새 범위는 새 회차로 등록하고 기존 회차의 index·meta·봉인 파일은 유지합니다. 개론 18차시 이상을 공개할 때는 1~17차시만 받는 `_MockSources.entries`, 보조 차시를 i01~i17로 거르는 `_mixed_mock_evidence`, `range`를 [1, 17]로 기대하는 `_mixed_shared_problems`도 고칩니다.

### 코드 작성 문항 검사

공개한 모든 차시 회차 1~5회에는 코드 작성 문항(kind=code)을 4문항씩 넣었습니다. 새 회차의 코드 작성 문항 수와 난이도는 `ALL_LESSON_RULES`에 적습니다. 기존 32문항 회차(m4·m5·m6)의 배분은 빈칸과 객관식만 받습니다. `tools/verify_ai.py`는 코드 작성 문항을 알고리즘 여행 실행기로 직접 돌려 아래 항목을 확인합니다.

- 예시는 2~3개, 숨은 테스트는 6~10개이고 두 목록에 같은 입력을 넣지 않습니다.
- 기대값은 정수·실수·문자열·불리언이나 그 리스트로 적습니다.
- 모범 답안은 시작 코드의 `____` 줄마다 한 줄씩 적고 빈 줄을 두지 않습니다. 채운 코드는 Python 3.10 문법에 맞아야 합니다.
- 모범 답안은 예시와 숨은 테스트를 모두 통과하고, 시간 제한을 4분의 1로 줄여 다시 돌려도 같은 결과를 내야 합니다.
- 시작 코드를 그대로 돌리면 숨은 테스트를 모두 틀려야 합니다.
- 예시의 입력과 기대값을 표로 외운 답과 첫 예시의 기대값만 돌려주는 답은 숨은 테스트를 하나 이상 틀려야 합니다.
- `boundaries`에는 숨은 테스트로 확인하는 경계를 글 목록으로 적습니다. 목록 한 칸에 경계 하나를 적습니다. 목록이 비었거나, 빈 글이나 글이 아닌 값이 있으면 실패합니다.
- stem, starter, conditions, sourcefacts는 화면과 수집 기록에 나가고, explain은 제출 뒤에 보이고, boundaries는 출제 기록에 남습니다. 이 가운데 어느 칸에든 숨은 테스트의 입력 전체나 기대값을 적으면 실패합니다. boundaries에는 값 대신 "나누어떨어지지 않는 간격"처럼 경계의 뜻을 적습니다.

인자가 여럿인 입력에서 인자 하나만 적은 값, 세 글자보다 짧은 값, 예시에도 있는 값, 다른 꼴로 풀어 쓴 값은 이 검사가 잡지 못하므로 재풀이 검토자가 확인합니다.

검사 메시지에는 문항 id와 숨은 테스트 번호만 나옵니다. 걸린 테스트의 입력과 기대값은 출제자 컴퓨터에서 `--show-hidden-tests`를 붙여 확인하고, 공개 CI에서는 이 옵션을 쓰지 않습니다. 이 옵션은 모범 답안이 돌려준 값을 보이지 않으므로 모범 답안을 그 입력으로 직접 돌려 봅니다.

재풀이 답안의 코드 작성 칸에는 채울 줄의 글을 목록으로 적습니다. 채울 줄이 하나인 m11-07이면 `{"m11-07": ["size = (w - f + 2 * p) // s + 1"]}`처럼 적습니다. `--answers`와 `--first-pass`는 학습자 제출과 같은 채점 함수로 숨은 테스트를 모두 통과했는지 봅니다.

## 강의 자료가 바뀌면 입력과 출력 나눠 확인하기

원본 파일의 SHA-256과 노트북 입력 셀을 각각 비교합니다. 파일 해시만 바뀌었고 입력 셀이 같으면 저장 출력·메타데이터 변경과 내용 변경을 구분합니다. 셀 위치는 실제 cells 배열의 0부터 센 번호를 기록합니다. 출처는 갱신한 파일 이름·해시와 실제로 내용을 지지하는 쪽·셀을 함께 확인합니다.

강의의 설정이나 수치가 잘못되었으면 확인한 조건으로 본문·그림·문항·해설을 고칩니다. 폴더 이름만으로 실습 내용을 추가하거나 저장 출력만 보고 모델 실행을 검증했다고 적지 않습니다. 새 자료에서도 유효한 기존 개념은 유지하고, 더 이상 지원하지 않는 문항을 뺄 때는 문항 ID와 과거 풀이 기록을 보존합니다.

차시 공개나 예제 개정에는 [코딩 실습 확인](#차시를-갱신할-때-코딩-실습-확인하기)도 포함합니다.

출처 위치만 정정해도 진행 중 연습의 전체 해시가 달라질 수 있습니다. 빈칸·객관식 문항의 출처를 고칠 때는 해당 묶음의 `meta.json`에 `resume_source_refs`를 등록할 수 있습니다. 문항 ID별 `previous`에는 직전 공개본의 전체 `ref` 목록을, `current`에는 정정한 목록을 적습니다. 이전 출처를 대입한 문항·용어·뼈대 전체가 저장된 해시와 같을 때만 이어풉니다. 지문·정답·해설까지 바뀐 문항의 복원을 허용하는 용도로 쓰지 않습니다. 일부 문항만 든 묶음과 실제 내용도 바뀐 반례를 함께 확인합니다. 수집용 문항 버전과 복습 계산용 버전은 별도로 대조합니다.

## 과정과 보충 설명 구분하기

개론의 `i01`·`l01`·`1a`는 유지합니다. 응용은 `a01`·`al01`·`a1a`로 구분하고 목록에 `course: app`을 적습니다. 같은 차시 번호가 있어도 문항·학습 자리·복습이 다른 과정에 섞이지 않는지 확인합니다. 초판의 개요 확인과 그 차시 전체 내용·문항·그림 검토를 구분하고 확인한 단원부터 공개합니다.

계산이나 예시 뒤에는 조건과 결과를 짧게 연결할 수 있습니다. 수학적으로 동치일 때만 등호나 같은 뜻이라고 적습니다. 역전파의 역방향 계산 규칙과 미분 가능성, 기울기 계산과 파라미터 갱신처럼 서로 다른 조건은 구분합니다. 새 요약도 기존 사실 목록·문항·해설과 대조합니다.

세 단계 블록의 심화 자료는 [심화 설명] 팝업에서도 봅니다. 추가 설명에는 같은 예시·그림과 검증한 출처를 사용합니다. 핵심 내용을 팝업에만 두지 않습니다. 팝업을 닫아도 원래 단계·스크롤·답안이 변하지 않는지 확인합니다. GIF는 보이는 위치에 도달하면 반복 재생하고 화면 밖으로 나가면 멈춥니다. 정지·다시 재생·장별 확인은 계속 지원합니다.
