# AI 개론·응용 출제 안내

AI 개론·응용에 학습 노트, 연습 문항, 생성기, 상황별 코드 뼈대, 그림을 넣는 사람이 보는 문서입니다. 파일 규격, 봉인·검증·서명 명령, 출제·재풀이·대조·검토를 나눠 맡는 교차 검증 순서, 쓰는 사람과 검토하는 사람이 같이 쓰는 체크 목록을 적었습니다. 학습 노트의 기본 꼴과 서명은 웹 면접 준비의 학습 페이지와 같아서 [WEB_AUTHORING.md](WEB_AUTHORING.md) 의 학습 페이지 절도 함께 읽습니다.

학습자가 적은 코드는 실행하지 않습니다. 앱에서 빈칸 채우기·고르기·순서 맞추기·고칠 줄 찾기로 코드 지식을 확인합니다. 강의 자료가 맞다고 가정하지 않습니다. 문항은 사실 확인을 마친 사실(`facts.json`)로만 만듭니다. 자료 오류의 대조는 사실 목록과 검토 기록에 보존하고, 학습 본문과 해설에는 확인한 원리와 조건을 바로 설명합니다. 외부 교재의 파일 이름이나 셀 번호를 몰라도 이해할 수 있게 씁니다.

## 1. 폴더와 파일

```
ai/
  index.json                차시(lessons), 상황별 코드(patterns), 모의고사(mocks), 시험 날짜(exam), 학습 노트 목록(pages, order)
  terms.json                낱말 사전. term·also·page 는 웹과 같고 accept(빈칸에서 더 받는 말)·intro(먼저 소개한 노트)를 더함
  retired.json              지운 카드·문장 id 목록. 한 번 쓴 id 는 다른 문항에 다시 쓰지 않습니다
  learn/l05/
    meta.json               공개. 웹 키(title, defines, needs, sections, outputs, sources) + lesson, credits, units
    page.md                 공개. 봉인하지 않습니다
    assets/l05-3.gif …      그림. 이름은 노트 그림 l05-3, 단원 그림 5c-1
    review.json             학습 노트 서명(verify_web.py 가 씀)
  items/i05/
    meta.json               공개. 단원별 카드 수
    gens.py, oracle.py      공개. 생성기와 그 정답(생성기를 보지 않고 독립 구현한 정답 함수)
    sealed.json             work/ 를 묶은 봉인 파일. 이것만 커밋합니다
    work/                   평문 작업본. 커밋하지 않습니다
      items.json            빈칸·고르기 문항
      statements.json       참거짓을 정한 문장 묶음
      facts.json            확인된 사실과 강의 자료 오류
      review.json           문항 묶음 서명(verify_ai.py --sign 이 씀)
  items/common/gens.py      여러 차시에서 같은 생성기를 쓸 때 추가하는 선택 파일(@base)
  items/pc/                 상황별 코드. meta.json, gens.py, oracle.py, sealed.json(facts.json과 review.json)
  patterns/S1.json          상황별 코드 뼈대. 공개라 봉인하지 않고 카드는 엔진이 여기서 만듭니다
  learn/l18/                상황별 코드 학습 노트(단원 키 18a~18h)
  mocks/m1/                 모의고사
tools/ai_art/
  lNN.py                    그 노트의 그림 스크립트(출제할 때 사용)
  manifest.json             스크립트로 그린 그림의 sha256
```

차시는 학습 노트 `meta.json`, 문항 `meta.json`, 봉인(또는 평문 작업본)이 모두 있으면 화면에 나옵니다. 학습 노트 `meta.json` 의 `units` 에 적은 단원만 보이므로 다 된 단원부터 낼 수 있습니다.

## 2. 학습 노트(page.md)

`#` 은 노트 제목, `##` 는 단원, `###` 는 단계입니다. 단원 제목은 `meta.json` 의 `sections` 값과 같아야 하고, 단원 키는 `<차시 번호><a~i>`(5c), 응용은 `a1a`처럼 앞에 a를 붙이고, 상황별 코드는 `18a`~`18h`입니다. `sections` 에 없는 `##`(그림 출처 등)는 단원으로 세지 않습니다. `##` 바로 밑에는 글을 두지 않고 첫 `###` 안에 씁니다.

단계 제목 바로 밑 줄에 그 단계가 설명하는 사실 id 를 적습니다. 이 줄은 화면에 넘기기 전에 지워지고 verify_ai 가 카드의 `step` 과 맞춰 봅니다.

```
### 시그모이드를 여러 번 지나면 기울기가 줄어듭니다
<!-- facts: F05-12 F05-13 -->
```

단계의 종류는 제목 앞머리로 정합니다. 「심화」로 시작하면 대학원 강의안 단계, 「보충 설명」은 시험 범위 안의 보충, 「더 알아보기」는 시험 범위 밖, 「외울 것」은 단원 마지막 단계입니다. 그 밖은 강의 단계입니다. 단원 단계는 먼저 풀어 보기와 외울 것을 넣어 4~7개이고, 마지막은 꼭 「외울 것」입니다.

울타리 블록은 JSON 한 덩이로 씁니다.

| 블록 | 필드 | 화면 |
|---|---|---|
| `ai-guess` | `id`, `q`, `options`(2~4), `answer`(0부터), `reveal_step`(답을 보일 뒤 단계 번호), `cards` | 먼저 풀어 보기. 채점하지 않음 |
| `ai-reveal` | `guess`(먼저 풀어 보기 id) | 처음 고른 답과 정답 한 줄 |
| `ai-recall` | `id`, `q`(`____` 하나), `answer`, `mode`, 선택 `why` | 떠올리기. 바로 채점, 상자는 움직이지 않음 |
| `ai-why` | `q`, `a` | 왜일까요. 답은 접어 둠 |
| `ai-memo` | `[{"q", "a", "cards"}]` | 외울 것. 질문을 누르면 답이 펴짐 |
| `ai-trend` | `title`, `text` | 2026 흐름. 단계 수에 넣지 않음 |
| `ai-diff` | `skel`, `left`, `right`(코드 예제 이름) | 뼈대 두 코드 예제 나란히 보기. 다른 줄에 바탕색을 칠함 |
| `ai-rotate` | `id`, `skel`, `variant`, 선택 `slots`(자리 id 목록) | 돌려 가며 빈칸. 자리를 하나씩 가리고 틀린 자리는 세 자리 뒤에 다시 냄. 상자는 움직이지 않음 |
| `ai-levels` | `id`, `concept`, `levels`(수준 7·15·20 의 객체 셋) | 세 단계로 다시 보기. 단계 끝에 접혀 있고 펴면 수준마다 그림, 글, 확인 물음이 나옴. 상자는 움직이지 않음 |
| `ai-formula` | `id`, `title`, `input`, `terms`, `operation`, `output`, `figure`, `q`, `a` | 수식 자세히 보기. 그림과 계산을 별도 창에서 읽고 확인 물음의 답을 펼칩니다. 기록하지 않습니다. |

`ai-guess`마다 같은 단원의 `ai-reveal`을 연결합니다. `reveal_step`은 그 해설이 실제로 나타나는 단계 번호와 맞춥니다.

`ai-rotate`·`ai-levels` 의 `id` 는 먼저 풀어 보기·떠올리기 id 와 같은 단원 안에서 겹치지 않게 씁니다. 뼈대 코드 예제를 코드 울타리로 보일 때는 울타리 바로 위 줄에 `<!-- skel: S1 표준형 -->` 를 적습니다. verify_ai 가 줄 끝 `#` 주석과 빈 줄을 뗀 울타리 줄이 그 코드 예제 `lines` 와 같은지 봅니다. 이 줄도 화면에 넘기기 전에 지워집니다.

외울 것의 `cards` 는 그 단원의 핵심 카드를 모두 덮어야 합니다. 자료의 오류는 확인한 원리와 성립 조건을 본문에 바로 반영합니다. 학습자에게 별도 정정 상자를 보이지 않습니다. 비교한 원문과 위치는 내부 검토 기록에 보존합니다. 필요한 배경 설명에는 `> **[보충 설명]** …`을 쓸 수 있습니다.

짧은 핵심어는 `<mark>기울기</mark>`처럼 형광펜과 볼드로 표시하고, 긴 핵심 원리는 `<u>역전파는 기울기를 계산하며 매개변수를 갱신하지 않습니다.</u>`처럼 밑줄로 표시합니다. 반복해서 쓰는 강의 개념과 공식 실무 예제의 사용을 근거로 고릅니다. 문단 전체를 강조하지 않으며 코드 울타리 안에는 강조 태그를 넣지 않습니다.

`terms.json` 의 낱말은 정의한 노트를 `page` 로 둡니다. 앞 차시가 그 낱말을 먼저 쓰면 그 차시를 `intro` 로 두고, 그 차시 `meta.json` 의 `defines` 에 넣고, 처음 쓰는 문장 앞에 "…을 오차라고 부릅니다" 꼴 정의 한 문장을 둡니다. 1차시가 어림값의 오차를 먼저 쓰고 4차시가 예측의 오차를 정의하는 경우처럼 쓰임이 조금 달라도 이렇게 소개합니다. `also` 에 적은 꼴은 한 낱말에만 두고, 다른 낱말에서도 받을 꼴은 `accept` 에 둡니다. 4차시의 오차와 손실처럼 서로 다른 낱말로 가르치는 두 말은 서로의 `accept` 에 넣지 않습니다.

그림 블록은 웹과 같은 꼴이고 GIF 의 `프레임:` 줄 수는 GIF 장 수와 같아야 합니다. 프레임 줄은 그림 아래 장 설명으로 보이는 글이라 말투 검사를 받습니다.

````
```figure
파일: assets/5c-1.gif
캡션: 그림 4. 층을 지날 때마다 곱해지는 미분값
프레임:
1. 가로는 층 번호, 세로는 곱한 값입니다. (2000ms)
2. 세 층을 지나면 0.25 를 세 번 곱합니다. (2000ms)
```
````

### 수식 자세히 보기(ai-formula)

수식 상세 설명은 `ai-formula`로 구분합니다. `input`에는 입력 모양과 값을, `terms`에는 각 항의 뜻을, `operation`에는 한 연산을, `output`에는 출력 모양과 적용 조건을 적습니다. 이 필드와 `id`·`title`·`q`·`a`는 비어 있지 않은 글이며 코드 울타리를 넣지 않습니다. 모르는 필드는 오류로 처리합니다. 핵심 조건은 단계 본문에도 남깁니다.

`figure`는 `file`, `caption`, `content`, `frames` 객체입니다. `file`은 `assets/` 아래 PNG 또는 GIF입니다. PNG의 `frames`는 빈 목록이며 GIF는 `{"text": "장 설명", "ms": 2200}` 형태의 목록을 씁니다. 기존 그림의 크기·이름·시간·장 수·manifest 검사를 따릅니다. 수식 본문과 그림은 학습 페이지의 기존 서명 대상에 포함됩니다.

수식 창은 그림을 크게 보여 준 뒤 입력·항·계산·출력과 확인 물음을 차례로 설명합니다. `q`의 답은 `a`에 쓰며 답 보기 전의 글과 그림에는 같은 답을 미리 쓰지 않습니다. 답을 펼치거나 창을 닫아도 채점·진도·동의·수집 기록을 쓰지 않습니다. 닫기·Esc 뒤 원래 단계·스크롤·답안·선택 영역을 유지하고 열었던 단추로 초점을 돌립니다. GIF는 기존의 보일 때 한 번 재생·정지·수동 넘김·움직임 줄이기를 따릅니다.

### 세 단계로 다시 보기(ai-levels)

어려운 개념을 처음 숫자로 다루는 단계의 맨 끝(떠올리기·왜일까요 뒤)에 블록 하나를 둡니다. 차시마다 3~5개이고 먼저 풀어 보기·외울 것·2026 흐름 단계에는 두지 않습니다. `concept` 는 20자 이하의 개념 이름이고 접힌 줄 제목 뒤에 붙습니다. terms.json 낱말이면 이름을 그대로 쓰고, 그 낱말의 `intro` 나 `page` 노트에 둡니다.

````
```ai-levels
{"id": "v1", "concept": "기울기",
 "levels": [
  {"level": 7, "text": "…", "figure": {"file": "assets/4b-31.png", "caption": "…", "content": "…"},
   "q": "… ____ 입니다.", "answer": ["2"], "mode": "number", "why": "…"},
  {"level": 15, "text": "…", "figure": {…}, "q": "…", "answer": ["…"], "mode": "number", "why": "…"},
  {"level": 20, "text": "…", "code": "…\n…", "mistake": "…",
   "figure": {…}, "q": "…", "answer": ["…"], "mode": "number", "why": "…"}
 ]}
```
````

`levels` 는 7·15·20 순서의 객체 셋입니다. `q`·`answer`·`mode`·`places`·`unit`·`why` 는 떠올리기와 같고, `code`(2~8줄)·`mistake`(자주 하는 착각 하나와 바른 문장)는 심화에만 씁니다. `where`는 어느 수준에도 쓰지 않습니다. 표에 없는 키, 모르는 `mode`, 초급·중급의 `code`·`mistake`, 글 안의 ``` 와 ~~~ 는 은행이 읽지 못하고 화면에 깨진 블록으로 보입니다. 코드는 `code` 에만 둡니다.

| 수준 | 쓰는 것 | 쓰지 않는 것 |
|---|---|---|
| 초급 | 단계 숫자 가운데 작은 수 하나둘, 상자와 화살표 그림, 짧은 문장 | terms.json 낱말(`known` 은 됨), 식 기호(= × ÷ + / ^ √ ∂ Σ ² * < >, 숫자 사이의 − 와 -), 인라인 코드, 낱말을 대신할 새 이름. `answer` 에도 쓰지 않음 |
| 중급 | 사칙연산, 그래프나 표, 식 한 줄과 그 식에 단계 숫자를 한 단계씩 넣은 계산. 2차원 값은 괄호 없는 숫자 칸 표 | 편미분 기호, `[[`, `@`, 라이브러리 이름(torch, numpy, np, nn), 인라인 코드 |
| 심화 | 정의 한 문장, 식, 코드 2~8줄, 자주 하는 착각 하나, 단계 그림에 없는 코드 결과나 모양을 보이는 그림 | 앞 수준 설명 되풀이, 단계 그림이나 표를 다시 그린 그림 |

- 비유를 쓰지 않습니다. 초급도 실제 숫자와 그림으로 쓰고, 낱말을 피하려고 "틀린 정도" 같은 이름을 짓지 않습니다. 숫자 앞에 붙은 −(−4)는 됩니다.
- 수준마다 그 단계의 숫자 예를 이어 쓰고 뒤 수준은 앞 수준의 숫자를 이어받습니다. 블록 글은 그 자리까지 정의된 낱말만 씁니다. 뒤 단계나 뒤 차시의 낱말은 미리 설명하지 않습니다.
- 블록에는 새 사실을 더하지 않습니다. 단계 facts 줄의 사실, 그 단계 숫자로 다시 계산한 값, 공식 문서·원논문으로 확인해 meta.json `sources` 에 적은 사실만 씁니다. 본문에 빠진 내용이나 뒤 단계 내용은 블록에 넣지 않고 본문에 씁니다. 접힌 블록을 펴지 않는 사람에게는 보이지 않기 때문입니다.
- 확인 물음은 그 수준의 글과 그림만 보고 풀리고 답은 숫자나 짧은 말로 정해집니다. 초급·중급은 되도록 `number` 로 내고, `word` 면 받는 답을 둘 이상 둡니다. 그 단계의 떠올리기·왜일까요와 같은 물음이나 같은 답을 쓰지 않습니다. 세 수준이 한 화면에 같이 펴지므로 낮은 수준 물음의 답을 높은 수준의 글, 캡션, 코드에 그대로 쓰지 않습니다.
- `answer` 는 모두 자기 `mode` 로 채점해 맞음이 되는 꼴로 적습니다. `number` 칸의 답을 "약 2.4" 로 적으면 화면에서 2.4 도 약 2.4 도 틀림이 됩니다. 0.10536 처럼 끝나지 않는 소수는 `places` 를 두고 물음에 "소수 셋째 자리까지"처럼 몇 자리로 쓸지 적습니다.
- 블록 글도 본문처럼 영어 낱말이나 코드 뒤의 조사를 "W가", "`x[0]`은" 처럼 붙여 씁니다. web_lint 가 울타리 안을 보지 않아서 verify_ai 가 text, caption, q, why, mistake를 봅니다.
- 확인 물음 결과는 떠올리기처럼 `record.json` 에 `level` 과 함께 남고 복습 날짜와 외울 것에 들어가지 않습니다.
- 단원 첫 단계의 읽는 시간과 meta.json `minutes` 는 접힌 블록을 넣지 않고 셉니다.

## 3. 문항

카드 id 는 `i05-b07`(빈칸), `i05-c03`(고르기), `i05-s21`(문장), `i05-g02`(생성기), 주제는 `i05-t03` 입니다. 모든 카드에 `unit`, `step`(`5c/3`), `facts`, `core`, `prio`(1~3), `level`(1~3), `tags`(1~3개), `ref` 를 둡니다. 선택 필드는 `family`(같은 계산·같은 사실 묶음), `confuse`(헷갈리는 짝 태그, `confuse:axis-0-1` 꼴), `deep`(대학원 근거), `errata`(걸린 강의 자료 오류 id), `alt`(같은 사실을 바꿔 쓴 문항)입니다. `step` 단계의 `<!-- facts -->` 줄과 카드 `facts` 가 하나 이상 겹쳐야 합니다. 단원마다 핵심 카드(`core`)는 3~4개입니다.

빈칸 문항은 지문의 `____` 수와 `blanks` 수가 같아야 합니다. 칸마다 `answer`(첫째가 화면 정답), `mode`, 선택 `hint`·`places`·`unit`·`term` 을 둡니다.

| mode | 쓰는 곳 | 받는 차이 |
|---|---|---|
| `word` | 개념 낱말 | 공백·붙임표·가운뎃점·밑줄, 끝 조사 하나나 "입니다", terms.json 의 also·accept |
| `code` | 코드 토큰 | 공백, 따옴표 모양, 빈칸 좌우 문맥을 같이 쓴 답, 정답에 없는 끝 `()` 와 앞 `.` |
| `number` | 계산 값 | 천 단위 쉼표, 빼기표(U+2212), 분수, `unit` 꼬리, `places` 반올림 |
| `shape` | 텐서 모양 | 대괄호·소괄호·x·×, `torch.Size(...)` |
| `values` | 배열 값 | `tensor(...)`·`array(...)` 껍데기, `dtype=`, 원소 반올림. True·False 는 1·0 과 다르게 봄 |
| `exact` | 서식 문자열 | 앞뒤 공백만 |

빈칸 바로 뒤에 받침에 따라 갈리는 조사를 두지 않고 "____ 입니다" 꼴로 씁니다. 칸이 둘 이상이면 칸끼리 정답이 겹치지 않게 지문에 칸마다 무엇인지 적습니다. `register_full_backward_hook` 처럼 긴 API 이름은 고르기로만 냅니다.

고르기 문항은 보기 4개이고 `options[].ok` 는 그 보기 글이 참인지입니다. `pick: "right"` 면 참인 보기가, `"wrong"` 이면 거짓인 보기가 답입니다. 모두 고르기(`multi: true`)는 답 2~3개이고 지문에 "모두" 를 씁니다. 답이 아닌 보기의 `why` 는 바른 문장 한 줄이고, 옳은 것 고르기의 거짓 보기에는 노리는 착각을 짧게 적은 `aim` 을 둡니다(화면에 나오지 않음). "모두 옳다" 처럼 다른 보기를 가리키는 보기는 쓰지 않습니다.

문장 묶음(`statements.json`)은 주제마다 참 4·거짓 4 이상입니다. 참 문장에는 상자 2 부터 나오는 빈칸판 `cloze`(`____` 하나와 `answer`)를 둡니다. 상자는 문장마다 따로 셉니다.

같은 보기 묶음 안의 문장을 다른 단원에서 배운다면 그 문장에 `unit`과 `step`을 함께 적습니다. 주제의 `unit`을 따르는 다른 문장은 그대로 둡니다. `facts`와 `ref`, `meta.json`의 단원별 `stmt` 수도 실제 학습 위치와 맞춥니다. 보기 묶음을 유지하더라도 읽기 기록과 복습 노트는 문장이 지정한 단원을 따릅니다.

생성기는 `gens.py` 에 씁니다. 표준 라이브러리만 쓰고 `basis` 는 `lecture-example` 이나 `lecture-formula` 입니다.

```python
from aiprep.gen import blank, gen, num

@gen("i05-g02", unit="5b", level=2, tags=["Linear 파라미터 수"], ref=["5차시 과제 5번"], facts=["F05-20"],
     basis="lecture-formula", step="5b/3")
def linear_params(r):
    """입력 a, 출력 c 인 Linear 층의 학습 파라미터 수."""
    a, c = r.pick([8, 16, 32]), r.int(1, 10)
    return blank(stem="`nn.Linear(%d, %d)` 의 학습 파라미터는 ____ 개입니다." % (a, c),
                 blanks=[{"answer": [str(a * c + c)], "mode": "number", "unit": "개"}],
                 explain="입력 × 출력 + 출력(편향)입니다. %d×%d+%d = %s 입니다." % (a, c, c, num(a * c + c)),
                 params={"a": a, "c": c})
```

`oracle.py` 에는 생성기 id 의 붙임표를 밑줄로 바꾼 함수(`def i05_g02(params)`)를 둡니다. 빈칸이면 칸마다 정답 글의 목록, 고르기면 답 보기의 글을 돌려줍니다. 300 시드에서 생성기와 oracle 이 같아야 하고 서로 다른 지문이 20개 이상이어야 합니다. 반올림 경계는 `fixed(x, k)` 가 `Retry` 로 피합니다.

생성 조건을 수집할 문항은 `gen_spec.meta`의 `template_revision`에 `"affine-translation-1"`처럼 템플릿 버전을 문자열로 적고, `display_params`에 지문에 공개한 입력 조건의 키만 나열합니다. 정답·풀이 결과·해설이나 답을 구분하는 내부 표시는 넣지 않습니다. 선언하지 않은 생성기의 `params`는 전송하지 않습니다. 원래 문항군은 `family`로 연결하고 숫자가 바뀔 때마다 새 개념으로 등록하지 않습니다.

새 기록에는 생성기·템플릿 ID, 버전, 실행에 사용한 소스 해시, 시드와 선언한 조건이 남습니다. 지문·보기 순서와 함께 만든 `instance_id`는 실제로 제시한 문제를 구분합니다. 같은 문제를 다시 푼 시도는 기존 기록 고유번호로 구분합니다. 이전에 저장한 답안이나 생성 조건이 없는 초안을 현재 생성기로 다시 해석해 채우지 않습니다. 공개 전에 수집·서버 저장·공통 입력에서 같은 조건이 유지되는지 확인합니다.

`ref`에 쓸 수 있는 표기의 예입니다. `5차시 슬 p21`, `5차시 노트북 02 [7]`, `5차시 과제 4번`, `10차시 강의노트 [3]`, `요약 1주차 p14`, `대학원 05 p15`, `공식 13차시`, `PyTorch 문서 CrossEntropyLoss`. 첫 근거는 해당 과정과 차시의 강의 자료입니다. 응용은 `응용 1차시 슬 p3`처럼 과정 이름을 붙입니다. 개론은 해당 주차 요약본도 첫 근거로 쓸 수 있습니다. 심화 자료는 강의 근거 뒤에 적습니다.

강의 자료 위치는 문항의 `ref`, facts.json의 `where`, meta.json의 `sources`에 남깁니다. 본문·블록·캡션·문항·보기·해설·생성기 견본에는 붙이지 않습니다. 앞에서 소개하지 않은 파일 별칭이나 셀 번호를 설명의 전제로 삼지 않습니다. 필요한 데이터·코드·계산 조건을 같은 화면에서 설명합니다. 더 볼 곳은 "5차시 여섯째 단원 3단계"처럼 학습 화면으로 안내합니다. 공식 문서 이름과 외부 그림의 출처 표시는 유지합니다.

## 4. 상황별 코드 뼈대

상황별 코드 단원(l18)의 카드는 `ai/patterns/S1.json` 같은 뼈대 파일에서 엔진이 만듭니다. `ai/items/pc/` 에는 단원별 카드 수를 적은 `meta.json`, 계산 문항의 `gens.py`와 독립 정답 함수 `oracle.py`를 둡니다. `facts.json`과 `review.json`은 `sealed.json`에 묶습니다. 사실 id 는 `F18-01`, 강의 자료 오류는 `X18-01` 이고, 차시 사실을 옮긴 것은 `from` 에 원래 id 를 적습니다.

뼈대는 강의의 입력 조건과 호출 순서를 확인한 뒤 이 트랙의 예제로 씁니다. 변수 이름만 바꾼 것을 새 설명이나 독립 계산으로 세지 않습니다. 겹침 검사에서 같은 줄이 나오면 원문과 문맥을 직접 대조합니다. `loss.backward()`, `optimizer.step()`, `model.eval()`, `with torch.no_grad():`만으로 이뤄진 세 줄은 공통 호출 순서로 봅니다. 이 경우에도 코드 120자 전체 일치와 직접 쓴 계산이 포함된 세 줄, 산문 검사는 유지합니다. 예제의 변수 이름이 원문과 다르면 학습 노트에서 한 문장으로 밝힙니다.

```json
{"format": 1, "id": "S1", "title": "미니배치 학습 한 에폭", "tags": ["학습 루프"], "prio": 3,
 "variants": {"표준형": {"situation": "미니배치마다 파라미터를 한 번 갱신하며 한 에폭을 학습합니다.",
                         "lines": ["model.train()", "for x, y in loader:", "    optimizer.zero_grad()", "..."]}},
 "slots": [{"id": "pc-k01", "variant": "표준형", "line": 0, "token": "train", "answer": ["train"], "mode": "code",
            "hint": "메서드 이름", "line_answer": ["model.train()"], "facts": ["F18-03"], "step": "18a/2", "core": true,
            "level": 1, "ref": ["5차시 노트북 03 [23]"], "explain": "..."}],
 "orders": [{"id": "pc-o01", "variant": "표준형", "lines": [5, 6, 7, 8, 9], "valid": [[0, 1, 2, 3, 4], [1, 0, 2, 3, 4]], "...": "..."}],
 "picks": [{"id": "pc-p01", "variant": "표준형", "line": 10, "stem": "...",
            "wrong": [{"text": "loss_sum += loss.item()", "aim": "배치 평균을 그대로 더함", "why": "..."}], "...": "..."}],
 "changes": [{"id": "pc-x01", "from": "1차시 fit", "to": "표준형", "stem": "...", "back": null, "...": "..."}]}
```

- 코드 예제마다 `situation` 과 `lines` 를 둡니다. `situation` 은 가이드 말투 한두 문장이고 그 코드 예제로 만든 카드 지문의 첫 줄이 됩니다. `lines` 는 들여쓰기 4칸이고 주석, 탭, `____` 를 넣지 않습니다. 줄 번호는 0부터 셉니다.
- slot(`pc-k01`)은 코드 예제 전체를 보이고 그 자리를 가린 코드 빈칸, order(`pc-o01`)는 줄 순서 고르기, pick(`pc-p01`)은 그 자리에 맞는 줄 고르기, change(`pc-x01`)는 from 코드 예제를 to 코드 예제로 바꿀 때 고칠 줄을 모두 고르는 문항입니다.
- 모든 카드에 `facts`, `step`, `level`, `ref`, `explain` 을 적습니다. `level` 과 `ref` 는 머리에서 물려받지 않고, `tags` 와 `prio` 는 적지 않으면 머리 값을 씁니다. 첫 ref 는 그 줄을 가르친 강의 슬라이드·노트북·과제·강의노트나 요약본입니다.
- slot 의 `token` 은 그 코드 예제 전체에서 한 번만 나와야 합니다. slot 문항은 코드 예제 전체를 보여서 같은 토큰이 다른 줄에 있으면 그 줄에서 답을 옮겨 쓸 수 있습니다. 두 번 나오는 토큰(`to`, `item`, `size`)은 pick 으로 묻습니다. `answer` 첫째는 `token` 과 같고, `line_answer` 첫째는 들여쓰기를 뺀 그 줄입니다. 같은 코드 예제 자리끼리 답이 겹치면 함께 가렸을 때 칸을 구별할 수 없어 실패입니다.
- order 의 `valid` 는 `lines` 안 위치의 순열 목록이고 코드 예제 순서(`[0, 1, 2, 3, 4]`)를 꼭 넣습니다. 오답 보기는 엔진이 valid 하나에서 이웃 두 줄을 바꾸거나 한 줄을 옮겨 만듭니다.
- pick 의 `wrong` 에는 오답 보기 세 개를 적고 보기마다 `text`, `aim`(노리는 착각), `why`(바른 설명)를 둡니다.
- change 의 정답은 두 코드 예제를 difflib 로 견줬을 때 다른 줄이라 두 코드 예제는 다른 줄이 둘 이상이어야 합니다. `back` 에 반대 방향 지문을 적으면 묶음 안에서 다시 낼 때 반대 방향으로 냅니다.
- 같은 줄이나 같은 사실을 묻는 카드는 `family` 를 같이 줍니다. 한 묶음에 family 하나만 나오고, 엔진은 같은 코드 예제 카드를 order·pick, change, slot 순서로 냅니다. change 의 같은 줄 보기에는 pick 의 답 줄이 나올 수 있고, slot 은 코드 예제 전체를 보여서 앞 카드의 답이 됩니다.

slot 카드가 나올 때 엔진은 같은 코드 예제의 열린 자리 상자 평균으로 함께 가릴 자리 수(0~3)를 정하고, 상자가 낮은 자리부터 함께 가립니다. 함께 가린 칸을 틀리면 그 자리 카드가 다음 학습일 복습에 나옵니다. 함께 가릴 자리 수가 3 이고 주 자리 상자가 4 이상이면 `line_answer` 가 있는 줄은 줄 전체를 가립니다. 그래서 `line_answer` 에는 같은 동작을 하는 다른 꼴을 모두 적습니다.

CNN의 특징 수처럼 숫자를 바꿔 계산하는 문항은 `items/pc/gens.py`에 `pc-g01` 같은 ID로 등록합니다. 차시 생성기와 같은 필드를 쓰고 `unit`과 `step`은 해당 상황별 단원에 연결합니다. `meta.json`의 단원별 `gen` 목록에도 넣습니다. 코드 자리의 답을 숫자로 바꾸어 만들지 않습니다. 독립 계산 함수는 `oracle.py`에 두고 공개 지문 재풀이와 300개 시드 대조를 거칩니다. 이 문항도 단원을 읽은 뒤 열리며 권장 차시의 문제집과 상황별 오답 노트에 함께 나옵니다.

## 5. 사실 확인(facts.json)

`facts` 의 사실마다 `id`, `from`(factcheck 의 위치), `text`(확인 기록을 바꿔 쓴 한 문장), `verdict`, `where`, `checked` 를 둡니다. `verdict` 가 틀림·확인 못 함인 사실은 문항에 쓰지 않습니다. 단순화·부분적으로 맞음이면 `ask_as` 의 표현으로만 묻습니다. `concept_only` 사실은 number·exact·values 빈칸으로 묻지 않습니다. `errata` 를 다루는 기존 카드의 내부 해설에는 검증용 "정정:" 표기를 보존하며 화면에서는 이 표기를 빼고 바른 설명을 바로 보여 줍니다. 해당 문항은 모의고사에 넣지 않습니다. `sources` 에는 강의 폴더 기준 경로와 sha256 을 적습니다. 경로는 실제 폴더 이름을 그대로 써서 `강의_11기_AI개론_2차시_…/강의_11기_AI개론_2차시_01_numpy.ipynb` 꼴이고, 요약본은 맨 위 파일 이름만 씁니다. `verify_ai.py --sources` 가 이 경로로 파일을 찾습니다.

## 6. 그림

학습 노트 그림은 `tools/ai_art/lNN.py` 를 출제자 파이썬(numpy·matplotlib·Pillow)으로 돌려 직접 그리고, matplotlib 는 Agg 로만 씁니다. 파일은 폭 1120px·높이 600px 이하, GIF 는 10장 이하·장마다 1,600~2,500ms·250KB 이하, PNG 는 150KB 이하입니다. 그림에 찍는 숫자는 스크립트 안에서 assert 로 확인합니다.

GIF의 장 수는 보여 줄 계산 단계로 정합니다. 3~5장으로 변화 과정과 마지막 요약을 모두 보여 줄 수 있으면 같은 장을 늘리지 않습니다. 첫 입력, 바뀌는 값, 마지막 결과가 이어지는지 모든 장을 열어 확인합니다. μ·γ·√와 음수 부호는 실제 화면 폭으로 줄여서도 구분되는 글꼴이나 mathtext로 그립니다.

저장할 때는 `tools/ai_art` 의 `quantize()` 로 64색 팔레트를 만듭니다. `FIXED` 에 적힌 색은 팔레트에 먼저 들어가서 옅은 회색과 옅은 보라처럼 가까운 두 색도 서로 합쳐지지 않습니다. 스크립트에 새 색을 쓰면 `FIXED` 에도 넣어야 tests/test_ai_tools.py 가 통과합니다.

```
python3 -m tools.ai_art l05 5a-2  # 5a-2 그림을 그리고 manifest에 기록합니다.
python3 tools/ai_art/l02.py l02-1  # l02 스크립트로 l02-1 그림을 그립니다.
python3 -m tools.ai_art l02 --record  # l02의 기존 그림을 manifest에 기록합니다.
```

직접 그린 그림은 manifest에 등록합니다. 가져온 그림은 `meta.credits`에 출처를 적습니다. 이번에 확인한 3Blue1Brown 공식 글의 MP4 두 개는 원작자 FAQ의 짧은 인용 허락으로 사용합니다. 허락 이름은 `3Blue1Brown FAQ clip permission (under 60 seconds)`이며 author는 `3Blue1Brown · Grant Sanderson`, permission_url은 `https://www.3blue1brown.com/about/`, url은 해당 공식 MP4 주소로 적습니다. source_seconds에는 사용한 원본 구간의 초수를 적으며 전체 해당 credits의 합도 60초 미만으로 둡니다. 직접 그린 그림의 manifest나 CC 라이선스로 등록하지 않습니다. 화면마다 저작자와 공식 글 링크를 읽을 수 있게 두고 원본 장면과 추가 한글 설명을 구별합니다. 캡션과 주변 본문에는 대표 장면 발췌와 느린 표시임을 밝힙니다. 표시 시간과 원본 사용 시간을 구별하고 시그모이드의 입력 0·출력 0.5와 출력 범위를 다른 활성화 함수로 넓히지 않습니다. 검증기는 확인한 원작자·허락 URL·공식 자산 URL·기재한 시간 조건을 검사하며 주변 설명과 실제 원본 사용 범위는 별도로 대조합니다. 가져온 GIF에도 기존 크기·장 수·색 수·용량 한도를 적용합니다.

세 수준 블록 그림은 수준마다 새 PNG 하나이고 이름은 `<단원>-<단계 번호><수준 번호>`(초급 1, 중급 2, 심화 3)입니다. 4b 셋째 단계 블록이면 `4b-31`, `4b-32`, `4b-33` 입니다. 화면 520×280(파일 1040×560)이고 글자는 matplotlib 22 이상, 30KB 안팎으로 둡니다. 캡션은 "그림 N." 으로 시작하지 않는 문장 하나이고 `content` 에 그림에 무엇이 있는지 적습니다. `tools/ai_art/levels.py` 의 `chain`(초급 상자와 화살표), `grid`(괄호 없는 숫자 칸 표), `graph`(좌표 그래프)가 크기와 글자를 맞춘 Figure 를 돌려주고, 글이 칸을 넘으면 ValueError 를 냅니다. 블록마다 함수 하나가 수준을 인자로 받아 그리게 그 차시 스크립트에 둡니다.

그리는 명령에는 그림 이름을 꼭 붙입니다. 이름 없이 돌리면 서명된 그림을 모두 다시 그려 해시가 바뀝니다.

Qt로 만든 학습 패턴·조건 그림은 PyQt6와 Pillow가 있는 작성 환경에서 필요한 파일만 다시 만듭니다. 모델 코드는 실행하지 않습니다.

```
python -m tools.ai_art.l01_training_qt --only 1b-6 1b-7 1b-8
python -m tools.ai_art.conditions_qt --only 7f-4
python -m tools.ai_art.lesson_bridges_qt --only 10 11
python -m tools.ai_art.level_repairs_qt --only 13b-32 13c-33
```

차시를 잇는 그림은 같은 예의 배치 수·클래스 수·입출력 모양을 이어 씁니다. 입력 크기나 모델을 바꾸면 그 지점의 이유와 새 조건을 적습니다. 정답이 모델 입력으로 보이는 화살표를 쓰지 않으며, 축의 수·축의 크기·원소 수·갱신하는 파라미터를 구분합니다. 실제 실행 결과와 설명용 도식도 구분합니다. 같은 그림을 초급·중급·심화에 반복하지 않고 수준마다 계산이나 결과를 보탭니다.

단계와 사실은 실제 설명 내용으로 연결합니다. 같은 사실을 여러 단계에서 사용하거나 한 단계가 여러 사실을 설명할 수 있습니다. 그림의 연속 처리·조건 분기·방법 비교를 화살표로 구분하고 장별 설명에는 바뀐 값과 조건을 적습니다. 회전은 길이와 직각, 좌표 그림은 축 방향과 축척을 계산으로 확인합니다. 축척이 없는 도식은 그 점을 표시합니다. 확인 물음의 답을 같은 수준 그림에 미리 적지 않으며 심화에서는 입력이나 실패 조건을 바꿔 원리를 적용하게 합니다.

## 7. 명령

```
python3 tools/ai_seal.py seal [i05 ...] [--keep]          work/ → sealed.json
python3 tools/ai_seal.py unseal i05                       sealed.json → work/
python3 tools/ai_seal.py check                            평문이 남았거나 봉인이 깨졌으면 실패
python3 tools/ai_seal.py brief i05 --out DIR              재풀이용 문제지(sheet.md, cloze.md)와 빈 답안(answers.json), 저장소 밖에만
python3 tools/ai_seal.py brief pc --out DIR               상황별 코드 문제지(sheet.md, whole.md, skel.md)와 빈 답안·노트 답안
python3 tools/ai_seal.py levels l04 [l05 ...] --out DIR   세 수준 블록 재풀이 공개본(블록마다 0_step.md 와 수준 파일 셋)과 빈 답안 levels_answers.json
python3 tools/verify_ai.py [i05 a01 ...]               문항 꼴, 빈칸 규칙, 고르기, 문장, 생성기 300 시드, 사실 확인, 노트 블록, 근거, 말투, 그림
python3 tools/verify_ai.py pc                             상황별 코드. 위 검사에 더해 뼈대(코드 예제, 자리, 순서 300 시드, 고르기, 고칠 줄 300 시드)
python3 tools/verify_ai.py i05 --answers DIR/answers.json 재풀이 답안을 채점
python3 tools/verify_ai.py --levels-answers DIR/levels_answers.json   세 수준 물음 재풀이 답안을 채점(문항 재풀이와 따로 셈)
python3 tools/verify_ai.py i05 --sign --writer "출제 1" --resolver "재풀이 2" --checker "대조 3" --reviewer "검토 4" \
        --first-pass DIR/answers.json --minutes 95 --finding "i05-b09 지문이 두 가지로 읽혀 고침"
python3 tools/verify_ai.py i05 --sign --writer "출제 1" --resolver "재풀이 2" --checker "대조 3" --reviewer "검토 4" \
        --keep-first-pass --finding "문장을 고치고 다시 대조함"
python3 tools/verify_ai.py --require-review               문항 묶음·모의고사와 등록된 공용 생성기의 서명 확인(CI)
python3 tools/verify_web.py --bank ai --total-mb 32 l05 --require-review   학습 노트 형식·그림과 기존 서명 확인
python3 tools/web_lint.py --bank ai --no-external         학습 노트 말투와 맥락(낱말을 쓰기 전에 소개)
python3 tools/ai_overlap.py --lecture "$AI_LECTURE_DIR" l05 i05   강의 글 겹침(출제자 컴퓨터에서만, PDF 는 pypdf)
python3 tools/ai_overlap.py --lecture "$AI_LECTURE_DIR" l18       l18·pc·S1 가운데 하나만 줘도 l18, 뼈대 전부, items/pc 를 모든 차시 강의와 견줌
python3 tools/verify_ai.py --sources "$AI_LECTURE_DIR"    강의 폴더 sha256 을 facts.json 과 견줌
python3 tools/verify_ai.py --overrides                    [내 답도 맞음] 답 모아 보기
python3 tools/verify_ai.py --leeches                      자주 틀리는 문항 모아 보기
```

상황별 코드는 학습 노트 l18 을 `verify_web.py --bank ai --total-mb 32 l18 --sign …` 로, 카드를 `verify_ai.py pc --sign …` 으로 따로 서명합니다. pc 서명은 `ai/patterns/*.json` 을 모두 덮어서 뼈대를 더하거나 고치면 pc 를 다시 재풀이·대조·검토하고 서명합니다.

서명은 글 파일(.py, .json, .md)을 줄 끝 LF 로 읽어 해시를 세므로 Windows 에서 받아도 맞습니다. 봉인은 내용을 바꾸지 않아 봉인 앞뒤로 서명이 맞습니다. 서명 뒤에 한 글자라도 고치면 `--require-review` 가 떨어지고, 바뀐 카드를 다시 재풀이·대조·검토한 뒤 다시 서명합니다.

첫 재풀이 뒤 문장만 고쳐 다시 서명할 때는 `--keep-first-pass`로 이전 기록을 보존합니다. 이 옵션은 맞힌 수, 틀린 문항, 시간과 나머지 기록을 함께 보존합니다. `--first-pass`나 `--minutes`와 함께 쓰지 않습니다. 이전 기록을 읽을 수 없으면 서명하지 않습니다.

## 8. 교차 검증 순서

| 꼬리표 | 하는 일 | 겸할 수 없는 것 |
|---|---|---|
| 출제 | facts.json, 학습 노트, 그림 스크립트, 문항, 문장, 생성기를 씀 | 나머지 셋 |
| 재풀이 | 공개본과 학습 노트만 보고 모든 카드를 풂. 생성기는 견본 10개를 손으로 풀고 oracle.py 를 씀 | 출제, 대조 |
| 대조 | 카드의 사실마다 factcheck 줄과 원문 위치를 열어 확인, 정정 상자, 그림 숫자, 겹침 검사, 강의 폴더 sha256 | 출제, 재풀이 |
| 검토 | 학습자에게 보이는 문장을 하나씩 읽고 체크 목록과 말투를 보고 서명 | 출제 |

1. 출제가 factcheck·차시 분석·요약본·코드 보충을 읽고 쓸 사실을 facts.json 에 옮깁니다. 새 사실은 대조가 판정한 뒤에만 넣습니다.
2. 출제가 work/ 평문으로 노트·문항·생성기·그림을 쓰고 verify_web, web_lint, verify_ai, ai_overlap 을 통과시킵니다.
3. `ai_seal.py brief` 로 만든 공개본을 재풀이에게 넘깁니다. 재풀이는 answers.json 과 oracle.py, 걸린 시간, 막힌 곳을 돌려줍니다. 문제지는 주제 문장을 섞은 순서로 꼬리표(`i05-t01-3`)만 붙여 보여 주고, 빈칸판은 참 문장에만 있어서 cloze.md 로 따로 뺍니다. 재풀이는 문장 판정을 모두 적은 뒤에 cloze.md 를 엽니다.
   상황별 코드 공개본은 l18을 읽기 전에 sheet.md부터 풉니다. 순서·줄·고칠 줄 고르기의 첫 답을 저장한 뒤 whole.md를 엽니다. whole.md에는 코드 예제마다 모든 자리를 함께 가린 코드가 있습니다. 이 답도 저장한 뒤 skel.md의 부분 빈칸 견본을 풉니다. 앞에서 기록한 답은 고치지 않습니다. 코드 한 줄을 받는 칸은 그 입력 범위를 표시합니다. first_pass는 sheet.md와 whole.md의 첫 답으로 셉니다. 노트 물음은 note-answers.json에 별도로 적고 검토자가 본문과 대조합니다.
   세 수준 블록은 `ai_seal.py levels` 공개본으로 따로 풉니다. 블록 폴더마다 0_step.md 를 읽고, 1_l7.md 의 물음 답을 levels_answers.json 에 적은 뒤에 2_l15.md 를 열고, 같은 방식으로 3_l20.md 까지 갑니다. page.md 는 블록 JSON 에 정답이 있어 열지 않습니다. 결과는 학습 노트 서명의 `--finding` 에 적습니다.
4. 대조가 `verify_ai.py --answers` 로 채점하고 틀린 카드마다 원인을 하나로 정합니다(정답 틀림, 두 가지로 읽힘, 받는 답 빠짐, 공정한 함정, oracle 불일치).
5. 검토가 아래 체크 목록을 보고, 새로 걸린 말투 문장은 `tools/check_style.py` 패턴에 더합니다.
6. 학습 노트와 문항 묶음에 서명하고 `ai_seal.py seal`, `ai_seal.py check` 로 봉인합니다.

전체 재풀이의 범위에는 고정 문항·참거짓·참 문장의 빈칸·노트 물음·세 단계 물음·모의고사를 각각 기록합니다. 생성기는 모든 등록 형식과 고정한 견본을 구분해 셉니다. 원래 공개본과 첫 답안을 보존하며, 허용 답을 보완한 뒤의 판정이나 수정 지문의 재풀이로 첫 결과를 덮어쓰지 않습니다. 서술형은 뜻을 대조하고, 정답 오류·조건 누락·허용 답 부족·계산 실수를 나누어 기록합니다.

꼬리표는 "출제 1" 꼴로 쓰고 만든 도구 이름은 저장소 어디에도 적지 않습니다.

## 모의고사를 검증합니다

`python3 tools/verify_ai.py m1 m2 m3`는 실제 회차의 30문항·60분 구성과 차시별 배분을 검사합니다. m1·m2·m3는 문항 수를 작게 적어도 이 검사를 받습니다. m90 같은 작은 검증용 회차에는 기존 문항 꼴·빈칸·보기·정정 제외·deep 수 검사를 적용합니다.

모의고사 폴더의 meta.json에는 format=1, id, count=30, minutes=60과 blueprint를 적습니다. blueprint는 `{"i01": 1, "i02": 2, ...}`처럼 차시별 문항 수를 담습니다. 0개인 차시는 생략할 수 있습니다. index.json의 count·minutes·range도 함께 대조합니다. m1의 range는 `[1, 12]`이고 m2·m3는 `[1, 17]`입니다. meta에 range를 쓰면 같은 값을 적습니다.

문항은 id, lesson, unit, step, facts, ref, level, topic, kind, stem, explain을 사용합니다. lesson에는 iNN을 적고 topic에는 실제 개념명을 적습니다. 같은 topic은 한 회에 두 문항까지이며 공백·구분 기호·대소문자를 정규화해 셉니다. 같은 개념에 다른 이름을 붙인 경우는 대조자가 확인합니다. facts는 해당 차시의 사실 ID를 사용합니다. unit·step은 해당 학습 페이지에 존재하고 그 단계의 사실 줄과 facts가 겹쳐야 합니다. 첫 ref에는 집계 차시의 강의·과제·요약 근거를 적습니다.

kind=blank는 blanks를 사용하며 한 문항의 칸은 1~2개입니다. kind=choice는 options·pick을 사용합니다. multi를 생략하면 false이고 값을 적으면 bool을 사용합니다. 보기는 네 개이며 multi=true의 정답은 정확히 두 개입니다. 구성은 빈칸 14개와 고르기 16개입니다. 고르기는 right 단일 답 7개, wrong 단일 답 6개, multi 3개입니다. level 1/2/3은 8/15/7개입니다.

빈칸 문항은 범주 하나에만 넣습니다. 숫자·shape·values 칸이나 숫자만 답하는 칸이 하나라도 있으면 계산·모양 문항으로 셉니다. 숫자 상수·숫자 배열·숫자끼리의 산술식을 code 모드로 적어도 코드 수에 넣지 않습니다. 남은 문항에 word·exact 칸이 섞이면 낱말 문항으로 셉니다. 모든 칸이 실제 코드 토큰을 묻는 code 모드일 때만 코드 문항으로 셉니다. True·False·None은 코드 토큰으로 다룹니다. 코드 문항은 6개 이상, 계산·모양은 5개 이상, 낱말은 3개 이하입니다.

실제 과제형 코드 빈칸에는 assignment=true를 적습니다. 생략하면 false이고 값을 적으면 bool을 사용합니다. 이 표시는 코드 문항이며 Python 코드 울타리 안에 빈칸이 있을 때만 과제형 수에 포함합니다. 한 회에 과제형 코드 빈칸을 5개 이상 넣습니다. 상황별 코드 문항에는 pattern에 존재하는 S1 같은 뼈대 ID를 적고 해당하지 않으면 생략합니다. pattern 문항은 3개 이상이며 상황별 코드의 학습 단계와 사실 ID도 사용할 수 있습니다. assignment·pattern 표시와 수는 실제 과제·뼈대와의 대응을 증명하지 않습니다. 대조자가 지문과 원자료를 읽어 확인합니다.

errata가 붙은 문항과 기존 연습에서 정정 근거로 함께 쓴 사실 ID를 제외합니다. 사실 자체에 errata 표시가 있어도 제외합니다. deep은 bool이며 한 회에 두 문항까지입니다. concept_only 사실은 숫자·모양 빈칸과 숫자 보기로 묻지 않습니다. 등록 답이나 보기 하나라도 숫자·숫자 배열·산술식 형태를 쓰면 값으로 묻는 문항으로 봅니다. 긴 문장 안의 계산 요구나 기록에 연결하지 않은 정정 주제는 대조자가 확인합니다.

같은 사실은 세 회 중 두 회까지만 사용합니다. 같은 회에서 그 사실을 여러 번 써도 회차 사용은 한 번으로 셉니다. 다른 ID로 같은 사실을 새로 등록해 제한을 피하지 않도록 원래 사실 ID를 사용합니다. 다른 회차의 파일이 있으면 m1만 선택해도 회차 간 중복과 사실 사용을 함께 검사합니다. ID나 화면 지문·보기가 같은 문항을 여러 회에 넣으면 실패합니다. 보기 순서와 답·해설·근거만 바꾼 문항도 같은 문항으로 봅니다.

연습 지문은 정적 지문·대체 지문·참거짓·cloze·생성기 견본과 상황별 코드 공개 견본을 비교합니다. 생성기 견본은 --seeds 수만큼 시드 0부터 만듭니다. NFKC·casefold로 정규화한 어절·식별자·숫자의 집합을 만들고 빈칸 표시는 뺍니다. 교집합 크기를 합집합 크기로 나눈 자카드 값이 0.6 이상이면 실패합니다. 이 검사는 가능한 생성기 출력 전체를 대조하지 않습니다.

학습자에게 보이는 문장의 말투와 코드 울타리의 짝도 검사합니다. 빈칸에는 첫 등록 답을 채워 Python 코드 구문을 분석합니다. 코드의 실행 결과와 정답 사실은 대조자가 확인합니다. 고르기에 의도적으로 넣은 오류 코드는 구문 분석을 강제하지 않습니다. 검사를 통과한 회차는 기존 --answers·--first-pass·--keep-first-pass·--require-review 경로로 채점·기록·서명을 확인합니다. 첫 재풀이 파일을 읽지 못하면 서명을 중단하고 이전 기록을 보존합니다.

## 혼합 회차 m4를 검증합니다

`python3 tools/verify_ai.py m4`는 32문항을 검사합니다. 개론 16문항과 응용 16문항을 사용하며 개론 1~17차시의 누적 내용과 공개한 응용 1~3차시를 다룹니다. 연습 기본값은 120분입니다. 약 2시간 연습을 참고한 값이며 공식 평가 시간은 아닙니다. 기존 timed 경로를 사용하고 시간 제한 없는 분기를 추가하지 않습니다.

index.json과 meta.json에 `scope=mixed`, `courses=["intro", "app"]`, `course_counts={"intro": 16, "app": 16}`, `blueprint`, `blueprint_revision`을 함께 적습니다. 문항에는 course·lesson·concept·family·level·format·sourcefacts·conditions·allowed_answers·explain·transferaxis를 보존합니다. allowed_answers는 빈칸의 허용 답을 담으며 고르기의 정답은 options의 ok로 기록합니다. level_reason에는 난도를 나눈 출제 근거를 적습니다. 이 분류를 실제 학습자의 난도나 능력 측정값으로 사용하지 않습니다.

실제 문항은 빈칸 16개·고르기 16개이며 level 1/2/3은 8/16/8개입니다. 주 차시 배분은 i01~i09와 i11~i17에 한 문항씩이며 a01/a02/a03에 5/6/5문항입니다. i10의 내용은 i09 문항의 related_sources에 연결합니다. sourcefacts는 주 차시 facts와 보조 차시 related_sources의 사실 목록을 순서대로 합칩니다. 각 사실이 해당 과정·차시의 사실 목록과 공개 학습 단계에 있는지 대조하며 정정 근거·미확인 사실은 제외합니다.

문서로 보충한 사실의 첫 ref는 해당 사실의 where에 기록한 문서나 HTTPS 주소도 받습니다. 실제 내용의 지지는 별도 출처 검토 기록에서 확인합니다. 연습과의 어휘 겹침 검사는 풀이 원리의 독립성을 증명하지 않습니다. m4는 기존 회차와 지문·보기 중복을 비교하며 m1~m3의 세 회 중 두 회 사실 사용 제한은 기존 회차에 적용합니다.

meta.json의 draft=true에서는 구조 검사를 실행할 수 있습니다. 두 과정의 시작 목록에서는 숨기며 `--sign`과 `--require-review`는 실패합니다. 최종 검토 뒤 draft를 해제하고 기존 첫 재풀이 기록을 연결해 서명합니다. 서명은 meta.json과 문항 파일을 함께 덮습니다. 초안 원본·출처 해시·첫 답안은 비공개 검토 경로에 보존합니다. 봉인 뒤에도 같은 `--require-review`로 확인합니다. 검토 전 작업 파일을 봉인하거나 공개 준비 완료로 기록하지 않습니다.

## 강의 자료가 바뀌면 입력과 출력을 나눠 확인합니다

원본 파일의 SHA-256과 노트북 입력 셀을 각각 비교합니다. 파일 해시만 바뀌었고 입력 셀이 같으면 저장 출력·메타데이터 변경과 내용 변경을 구분합니다. 셀 위치는 실제 cells 배열의 0부터 센 번호를 기록합니다. 출처는 갱신한 파일 이름·해시와 실제로 내용을 지지하는 쪽·셀을 함께 확인합니다.

강의의 설정이나 수치가 잘못되었으면 확인한 조건으로 본문·그림·문항·해설을 고칩니다. 폴더 이름만으로 실습 내용을 추가하거나 저장 출력만 보고 모델 실행을 검증했다고 적지 않습니다. 새 자료에서도 유효한 기존 개념은 유지하고, 더 이상 지원하지 않는 문항을 뺄 때는 문항 ID와 과거 풀이 기록을 보존합니다.

출처 위치만 정정해도 진행 중 연습의 전체 해시가 달라질 수 있습니다. 빈칸·고르기 문항의 출처를 고칠 때는 해당 묶음의 `meta.json`에 `resume_source_refs`를 등록할 수 있습니다. 문항 ID별 `previous`에는 직전 공개본의 전체 `ref` 목록을, `current`에는 정정한 목록을 적습니다. 이전 출처를 대입한 문항·용어·뼈대 전체가 저장된 해시와 같을 때만 이어풉니다. 지문·정답·해설까지 바뀐 문항의 복원을 허용하는 용도로 쓰지 않습니다. 일부 문항만 든 묶음과 실제 내용도 바뀐 반례를 함께 확인합니다. 수집용 문항 버전과 복습 계산용 버전은 별도로 대조합니다.
