# 화면 정렬을 점검했습니다

[화면 기준으로 돌아갑니다](UI_DESIGN.md)

2026년 11월 11일 기준입니다. `gui/`의 파이썬 파일 42개와 명시적 정렬 호출 76곳을 읽고, 주요 화면 20종과 공통 부품의 배치를 대조했습니다. 전체 차시의 모든 단계와 가능한 모든 기록 조합을 캡처한 검사는 아닙니다.

## 고친 부분

| 위치 | 변경 내용 |
| --- | --- |
| 체크 항목과 결과 표시 | 오른쪽 메모·소요 시간과 판정 라벨을 본문 첫 글줄에 맞췄습니다. 여러 줄 정답도 같은 기준을 따릅니다. |
| 숫자와 설명 | 남은 시간, 완료 수, 단계 수, 팀 현황의 작은 설명을 숫자와 같은 기준선에 놓았습니다. |
| 그림 조작과 하단 도구 | 높이가 다른 글과 단추를 각 줄의 세로 가운데에 놓았습니다. |
| 입력 칸 | 초점·정답·오답 상태에서 테두리가 바뀌어도 바깥 높이를 유지합니다. |
| 안내 창과 메뉴 | 여러 줄 제목과 프로그램 이름에 공통 행간을 적용했습니다. |
| 코드 풀이 | 좁은 칸에서는 초기화 단추를 안내 아래에 놓고 ‘시작 코드 복원’으로 표시했습니다. 좁은 칸에서도 단추 글자를 유지합니다. 숨겨진 입력부가 다른 화면의 최소 높이를 늘리지 않게 했습니다. |
| 제출 결과 | 알림용 여백 때문에 점수 글자가 눌리던 문제를 고쳤습니다. 결과 내용을 스크롤로 보고 하단 조작부는 유지합니다. |
| 웹 미션 정보 | 이름 열의 폭을 유지하면서 각 값을 첫 글줄에 맞췄습니다. 현재 메뉴에서 진입을 숨긴 화면도 포함했습니다. |

## 확인 범위

| 화면 묶음 | 확인한 화면 |
| --- | --- |
| 시작과 과목 선택 | 시작 안내, 전체 홈, 파이썬 홈, 팀 현황, 오답 목록 |
| 파이썬 | 회차 목록, 객관식·출력·단답·코드 입력, 제출 결과 |
| 알고리즘 여행 | 지도, 문제와 코드 입력, 실행 예시 창 |
| AI 개론·응용 | 과목 홈, 차시, 학습, 노트, 복습, 연습, 모의고사 |
| 웹 면접 준비 | 과목 홈, 학습, 드릴, 미션 정보, 성공·실패 검사 결과 |
| 별도 창 | 사용자 식별자, 일반 안내, 오류 안내, 학습 데이터, 사용법, 실행 환경 준비 |

로컬 화면은 Qt offscreen에서 760×480·가장 큰 글자와 1280×800·보통 글자를 밝은·어두운 테마로 확인했습니다. 길게 이어지는 화면은 관련 스크롤 영역의 끝도 확인했습니다. 실제 사용자 기록 대신 임시 기록과 고정 예제를 썼고, 코드 실행·환경 설치·자료 전송은 하지 않았습니다.

짧은 글·여러 줄 글의 체크 표시와 메모는 캡처의 첫 글줄과 중심 차이가 1.5px 이내였습니다. 숫자와 설명의 기준선 차이는 1px 이내였고, 입력 칸의 바깥 높이는 초점·정답·오답 전환 뒤에도 유지됐습니다. 기존 테스트는 유지하고 관련 검사와 새 정렬 회귀 검사를 실행했습니다.

호스팅 Windows의 Qt 6.12.0 네이티브 창에서 760×480·가장 큰 글자와 1024×650·보통 글자를 두 테마로 확인했습니다. Qt 배율은 150%, 실제 작업 영역은 1280×688이었습니다. 화면 38가지와 스크롤 끝을 포함한 캡처 259개에서 요청한 창 크기와 버튼 글자 폭을 대조했습니다. 결과 화면과 코드 입력부를 추가 수정한 뒤에는 영향을 받는 화면 3가지의 캡처 18개만 다시 확인했습니다. 새 정렬 회귀 검사 7개도 Windows에서 통과했습니다. 사용자 PC나 Windows의 글자 크기 설정을 직접 시험한 결과와는 구분합니다. 이 점검은 실제 학습자의 이해도나 모든 모니터·운영체제의 배치를 검증한 결과가 아닙니다.
