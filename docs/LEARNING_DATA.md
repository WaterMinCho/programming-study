# 과목별 풀이 기록과 전송 방법

<a id="풀이-데이터를-보관하고-공유합니다"></a>

첫 실행 또는 [내 정보·데이터]에서 수집에 동의한 뒤 새 기록을 수집하고 비공개로 자동 전송합니다. [내 정보·데이터](LEARNING_PRIVACY.md)에서 동의 내용·선택 시각·철회·삭제를 관리합니다. 동의하지 않아도 학습·로컬 채점을 사용할 수 있습니다. 수집에 동의하면 [풀이 제출]로 답안 파일을 직접 보낼 수 있습니다. 자동으로 보내려면 [답안 파일도 자동 제출]을 따로 선택합니다.

<a id="이-기기에-보관합니다"></a>

## 이 컴퓨터에 쌓이는 학습 기록

수집을 시작한 뒤의 새 기록을 보관합니다. 동의서 버전·내용 해시와 실제 선택 시각을 남깁니다. 배포 시점을 동의한 시각으로 쓰지 않습니다. 기존 풀이를 가져오거나 과거에 없던 값을 채우지 않습니다.

아래 표는 AI 개론·응용의 수집 항목입니다.

| 기록 | 포함하는 내용 |
|---|---|
| 연습 묶음 | 모드, 선정 전 후보 묶음과 예비 후보, 실제 선택한 문항 목록, 묶음 생성 시드, 규칙 버전 |
| 연습 문항 | 서비스가 처음 반환한 지문, 빈칸 형식, 보기 순서, 문항 버전, 개념 태그 |
| 입력 변경 | 연습·모의고사의 답을 바꿔 저장한 기록입니다. 변경 기록에는 입력한 본문을 담지 않습니다. |
| 연습 답 | 맞힌 답을 포함한 입력값, 채점 결과, 응답 시간, 확신 여부, 묶음 안 첫 답인지 여부 |
| 다시 풀기 | 묶음 안 재시도, 모르겠어요, 내 답도 맞음 처리의 별도 기록 |
| 학습 활동 | 읽기, 다시 보기, 짐작, 떠올리기, 세 단계 확인 물음, 돌려 가며 빈칸 |
| 모의고사 | 시작, 서비스가 반환한 문항, 최종 제출한 답과 문항별 판정, 회차 소요 시간, 자동 제출 여부 |
| 희망 직무 | 직접 고른 목표 또는 미선택, 선택 시각·선택 번호, 당시 로드맵 내용의 SHA-256과 갱신일 |

[학습 데이터]에서 희망 직무를 고르고 [희망 직무 저장]을 누릅니다. 로드맵의 여섯 직무 중 하나를 고르거나 미선택으로 저장할 수 있습니다. 이곳에 저장한 목표는 [커리어] 화면에서 고르는 관심 직무와 별도로 보관합니다. 선택은 본인이 밝힌 진로 목표이며 능력 등급이나 직무 적합도 판정에 쓰지 않습니다. 선택하지 않아도 수집과 학습을 계속할 수 있습니다.

각 이벤트의 `data.goal`에 그때 저장한 목표와 로드맵 버전을 복사합니다. 직무나 로드맵이 바뀌어도 과거 답을 다시 분류하지 않습니다. 같은 직무를 다시 저장하면 그때의 로드맵 버전과 새 선택 번호를 기록합니다. 수집 중단과 수집 재시작 때는 현재 목표를 미선택으로 초기화합니다. 이전 선택을 다시 적용하려면 직접 저장해야 합니다. 이 기능 이전의 기록에는 목표를 채워 넣지 않습니다.

로드맵 버전은 JSON의 키 순서·들여쓰기·줄 끝을 정규화한 내용으로 계산합니다. Windows와 macOS에서 줄 끝만 달라졌을 때 같은 로드맵 버전의 풀이가 서로 다른 집단으로 나뉘지 않게 합니다.

학습 활동의 입력 답은 화면에서 채점·저장한 경우에 남습니다. 읽기 전용 노트의 확인 물음은 수집하지 않습니다. 짐작은 정오답으로 채점하지 않으며 모델 학습의 정답 자료로 바로 쓰지 않습니다. 연습의 해설은 채점 뒤 반환했다는 사실을 남깁니다. 실제로 읽었는지, 주의를 기울였는지까지 측정하지 않습니다.

서비스의 문항 반환 기록은 재조회·화면 복원 때문에 같은 문항을 중복 집계하지 않습니다. 실제 화면 노출 횟수와 시선 기록을 의미하지 않습니다. 연습 시간은 현재 앱이 전달한 초 단위 값이며 순수 집중 시간을 보장하지 않습니다. 모의고사에는 문항별 응답 시간을 새로 추정하지 않습니다. 시험 도중 수정하는 모든 글자도 수집하지 않습니다. 수집 시작 전에 입력한 모의고사 초안은 이후 제출하더라도 추가 답안으로 복사하지 않습니다. 중단 뒤 다시 시작한 경우에도 이전 수집 기간의 입력값을 가져오지 않습니다.

AI 공통 학습 자료는 같은 과정·풀이 묶음·문항 버전·위치의 반환 기록을 답과 연결합니다. 그 반환 시각을 예측 기준으로 사용하며 원본 기록의 시각을 바꾸지 않습니다. 연결한 기록의 고유번호와 출처도 남깁니다. 반환 기록이 없거나 여러 건으로 겹친 경우, 수집을 중단하고 다시 시작한 경우에는 시각을 추정하지 않습니다.

선정 후보는 해당 연습 모드에서 실제로 구성한 목록입니다. 문제 은행 전체나 모든 후보의 출제 확률을 뜻하지 않습니다. 선정 코드 버전도 보관합니다. 오답 노트에서는 직접 고른 문항과 규칙이 함께 넣은 문항의 출처를 각각 기록합니다. 현재 규칙의 선택 확률은 계산하지 않으므로 빈 값으로 남깁니다. 모델이 예측한 정답 확률을 문항의 선택 확률로 기록하지 않습니다.

공통 수집 구현은 `learning_data/collection.py`에 있습니다. 문항 버전 계산에는 실제 공통 구현과 과목별 실행 파일을 포함합니다. 폴더를 옮기기 전에 저장한 문항·답안·이벤트의 버전은 그대로 보존합니다.

기록에는 고유번호와 순서를 붙입니다. 문항 버전 해시는 지문·채점 조건·보기 순서·생성 시드·관련 실행 코드 버전과 허용 답 사전 버전을 포함합니다. 지문과 보기 스냅샷에는 채점용 정답표를 넣지 않습니다. 저장 시각에는 시간대를 포함하고, 기존 학습 기록의 시각은 `source_at`에 따로 보관합니다.

숫자나 조건을 바꿔 내는 문항에는 `generation`을 함께 남깁니다. 생성기·템플릿 ID와 버전, 코드 해시, 생성 시드, 지문에 공개한 입력 조건과 `instance_id`가 들어갑니다. 조건을 따로 선언하지 않은 생성기는 `params_status=undeclared`로 남기고 내부 `params`를 복사하지 않습니다. 예전 기록이나 업데이트 전 초안에 이 값이 없으면 미확인으로 유지합니다.

`instance_id`는 같은 조건과 보기 순서로 제시한 문제를 구분합니다. 다시 푼 횟수는 별도의 기록 고유번호로 셉니다. 모델 실험에서는 문항군·템플릿 버전과 실제 제시 조건을 구분하고, 한 문항의 숫자 변형을 서로 독립적인 개념처럼 세지 않습니다. 생성 조건만으로 정답을 계산하는 실험과 학습자의 다음 정오답을 예측하는 실험도 구분합니다.

### 이미 푼 문제가 바뀌면

새로 푼 기록에는 문항 ID와 그때의 문항 버전을 함께 남깁니다. 같은 ID의 지문이나 채점 조건이 바뀌면 다른 버전으로 기록합니다. 이전 답안과 당시 채점 결과는 덮어쓰지 않습니다.

| 풀이 시점 | 문항 ID | 문제와 결과 | 보관 방식 |
|---|---|---|---|
| 수정 전 | `q1` | `range(1, 4)`의 마지막 값에 `3`을 답해 정답 | 이전 버전의 기록으로 유지 |
| 수정 후 | `q1` | `range(1, 5)`의 마지막 값에 `3`을 답해 오답 | 새 버전의 기록을 추가 |

추천 모델용 공통 자료에서도 문항 ID와 버전을 함께 사용합니다. 버전 정보가 없던 과거 기록에는 현재 버전을 임의로 붙이지 않습니다. 문항 버전에는 보기 순서와 관련 실행 코드도 들어갑니다. 버전이 달라도 같은 개념일 수 있습니다.

현재 화면의 복습·숙달 계산에는 문항 ID를 기준으로 처리하는 부분이 남아 있습니다. 정답이나 조건을 바꾸는 출제 수정은 새 문항 ID 또는 별도의 버전 전환 처리를 정한 뒤 공개합니다. 관련 보완은 [문항 갱신과 숙달 표시 과제](https://github.com/WaterMinCho/programming-study/issues/163)에서 관리합니다.

자동으로 수집한 풀이 과정과 제출한 답안 파일은 보관 방식이 다릅니다. 풀이 과정은 기록별로 쌓이고, 제출 파일은 서버에 가장 최근 묶음만 남습니다. 이전 파일의 접수 번호와 시각은 유지합니다. 이 컴퓨터의 원본 답안은 지우지 않습니다.

추가 파일은 `~/.rokey-study/ai/<내 ID>/learning-data.sqlite3`에 있습니다. `STUDY_AI_HOME`을 지정했다면 그 폴더를 따릅니다. 공개 저장소 안의 경로에는 새로 수집할 수 없습니다. 기존 `submissions/<내 ID>/ai/record.json`과 진도·복습 계산은 바꾸지 않습니다.

추가 저장에 실패해도 기존 학습은 계속할 수 있습니다. 관리 화면과 과목 홈에서 실패를 알립니다. 실패한 구간의 입력값을 과거 제출 기록으로 추정해 복원하지 않습니다. 파일·잠금·저장 공간 문제를 해결한 뒤 다시 확인해 주세요.

출제 난이도는 문항을 제시할 때의 1~3단계 설정값입니다. 새 AI 연습·모의고사 기록과 파이썬 문항 기록에서 이 값을 읽어 공통 입력에 연결합니다. 난이도를 저장하지 않은 과거 문항 버전은 미확인으로 남깁니다. 학습자의 정답률로 계산한 난이도와는 출처를 구분합니다.

## 파이썬 입력과 채점을 보관합니다

파이썬과 AI는 과목별 파일에 보관합니다. 두 과목 모두 수집에 동의한 뒤 새 기록을 모읍니다. 파이썬 기록은 `~/.rokey-study/python/<내 ID>/learning-data.sqlite3`에 저장하며 `STUDY_PYTHON_HOME`으로 위치를 바꿀 수 있습니다. 기존 `profile.json`, `quiz.py`, 코드 답안은 기기에 유지합니다. [풀이 제출]을 누르면 제출 대상 파일을 비공개 서버에 보냅니다.

수집 중 프로그램에서 실제로 바꿔 저장한 퀴즈·코드 입력, 입력 당시 목표와 시각, 문항·채점 조건 버전, 채점 결과와 재시도를 보관합니다. 화면에 실제 선택한 문항만 표시 기록을 남기며 회차 전체를 읽었다고 처리하지 않습니다. 같은 입력을 그대로 저장하거나 채점을 반복한 경우에는 답 기록을 늘리지 않습니다. 시작 코드와 빈 답은 오답 학습 자료로 만들지 않습니다.

수집 시작 전에 저장한 답, 이전 수집 기간의 답, 외부 편집기에서 바꿔 일치하지 않는 답은 새 답 기록으로 가져오지 않습니다. 채점 중 입력이 바뀌어도 이전 판정을 새 입력에 붙이지 않습니다. 외부 편집기의 입력 시각·읽은 시간·응답 시간·확신은 추정하지 않습니다. 기존 기록을 활용할 때는 [공통 학습 자료 준비](LEARNING_STARTER.md) 도구에서 소유자의 동의를 별도로 확인합니다.

AI의 개론·응용은 같은 가명 구분값과 수집 순서를 사용합니다. 문항과 새 풀이에 `course`를 기록해 같은 번호의 차시가 섞이지 않게 합니다. 새 문항은 개론 `i01`, 응용 `a01`처럼 고유번호도 구분합니다. 예전 기록의 과정 값이 없으면 관측값은 비워 두고 차시 번호에서 추정한 값은 별도 칸에 남깁니다.

혼합 모의고사는 회차의 범위를 `scope=mixed`로 구분합니다. 문항의 `course`에는 검증한 개론 `intro` 또는 응용 `app`만 사용합니다. 문항의 차시 번호·지문·보기 순서·회차 시드·배분 버전도 같은 문항 버전에 연결합니다. 두 탭은 공통 로컬 답안과 수집 파일을 사용하며 동의 시점과 철회 상태를 공유합니다.

혼합 회차의 제출 집계는 과정별로 나누어 같은 채점 공개 시각에 기록합니다. 문항 반환 시각과 채점 공개 시각은 구분합니다. 동의 전에 입력한 답과 이전 수집 기간의 답은 제출 때 새 답으로 가져오지 않습니다.

m4의 문항 스냅샷에는 concept·format·transferaxis·conditions·sourcefacts를 보존합니다. classification_basis=author로 출제자가 정한 분류임을 표시하며 실제 학습자의 난도·능력 추론과 구분합니다. 오답의 family·tags로 관련 카드를 찾지 못하면 같은 과정·같은 차시에서 facts가 겹치는 연습 카드를 찾습니다. 겹치는 사실이 많은 카드를 먼저 고르고 한 제출에서 같은 카드를 거듭 넣지 않습니다.

## 수집 중단과 기록 내보내기

[수집 중단]은 이후의 추가 저장을 멈춥니다. 이미 모은 기록은 삭제하기 전까지 남습니다. [파일로 내보내기]는 JSONL 파일을 만들고 다시 읽어 확인합니다. 기본은 입력 답안 제외이며, [내보낼 때 입력 답안 포함]을 선택하면 입력값도 들어갑니다. 기존 파일을 덮어쓰거나 공개 저장소 안에 내보내지 않습니다. 내보내기는 하드 링크를 지원하는 기기의 기본 저장 공간에 먼저 저장합니다. exFAT USB 등으로 옮길 때는 저장한 파일을 복사합니다.

가명 구분값은 이 기기의 추가 데이터마다 생성합니다. GitHub ID와 이름을 내보내기 항목에 넣지 않지만 가명 자료를 완전한 익명 자료로 취급하지 않습니다. 입력 답안에 개인정보를 적었다면 답안 포함 내보내기·전송 전에 확인해 주세요.

[동의 철회·비공개 기록 삭제]는 모든 과목의 추가 수집·전송을 멈추고 이 기기와 서버의 비공개 기록·제출 파일을 삭제합니다. 기존 학습의 답안·진도는 유지합니다. 서버 삭제가 확인되기 전에는 완료로 표시하지 않으며 연결 후 다시 확인합니다. 동의 내용이 바뀌어 재선택이 필요한 상태에서도 이전 기록을 삭제할 수 있습니다.

운영자는 터미널에서도 관리할 수 있습니다. 아래 `delete` 명령은 해당 기기의 추가 수집 파일만 지우는 로컬 관리 명령입니다. 서버 기록과 제출 파일까지 지우려면 화면의 [동의 철회·비공개 기록 삭제]를 사용합니다.

```sh
python study.py ai-data status
python study.py ai-data enable --agree
python study.py ai-data disable
python study.py ai-data export --out /저장소밖경로/learning-data.jsonl
python study.py ai-data delete --agree
python study.py python-data status
python study.py python-data enable --agree
python study.py python-data disable
python study.py python-data export --out /저장소밖경로/python-learning-data.jsonl
python study.py python-data delete --agree
```

다른 ID는 `--user <ID>`로 지정합니다. 입력 답안까지 내보낼 때만 `--include-answers`를 붙입니다. Windows에서는 `C:\Users\내이름\Downloads\learning-data.jsonl`처럼 실제 경로를 지정합니다.

## 수집 서버에 보냅니다

일반 배포에서는 수집·이용과 비공개 서버 보관에 동의한 뒤 기본 서버에 자동 연결합니다. 개인 초대 코드와 별도 회원가입은 필요하지 않습니다. 새 기록은 정상 상태에서 약 1분 간격으로 보내며 입력 답안 본문은 제외합니다. 연결 실패가 반복되면 최대15분까지 간격을 늘리고, 철회 요청은 약 1분 간격으로 다시 확인합니다. 자동 전송은 모델 학습이나 GitHub 공개 제출을 실행하지 않습니다. 과목별 [학습 데이터]의 [지금 전송]도 같은 자동 전송 경로를 사용합니다.

과정 기록 전송용 인증 값은 같은 로컬 폴더의 `learning-data-sharing.json`에 보관합니다. 이 파일은 풀이 제출과 데이터 내보내기에서 제외합니다. 운영체제 계정의 파일 접근 권한으로 보호하며 별도로 암호화한 파일은 아닙니다. 인증 값과 초대 코드는 공유 문서·공개 이슈·화면 캡처에 넣지 마세요.

서버가 저장 확인을 보내면 마지막 전송 순서를 보관합니다. 응답이 끊기면 다음 전송에서 다시 보내며, 서버는 같은 고유번호의 같은 기록을 한 번만 저장합니다. 같은 번호의 내용이 달라지면 덮어쓰지 않고 요청을 거절합니다. 과정 기록 전송에서는 답안 본문을 제외합니다. 답안 파일은 [풀이 제출]을 누르거나 [답안 파일도 자동 제출]을 선택했을 때 별도 경로로 보냅니다. 파일 자동 제출은 두 과목의 수집이 모두 켜져 있을 때 작동하며, 선택 전에 작성한 미제출 파일도 포함합니다. [파일 제출 범위와 시점](API_SUBMISSIONS.md)을 확인하세요.

[동의 철회·비공개 기록 삭제]는 전송을 먼저 멈추므로 삭제한 기록을 자동으로 다시 올리지 않습니다. 중복 전송을 막기 위한 최소 등록·철회 정보는 남습니다. 학습용으로 이미 내보낸 파일과 백업의 삭제는 운영자에게 요청해야 합니다. 서버 삭제가 확인된 뒤 다시 동의하면 새 가명으로 수집을 시작합니다.

앱과 서버는 `ai`와 `python`을 별도 과목으로 다룹니다. 연구용 과정 기록은 동의 전에 저장한 파이썬 풀이를 소급 수집하지 않습니다. 서버 배포 운영과 데이터 준비는 WaterMinCho가 맡으며 팀원 딥러닝 미션에 넘기지 않습니다.

서버 설치는 [수집 서버 운영](LEARNING_SERVER.md), 전체 배포 전에 남은 조건은 [수집 범위와 배포 점검](LEARNING_READINESS.md), 개발 분담은 [딥러닝 미션](LEARNING_MISSIONS.md)을 참고하세요.
