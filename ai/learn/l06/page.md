### MSE는 오차를 제곱해 평균 냅니다
<!-- facts: F06-03 F06-04 F06-60 F06-17 F06-85 -->

앞 단계의 오차 [2, −1, 5]를 숫자 하나로 바꿉니다. 4차시에서 쓴 평균 제곱 오차(MSE)부터 계산합니다.

```figure
파일: assets/6a-2.gif
캡션: 그림 2. 오차를 제곱해 평균 내기. 검은 점은 정답, 파랑은 예측, 빨강은 오차, 주황은 오차의 제곱과 MSE, 회색 점선은 평균입니다.
프레임:
1. 왼쪽 칸의 검은 점이 정답, 빈 원이 예측입니다. 가로축은 데이터 번호입니다. (1800ms)
2. 빨간 선과 막대가 오차 e = 예측 − 정답 = [2, −1, 5]입니다. 예측이 정답보다 크면 막대가 위쪽으로 그려집니다. (2200ms)
3. 오차를 제곱하면 주황 막대 [4, 1, 25]가 됩니다. −1도 제곱하면 1이 되어 부호가 사라집니다. (2200ms)
4. 세 막대를 더하면 30입니다. (1800ms)
5. 데이터 수 3으로 나눈 평균 10을 회색 점선으로 그었습니다. (2200ms)
6. 이 평균 10이 MSE입니다. 제곱의 합 30 가운데 25가 데이터 3에서 나왔습니다. (2500ms)
```

**MSE = (오차²의 합) ÷ 데이터 수**

```python
y_true = torch.tensor([10.0, 20.0, 30.0])
y_pred = torch.tensor([12.0, 19.0, 35.0])
criterion = nn.MSELoss()        # MSE를 계산하는 손실 객체
criterion(y_pred, y_true)       # tensor(10.)
```

`nn.MSELoss()`는 MSE를 계산하는 손실 객체를 만듭니다. 만든 객체에 (예측, 정답) 순서로 넣으면 손실을 돌려줍니다.

> **[보충 설명]** 데이터 하나의 예측과 정답 차이를 재는 함수를 손실 함수, 여러 데이터의 평균 오차를 재는 함수를 비용 함수(cost function)로 나눠 부르기도 합니다. 이 예에서는 4, 1, 25가 데이터마다 나온 손실이고 평균 10이 비용입니다. 코드나 문서에 따라 두 이름을 같은 뜻으로 쓰기도 하므로 무엇을 평균했는지 확인하세요.

`nn.MSELoss()`는 인자를 주지 않으면 데이터마다 나온 값을 평균 낸 숫자 하나를 돌려줍니다. 이 동작을 정하는 인자는 `reduction`이고 기본값은 `'mean'`입니다. 다른 값은 이 차시 마지막 단원에서 봅니다.

### MAE는 오차의 절댓값을 평균 냅니다
<!-- facts: F06-05 F06-06 F06-09 F06-07 F06-85 -->

앞 단계의 MSE 10은 대부분 데이터 3의 25에서 나왔습니다. 오차를 제곱하지 않고 크기만 쓰면 어떻게 될까요? 오차의 절댓값 [2, 1, 5]를 평균 내면 (2 + 1 + 5) ÷ 3 = 2.6667입니다. 이 값은 4차시에서 회귀 모델을 평가할 때 본 평균 절대 오차(MAE)입니다. 6차시는 같은 값을 손실로 씁니다.

```figure
파일: assets/6a-3.png
캡션: 그림 3. 오차를 제곱할 때와 절댓값을 낼 때. 주황은 제곱과 MSE, 초록은 절댓값과 MAE입니다.
내용: 가로 오차 e 가 −6~6 인 그래프. 주황 포물선 e² 과 초록 꺾은선 |e|, 오차 −1, 2, 5 의 점(제곱 1, 4, 25 와 절댓값 1, 2, 5). 초록 꺾은선이 0 에서 꺾임을 화살표로 가리킴. 오른쪽에 MSE = 30 ÷ 3 = 10, MAE = 8 ÷ 3 = 2.6667.
```

MAE가 2.6667이면 예측이 평균 2.67쯤 틀렸다고 바로 읽을 수 있습니다. PyTorch는 이름에 MAE가 없는 `nn.L1Loss()`로 MAE를 계산합니다.

```python
criterion = nn.L1Loss()         # MAE를 계산하는 손실 객체
criterion(y_pred, y_true)       # tensor(2.6667)
```

그림 3의 초록 꺾은선은 오차 0에서 뾰족하게 꺾입니다. 그 한 점에서는 기울기를 하나로 정할 수 없습니다. 오차가 0이 아닌 곳에서는 기울기 크기가 언제나 1입니다.

### Huber 손실은 작은 오차만 제곱합니다
<!-- facts: F06-12 F06-13 F06-14 F06-16 F06-53 F06-69 F06-50 -->

앞 단계에서 MSE는 이상치 하나 때문에 720.8배가 되었고 MAE는 12.8배로 덜 늘었습니다. 첫 단원 그림 3에서 초록 꺾은선은 오차 하나의 절댓값 |e|입니다. 오차가 0이 아닌 구간에서는 e에 대한 기울기 크기가 1입니다. 오차가 0.1이든 60이든 이 크기는 같습니다.

주황 포물선 e²은 e에 대한 기울기가 2e라서 오차가 작아지면 기울기 크기도 작아집니다. 여기서는 오차 하나에 대한 기울기를 비교합니다. 실제 파라미터가 바뀌는 양은 모델과 학습률·갱신 방법에도 영향을 받습니다.

작은 오차는 MSE처럼 제곱하고 큰 오차는 MAE처럼 크기에 비례해 계산하는 손실을 <mark>Huber 손실</mark>(Huber loss)이라고 부릅니다.

작은 오차와 큰 오차를 나누는 경계값은 δ로 적고 델타라고 읽습니다. δ는 학습 전에 사람이 정하는 하이퍼파라미터입니다. 오차 e의 절댓값이 δ 이하이면 0.5 × e²으로 계산합니다. δ보다 크면 δ × (|e| − 0.5δ)로 계산합니다.

**|e| ≤ δ 이면 0.5 × e²**

**|e| > δ 이면 δ × (|e| − 0.5δ)**

```figure
파일: assets/6b-2.png
캡션: 그림 2. δ = 1인 Huber 손실. 보라는 Huber 손실, 옅은 보라 칸은 제곱 구간, 주황 점선은 0.5e², 초록 점선은 |e|입니다.
내용: 가로 오차 e 가 −6~6 인 그래프. 보라 곡선은 |e| ≤ 1 에서 주황 점선 0.5e² 과 겹치고 그 밖에서는 초록 점선 |e| 보다 0.5 낮은 직선. 오차 2, −1, 5 의 점에 1.5, 0.5, 4.5. 오른쪽에 두 식과 평균 6.5 ÷ 3 = 2.1667.
```

앞 단원의 오차 [2, −1, 5]에 δ = 1을 쓰면 2와 5는 직선 구간, −1은 제곱 구간에 듭니다.

- 오차 2는 1 × (2 − 0.5) = 1.5입니다.
- 오차 −1은 절댓값 1이 δ 이하라 0.5 × 1² = 0.5입니다.
- 오차 5는 1 × (5 − 0.5) = 4.5입니다.

세 값을 평균 내면 Huber 손실 6.5 ÷ 3 = 2.1667이 나옵니다.

```python
criterion = nn.HuberLoss(delta=1.0)    # delta를 적지 않아도 1.0
criterion(y_pred, y_true)              # tensor(2.1667)
```

`nn.HuberLoss()`의 delta 기본값은 1.0입니다. 오차의 절댓값이 δ와 같으면 두 식이 모두 0.5δ²을 냅니다. 그래서 경계를 ≤로 적어도, <로 적어도 결과가 같습니다.


앞 단계의 이상치 실험에 Huber 손실(δ = 1)을 쓰면 손실이 0.5에서 12.3으로 늘어납니다. 처음 값이 0.5로 작아서 배율은 24.6배로 크지만, 늘어난 값은 MAE와 같은 11.8입니다. 넷째 오차의 크기는 1에서 60으로 커졌고, 크기 1부터는 δ = 1인 직선 구간입니다. 이 구간에서는 오차가 1 커질 때 Huber 손실이 δ = 1만큼 커지고 MAE도 1만큼 커져서, 두 손실의 합이 똑같이 59 늘어납니다.

같은 식을 `torch.where`로 직접 계산할 수 있습니다. 먼저 오차의 절댓값을 구하고 δ와 비교해 어느 식을 쓸지 고릅니다. 데이터마다 고른 식으로 계산한 뒤 평균을 냅니다.

```python
def huber(pred, target, delta=1.0):
    diff = torch.abs(pred - target)           # 오차의 절댓값
    small = diff <= delta                     # 원소마다 True 나 False
    each = torch.where(small, 0.5 * diff**2, delta * (diff - 0.5 * delta))
    return each.mean()
```

`diff`는 앞에서 쓴 오차의 절댓값 |e|입니다. `small`에는 그 값이 δ 이하인지가 True와 False로 담깁니다. `torch.where(조건, a, b)`는 원소마다 조건이 True이면 a의 값을 고르고 False이면 b의 값을 고릅니다.

위의 오차 −1은 절댓값이 δ = 1 이하이므로 `small`이 True입니다. a 자리에 있는 제곱식으로 계산해 0.5를 고릅니다. 오차 2와 5는 δ보다 커서 b 자리의 직선 구간 식을 씁니다. `each.mean()`은 이렇게 고른 1.5, 0.5, 4.5의 평균 2.1667을 냅니다.

### δ를 바꾸면 제곱 구간의 폭이 바뀝니다

### BCE는 정답이 1이면 −log p, 0이면 −log(1 − p)입니다
<!-- facts: F06-19 F06-20 F06-21 F06-22 -->

앞 두 단원은 숫자 값을 맞히는 회귀 문제였습니다. 이번에는 메일이 스팸인지 아닌지를 맞히는 문제처럼 정답이 0과 1로 나뉩니다. 정답이 0과 1 두 종류뿐인 문제를 이진 분류(binary classification)라고 부릅니다. 이진 분류는 8차시에서 자세히 배웁니다.

분류에서 클래스는 정답이 될 수 있는 종류 하나를 말합니다. 1차시에서 코드를 묶을 때 쓴 파이썬 클래스와 낱말만 같습니다. 모델의 마지막 선형층이 낸 숫자를 3차시에서 배운 시그모이드에 넣으면 0과 1 사이의 값이 됩니다. 이 값을 정답이 1일 확률 p로 읽습니다.

정답이 1이면 p가 1에 가까울수록, 정답이 0이면 p가 0에 가까울수록 잘 맞힌 것입니다. 정답이 1이면 −log p로, 0이면 −log(1 − p)로 손실을 재는 방법을 <mark>이진 교차 엔트로피</mark>(BCE, Binary Cross Entropy)라고 부릅니다.

**BCE = −[y × log p + (1 − y) × log(1 − p)]**

식의 y는 정답 0이나 1입니다. log는 자연로그입니다. y = 1이면 둘째 항이 0이 되어 −log p만 남고, y = 0이면 첫째 항이 0이 되어 −log(1 − p)만 남습니다.

### BCEWithLogitsLoss는 log 0을 만들지 않습니다
<!-- facts: F06-24 F06-25 F06-63 F06-64 F06-71 F06-87 F06-90 -->

앞 단계에서는 시그모이드 뒤에 BCE를 따로 계산해도 0.7111이 나왔습니다. 그런데 logit이 −100처럼 큰 음수이면 따로 계산하는 쪽이 무한대를 냅니다.

```figure
파일: assets/6c-3.png
캡션: 그림 3. 정답이 1인 데이터의 손실을 logit z로 그린 것. 초록은 안정한 식으로 계산한 값이며 BCEWithLogitsLoss가 내는 손실과 같습니다. 빨강 점선은 시그모이드 식 1 ÷ (1 + e^(−z))를 float32로 차례대로 계산한 뒤 log를 씌운 값입니다.
내용: 가로 logit z 가 −120~10, 세로 BCE 가 0~140 인 그래프. 초록 직선은 z 가 작아질수록 손실이 z 의 크기만큼 커지고 z = −120 에서 120. 빨간 점선은 초록과 겹치다가 z 가 약 −88.7 보다 작은 곳에서 끊기고, 그 자리에서 위로 향한 빨간 화살표에 무한대(inf). 오른쪽에 e^(−z) 가 무한대가 되어 시그모이드 값이 0 이 되는 설명과 z = −100 이면 손실 100.
```

정답이 1인 데이터의 logit이 −100이면 시그모이드 값은 약 3.7 × 10⁻⁴⁴로 0에 가깝습니다. logit을 z라고 하면 시그모이드 식은 1 ÷ (1 + e^(−z))입니다. z = −100이면 e^(−z)는 e^100입니다. 컴퓨터가 흔히 쓰는 32비트 실수(float32)로 이 식을 차례대로 계산하면 e^100이 float32의 가장 큰 수 약 3.4 × 10³⁸을 넘어 무한대가 됩니다. 그러면 시그모이드 값이 0이 되고, −log 0은 무한대(inf)가 됩니다. 그림 3의 빨간 점선은 logit이 약 −88.7보다 작아지는 곳에서 이렇게 끊깁니다. 계산 순서를 바꾼 함수는 −100에서 0 대신 약 3.8 × 10⁻⁴⁴를 내기도 합니다. 그래도 logit이 약 −104보다 작으면 float32 시그모이드 값은 계산 순서와 상관없이 0입니다. `nn.BCEWithLogitsLoss()`는 시그모이드와 log를 한 식으로 묶어 계산해서 같은 자리에서 손실 100을 냅니다.

> **[보충 설명]** BCE 식에 시그모이드를 넣고 z가 양수일 때와 음수일 때로 나눠 정리하면 max(z, 0) − z × y + log(1 + e^(−|z|))라는 안정한 식이 나옵니다. e의 지수에 0 이하의 수만 들어가서 e^(−|z|)가 1을 넘지 않습니다. 지수를 먼저 크게 만들지 않도록 식을 바꾸는 계산을 log-sum-exp 트릭이라고 부릅니다. 시그모이드를 거친 확률을 받는 `nn.BCELoss()`는 log 값이 −100 아래로 내려가지 않게 잘라 무한대를 막습니다.

`nn.BCELoss()`는 log 값을 −100에서 자릅니다. logit을 내는 모델에서는 시그모이드와 log를 묶어 계산하는 `nn.BCEWithLogitsLoss()`를 사용합니다.

모델 끝과 손실은 짝을 맞춰 씁니다.

```python
# 짝 1: 모델 끝에 시그모이드가 없음. logit 을 넣음
criterion = nn.BCEWithLogitsLoss()
loss = criterion(model(x), y)

# 짝 2: 시그모이드로 확률을 만든 뒤 넣음
criterion = nn.BCELoss()
loss = criterion(torch.sigmoid(model(x)), y)
```

짝을 바꿔 시그모이드를 거친 확률을 `nn.BCEWithLogitsLoss()`에 넣으면 이 손실이 그 확률에 시그모이드를 한 번 더 적용합니다. 확률은 0과 1 사이라 두 번째 시그모이드 값은 0을 넣은 값 0.5와 1을 넣은 값 0.7311 사이에만 있습니다. 그래서 정답이 1인 데이터의 손실은 −log 0.7311 ≈ 0.313 아래로 내려가지 않습니다. 이렇게 짝을 바꿔도 오류가 나지 않아서 알아차리기 어렵습니다. `nn.BCELoss()`는 0과 1 사이의 확률을 받으므로 logit을 그대로 넣지 않습니다.

### 소프트맥스, log, 정답 칸을 거쳐 손실 0.417이 나옵니다
<!-- facts: F06-28 F06-31 F06-56 F06-68 -->

앞 단원의 이진 분류는 정답이 0과 1 둘이었습니다. 사진 한 장이 고양이, 개, 말 가운데 무엇인지 맞히는 문제처럼 클래스가 셋 이상이면 모델은 클래스마다 logit을 하나씩 냅니다. 정답이 셋 이상의 클래스 가운데 하나인 문제를 다중 분류(multi-class classification)라고 부릅니다. 다중 분류는 9차시에서 자세히 배웁니다.

logit 여러 개를 합이 1인 확률로 바꾸는 함수를 소프트맥스(softmax)라고 부릅니다. 소프트맥스의 식은 9차시에서 배웁니다. 세 클래스의 logit이 [2.0, 1.0, 0.1]이고 정답이 클래스 0이라고 합시다. 클래스 번호는 0부터 세므로 클래스 0이 첫째 칸입니다.

### CrossEntropyLoss에는 logit과 클래스 번호를 넣습니다
<!-- facts: F06-27 F06-29 F06-30 F06-65 F06-91 -->

```python
outputs = torch.tensor([[2.0, 1.0, 0.1],
                        [0.5, 2.5, 0.0]])   # logit, 모양 [2, 3]
labels = torch.tensor([0, 1])             # 클래스 번호, 모양 [2]
criterion = nn.CrossEntropyLoss()
loss = criterion(outputs, labels)         # tensor(0.3069)
```

### 라벨 스무딩은 정답 클래스의 목표를 1보다 조금 낮춥니다
<!-- facts: F06-32 F06-33 F06-34 F06-35 F06-36 F06-57 F06-79 F06-88 F06-92 -->

앞 단계의 교차 엔트로피로 학습하면, 정답이 클래스 0인 데이터에서 모델은 확률을 원-핫 벡터 [1, 0, 0]에 가깝게 내도록 바뀝니다. 이때 정답 클래스의 목표는 1, 나머지 클래스의 목표는 0입니다. 이 목표로 학습을 이어 가면 모델은 정답 확률을 0.99 넘게 내도록 정답 클래스의 logit을 계속 키웁니다. 정답을 지나치게 확신하는 모델은 새 데이터에서 틀리기 쉽습니다.

정답은 라벨(label)이라고도 부릅니다. 정답 클래스의 목표를 1보다 조금 낮추고 그만큼을 다른 클래스에 고르게 나눠 주는 방법을 <mark>라벨 스무딩</mark>(label smoothing)이라고 부릅니다.

**목표 = y × (1 − α) + α ÷ K**

y는 원-핫 벡터의 칸 값입니다. 정답 칸은 1이고 나머지 칸은 0입니다. K는 클래스 수입니다. α는 정답 칸에서 덜어 내 모든 칸에 고르게 나눠 주는 양입니다.

```figure
파일: assets/6d-3.png
캡션: 그림 3. 원-핫 벡터와 라벨 스무딩 목표(K = 3, α = 0.1). 회색은 원-핫 벡터, 슬레이트색은 라벨 스무딩 목표입니다.
내용: 클래스 0~2 의 막대 묶음. 회색 원-핫 벡터 1, 0, 0 과 슬레이트색 라벨 스무딩 목표 0.933, 0.033, 0.033. 오른쪽에 식, 정답과 나머지 칸 계산, 손실 0.4170 → 0.5137, K = 10 이면 0.91 과 0.01.
```

K = 3, α = 0.1이면 정답 칸은 1 × 0.9 + 0.1 ÷ 3 = 0.933, 나머지 칸은 0 × 0.9 + 0.1 ÷ 3 = 0.033입니다. 세 값을 더하면 1입니다. K = 10, α = 0.1이면 정답 칸은 0.91, 나머지는 0.01입니다. α는 보통 0.1을 씁니다. PyTorch에서는 인자 하나로 라벨 스무딩을 켭니다.

```python
criterion = nn.CrossEntropyLoss(label_smoothing=0.1)
```

라벨 스무딩을 켜면 손실은 칸마다 목표와 그 칸 확률의 −log 값을 곱해 더한 값입니다. 같은 logit [2.0, 1.0, 0.1], 정답 0에서는 손실이 0.4170에서 0.5137로 커집니다. 목표 0.933은 0.9 + 0.1 ÷ 3이고 0.033은 0.1 ÷ 3입니다. 0.9를 곱하는 항과 0.1 ÷ 3을 곱하는 항으로 나눠 묶으면 0.9 × 0.417 + 0.1 × (0.417 + 1.417 + 2.317) ÷ 3 = 0.3753 + 0.1384 = 0.5137입니다. 정답이 아닌 클래스 1, 2의 −log 값 1.417, 2.317이 뒤 항에 들어가서 손실이 커집니다. 이 손실은 모델의 확률이 목표 [0.933, 0.033, 0.033]과 같을 때 가장 작아집니다. 그래서 모델이 정답 확률을 1까지 끌어올리지 않습니다.

### 가중 교차 엔트로피는 적은 클래스에 큰 가중치를 줍니다
<!-- facts: F06-38 F06-39 F06-40 F06-75 -->

앞 단계의 자료는 정상 9,900명, 질병 100명입니다. 질병 데이터 수는 전체의 1%입니다. 데이터마다 손실이 비슷하다면 질병 데이터가 더하는 손실의 합도 전체의 약 1%에 그칩니다. 클래스마다 손실에 곱할 가중치를 따로 정해 데이터가 적은 클래스의 손실을 크게 만드는 방법을 가중 교차 엔트로피(weighted cross entropy)라고 부릅니다.

**가중치 = 전체 데이터 수 ÷ (클래스 수 × 그 클래스의 데이터 수)**

```figure
파일: assets/6e-2.gif
캡션: 그림 2. 데이터 수에서 가중치까지. 파랑은 정상, 빨강은 질병입니다. n_c는 그 클래스의 데이터 수입니다. w_c는 가중치입니다.
프레임:
1. 정상 9,900, 질병 100이고 전체는 10,000, 클래스는 2개입니다. (2000ms)
2. 정상의 가중치는 10,000 ÷ (2 × 9,900) ≈ 0.505, 질병은 10,000 ÷ (2 × 100) = 50입니다. (2500ms)
3. 데이터 수에 가중치를 곱하면 두 클래스 모두 5,000입니다. (2500ms)
```

이 식은 클래스마다 데이터 수에 가중치를 곱한 합을 5,000으로 맞춥니다. 정상 한 건과 질병 한 건의 가중 전 손실이 같다면 가중 뒤 질병 한 건의 손실은 정상 한 건의 약 99배가 됩니다. 실제 클래스별 손실 합은 각 예측 확률에도 달려 있습니다.

```python
criterion = nn.CrossEntropyLoss(weight=weights)
```

### Focal Loss는 잘 맞히는 데이터의 손실을 줄입니다
<!-- facts: F06-41 F06-42 F06-43 F06-58 F06-67 -->

앞 단계의 가중치는 클래스마다 하나로 정해져서 같은 클래스의 데이터는 모두 같은 가중치를 받습니다. 같은 클래스 안에도 모델이 이미 잘 맞히는 데이터와 아직 틀리는 데이터가 섞여 있습니다. 이미 잘 맞히는 데이터를 쉬운 샘플이라고 부릅니다. 아직 틀리는 데이터는 어려운 샘플이라고 부릅니다.

이 단계에서는 정답 클래스의 예측 확률을 p라고 하겠습니다. 이진 분류 단원의 p는 정답이 1일 확률이었으니, 정답이 0인 데이터에서는 그때의 1 − p가 이 단계의 p입니다. 교차 엔트로피 −log p에 (1 − p)^γ를 곱해 잘 맞히는 데이터의 손실을 줄이는 손실을 <mark>Focal Loss</mark>라고 부릅니다.

**Focal Loss = −α × (1 − p)^γ × log p**

γ는 감마라고 읽습니다. γ는 잘 맞히는 데이터의 손실을 얼마나 줄일지 정합니다. α는 정답 클래스에 따라 곱하는 가중치입니다. Focal Loss를 처음 낸 논문(Lin 외 2017)은 식의 α 자리에 정답이 1인 데이터는 α를, 정답이 0인 데이터는 1 − α를 넣습니다. 이 α는 앞 단원 라벨 스무딩의 α와 글자만 같고 다른 값입니다. 이 예제에서는 γ = 2, α = 0.25를 씁니다.

```figure
파일: assets/6e-3.png
캡션: 그림 3. γ에 따른 Focal Loss(α = 1). 회색은 γ = 0인 보통 교차 엔트로피, 슬레이트색은 옅은 것부터 γ = 1, 2, 5입니다.
내용: 가로 정답 클래스의 예측 확률 p 가 0~1, 세로 손실 0~4.6 인 그래프. γ 가 클수록 곡선이 아래로 붙음. p = 0.9 의 회색 점 0.105 와 슬레이트 점 0.00105 를 화살표로 이음. 오른쪽에 식과 γ = 2 일 때 곱하는 수 p = 0.9 → 0.01, p = 0.1 → 0.81.
```

γ = 2이면 p = 0.9인 데이터에는 (1 − 0.9)² = 0.01이 곱해져 손실이 100분의 1이 됩니다. p = 0.1인 데이터에는 0.81이 곱해져 손실이 대부분 남습니다. 정답이 1인 데이터라면 α = 0.25까지 곱해 손실은 p = 0.9에서 약 0.00026, p = 0.1에서 약 0.4663입니다. γ = 0이면 (1 − p)⁰ = 1이라 Focal Loss는 α를 곱한 보통 교차 엔트로피와 같습니다.

Focal Loss는 이미 잘 맞히는 데이터가 손실 대부분을 차지하는 상황에서 그 데이터의 비중을 줄이는 데 씁니다. Lin 외 2017 논문은 물체를 찾는 모델에서 배경 영역이 물체보다 훨씬 많은 문제를 다뤘습니다.

### 불균형 대응 방법을 적용하는 때
<!-- facts: F06-44 F06-73 F06-74 -->

앞 두 단계의 방법은 학습할 때 손실을 바꿉니다. 손실 대신 학습 전에 데이터를 바꿔 클래스 비율을 맞추는 방법도 있습니다.

- 적은 클래스의 데이터를 복제해 늘리는 방법을 오버샘플링(over-sampling)이라고 부릅니다.
- 많은 클래스의 데이터를 줄이는 방법을 언더샘플링(under-sampling)이라고 부릅니다.
- 적은 클래스의 데이터를 바탕으로 새 데이터를 합성해 늘리는 방법을 SMOTE(Synthetic Minority Over-sampling Technique)라고 부릅니다. SMOTE는 적은 클래스의 데이터 하나와 같은 클래스의 가까운 데이터 사이에 새 데이터를 만듭니다.

### reduction 인자와 직접 만든 손실 코드 읽기
<!-- facts: F06-17 F06-80 F06-49 F06-85 -->

앞 단계의 손실 줄은 모두 손실 객체를 만든 뒤 (예측, 정답)을 넣어 불렀습니다. 객체를 만들 때 `reduction` 인자를 주면 결과의 꼴이 바뀝니다.

```figure
파일: assets/6f-2.png
캡션: 그림 2. 제곱 오차 [4, 1, 25]와 reduction의 세 값. 주황은 제곱 오차, 회색 점선은 평균입니다.
내용: 데이터 1~3 의 주황 막대 4, 1, 25 와 평균 10 의 회색 점선. 오른쪽에 reduction='none' → tensor([4., 1., 25.]), reduction='mean' → tensor(10.)(기본값), reduction='sum' → tensor(30.).
```

첫 단원의 오차 [2, −1, 5]를 다시 쓰면, `nn.MSELoss()`의 `reduction='mean'`은 평균 10, `'sum'`은 합 30, `'none'`은 데이터마다 하나씩 [4, 1, 25]를 돌려줍니다. 따로 적지 않으면 `'mean'`입니다. 오차마다 Huber 손실을 구해 곡선을 그리려면 `reduction='none'`을 씁니다.

손실을 직접 만들 수도 있습니다. `nn.Module`을 물려받은 파이썬 클래스의 `forward`에서 MAE나 MSE를 계산할 수 있습니다. 아래 클래스는 MSE를 계산합니다.

```python
class MyMSELoss(nn.Module):
    def forward(self, pred, target):
        return ((pred - target) ** 2).mean()

criterion = MyMSELoss()
criterion(y_pred, y_true)      # tensor(10.)
```

만든 객체에 (예측, 정답)을 넣어 부르면 `forward`가 계산한 손실이 나옵니다. `.mean()` 대신 `.sum()`을 쓰면 `reduction='sum'`과 같은 30이 나옵니다.

### 손실 곡면은 파라미터를 바꾸며 잰 손실의 모양입니다
<!-- facts: F06-45 F06-46 F06-47 F06-48 F06-89 F06-93 -->

앞 단계까지는 파라미터 값을 정해 둔 채 손실 값 하나를 계산했습니다. 파라미터를 바꿔 가며 손실을 재면 손실이 파라미터에 따라 어떻게 오르내리는지 볼 수 있습니다. 파라미터를 바꿔 가며 잰 손실을 높이로 그린 모양을 손실 곡면(loss surface)이라고 부릅니다. 4차시 둘째 단원에서 W와 B를 함께 바꾸며 그린 손실 등고선은 이 곡면에서 높이가 같은 점을 이은 선입니다.

```figure
파일: assets/6f-3.png
캡션: 그림 3. 왼쪽은 4차시 직선 예의 손실 곡면, 오른쪽은 예로 그린 손실 곡선 둘. 왼쪽 면은 색이 진할수록 손실이 작고, 별은 손실이 가장 작은 곳입니다. 오른쪽 파랑은 매끄러운 곡선, 회색은 울퉁불퉁한 곡선입니다.
내용: 왼쪽 3차원 그래프는 가로 W 0~3.6, 안쪽 B −3~3, 세로 손실. 그릇 모양 면과 손실이 가장 작은 곳 W 1.8207, B 0(손실 4.539)의 별, 시작점 W 1, B 1(손실 13.352)의 점. 오른쪽은 예로 그린 곡선으로, 파란 매끄러운 곡선과 국소 최적해가 여러 개인 회색 울퉁불퉁한 곡선.
```

학습은 손실 곡면에서 손실이 가장 작은 곳을 찾아가는 일입니다. 4차시 예의 곡면은 그릇 모양이고 손실이 가장 작은 곳은 W = 1.8207, B = 0입니다. 경사하강법은 그쪽으로 다가가서 500번 갱신한 뒤 W = 1.8207, B = 0.3675에 이르렀습니다. 그림에서는 매끄러운 곡면과 국소 최적해가 여럿인 곡선을 비교합니다. 넓은 최솟값은 손실이 가장 작은 곳의 둘레가 평평하게 넓은 모양을 말합니다. 4차시에서 배운 국소 최적해는 둘레에서만 손실이 가장 낮은 곳입니다. 오른쪽 회색 곡선처럼 국소 최적해가 많으면 기울기가 0인 곳이 많아 경사하강법이 그곳에 머물 수 있습니다.

기울기의 크기가 정한 값을 넘으면 그 값으로 줄이는 방법을 기울기 자르기(gradient clipping)라고 부릅니다. 기울기 자르기는 기울기가 갑자기 커져서 파라미터가 한 번에 크게 바뀌는 것을 막습니다. 학습 초반에 학습률을 작게 시작해 키워 가는 방법은 Warm-up이라고 부릅니다.

새 데이터의 예측 성능은 손실 곡면의 모양과 별도로 검증 데이터에서 확인합니다.
