### 선형 모델: Yp = W × X + B
<!-- facts: F04-08 F04-17 F04-27 F04-64 -->

입력을 받아 예측을 내놓는 식을 모델이라고 부릅니다. 이 단원은 가장 단순한 모델인 직선을 씁니다.

**Yp = W × X + B**

- X는 입력(평균을 뺀 신장)이고 Yp는 예측한 체중입니다. p는 predict(예측)의 머리글자입니다.
- W는 직선의 기울기입니다. X가 1 커질 때 Yp가 W만큼 커집니다.
- B는 X = 0일 때 직선의 높이입니다.

이렇게 입력에 W를 곱하고 B를 더하는 직선 꼴의 모델을 선형 모델이라고 부릅니다. W와 B처럼 학습하면서 고쳐 갈 값은 파라미터라고 부릅니다. 강의는 이 식을 앞으로 배울 모델들의 기본 블록으로 소개합니다(4차시 슬라이드 11쪽, 13쪽). 노트북은 W = 1, B = 1에서 시작합니다.

```figure
파일: assets/4a-3.gif
캡션: 그림 3. 직선 하나로 예측하기
프레임:
1. 앞 단계에서 옮긴 다섯 점입니다. (1600ms)
2. W = 1, B = 1인 직선 Yp = 1 × X + 1을 그었습니다. (1800ms)
3. 파란 계단은 X가 1 커질 때 Yp가 W = 1만큼 커지는 모습입니다. 보라 원은 X = 0일 때의 높이 B = 1입니다. (2400ms)
4. 사람 1의 X = −5를 넣으면 1 × (−5) + 1 = −4입니다. 직선 위의 빈 원이 예측입니다. (2200ms)
5. 사람 2는 1 × 5 + 1 = 6입니다. (2200ms)
6. 나머지 세 사람까지 넣으면 Yp = [−4, 6, 1, 3, −1]입니다. (2500ms)
```

PyTorch 코드로는 이렇게 씁니다.

```python
X = torch.tensor(X).float()   # numpy 배열을 텐서로 바꿈
Y = torch.tensor(Y).float()

W = torch.tensor(1.0, requires_grad=True).float()
B = torch.tensor(1.0, requires_grad=True).float()

def pred(X):
    return W * X + B

Yp = pred(X)
# tensor([-4.,  6.,  1.,  3., -1.], grad_fn=<AddBackward0>)
```

`torch.tensor(...)`는 값을 텐서(PyTorch가 다루는 숫자 배열)로 만들고, `.float()`는 그 텐서를 32비트 실수로 맞춥니다. X, Y는 numpy의 64비트 실수에서 32비트로 바뀌고, 1.0으로 만든 W, B는 처음부터 32비트 실수라 바뀌는 것이 없습니다.

`requires_grad=True`는 이 텐서가 들어간 계산을 PyTorch가 기록해 두라는 표시입니다(3차시 슬라이드 11쪽, 4차시 슬라이드 23쪽). 출력 끝의 `grad_fn=<AddBackward0>`는 Yp를 만든 마지막 계산이 덧셈이었다는 기록입니다. 이 기록을 쓰는 곳은 이 차시 셋째 단원에서 봅니다.

### 손실: 얼마나 틀렸는지 숫자 하나로
<!-- facts: F04-28 F04-30 -->

예측이 정답에서 얼마나 벗어났는지부터 잽니다. 예측에서 정답을 뺀 값을 오차(e)라고 부릅니다.

**e = Yp − Y**

사람 1은 −4 − (−6.7) = 2.7이라 예측이 2.7 높습니다. 사람 2는 6 − 10.3 = −4.3이라 예측이 4.3 낮습니다.

2. 빨간 세로선이 사람마다의 오차입니다. e = [2.7, −4.3, 4.3, −2.0, 4.3]입니다. 오른쪽 칸의 막대가 같은 오차이고, 위로 선 막대는 예측이 정답보다 높은 사람(양수), 아래로 선 막대는 낮은 사람(음수)입니다. (2200ms)

이렇게 오차를 제곱해 평균 낸 값을 평균 제곱 오차(MSE, Mean Squared Error)라고 부릅니다. 모델이 얼마나 틀렸는지 나타내는 숫자 하나를 손실(loss)이라고 부르고, 작을수록 정답에 가깝습니다. 세 단원의 손실은 MSE이고, 지금 직선의 손실은 13.352입니다.

```python
def mse(Yp, Y):
    loss = ((Yp - Y)**2).mean()
    return loss

loss = mse(Yp, Y)
# tensor(13.3520, grad_fn=<MeanBackward0>)
```

`(Yp - Y)**2`는 다섯 오차를 하나씩 제곱하고, `.mean()`은 그 다섯 값의 평균을 냅니다.

W와 `W.grad`는 둘 다 "기울기"라고 불려서 헷갈리기 쉽습니다.

| | W | `W.grad` |
|---|---|---|
| 무엇의 기울기 | 직선 Yp = W × X + B의 기울기 | 손실 곡선의 기울기(경사) |
| 그림 1에서 | 왼쪽 칸 파란 직선이 얼마나 가파른가 | 오른쪽 칸 주황 접선이 얼마나 가파른가 |

| 누가 정하나 | 학습(다음 단계의 수정)이 고쳐 감 | `loss.backward()`가 계산해 채움 |
| 0이면 | 직선이 수평 | W를 조금 바꿔도 손실이 거의 바뀌지 않는 자리(이 곡선에서는 바닥) |

### 경사하강법: 경사의 반대쪽으로 한 걸음
<!-- facts: F04-11 F04-12 F04-34 F04-74 -->

경사는 손실이 가장 빨리 커지는 쪽을 가리킵니다. 손실을 줄이려면 반대쪽으로 움직이면 됩니다. 이렇게 파라미터를 경사의 반대쪽으로 조금씩 고치는 방법을 경사하강법(gradient descent)이라고 부릅니다.

**새 W = W − 학습률 × W.grad**

**새 B = B − 학습률 × B.grad**

경사에 곱해 한 번에 움직이는 크기를 조절하는 작은 수를 학습률(learning rate)이라고 부르고, 코드에서는 `lr`로 씁니다. 노트북은 0.001을 씁니다.

- W는 1 − 0.001 × (−19.04) = 1 + 0.01904 = 1.01904가 됩니다.
- B는 1 − 0.001 × 2.0 = 0.998이 됩니다.

`W.grad`가 음수라서 빼기를 거치면 W는 커집니다. `B.grad`는 양수라서 B는 작아집니다. 앞 단계에서 본 "W를 키우면 손실이 줄어든다"와 같은 방향입니다.

### 연쇄법칙: 사람 2 하나만 따라가기
<!-- facts: F04-14 F04-15 F04-65 -->

앞 단원에서는 W를 바꿔 가며 손실을 두 번 계산해 경사를 구했습니다. 파라미터가 수만 개면 파라미터마다 손실을 두 번씩 다시 계산해야 합니다. PyTorch는 다른 방법을 씁니다. 손실을 만든 계산을 작은 단계로 나누고, 단계마다 미분을 구해 곱합니다. 이 원리를 연쇄법칙(chain rule)이라고 부릅니다(4차시 슬라이드 21쪽).

사람 2(X = 5, Y = 10.3) 하나만 따라가 봅니다. 입력에서 손실 쪽으로 값을 차례로 계산하는 것을 순전파라고 부르고, 손실에서 입력 쪽으로 미분을 곱해 가는 것을 역전파라고 부릅니다.

사람 2의 계산을 네 단계로 나눠 표에 적었습니다. 마지막 단계의 L은 다섯 사람의 s를 더해 5로 나누므로, 표에는 사람 2가 L에 보태는 값만 적었습니다.

| 단계 | 계산 | 값 | 이 단계의 미분 |
|---|---|---|---|
| 예측 | Yp = W × X + B | 1 × 5 + 1 = 6 | Yp를 W로 미분하면 X = 5 |
| 오차 | e = Yp − Y | 6 − 10.3 = −4.3 | e를 Yp로 미분하면 1 |
| 제곱 | s = e² | 18.49 | s를 e로 미분하면 2e = −8.6 |
| 평균 | L = (다섯 사람의 s의 합) ÷ 5 | 사람 2가 보태는 값 18.49 ÷ 5 = 3.698 | L을 s로 미분하면 1/5 = 0.2 |

사람 2가 손실 L에 보태는 값 3.698과 `W.grad`에 보태는 값은 서로 다르고, 이 단계에서 구할 것은 뒤의 값입니다.

앞 단원에서 본 것처럼 미분은 앞 칸을 조금 바꿀 때 뒤 칸이 그 몇 배로 바뀌는지입니다. W를 0.01 키우면 변화가 이렇게 이어집니다.

- Yp는 5배인 0.05만큼 커집니다.
- e도 0.05만큼 커집니다.
- s는 −8.6배인 약 −0.43만큼 바뀝니다.
- 사람 2가 L에 보태는 값은 0.2배인 약 −0.086만큼 바뀝니다.

### 역전파: 손실 쪽에서 한 번에
<!-- facts: F04-14 F04-16 F04-17 F04-30 F04-65 -->

`W.grad`는 다섯 사람이 보태는 값의 합입니다. 앞 단계의 계산을 다섯 사람 모두에게 하되, 손실 쪽에서부터 거꾸로 갑니다.

- W 쪽은 Yp를 W로 미분한 값이 X이므로 2e ÷ 5에 X를 곱합니다.

### PyTorch로 한 걸음: backward, no_grad, zero_
<!-- facts: F04-17 F04-18 F04-31 F04-32 F04-33 F04-34 F04-35 F04-72 -->

앞의 두 단계에서 손으로 한 계산은 `loss.backward()` 한 줄이 합니다. 노트북 코드를 한 줄씩 따라가며 W, B, `W.grad`, `B.grad`가 어떻게 바뀌는지 봅니다.

```python
lr = 0.001
Yp = pred(X)
loss = mse(Yp, Y)
loss.backward()            # 경사 계산, W.grad와 B.grad를 채움
with torch.no_grad():      # 이 안의 계산은 기록하지 않음
    W -= lr * W.grad
    B -= lr * B.grad
W.grad.zero_()             # 경사를 0으로 지움
B.grad.zero_()
```

- `loss.backward()`는 경사를 계산해 `.grad`에 둘 뿐 W와 B를 바꾸지 않습니다. 값을 바꾸는 것은 그다음의 갱신 줄입니다.
- `requires_grad=True`인 W를 `W -= ...`로 바로 고치면 오류가 납니다. 그림 3의 6번 장에 적은 오류 문구에서 leaf Variable(잎 텐서)은 W처럼 사용자가 직접 만든 텐서를, in-place operation은 `-=`처럼 자기 자신을 고치는 연산을 가리킵니다. `with torch.no_grad():` 안에서는 기록을 멈추므로 고칠 수 있습니다(4차시 슬라이드 34쪽).
- PyTorch는 `backward()`를 부를 때마다 새 경사를 `.grad`에 더합니다(3차시 슬라이드 11쪽, 4차시 슬라이드 23쪽). 지우지 않으면 지난 경사가 남아 그림 3의 7번 장처럼 두 배 가까이 움직입니다.

> **[정정]** 4차시 노트북 32번 셀은 이 오류의 까닭을 W와 B의 계산이 이미 끝났기 때문이라고 설명합니다. 오류 문구가 말하듯 까닭은 경사를 기록하는 잎 텐서를 기록하는 도중에 제자리에서 고쳤기 때문이고, 4차시 슬라이드 34쪽의 설명도 이와 같습니다. 그래서 `with torch.no_grad():`로 기록을 멈추면 같은 줄이 오류 없이 실행됩니다.

### optimizer로 줄여 쓰는 표준 학습 루프
<!-- facts: F04-18 F04-40 F04-41 F04-69 -->

파라미터를 고치는 일을 맡는 PyTorch 객체를 최적화 함수(optimizer)라고 부릅니다. `torch.optim`에 들어 있고, 앞 단계의 수정과 지우기를 대신합니다.

```python
import torch.optim as optim

W = torch.tensor(1.0, requires_grad=True).float()
B = torch.tensor(1.0, requires_grad=True).float()
optimizer = optim.SGD([W, B], lr=0.001)

for epoch in range(500):
    optimizer.zero_grad()     # W.grad.zero_(), B.grad.zero_()를 대신함
    Yp = pred(X)              # ① 예측
    loss = mse(Yp, Y)         # ② 손실
    loss.backward()           # ③ 경사 계산(역전파)
    optimizer.step()          # ④ 수정, no_grad 안의 W -= lr * W.grad를 대신함
```

`optim.SGD([W, B], lr=0.001)`은 W와 B를 학습률 0.001로 고치는 optimizer를 만듭니다. `optimizer.step()`은 앞 단계의 `no_grad` 블록과 같은 계산을 하고, `optimizer.zero_grad()`는 연결된 파라미터의 경사를 지웁니다. 노트북의 결과도 W 1.820683, B 0.3675114, 손실 4.6796으로 수동 갱신과 같습니다(4차시 노트북 01의 50번 셀). 4차시 노트북은 `optimizer.zero_grad()`를 루프 맨 끝에 두는데, 맨 앞에 두어도 결과가 같은 까닭은 다음 단계에서 봅니다.

이 다섯 줄은 5차시부터의 학습 코드에 이름만 바뀌어 거듭 나옵니다. 5차시부터는 `pred` 대신 모델 `net`, `mse` 대신 `criterion`을 씁니다(5차시 슬라이드 8~9쪽).

| 이 단원 | 5차시 노트북 |
|---|---|
| `Yp = pred(X)` | `outputs = net(inputs)` |
| `loss = mse(Yp, Y)` | `loss = criterion(outputs, labels)` |
| `optim.SGD([W, B], lr=lr)` | `optim.SGD(net.parameters(), lr=lr)` |

학습 루프에서 헷갈리는 코드들을 한 표에 모았습니다.

| 코드 | 하는 일 | W, B의 값 | `.grad` |
|---|---|---|---|
| `loss.backward()` | 손실에서 거꾸로 경사를 계산합니다 | 바꾸지 않습니다 | 새 경사를 더합니다 |
| `optimizer.step()` | W ← W − lr × `W.grad`로 고칩니다 | 바꿉니다 | 건드리지 않습니다 |
| `optimizer.zero_grad()` | 연결된 파라미터의 경사를 지웁니다 | 바꾸지 않습니다 | None으로 비웁니다(PyTorch 2.x) |
| `W.grad.zero_()` | W의 경사만 지웁니다 | 바꾸지 않습니다 | 0이 됩니다 |
| `with torch.no_grad():` | 안쪽 계산을 기록하지 않습니다 | 안에서 직접 고칠 수 있게 합니다 | 바꾸지 않습니다 |

> **[정정]** 4차시 슬라이드 42쪽과 노트북의 주석은 이 optimizer를 확률적 경사하강법이라고 부릅니다. SGD는 Stochastic Gradient Descent(확률적 경사하강법)의 줄임말이 맞지만, 이 예는 다섯 사람을 모두 써서 경사를 구하므로 실제 계산은 전체 데이터로 하는 경사하강법입니다. "확률적"은 데이터 일부를 무작위로 뽑아 경사를 구할 때 붙는 이름이고, 데이터를 작은 묶음으로 나눠 쓰는 방법은 5차시에서 배웁니다.

### 코드 읽기: zero_grad의 자리와 None
<!-- facts: F04-35 F04-44 F04-67 F04-68 F04-72 -->

노트북에 자주 나오지만 슬라이드가 따로 설명하지 않는 코드를 읽어 봅니다. `optimizer.zero_grad()`는 노트북마다 자리가 다릅니다. 4차시 노트북 01은 루프 맨 끝(step 뒤)에, 5차시부터의 노트북은 루프 맨 앞에 둡니다(5차시 노트북 01의 18번 셀). backward는 경사를 `.grad`에 더하므로, 이번 `backward()`를 부르기 전에 지난 경사가 지워져 있기만 하면 두 자리의 결과는 같습니다. 세 단원은 5차시부터 쓰는 자리인 루프 맨 앞에 둡니다.

```figure
파일: assets/4c-5.png
캡션: 그림 5. zero_grad를 루프 맨 앞에 둘 때와 맨 끝에 둘 때
내용: 두 열. 왼쪽은 zero_grad 를 맨 앞에 둔 루프, 오른쪽은 맨 끝에 둔 4차시 노트북 루프. 줄마다 그 줄 뒤의 W.grad(None, −19.04, 둘째 바퀴 −18.598). backward 바로 앞 줄을 노랗게 칠해 두 자리 모두 그때 W.grad 가 None 임을 보임.
```

PyTorch 2.0부터 `optimizer.zero_grad()`는 경사를 0으로 채우지 않고 `None`으로 비웁니다(기본값 `set_to_none=True`). 그래서 PyTorch 2.x에서 `optimizer.zero_grad()` 직후 `print(W.grad)`를 하면 `None`이 찍히고, 4차시 노트북 주석처럼 0으로 채우는 것은 1.x의 기본 동작입니다. 앞에서 본 `W.grad.zero_()`는 0을 채워 `tensor(0.)`가 찍힙니다. 4차시 과제 4번을 완성해 실행하면 마지막 줄의 경사가 `None`으로 찍힙니다.

`with torch.no_grad():`는 갱신 말고도 쓰입니다. 블록 안의 계산을 기록하지 않으므로, 학습이 끝난 모델로 예측만 할 때도 이 블록을 씁니다. 그 쓰임은 10차시 평가 코드에서 다시 봅니다.
