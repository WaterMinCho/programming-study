### 계산할 기울기와 바꿀 가중치는 별도 목록입니다
<!-- facts: F14-201 F14-202 F14-203 F14-204 -->

5차시에서 backward는 기울기를 계산하고 optimizer.step은 등록한 가중치를 바꿨습니다. `requires_grad=True`는 기울기를 계산할 수 있게 합니다. 옵티마이저에 파라미터를 넘기는 코드는 그 옵티마이저가 갱신할 대상을 정합니다.

<u>모든 층의 기울기를 계산해도 fc만 전달하면 fc만 갱신합니다.</u> 이때 optimizer.zero_grad도 등록한 fc의 기울기만 비웁니다. 백본의 기울기를 계산하는 설정과 실제 갱신 대상을 따로 확인하세요.

전체 파라미터를 갱신하려면 optimizer에도 `model.parameters()`로 전체 대상을 전달합니다. fc만 전달한 optimizer는 백본의 기울기를 지우거나 백본을 갱신하지 않습니다.

### 기존 가중치와 새 가중치에 다른 보폭을 줍니다

### 그룹의 lr를 기본값보다 먼저 적용합니다

### 객체 식별자로 그룹을 나눕니다
<!-- facts: F14-301 F14-302 F14-303 -->

파라미터 텐서의 값을 비교하는 대신 `id(p)`로 같은 객체인지 확인합니다. 아래 코드에서 head는 fc, last는 layer4의 파라미터 목록입니다. 두 목록에 넣은 객체의 식별자를 used에 모은 뒤 나머지를 rest에 넣습니다. rest에는 conv1과 bn1도 들어갑니다.

파라미터를 차례로 꺼내는 iterator는 한 번 소진하면 다시 꺼낼 수 없습니다. `model.parameters()`를 다시 호출하면 새로운 iterator를 받습니다. 그룹들의 교집합으로 중복 등록을 확인하고 합집합으로 학습 대상이 빠지지 않았는지 확인합니다.

```python
head = list(model.fc.parameters())
last = list(model.layer4.parameters())
used = {id(p) for p in head + last}
rest = [p for p in model.parameters() if id(p) not in used]
groups = [{"params": head, "lr": 0.01},
          {"params": last, "lr": 0.001},
          {"params": rest, "lr": 0.0001}]
```

### 그룹별로 다른 함수가 필요하면 목록을 전달합니다

```python
f = lambda e: 1.0 if e < 3 else 0.1

    scheduler.step()
```

### 백본은 평가하고 분류기는 학습합니다
<!-- facts: F14-801 F14-802 F14-803 -->

ResNet-18 전체 파라미터를 고정한 뒤 새 fc만 기울기를 계산한다고 가정합니다. 매 에폭 시작에 아래처럼 모델을 eval로 두고 fc만 train으로 바꾸면 백본의 기본 BN 통계를 고정할 수 있습니다. fc가 Linear 하나이면 모드에 따른 계산 차이는 없지만 Dropout이 든 새 분류기라면 이 구분이 동작을 바꿉니다.

<u>eval은 BN과 Dropout의 동작을 바꾸는 모드 설정입니다. 새 역전파 그래프 기록을 끄는 no_grad와 구분합니다.</u> 아래 코드는 no_grad로 감싸지 않아서 새 fc의 기울기를 계산하고 갱신합니다.

```python
model.eval()
model.fc.train()
optimizer.zero_grad(set_to_none=True)
logits = model(images)
loss = criterion(logits, labels)
loss.backward()
optimizer.step()
```

### 평가에는 모드 전환과 기록 중단을 같이 씁니다
<!-- facts: F14-801 F14-802 F14-803 -->

검증 때는 model.eval과 no_grad를 함께 씁니다. 아래 코드는 평가 모드를 정한 뒤 모델 출력과 손실을 구하는 동안 새 역전파 그래프를 기록하지 않습니다. labels는 배치 길이의 long 클래스 번호, logits는 배치×클래스의 실수 점수로 둡니다.

학습 때 backbone 출력만 no_grad로 계산해도 그 뒤 head를 범위 밖에서 계산하면 head의 가중치 기울기를 만들 수 있습니다. 반대로 head 계산까지 no_grad 안에 넣으면 일반적인 head 학습도 역전파하지 못합니다.

```python
model.eval()
with torch.no_grad():
    logits = model(images)
    loss = criterion(logits, labels)
```
