### 가중치 행렬의 행 하나가 logit 하나를 만듭니다
<!-- facts: F09-03 F09-04 F09-05 F09-82 -->

앞 단계에서 클래스가 3개이면 모델이 숫자 3개를 냈습니다. 4차시 첫째 단원의 선형 모델은 입력에 W를 곱하고 B를 더해 숫자 하나를 냈습니다. PyTorch에서는 5차시 첫째 단원에서 본 것처럼 W가 weight, B가 bias입니다. 특징이 두 개이면 특징마다 곱할 가중치가 하나씩 있어서 가중치는 [w1, w2]처럼 숫자 두 개입니다. 클래스가 셋이면 이런 가중치가 클래스마다 하나씩 셋 필요합니다. 클래스마다 하나씩 있는 가중치를 한 행씩 쌓은 행렬을 <mark>가중치 행렬</mark>(weight matrix)이라고 부릅니다.

특징 두 개가 x = [1, 2]인 데이터 하나로 따라갑니다. 클래스마다 가중치 행과 x를 곱해 더하고 bias를 더합니다.

| 클래스 | 가중치 행 | bias | logit |
|---|---|---|---|
| 0 | [1, 1] | −1 | 1 × 1 + 1 × 2 − 1 = 2 |
| 1 | [0, 1] | −1 | 0 × 1 + 1 × 2 − 1 = 1 |
| 2 | [1, −1] | 1 | 1 × 1 − 1 × 2 + 1 = 0 |


x = [1, 2]의 logit은 [2, 1, 0]입니다. 둘째 단원부터 이 logit을 확률과 손실로 바꿔 봅니다.

### 소프트맥스는 e의 거듭제곱을 합으로 나눕니다
<!-- facts: F09-06 F09-07 F09-10 F09-51 -->

첫째 단원 3단계에서 x = [1, 2]의 logit은 [2, 1, 0]이었습니다. logit은 음수도 될 수 있고 더해도 1이 되지 않아 확률로 읽을 수 없습니다. 6차시 셋째 단원의 시그모이드 식에 나온 e는 약 2.718인 수입니다. e^(logit)은 e를 logit만큼 거듭제곱한 값입니다. logit마다 e^(logit)을 구하고, 그 값을 모든 클래스의 e^(logit)을 더한 수로 나눠 확률을 만드는 함수를 소프트맥스(softmax)라고 부릅니다. 6차시 넷째 단원 2단계에서는 이름만 보고 식은 이 차시로 미뤘습니다.

**클래스 i의 확률 = e^(클래스 i의 logit) ÷ (모든 클래스의 e^(logit)을 더한 값)**

### 확률의 비는 logit의 차이로 정해집니다
<!-- facts: F09-70 F09-71 F09-65 -->

앞 단계의 [0.665, 0.245, 0.090]은 logit [2, 1, 0]의 비율 2 : 1 : 0과 맞을까요? 2 : 1 : 0을 합 3으로 나누면 [0.667, 0.333, 0]이라 소프트맥스의 0.245, 0.090과 맞지 않습니다. 첫째 값 0.667과 0.665가 비슷한 것은 우연입니다. logit을 두 배로 한 [4, 2, 0]도 비율은 2 : 1 : 0이지만, 소프트맥스는 [0.867, 0.117, 0.016]입니다.

두 클래스의 확률을 나누면 분모가 같아서 지워지고 e^(첫 logit) ÷ e^(둘째 logit)이 남습니다. e의 거듭제곱끼리 나누면 지수끼리 빼서 e^a ÷ e^b = e^(a − b)이므로, 남는 값은 e^(두 logit의 차이)입니다. 클래스 0과 클래스 1은 logit이 1 차이라 클래스 0의 확률은 클래스 1의 확률의 e¹ ≈ 2.718배입니다. 그래서 logit이 큰 클래스가 늘 확률도 크고, logit의 크기 순서와 확률의 크기 순서가 같습니다.

<u>모든 logit에 같은 수를 더해도 차이는 바뀌지 않습니다.</u> [2, 1, 0]에 10씩 더한 [12, 11, 10]의 소프트맥스도 [0.665, 0.245, 0.090]입니다.

### 다른 클래스에도 확률을 나눠 주고, 클래스가 둘이면 시그모이드와 같습니다

앞 단계에서 logit이 1 크면 확률이 e배였습니다. 그래서 logit이 가장 큰 클래스가 가장 큰 확률을 받습니다. e^(logit)은 언제나 0보다 커서 나머지 클래스도 0보다 큰 확률을 받습니다. 가장 큰 값만 1로 두고 나머지를 0으로 만들면 [2, 1, 0]은 [1, 0, 0]이 됩니다. 소프트맥스는 [0.665, 0.245, 0.090]처럼 나머지 클래스에도 확률을 나눠 줍니다. 이처럼 가장 큰 값 이외에도 확률을 나눠 주는 성질을 이름의 soft로 나타냅니다.

6차시 셋째 단원 3단계에서 logit 2를 시그모이드에 넣으면 p = 0.8808이었습니다. logit [2, 0]을 소프트맥스에 넣으면 클래스 0의 확률은 e² ÷ (e² + e⁰) = 0.8808로 같습니다. 분자와 분모를 e²으로 나누면 1 ÷ (1 + e^(−2))가 되어 시그모이드 식이 나옵니다. 클래스가 둘이면 소프트맥스는 두 logit의 차이를 시그모이드에 넣은 값과 같습니다.

시그모이드는 이진 분류에서 logit 하나를, 소프트맥스는 다중 분류에서 logit 여러 개를 확률로 바꿉니다. 소프트맥스는 다중 분류 모델의 출력 점수를 확률로 바꾸는 활성화 함수입니다. PyTorch 코드에서는 6차시 넷째 단원처럼 `nn.CrossEntropyLoss()`가 소프트맥스를 안에서 계산하므로 모델 끝에 소프트맥스를 두지 않습니다.

### 배치에서는 dim=1로 행마다 합이 1입니다
<!-- facts: F09-34 F09-35 F09-25 F09-55 -->

앞 단계까지는 데이터 하나의 logit이었습니다. 데이터 두 개를 한 번에 넣으면 6차시 넷째 단원 3단계처럼 출력은 데이터마다 한 행, 클래스마다 한 열인 [2, 3] 모양입니다. 둘째 데이터의 logit을 [0.5, 0.2, 1.5]라고 합시다.

```python

                       [0.5, 0.2, 1.5]])   # [데이터 2, 클래스 3]
```

### 로그 소프트맥스는 logit에서 로그 확률을 바로 냅니다
<!-- facts: F09-38 F09-76 F09-60 F09-52 -->

둘째 단원 2단계의 확률을 반올림하기 전 값으로 log에 넣으면 [−0.4076, −1.4076, −2.4076]입니다. 6차시 넷째 단원 2단계처럼 정답이 클래스 0이면 −0.4076의 부호를 바꾼 0.4076이 손실입니다.

logit에서 소프트맥스 확률의 log를 한 번에 계산하는 함수를 <mark>로그 소프트맥스</mark>(log softmax)라고 부릅니다. PyTorch에서는 함수 `F.log_softmax`와 층 `nn.LogSoftmax`가 이 계산을 합니다. `F`는 `import torch.nn.functional as F`로 불러온 모듈입니다.

### NLLLoss는 정답 칸의 값을 골라 부호를 바꿉니다
<!-- facts: F09-26 F09-27 F09-28 F09-61 F09-56 F09-81 -->

앞 단계의 로그 소프트맥스 값에서 정답 칸을 골라 부호를 바꾸는 일은 `nn.NLLLoss()`가 맡습니다. NLL은 음의 로그 가능도(Negative Log Likelihood)의 머리글자입니다. 데이터가 여럿이면 데이터마다 정답 칸 값의 부호를 바꿔 평균을 냅니다(PyTorch 문서 NLLLoss). 둘째 단원 5단계의 데이터 두 개로 따라갑니다.

```python
logits = torch.tensor([[2.0, 1.0, 0.0],
                       [0.5, 0.2, 1.5]])
labels = torch.tensor([0, 2])                 # 클래스 번호
log_probs = F.log_softmax(logits, dim=1)      # [[-0.4076, -1.4076, -2.4076],
                                              #  [-1.4949, -1.7949, -0.4949]]
nn.NLLLoss()(log_probs, labels)               # tensor(0.4513)
```

코드의 `log_probs`는 행마다 데이터 하나를 놓고 열마다 클래스를 놓은 표입니다. `labels`의 [0, 2]는 데이터마다 고를 클래스 번호입니다. 첫째 행에서는 0번 칸을 고르고 둘째 행에서는 2번 칸을 고릅니다.

데이터 1은 0번 칸의 −0.4076을, 데이터 2는 2번 칸의 −0.4949를 골라 부호를 바꿉니다. 두 값 0.4076과 0.4949의 평균은 0.4513입니다. `nn.NLLLoss()(log_probs, labels)`가 이 고르기와 평균 계산을 합니다.

정답은 원-핫 벡터로 바꾸지 않고 클래스 번호를 [배치] 모양의 long으로 넣습니다. 클래스마다 확률을 넣는 표와 달리 데이터마다 번호 하나만 필요합니다.

### CrossEntropyLoss는 로그 소프트맥스와 NLLLoss를 이은 손실입니다
<!-- facts: F09-30 F09-31 F09-32 F09-33 F09-58 F09-79 F09-14 -->

앞 두 단계를 이으면 logit [2, 1, 0], 정답 0에서 로그 소프트맥스와 NLLLoss가 0.4076을 냅니다. 6차시 넷째 단원의 `nn.CrossEntropyLoss()`에 같은 logit과 정답을 넣어도 0.4076이 나옵니다. PyTorch 문서도 클래스 번호를 정답으로 줄 때 CrossEntropyLoss가 입력에 LogSoftmax를 쓰고 NLLLoss를 이어 계산한 것과 같다고 적습니다.

같은 붓꽃 분류를 모델 출력과 손실 함수의 짝이 다른 세 패턴으로 비교합니다. 이 비교에서는 붓꽃 특징 넷을 모두 받는 `nn.Linear(4, 3)`을 씁니다. 일곱째 단원 3단계에서 특징 둘을 쓰는 모델과도 비교합니다.

```python
# 패턴 1: 모델은 logit을 내고, 손실이 로그 소프트맥스까지 계산
criterion = nn.CrossEntropyLoss()
loss = criterion(net(inputs), labels)

# 패턴 2: 모델 끝에 nn.LogSoftmax(dim=1), 손실은 정답 칸 고르기만
criterion = nn.NLLLoss()
loss = criterion(net(inputs), labels)        # net 출력이 로그 확률

# 패턴 3: 모델 끝에 nn.Softmax(dim=1), log는 루프에서 따로
criterion = nn.NLLLoss()
loss = criterion(torch.log(net(inputs)), labels)
```

### 큰 logit은 가장 큰 값을 빼고 계산합니다
<!-- facts: F09-37 F09-38 F09-59 F09-77 -->

앞 단계의 패턴 3은 소프트맥스 확률을 먼저 만들고 log를 씌웁니다. logit [1000, 999, 995]로 이 순서를 시험합니다. 컴퓨터가 흔히 쓰는 32비트 실수(float32)가 나타낼 수 있는 가장 큰 수는 약 3.4 × 10³⁸이고, e^1000은 약 2 × 10⁴³⁴입니다. 그래서 `torch.exp`로 e^(logit)을 바로 계산하면 셋 다 무한대(inf)가 되고, 합으로 나누면 숫자가 아닌 값(nan)이 됩니다.

둘째 단원 3단계처럼 모든 logit에서 같은 수를 빼도 소프트맥스는 같습니다. 가장 큰 값 1000을 빼면 [0, −1, −5]가 되고 e^(logit)은 [1, 0.3679, 0.0067]이라 1을 넘지 않습니다. 합 1.3746의 log는 0.3182이고, 정답 0의 로그 소프트맥스는 0 − 0.3182라서 손실은 0.3182입니다. 앞 단락의 inf와 nan은 logit [1000, 999, 995]의 e^(logit)이 float32로 나타낼 수 없을 만큼 커서 생겼습니다. 이렇게 계산 중간의 값이 float32로 나타낼 수 있는 범위를 벗어나 결과가 틀어질 수 있는 계산을 수치적으로 불안정한 계산이라고 부릅니다. PyTorch 문서는 log와 소프트맥스를 따로 계산하면 느리고 수치적으로 불안정하다고 적습니다. 그래서 `F.log_softmax`는 다른 식으로 계산합니다. 가장 큰 값을 빼고 계산하는 이 방법은 6차시 셋째 단원에서 본 log-sum-exp 트릭입니다.

### 정답 분포와 예측 분포의 차이를 KL divergence로 잽니다
<!-- facts: F09-39 F09-40 F09-41 F09-62 F09-86 -->

셋째 단원 2단계에서 정답이 클래스 0인 데이터의 손실은 0.4076이었습니다. 이 손실을 만든 소프트맥스 확률 [0.665, 0.245, 0.090]은 모두 0 이상이고 더하면 1입니다. 이렇게 클래스마다 확률을 하나씩 두고 모두 더하면 1인 값의 묶음을 확률 분포라고 부릅니다. 정답도 확률 분포로 쓸 수 있습니다. 클래스 0이 정답이면 정답 분포 P는 원-핫 벡터 [1, 0, 0]이고, 모델이 낸 예측 분포 Q는 [0.665, 0.245, 0.090]입니다. 두 확률 분포 P와 Q에서 클래스마다 P × log(P ÷ Q)를 구해 더한 값을 <mark>KL divergence</mark>라고 부릅니다. P를 기준으로 Q와 견준 값이라 KL(P‖Q)로 적습니다.

P가 0인 칸은 Q가 0이어도 그 항을 0으로 셉니다. P가 양수인 칸의 Q는 양수여야 KL이 유한합니다. 그 칸에서 Q가 0이면 KL은 +∞입니다. 이 예제의 Q는 모든 칸이 양수입니다. 남는 것은 정답 칸의 1 × log(1 ÷ Q) = −log Q입니다. 정답 칸의 Q를 반올림하기 전 값으로 넣으면 0.4076이고, 셋째 단원 2단계의 교차 엔트로피와 같은 값입니다. 예측 분포를 Q = [0.7, 0.2, 0.1]로 바꿔 log(1 ÷ 0.7) = 0.3567을 얻습니다. 이 단원 4단계의 코드도 이 Q를 씁니다. 두 분포가 같으면 P가 양수인 칸마다 log 1 = 0이고 P가 0인 칸은 0으로 세어 KL divergence는 0입니다. 값이 작을수록 두 분포가 비슷합니다.

### KL divergence는 방향을 바꾸면 값이 달라질 수 있습니다
<!-- facts: F09-69 F09-68 -->

앞 단계의 P는 원-핫 벡터였습니다. 6차시 넷째 단원 4단계의 라벨 스무딩처럼 정답 분포도 여러 클래스에 확률을 나눠 가질 수 있습니다. P = [0.6, 0.3, 0.1], Q = [0.7, 0.2, 0.1]로 KL(P‖Q)와 KL(Q‖P) 두 방향을 계산합니다.

- KL(P‖Q) = 0.6 × log(0.6 ÷ 0.7) + 0.3 × log(0.3 ÷ 0.2) + 0.1 × log(0.1 ÷ 0.1) = −0.0925 + 0.1216 + 0 = 0.0291
- KL(Q‖P) = 0.7 × log(0.7 ÷ 0.6) + 0.2 × log(0.2 ÷ 0.3) + 0.1 × log(0.1 ÷ 0.1) = 0.1079 − 0.0811 + 0 = 0.0268

방향을 바꾸면 0.0291이 0.0268로 바뀝니다. 손실로 쓸 때는 정답 분포를 P 자리에 둡니다.

### F.kl_div에는 log를 씌운 Q를 먼저 넣습니다
<!-- facts: F09-42 F09-62 F09-69 F09-85 -->

앞 단계까지 손으로 구한 KL divergence를 PyTorch에서는 `F.kl_div`로 계산합니다. 2단계의 P = [1, 0, 0], Q = [0.7, 0.2, 0.1]로 이렇게 씁니다.

```python
P = torch.tensor([1.0, 0.0, 0.0])            # 정답 분포
Q = torch.tensor([0.7, 0.2, 0.1])            # 예측 분포
F.kl_div(torch.log(Q), P, reduction='sum')   # tensor(0.3567)
```

첫 인자는 예측 분포의 로그 확률, 둘째 인자는 정답 분포입니다. 이 코드의 Q는 모든 원소가 양수여서 torch.log(Q)를 계산합니다. 모델의 logit에서 로그 확률을 구할 때는 앞 단원의 F.log_softmax로 작은 확률이 먼저 0이 되는 문제를 줄입니다. 수식 KL(P‖Q)는 P를 앞에 적지만 코드는 log Q를 앞에 넣어서 순서를 바꿔 넣기 쉽습니다. `reduction='sum'`은 클래스마다 구한 값을 더해 정의와 같은 0.3567을 냅니다.

```figure
파일: assets/9d-3.png
캡션: 그림 3. F.kl_div의 두 인자와 수식 KL(P‖Q)의 자리. 주황은 예측 분포 Q, 초록은 정답 분포 P입니다.
내용: 위 줄에 F.kl_div(torch.log(Q), P, reduction='sum') 코드. 첫째 인자 아래 주황 상자 예측 분포의 로그 확률, 둘째 인자 아래 초록 상자 정답 분포. 아래 줄에 수식 KL(P‖Q) = Σ P × log(P ÷ Q) 의 P 와 Q 자리를 같은 색으로 칠하고 결과 0.3567.
```

`reduction='mean'`은 합을 원소 수로 나누고 `'batchmean'`은 입력의 0번 축 크기로 나눕니다. 입력이 `[배치, 클래스]`이면 `'batchmean'`으로 데이터마다 구한 KL divergence의 평균을 냅니다. 이 단원의 P와 Q는 클래스 3개만 있는 1차원 배열이므로 데이터 하나의 KL divergence를 구할 때 `'sum'`을 씁니다.

### torch.max(outputs, 1)의 indices가 예측 클래스입니다
<!-- facts: F09-19 F09-20 F09-21 F09-22 -->

둘째 단원 5단계의 logit은 데이터가 2개라 [2, 3] 모양이었습니다. 이 예제에서 학습 데이터 75송이를 넣으면 출력은 [75, 3]입니다. 데이터 네 개의 logit과 정답으로 예측 클래스를 골라 봅니다.

```python
outputs = torch.tensor([[2.0, 1.0, 0.0],
```

### 정확도는 맞힌 수를 데이터 수로 나눕니다
<!-- facts: F09-23 -->

2단계의 예측 [0, 1, 2, 1]을 정답 [0, 1, 1, 0]과 견줍니다.

```python
predicted = torch.max(outputs, 1)[1]           # tensor([0, 1, 2, 1])
predicted == labels                            # tensor([True, True, False, False])
correct = (predicted == labels).sum().item()   # 2
accuracy = correct / len(labels)               # 0.5
```

`predicted == labels`는 자리마다 같은지를 True와 False로 냅니다. `.sum()`이 True의 개수 2를 세고 `.item()`이 파이썬 숫자로 꺼냅니다. 데이터 수 4로 나누면 정확도 0.5입니다. 상황별 코드 첫째 단원 4단계에서 맞힌 수를 세는 줄과 같은 계산입니다. `.item()` 없이 `(predicted == labels).sum() / len(labels)`로 나눠서 정확도가 원소 하나짜리 텐서로 남지만, 찍히는 값은 같습니다.

### wine 다층 신경망: 13-64-32-3과 파라미터 3,075개

앞 단계까지의 모델은 `nn.Linear` 층 하나였습니다. 다음 모델은 와인 178병의 특징 13개로 품종 3개를 맞히는 데 은닉층 둘을 쌓습니다. X는 특징을 담은 (178, 13) 배열이고 y는 품종 번호입니다. `np.bincount(y)`는 정답 0, 1, 2가 몇 번 나오는지 세어 [59, 71, 48]을 돌려줍니다.


첫 줄이 테스트 데이터를 떼고, 둘째 줄이 남은 142병에서 검증 데이터를 뗍니다. 분할 결과는 학습 106병, 검증 36병, 테스트 36병입니다. 178 × 0.2 = 35.6과 142 × 0.25 = 35.5를 올림해 36병씩 뗍니다. 세 묶음의 비율은 6 : 2 : 2쯤입니다. `stratify`는 5차시 일곱째 단원 2단계처럼 나눈 두 묶음의 클래스 비율을 y의 비율에 가깝게 맞춥니다.

아래는 와인 특징을 받는 모델 코드입니다. 클래스 이름 WineNet과 층 이름은 이 노트에서 붙였습니다.

```python
class WineNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(13, 64)    # 13 × 64 + 64 = 896개
        self.fc2 = nn.Linear(64, 32)    # 64 × 32 + 32 = 2,080개
        self.fc3 = nn.Linear(32, 3)     # 32 × 3 + 3 = 99개
        self.relu = nn.ReLU()
        self.drop = nn.Dropout(0.3)     # 만들어 두기만 함

    def forward(self, x):
        x = self.relu(self.fc1(x))
        # x = self.drop(x)              # 주석 처리해 Dropout을 호출하지 않음
        x = self.relu(self.fc2(x))
        return self.fc3(x)              # logit 3개
```

`p.numel()`은 파라미터 텐서 하나에 든 숫자 개수를 셉니다. `sum(p.numel() for p in model.parameters())`로 모든 파라미터를 더하면 896 + 2,080 + 99 = 3,075입니다. ReLU와 Dropout은 학습 파라미터가 없어서 이 합에 들지 않습니다. 이 예제는 Adam(lr=0.001)으로 2,000 에폭 학습합니다.

### 평가 함수와 표준화 결과 받기
<!-- facts: F09-49 F09-22 F09-80 -->

앞 단계의 모델은 다음 함수로 평가합니다.

```python
def evaluate(model, x, y):
    model.eval()                              # 평가할 때의 동작으로
    with torch.no_grad():                     # 기울기 계산 기록을 끔
        out = model(x)
        loss = criterion(out, y)
        _, predicted = torch.max(out, 1)      # 클래스 번호만 받음
        correct = (predicted == y).sum().item()
    return loss.item(), correct / len(y)
```

`model.eval()`은 5차시 여섯째 단원 4단계처럼 층을 평가할 때의 동작으로 바꾸고, `torch.no_grad()`는 3차시 일곱째 단원 6단계처럼 기울기 계산 기록을 끕니다. 평가에서는 backward를 부르지 않아 기울기 계산 기록이 필요 없고, Dropout 같은 층도 평가할 때의 동작으로 바꿔야 해서 둘을 함께 씁니다.


학습·검증·테스트에 표준화한 값을 쓰려면 변환 결과를 x_train, x_val, x_test에 받습니다.

```python
scaler = StandardScaler()
x_train = scaler.fit_transform(x_train)   # 돌려준 값을 x_train에 받음
x_val = scaler.transform(x_val)
x_test = scaler.transform(x_test)
```

`fit_transform`은 표준화한 새 배열을 돌려주고, 기본 설정 `copy=True`에서는 넣은 배열을 바꾸지 않습니다(scikit-learn 문서 StandardScaler). 5차시 일곱째 단원 2단계처럼 돌려준 값을 x_train에 다시 받아야 표준화한 값으로 학습합니다.
