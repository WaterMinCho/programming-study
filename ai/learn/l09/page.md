### 가중치 행렬의 행 하나가 logit 하나를 만듭니다
<!-- facts: F09-03 F09-04 F09-05 F09-82 -->

앞 단계에서 클래스가 3개이면 모델이 숫자 3개를 냈습니다. 4차시 첫째 단원의 선형 모델은 입력에 W를 곱하고 B를 더해 숫자 하나를 냈습니다. PyTorch에서는 5차시 첫째 단원에서 본 것처럼 W가 weight, B가 bias입니다. 특징이 두 개이면 특징마다 곱할 가중치가 하나씩 있어서 가중치는 [w1, w2]처럼 숫자 두 개입니다. 클래스가 셋이면 이런 가중치가 클래스마다 하나씩 셋 필요합니다. 클래스마다 하나씩 있는 가중치를 한 행씩 쌓은 행렬을 가중치 행렬(weight matrix)이라고 부릅니다(9차시 슬라이드 6쪽).

특징 두 개가 x = [1, 2]인 데이터 하나로 따라갑니다. 클래스마다 가중치 행과 x를 곱해 더하고 bias를 더합니다.

| 클래스 | 가중치 행 | bias | logit |
|---|---|---|---|
| 0 | [1, 1] | −1 | 1 × 1 + 1 × 2 − 1 = 2 |
| 1 | [0, 1] | −1 | 0 × 1 + 1 × 2 − 1 = 1 |
| 2 | [1, −1] | 1 | 1 × 1 − 1 × 2 + 1 = 0 |

```figure
파일: assets/9a-2.gif
캡션: 그림 2. 가중치 행렬로 logit 세 개 만들기. 회색은 입력 x, 주황 테두리는 지금 계산하는 행, 파랑은 logit입니다.
프레임:
1. 입력 x = [1, 2]와 3 × 2 가중치 행렬, bias 세 개입니다. (2000ms)
2. 0번 행 [1, 1]과 x를 곱해 더하면 3이고, bias −1을 더해 logit 2가 나옵니다. (2200ms)
3. 1번 행 [0, 1]과 x를 곱해 더하면 2이고, bias −1을 더해 logit 1이 나옵니다. (2200ms)
4. 2번 행 [1, −1]과 x를 곱해 더하면 −1이고, bias 1을 더해 logit 0이 나옵니다. (2200ms)
5. 행이 셋이라 logit도 [2, 1, 0] 셋입니다. (2500ms)
```

x = [1, 2]의 logit은 [2, 1, 0]입니다. 둘째 단원부터 이 logit을 확률과 손실로 바꿔 봅니다.

```python
layer = nn.Linear(2, 3)    # 입력 2개, 출력 3개
layer.weight.shape         # torch.Size([3, 2])
layer.bias.shape           # torch.Size([3])
```

`nn.Linear(2, 3)`의 weight는 [출력 수, 입력 수]인 [3, 2] 모양이고 행 하나가 클래스 하나를 맡습니다(PyTorch 문서 Linear). bias는 클래스마다 하나씩 3개입니다. 학습 파라미터는 2 × 3 + 3 = 9개이고, 노트북 01의 27번 셀 summary도 9를 찍습니다.

### 소프트맥스는 e의 거듭제곱을 합으로 나눕니다
<!-- facts: F09-06 F09-07 F09-10 F09-51 -->

첫째 단원 3단계에서 x = [1, 2]의 logit은 [2, 1, 0]이었습니다. logit은 음수도 될 수 있고 더해도 1이 되지 않아 확률로 읽을 수 없습니다. 6차시 셋째 단원의 시그모이드 식에 나온 e는 약 2.718인 수입니다. e^(logit)은 e를 logit만큼 거듭제곱한 값입니다. logit마다 e^(logit)을 구하고, 그 값을 모든 클래스의 e^(logit)을 더한 수로 나눠 확률을 만드는 함수를 소프트맥스(softmax)라고 부릅니다(9차시 슬라이드 7쪽). 6차시 넷째 단원 2단계에서는 이름만 보고 식은 이 차시로 미뤘습니다.

**클래스 i의 확률 = e^(클래스 i의 logit) ÷ (모든 클래스의 e^(logit)을 더한 값)**

```figure
파일: assets/9b-1.gif
캡션: 그림 1. logit [2, 1, 0]이 확률이 되기까지. 파랑은 logit, 보라는 e^(logit), 주황은 확률입니다.
프레임:
1. 파랑 막대는 첫째 단원에서 만든 logit [2, 1, 0]입니다. (2000ms)
2. e를 logit만큼 거듭제곱하면 보라 막대 [7.389, 2.718, 1]입니다. logit 0도 e⁰ = 1이 됩니다. (2200ms)
3. 세 값을 더하면 11.107입니다. (2000ms)
4. 세 값을 11.107로 나누면 주황 막대 [0.665, 0.245, 0.090]입니다. (2200ms)
5. 세 확률을 더하면 1입니다. (2500ms)
```

### 확률의 비는 logit의 차이로 정해집니다
<!-- facts: F09-70 F09-71 F09-65 -->

### NLLLoss는 정답 칸의 값을 골라 부호를 바꿉니다

앞 단계의 로그 소프트맥스 값에서 정답 칸을 골라 부호를 바꾸는 일은 `nn.NLLLoss()`가 맡습니다. NLL은 음의 로그 가능도(Negative Log Likelihood)의 머리글자입니다(9차시 슬라이드 15쪽). 데이터가 여럿이면 데이터마다 정답 칸 값의 부호를 바꿔 평균을 냅니다(PyTorch 문서 NLLLoss). 둘째 단원 5단계의 데이터 두 개로 따라갑니다.

```python
logits = torch.tensor([[2.0, 1.0, 0.0],
                       [0.5, 0.2, 1.5]])
labels = torch.tensor([0, 2])                 # 클래스 번호
log_probs = F.log_softmax(logits, dim=1)      # [[-0.4076, -1.4076, -2.4076],
                                              #  [-1.4949, -1.7949, -0.4949]]
nn.NLLLoss()(log_probs, labels)               # tensor(0.4513)
```

데이터 1은 0번 칸의 −0.4076을, 데이터 2는 2번 칸의 −0.4949를 골라 부호를 바꿉니다. 두 값 0.4076과 0.4949의 평균은 0.4513입니다(노트북 02의 13번 셀). 정답은 원-핫 벡터로 바꾸지 않고 클래스 번호를 [배치] 모양의 long으로 넣습니다.

### CrossEntropyLoss는 로그 소프트맥스와 NLLLoss를 이은 손실입니다
<!-- facts: F09-30 F09-31 F09-32 F09-33 F09-58 F09-79 F09-14 -->

앞 두 단계를 이으면 logit [2, 1, 0], 정답 0에서 로그 소프트맥스와 NLLLoss가 0.4076을 냅니다. 6차시 넷째 단원의 `nn.CrossEntropyLoss()`에 같은 logit과 정답을 넣어도 0.4076이 나옵니다(노트북 02의 11번 셀). PyTorch 문서도 클래스 번호를 정답으로 줄 때 CrossEntropyLoss가 입력에 LogSoftmax를 쓰고 NLLLoss를 이어 계산한 것과 같다고 적습니다.

노트북 01의 76~90번 셀은 같은 붓꽃 모델을 세 가지 짝으로 만듭니다(9차시 슬라이드 16쪽). 76~90번 셀은 57번 셀에서 입력을 붓꽃 특징 4개로 바꾼 뒤에 실행되어서, 모델은 특징 2개가 아니라 4개를 받는 `nn.Linear(4, 3)`입니다. 특징 4개 모델은 일곱째 단원 3단계에서 특징 2개 모델과 견줍니다.

```python
# 패턴 1: 모델은 logit을 내고, 손실이 로그 소프트맥스까지 계산
criterion = nn.CrossEntropyLoss()
loss = criterion(net(inputs), labels)

# 패턴 2: 모델 끝에 nn.LogSoftmax(dim=1), 손실은 정답 칸 고르기만
criterion = nn.NLLLoss()
loss = criterion(net(inputs), labels)        # net 출력이 로그 확률

# 패턴 3: 모델 끝에 nn.Softmax(dim=1), log는 루프에서 따로
criterion = nn.NLLLoss()
loss = criterion(torch.log(net(inputs)), labels)
```

특징 4개로 학습한 세 패턴은 검증 손실 0.14243과 정확도 0.96을 똑같이 얻습니다(노트북 01의 62·83·89번 셀). 슬라이드는 패턴 1을 권하고 패턴 3은 권하지 않습니다. 패턴 2는 패턴 1과 같은 결과를 낸다고 적습니다. 패턴 2의 모델은 로그 확률을 내므로 확률을 보려면 `torch.exp(outputs)`를 씌웁니다(노트북 01의 84번 셀). `nn.Softmax` 문서도 Softmax 출력은 NLLLoss와 바로 쓸 수 없으니 LogSoftmax를 쓰라고 적습니다.

### 큰 logit은 가장 큰 값을 빼고 계산합니다
<!-- facts: F09-37 F09-38 F09-59 F09-77 -->

앞 단계의 패턴 3은 소프트맥스 확률을 먼저 만들고 log를 씌웁니다. 노트북 02의 12번 셀은 logit [1000, 999, 995]로 이 순서를 시험합니다. 컴퓨터가 흔히 쓰는 32비트 실수(float32)가 나타낼 수 있는 가장 큰 수는 약 3.4 × 10³⁸이고, e^1000은 약 2 × 10⁴³⁴입니다. 그래서 `torch.exp`로 e^(logit)을 바로 계산하면 셋 다 무한대(inf)가 되고, 합으로 나누면 숫자가 아닌 값(nan)이 됩니다.

둘째 단원 3단계처럼 모든 logit에서 같은 수를 빼도 소프트맥스는 같습니다. 가장 큰 값 1000을 빼면 [0, −1, −5]가 되고 e^(logit)은 [1, 0.3679, 0.0067]이라 1을 넘지 않습니다. 합 1.3746의 log는 0.3182이고, 정답 0의 로그 소프트맥스는 0 − 0.3182라서 손실은 0.3182입니다. 앞 단락의 inf와 nan은 logit [1000, 999, 995]의 e^(logit)이 float32로 나타낼 수 없을 만큼 커서 생겼습니다. 이렇게 계산 중간의 값이 float32로 나타낼 수 있는 범위를 벗어나 결과가 틀어질 수 있는 계산을 수치적으로 불안정한 계산이라고 부릅니다. PyTorch 문서는 log와 소프트맥스를 따로 계산하면 느리고 수치적으로 불안정하다고 적습니다. 그래서 `F.log_softmax`는 다른 식으로 계산합니다. 노트북 02의 12번 셀 주석은 가장 큰 값을 빼고 계산하는 이 방법을 6차시 셋째 단원에서 본 log-sum-exp 트릭으로 부릅니다.

### 정답 분포와 예측 분포의 차이를 KL divergence로 잽니다
<!-- facts: F09-39 F09-40 F09-41 F09-62 F09-86 -->

셋째 단원 2단계에서 정답이 클래스 0인 데이터의 손실은 0.4076이었습니다. 이 손실을 만든 소프트맥스 확률 [0.665, 0.245, 0.090]은 모두 0 이상이고 더하면 1입니다. 이렇게 클래스마다 확률을 하나씩 두고 모두 더하면 1인 값의 묶음을 확률 분포라고 부릅니다. 정답도 확률 분포로 쓸 수 있습니다. 클래스 0이 정답이면 정답 분포 P는 원-핫 벡터 [1, 0, 0]이고, 모델이 낸 예측 분포 Q는 [0.665, 0.245, 0.090]입니다. 두 확률 분포 P와 Q에서 클래스마다 P × log(P ÷ Q)를 구해 더한 값을 KL divergence라고 부릅니다(노트북 02의 15·16번 셀). P를 기준으로 Q와 견준 값이라 KL(P‖Q)로 적습니다.

### KL divergence는 방향을 바꾸면 값이 달라질 수 있습니다
<!-- facts: F09-69 F09-68 -->

앞 단계의 P는 원-핫 벡터였습니다. 6차시 넷째 단원 4단계의 라벨 스무딩처럼 정답 분포도 여러 클래스에 확률을 나눠 가질 수 있습니다. P = [0.6, 0.3, 0.1], Q = [0.7, 0.2, 0.1]로 KL(P‖Q)와 KL(Q‖P) 두 방향을 계산합니다.

- KL(P‖Q) = 0.6 × log(0.6 ÷ 0.7) + 0.3 × log(0.3 ÷ 0.2) + 0.1 × log(0.1 ÷ 0.1) = −0.0925 + 0.1216 + 0 = 0.0291
- KL(Q‖P) = 0.7 × log(0.7 ÷ 0.6) + 0.2 × log(0.2 ÷ 0.3) + 0.1 × log(0.1 ÷ 0.1) = 0.1079 − 0.0811 + 0 = 0.0268

방향을 바꾸면 0.0291이 0.0268로 바뀝니다. 손실로 쓸 때는 정답 분포를 P 자리에 둡니다.

### F.kl_div에는 log를 씌운 Q를 먼저 넣습니다
<!-- facts: F09-42 F09-62 F09-69 F09-85 -->

앞 단계까지 손으로 구한 KL divergence를 PyTorch에서는 `F.kl_div`로 계산합니다. 노트북 02의 21번 셀은 2단계의 P = [1, 0, 0], Q = [0.7, 0.2, 0.1]로 이렇게 씁니다.

```python
P = torch.tensor([1.0, 0.0, 0.0])            # 정답 분포
Q = torch.tensor([0.7, 0.2, 0.1])            # 예측 분포
F.kl_div(torch.log(Q), P, reduction='sum')   # tensor(0.3567)
```

첫째 인자는 예측 분포의 로그 확률이고, 둘째 인자는 정답 분포의 확률입니다(PyTorch 문서 kl_div). 수식 KL(P‖Q)는 P를 앞에 적지만 코드는 log Q를 앞에 넣어서 순서를 바꿔 넣기 쉽습니다. `reduction='sum'`은 클래스마다 구한 값을 더해 정의와 같은 0.3567을 냅니다.

```figure
파일: assets/9d-3.png
캡션: 그림 3. F.kl_div의 두 인자와 수식 KL(P‖Q)의 자리. 주황은 예측 분포 Q, 초록은 정답 분포 P입니다.
내용: 위 줄에 F.kl_div(torch.log(Q), P, reduction='sum') 코드. 첫째 인자 아래 주황 상자 예측 분포의 로그 확률, 둘째 인자 아래 초록 상자 정답 분포. 아래 줄에 수식 KL(P‖Q) = Σ P × log(P ÷ Q) 의 P 와 Q 자리를 같은 색으로 칠하고 결과 0.3567.
```

> **[정정]** 같은 셀 주석은 reduction 기본값이 평균이고 배치 크기와 상관없이 손실 크기를 맞추려는 것이라고 적었습니다. 기본값 `'mean'`은 칸마다 구한 값을 더해 원소 수로 나눕니다. 이 예는 원소가 3개라 `'mean'`은 0.3567 ÷ 3 = 0.1189를 내고, KL divergence 0.3567이 나오지 않습니다. PyTorch 문서는 KL divergence의 정의와 맞추려면 `'batchmean'`을 쓰라고 적습니다. `'batchmean'`은 더한 값을 입력의 0번 축 크기로 나눕니다(PyTorch 문서 KLDivLoss). 입력이 [배치, 클래스] 모양이면 0번 축 크기가 배치 크기라서 데이터마다 구한 KL divergence의 평균이 나옵니다. 이 예의 P와 Q는 클래스 3개만 있는 1차원이라 `'batchmean'`도 3으로 나눕니다. 그래서 데이터 하나의 KL divergence는 `'sum'`으로 구합니다.

### 정확도는 맞힌 수를 데이터 수로 나눕니다
<!-- facts: F09-23 -->

2단계의 예측 [0, 1, 2, 1]을 정답 [0, 1, 1, 0]과 견줍니다.

```python
predicted = torch.max(outputs, 1)[1]           # tensor([0, 1, 2, 1])
predicted == labels                            # tensor([True, True, False, False])
correct = (predicted == labels).sum().item()   # 2
accuracy = correct / len(labels)               # 0.5
```

`predicted == labels`는 자리마다 같은지를 True와 False로 냅니다. `.sum()`이 True의 개수 2를 세고 `.item()`이 파이썬 숫자로 꺼냅니다. 데이터 수 4로 나누면 정확도 0.5입니다(노트북 03의 31번 셀, 9차시 과제 6번). 상황별 코드 첫째 단원 4단계에서 맞힌 수를 세는 줄과 같은 계산입니다. 노트북 01의 41번 셀은 `.item()` 없이 `(predicted == labels).sum() / len(labels)`로 나눠서 정확도가 원소 하나짜리 텐서로 남지만, 찍히는 값은 같습니다.

아래 모델 코드는 노트북 03의 23번 셀을 줄여 다시 쓴 것이고, 클래스 이름 WineNet과 층 이름은 이 노트에서 붙였습니다.

```python
class WineNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(13, 64)    # 13 × 64 + 64 = 896개
        self.fc2 = nn.Linear(64, 32)    # 64 × 32 + 32 = 2,080개
        self.fc3 = nn.Linear(32, 3)     # 32 × 3 + 3 = 99개
        self.relu = nn.ReLU()
        self.drop = nn.Dropout(0.3)     # 만들어 두기만 함

    def forward(self, x):
        x = self.relu(self.fc1(x))
        # x = self.drop(x)              # 노트북도 이 줄을 주석으로 막음
        x = self.relu(self.fc2(x))
        return self.fc3(x)              # logit 3개
```

`p.numel()`은 파라미터 텐서 하나에 든 숫자 개수를 셉니다. `sum(p.numel() for p in model.parameters())`로 모든 파라미터를 더하면 896 + 2,080 + 99 = 3,075입니다(노트북 03의 25번 셀). ReLU와 Dropout은 학습 파라미터가 없어서 이 합에 들지 않습니다. 노트북은 Adam(lr=0.001)으로 2,000 에폭 학습합니다.

### 평가 함수와 표준화 결과 받기
<!-- facts: F09-49 F09-22 F09-80 -->

앞 단계의 모델을 평가할 때 노트북 03의 31번 셀은 이런 함수를 씁니다.

```python
def evaluate(model, x, y):
    model.eval()                              # 평가할 때의 동작으로
    with torch.no_grad():                     # 기울기 계산 기록을 끔
        out = model(x)
        loss = criterion(out, y)
        _, predicted = torch.max(out, 1)      # 클래스 번호만 받음
        correct = (predicted == y).sum().item()
    return loss.item(), correct / len(y)
```

`model.eval()`은 5차시 여섯째 단원 4단계처럼 층을 평가할 때의 동작으로 바꾸고, `torch.no_grad()`는 3차시 일곱째 단원 6단계처럼 기울기 계산 기록을 끕니다. 평가에서는 backward를 부르지 않아 기울기 계산 기록이 필요 없고, Dropout 같은 층도 평가할 때의 동작으로 바꿔야 해서 둘을 함께 씁니다.

> **[정정]** 노트북 03의 31번 셀 주석은 `eval()`이 Dropout과 배치 정규화(BatchNorm)를 끈다고 적었습니다. Dropout은 평가할 때 입력을 그대로 내보내지만, 배치 정규화 층은 꺼지지 않습니다. 5차시 여섯째 단원 4단계에서 본 것처럼 학습하며 모아 둔 이동 평균과 이동 분산으로 정규화합니다(PyTorch 문서 BatchNorm1d).

같은 노트북의 11·12번 셀은 특징을 표준화하려고 `StandardScaler`를 만든 뒤 `scaler.fit_transform(x_train)`만 부르고 돌려준 값을 받지 않습니다. 아래의 고친 코드는 돌려준 값을 x_train, x_val, x_test에 다시 받습니다.

```python
scaler = StandardScaler()
x_train = scaler.fit_transform(x_train)   # 돌려준 값을 x_train에 받음
x_val = scaler.transform(x_val)
```
