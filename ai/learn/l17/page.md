### 어휘를 만든 뒤 번호를 붙입니다
<!-- facts: F17-101 F17-102 F17-103 -->

영화 리뷰가 긍정인지 부정인지 맞히는 감성 분류를 생각합니다. 문장을 조각으로 나누는 일을 <mark>토큰화</mark>라고 부르고 그 조각을 토큰이라고 부릅니다. 이 예에서는 문장을 소문자로 바꾼 뒤 영문·숫자·아포스트로피 조각을 정규식으로 찾습니다. 이 방식이 한국어 형태소 분석까지 해 주지는 않습니다.

### 검증 문장이 어휘 선택에 섞이지 않게 합니다
<!-- facts: F17-101 F17-102 F17-103 -->

어휘를 고를 때 검증과 시험 문장까지 세면 평가 입력의 정보를 미리 사용합니다. 학습 자료에서 번호 대응을 정한 뒤 모든 분할에 같은 대응을 적용합니다.

아래 예에서 bright와 film은 vocab에 있지만 new는 없습니다. vocab.get은 어휘에 없는 토큰에 기본값 1인 UNK 번호를 줍니다. 이 번호는 학습용으로 정했으며 실제 사전학습 토크나이저의 번호가 아닙니다. 번호의 크기가 감성의 크기를 뜻하지는 않습니다.

```python
tokens = ["bright", "new", "film"]
vocab = {"bright": 2, "film": 3}
ids = [vocab.get(t, 1) for t in tokens]
```

### PAD 벡터 0과 순환 계산 생략은 다릅니다
<!-- facts: F17-201 F17-202 F17-203 -->

새 Embedding에 padding_idx=0을 주면 0번 행을 기본적으로 0으로 초기화하고 그 행의 기울기를 만들지 않습니다. 직접 weight를 바꾸거나 다른 값을 불러온 경우까지 항상 0이라고 단정하지 않습니다.

이 설정은 Embedding의 특정 행을 다룹니다. 뒤에 연결할 LSTM이 0 벡터를 받았다고 그 시점을 자동으로 건너뛰지는 않습니다. 다음 단원에서 실제 길이를 전달하는 방법과 마지막 상태를 확인합니다.

### 게이트가 상태를 이어 계산합니다
<!-- facts: F17-301 F17-302 F17-303 F17-304 -->

LSTM은 문장의 자리를 순서대로 읽으며 다음 자리로 상태를 넘기는 순환 신경망의 한 종류입니다. <mark>셀 상태</mark>는 이전 내용과 새로 더할 내용을 반영해 이어 가는 값입니다. 현재 셀 상태에서 출력으로 내는 값은 은닉 상태라고 부릅니다.

상태를 계산할 때 남기거나 더하거나 출력할 비중을 정하는 부분이 <mark>게이트</mark>입니다. 망각 게이트는 이전 셀 상태를 얼마나 남길지, 입력 게이트는 새로 더할 후보 값을 얼마나 반영할지 정합니다. 출력 게이트는 현재 셀 상태에서 은닉 상태를 내는 비중을 정합니다. 셀 상태의 덧셈 경로는 긴 의존성 학습을 돕지만 기울기 소실을 완전히 없앤다고 보장하지 않습니다.

양방향 LSTM은 문장을 앞과 뒤에서 읽은 상태를 따로 만듭니다. 반환 값 h_n은 각 층·방향의 마지막 은닉 상태이고 c_n은 마지막 셀 상태입니다. <u>h_n의 축 순서는 층 수×방향 수, 배치, 은닉 길이 H입니다.</u> batch_first=True여도 h_n의 첫 축은 배치로 바뀌지 않습니다.

### 실제 길이의 끝과 마지막 층을 확인합니다
<!-- facts: F17-301 F17-302 F17-303 F17-304 -->

여러 층에서는 h_n[-2]와 h_n[-1]이 마지막 층의 두 방향입니다. 배치 수를 B로 쓰면 각 상태는 (B,H)입니다. 특징 축인 dim=1로 붙이면 (B,2H)입니다. output[:, -1]은 두 방향의 최종 상태를 모은 값과 같지 않습니다.

뒤에 PAD를 그냥 넣으면 정방향의 마지막 상태가 PAD를 처리한 뒤의 상태가 됩니다. 길이 텐서를 CPU에 두고 pack_padded_sequence를 쓰면 실제 토큰 구간만 LSTM에 전달할 수 있습니다. lengths에는 각 문장을 최대 길이로 자른 뒤 PAD를 붙이기 전의 토큰 수를 넣습니다. 원래 길이가 5이고 최대 길이가 4라면 4를 넣습니다. 아래 코드는 모든 길이가 1 이상이며 현재 입력의 시간 축 길이 이하라고 가정합니다. enforce_sorted=False를 주면 길이의 내림차순으로 미리 정렬하지 않아도 됩니다.

```python
packed = nn.utils.rnn.pack_padded_sequence(e, lengths.cpu(),
                                            batch_first=True, enforce_sorted=False)
_, (h_n, _) = lstm(packed)
last = torch.cat((h_n[-2], h_n[-1]), dim=1)
```

```figure
파일: assets/17c-3.png
캡션: 그림 3. 마지막 상태의 방향과 실제 길이를 함께 확인합니다.
내용: 구분 · 읽을 대상 / 마지막 층 두 방향 · h_n[-2]와 h_n[-1] / 뒤 PAD 제외 · 실제 길이 / 분류기 입력 · 두 방향 특징 연결
```

위 코드는 실제 길이까지 읽은 마지막 상태를 분류기 입력으로 연결합니다. 이 상태를 계산하는 LSTM의 파라미터 수는 입력 벡터 길이 I와 은닉 길이 H로 셉니다. I는 문장의 토큰 수가 아니라 한 토큰을 나타내는 벡터의 길이입니다.

PyTorch의 projection 없는 1층 LSTM에서 방향 하나는 입력 가중치 4H×I, 은닉 가중치 4H×H, 두 bias의 합 8H를 가집니다. I=4,H=6을 넣으면 4×6×4+4×6×6+8×6=288개이고 양방향은 576개입니다.

### 순환 대신 위치 사이 참조를 계산합니다
<!-- facts: F17-401 F17-402 F17-403 -->

앞 단원의 LSTM은 시간 단계마다 이전 상태를 이어받습니다. Transformer의 인코더는 같은 입력의 위치들을 서로 참조하는 <mark>self-attention</mark>을 사용합니다. 같은 입력에서 query, key, value를 만들고 query와 key를 비교해 위치마다 가중치를 구합니다. 이 가중치를 value에 적용해 참조 가능한 위치의 값을 합칩니다.

첫 단원에서 번호로 바꾼 bright, new, film을 다시 생각합니다. film 자리의 값을 계산할 때 그 자리의 query를 각 자리의 key와 비교합니다. 여기서 얻은 가중치를 각 자리의 value에 곱해 더합니다. 한 자리의 출력에도 참조를 허용한 다른 자리의 값이 반영됩니다.

원 논문은 query와 key의 내적을 차원 제곱근으로 나눈 뒤 Softmax로 가중치를 구합니다. 다만 self-attention이 늘 모든 위치를 보는 것은 아닙니다. 디코더는 아직 오지 않은 미래 위치를, 패딩이 있는 배치는 PAD 자리를 마스크로 가릴 수 있습니다.

### 사용할 IDF 식을 지문에 고정합니다
<!-- facts: F17-501 F17-502 F17-503 F17-504 -->

문서 빈도에 따라 토큰에 줄 가중치를 계산하는 값이 <mark>IDF</mark>입니다. 전체 문서 수를 N으로 쓰고 이 예의 식 IDF=ln(N/(DF+1))을 사용합니다. 이번 계산에서는 벡터를 정규화하지 않습니다. ln은 자연로그입니다. 이번 계산은 같은 N=6,DF=2에서 TF=3인 문서를 사용합니다. 식에 넣으면 IDF는 ln(6/(2+1))=ln(2)입니다. 여기에 TF=3을 곱한 TF-IDF는 3×ln(2)≈2.0794입니다. 중간 로그 값을 먼저 반올림하지 않고 마지막 결과를 반올림했습니다.

DF가 모든 문서 수와 같으면 이 식의 IDF는 음수가 될 수 있습니다. scikit-learn 기본값은 ln((1+N)/(1+DF))+1에 문서별 L2 정규화까지 사용하므로 같은 결과라고 가정하지 않습니다.

어휘별 TF-IDF 값을 모으면 문서의 벡터로 비교할 수 있습니다. 벡터의 방향을 비교하는 <mark>코사인 유사도</mark>는 0이 아닌 벡터에서 정의합니다. 크기가 달라도 방향이 같으면 1입니다. 다음 단계에서는 크기의 차이를 재는 거리와 비교합니다.

### Trainer가 맡는 학습 기본 패턴을 확인합니다
<!-- facts: F17-602 -->

반복 학습과 평가를 관리하는 도구를 <mark>Trainer</mark>라고 합니다. 도구를 사용해도 학습의 계산 관계는 같습니다. 학습 배치의 예측과 정답으로 손실을 만들고 기울기를 구한 뒤 파라미터를 갱신합니다. 학습에서는 이전 기울기를 초기화하며, 평가에서는 파라미터를 갱신하지 않습니다.

다음 코드는 이미 준비한 객체의 연결을 읽는 예입니다. `train_rows`와 `valid_rows`는 각각 전처리한 학습·검증 자료입니다. 검증 자료는 원래 학습 자료 일부를 떼어 만들고 가중치 갱신에는 쓰지 않습니다. `args`는 학습과 평가·저장 방식을 정한 설정입니다. `collator`는 배치를 만들고 `metrics`는 예측과 정답으로 지표를 계산합니다. 변수 이름은 이 설명을 위해 정했습니다.

```python
trainer = Trainer(
    model=model, args=args, train_dataset=train_rows,
    eval_dataset=valid_rows, data_collator=collator,
    processing_class=tokenizer, compute_metrics=metrics,
)
trainer.train()
```

### 클래스 점수와 비교 지표를 나눠 읽습니다
<!-- facts: F17-603 F17-605 -->

모델이 내는 logit은 아직 확률이 아닌 클래스 점수입니다. 점수 [0.2,1.1]이면 클래스 축에서 가장 큰 값을 찾는 `argmax`로 긍정 1을 고릅니다. 확률이 필요할 때 `softmax`로 바꿉니다. 학습에 쓰는 클래스 번호 방식의 CrossEntropyLoss 앞에는 별도 softmax를 붙이지 않습니다.

같은 예측도 지표마다 다른 면을 봅니다. accuracy는 전체에서 맞힌 비율입니다. 양성 클래스를 1로 정했을 때 TP는 양성을 맞힌 수, TN은 음성을 맞힌 수, FP는 음성을 양성으로 고른 수, FN은 양성을 놓친 수입니다. 분모가 0이 아닌 경우 <u>F1 점수는 2TP/(2TP+FP+FN)으로 계산합니다.</u>

TP=2, TN=4, FP=1, FN=1인 설명용 여덟 문장에서 accuracy는 (2+4)/8=0.75입니다. F1은 4/(4+1+1)=2/3≈0.667입니다. 두 값의 이름과 양성 클래스·평가 자료를 함께 적습니다. 학습 곡선만으로 새 문장의 성능이 좋아졌다고 판단하지 않습니다.
