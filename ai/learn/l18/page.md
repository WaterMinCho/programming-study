### 한 에폭을 학습하는 코드 열다섯 줄
<!-- facts: F18-03 F18-04 F18-10 -->

1단계의 배치 셋을 차례로 꺼내 학습하는 코드는 아래 열다섯 줄입니다. `model`, `criterion`, `optimizer`, `device`, `loader`는 루프 앞에서 만들어 두었고, `model`은 이미 `device`에 있습니다.

<u>이 코드는 클래스마다 점수를 내는 다중 분류 모델에 씁니다.</u> `out`은 `[배치, 클래스 수]` 모양이고 `y`는 `[배치]` 모양의 long 클래스 번호입니다. `criterion`은 클래스 가중치와 무시할 라벨을 지정하지 않은 기본 평균 `nn.CrossEntropyLoss()`이며 `loader`에는 데이터가 하나 이상 있습니다.

<!-- skel: S1 표준형 -->
```python
model.train()
loss_sum, correct, total = 0.0, 0, 0
for x, y in loader:                               # 배치를 하나씩 꺼냄
    x = x.to(device)                              # 옮긴 텐서를 받음
    y = y.to(device)
    optimizer.zero_grad()
    out = model(x)
    loss = criterion(out, y)                      # 배치 평균 손실
    loss.backward()
    optimizer.step()
    loss_sum += loss.item() * x.size(0)           # 이번 배치 손실의 합
    total += y.size(0)                            # 이번 배치의 데이터 수
    correct += (out.argmax(1) == y).sum().item()  # 이번 배치에서 맞힌 수
epoch_loss = loss_sum / total                     # 데이터 하나당 평균 손실
epoch_acc = correct / total                       # 정확도
```

입력은 `x`, 정답은 `y`, 모델 출력은 `out`으로 적습니다. 다른 코드에서는 같은 값의 이름이 `inputs`, `labels`, `outputs`일 수 있습니다. 여기서는 이 열다섯 줄을 표준형이라고 부릅니다.

### 학습 다섯 줄과 zero_grad를 둘 수 있는 자리
<!-- facts: F18-01 F18-02 F18-15 F18-16 -->

2단계 코드에서 `optimizer.zero_grad()`부터 `optimizer.step()`까지 다섯 줄은 1차시 둘째 단원 3단계의 학습 다섯 줄과 같습니다. 배치를 하나 꺼낼 때마다 이 다섯 줄로 파라미터를 한 번 갱신하므로, 1단계의 배치 셋이면 한 에폭에 3번 갱신합니다.

순전파, 손실, `backward()`, `step()` 네 줄은 앞 줄이 만든 값을 다음 줄이 쓰므로 순서를 바꿀 수 없습니다. 손실은 `out`으로 계산하고, `backward()`는 `loss`에서 기울기를 구하고, `step()`은 `backward()`가 `.grad`에 담은 기울기로 파라미터를 갱신합니다.

4차시 셋째 단원 6단계에서 본 것처럼 `backward()`는 새 기울기를 `.grad`에 있던 값에 더합니다. 그래서 `zero_grad()`는 이번 배치의 `backward()`가 기울기를 더하기 전에 지난 배치의 기울기를 지워야 합니다. `backward()` 앞이나 `step()` 뒤에 두면 이 조건을 지킵니다. `backward()`와 `step()` 사이에 두면 `step()`이 쓸 기울기까지 지우므로 둘 수 없습니다.

### 데이터 하나당 평균 손실과 정확도 세기
<!-- facts: F18-05 F18-06 F18-07 F18-08 F18-09 F18-10 F18-11 F18-14 -->

3단계의 `loss = criterion(out, y)`에서 `criterion`이 돌려주는 손실은 배치 평균입니다. 6차시 첫째 단원 3단계에서 본 것처럼 손실 함수의 `reduction` 기본값이 `'mean'`이라서, `criterion`은 데이터마다 구한 손실을 더해 그 배치의 데이터 수로 나눈 숫자 하나를 돌려줍니다. 6차시 다섯째 단원처럼 `CrossEntropyLoss`에 `weight=`를 주면 데이터 수 대신 데이터마다 정답 클래스의 가중치를 더한 값으로 나눕니다. 이 단원에서는 `weight=`를 주지 않은 손실만 다룹니다.

1단계의 첫 배치는 데이터 4개의 평균 손실이 0.5이므로 네 손실을 더하면 0.5 × 4 = 2.0입니다. 배치 평균에 그 배치의 데이터 수를 곱하면 그 배치 손실의 합이 됩니다. `loss_sum += loss.item() * x.size(0)`이 배치마다 이 합을 `loss_sum`에 더합니다. 5차시 일곱째 단원 3단계에서 본 것처럼 `x.size(0)`은 이번 배치의 데이터 수입니다. `loss.item()`은 3차시 여덟째 단원 3단계에서 본 것처럼 손실 값을 계산 기록이 없는 파이썬 수로 꺼냅니다. 루프가 끝나면 `epoch_loss = loss_sum / total`이 손실의 합을 데이터 수로 나눠 데이터 하나당 평균 손실을 냅니다.

맞힌 수를 세는 줄은 5차시 일곱째 단원 4단계의 줄과 같습니다. `out.argmax(1)`이 행마다 가장 큰 점수의 열 번호를 고르고, `== y`가 예측이 정답과 같은 데이터를 True로 만듭니다. `.sum()`이 True의 개수를 세고, `.item()`이 그 수를 파이썬 정수로 꺼냅니다. `epoch_acc = correct / total`은 맞힌 수를 데이터 수로 나눈 정확도입니다.

### 배치의 손실 합과 데이터 수를 모읍니다
<!-- facts: F18-19 F18-20 -->


배치마다 평균을 구했더라도 마지막 배치가 작을 수 있습니다. 앞 단원의 `loss_sum`처럼 평균에 그 배치의 데이터 수를 곱합니다. 크기 4인 배치는 0.3 × 4 = 1.2이고 크기 2인 배치는 0.9 × 2 = 1.8입니다. 두 합을 더한 3.0을 데이터 6개로 나누면 0.5입니다.

아래 코드의 `loader`에는 데이터가 하나 이상 있습니다. `x`는 float32이며 모양은 `[배치, 특징]`입니다. `y`는 long이며 모양은 `[배치]`, 값은 0~2입니다. 모델은 `device`에서 `[배치, 3]` 로짓을 냅니다. 손실 함수 `criterion`은 가중치와 무시할 라벨을 지정하지 않은 `nn.CrossEntropyLoss()`입니다.

<!-- skel: S2 평가 -->
```python
def evaluate(model, loader):
    model.eval()
    loss_sum, correct, total = 0.0, 0, 0
    with torch.no_grad():
        for x, y in loader:
            x = x.to(device)
            y = y.to(device)
            out = model(x)
            loss = criterion(out, y)
            loss_sum += loss.item() * y.size(0)
            correct += (out.argmax(1) == y).sum().item()
            total += y.size(0)
    return loss_sum / total, correct / total
```

`x.to(device)`와 `y.to(device)`의 반환값을 받아 모델과 같은 장치에 놓습니다. `loss.item()`은 배치 평균을 파이썬 수로 꺼냅니다. 여기에 `y.size(0)`을 곱해 배치 손실의 합을 더합니다. `total`에는 실제 데이터 수를 더하므로 마지막 배치가 2개인 경우도 2개로 셉니다.

`argmax(1)`은 데이터마다 클래스 번호를 고릅니다. 예측이 정답과 같은 수를 `correct`에 모읍니다. 6개 중 4개를 맞혔다면 반환할 정확도는 4 ÷ 6입니다. 지표의 뜻과 비교는 4차시 여덟째 단원에서 다뤘습니다.

### 개선이 없었던 평가 횟수를 셉니다
<!-- facts: F18-22 F18-23 -->

개선이 없는 평가가 이어지면 학습을 멈추는 방법을 조기 종료라고 합니다. 기다릴 횟수를 `patience`로 정합니다. 이 예에서는 검증 손실이 직전 최저 손실보다 작을 때만 개선으로 셉니다. 같은 값도 개선이 없는 평가에 넣습니다.

아래 `train_one_epoch()`은 앞에서 비교한 학습판 함수입니다. `evaluate()`는 앞 단계의 평가 함수입니다. 검증 데이터는 비어 있지 않으며 검증 손실은 유한한 수입니다. `float('inf')`는 처음 비교할 최저 손실을 무한대로 둡니다. 첫 유한 손실은 이 값보다 작으므로 첫 상태를 저장합니다. `load_state_dict()`는 이름과 모양이 같은 모델에 저장한 파라미터와 버퍼를 읽어 넣습니다.

<!-- skel: S9 최고 상태 -->
```python
import copy
best_loss = float('inf')
best_state = None
waiting = 0
patience = 2
for epoch in range(6):
    train_one_epoch(model, train_loader)
    val_loss, val_acc = evaluate(model, valid_loader)
    if val_loss < best_loss:
        best_loss = val_loss
        best_state = copy.deepcopy(model.state_dict())
        waiting = 0
    else:
        waiting += 1
    if waiting >= patience:
        break
if best_state is not None:
    model.load_state_dict(best_state)
```

손실을 갱신한 줄 뒤에 당시 모델의 값을 보관하고 `waiting`을 0으로 돌립니다. 개선이 없으면 `waiting`만 1씩 더합니다. 반복이 끝난 뒤에는 저장한 최고 상태를 읽어 넣습니다. 이 상태 사전에는 최적화 객체의 내부 상태는 들어 있지 않습니다.

동작을 따라 보려고 검증 손실을 0.8, 0.5, 0.6, 0.7로 놓습니다. 앞 단계에서 본 가중치 하나의 값도 각 평가 시점에서 1, 2, 3, 4였다고 놓습니다. `epoch`는 0부터 시작합니다. `epoch` 1에서 최저 손실 0.5를 기록한 뒤 2와 3에서 개선이 없어 `waiting`은 1과 2가 됩니다. `epoch` 3의 평가 뒤에 멈추고 `epoch` 1의 모델 값을 읽어 넣습니다.

### 층을 등록하고 입력이 지나는 순서를 정합니다
<!-- facts: F18-36 F18-37 -->

이번에는 8×8 흑백 이미지 두 개를 클래스 0·1·2로 분류합니다. 입력 `x`는 CPU의 float32 텐서이며 모양은 `[2, 1, 8, 8]`입니다. 축은 이미지 수, 채널 수, 높이, 너비 순서입니다. 정답은 클래스 번호를 담은 long `[2]`입니다.

직접 모델 클래스를 만들 때는 파이토치가 층과 파라미터를 관리하는 `nn.Module`을 상속합니다. 생성할 층은 `__init__`에 등록하고 입력이 지나는 순서는 `forward`에 적습니다. `self`는 지금 만든 모델을 가리킵니다. 기반 클래스의 준비를 마치는 `super().__init__()`을 먼저 호출한 뒤 층을 `self`에 붙입니다. 한 이미지의 수를 한 행으로 펼칠 때는 `torch.flatten`을 사용합니다. <u>`start_dim=1`로 0번 이미지 축을 남깁니다.</u>

### 합성곱과 풀링으로 이미지의 특징을 구합니다
<!-- facts: F18-36 F18-37 F18-38 -->

같은 이미지에 합성곱을 적용하는 모델을 만듭니다. 합성곱 층 `Conv2d`는 입력 채널 수, 출력 채널 수, 커널 크기를 받습니다. 이 예의 커널은 3×3이며 가장자리에 0을 한 칸씩 덧댑니다. 이 덧붙임을 `padding=1`로 지정합니다. 한 칸씩 이동하는 `stride=1`과 커널 칸 사이의 간격을 늘리지 않는 `dilation=1`을 쓰면 높이와 너비를 유지합니다. 합성곱의 계산은 11차시 첫째 단원에서 다뤘습니다.

음수를 0으로 바꾸는 `ReLU` 뒤에는 `MaxPool2d`를 둡니다. 이 풀링은 채널마다 2×2 영역의 최댓값을 고르고 두 칸씩 이동합니다. 높이 8은 4가 되고 다음 풀링에서 2가 됩니다. 아래에서는 층을 적은 순서대로 호출하는 `nn.Sequential`로 이 과정을 묶습니다.

<!-- skel: S4 CNN -->
```python
class PatchNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(1, 4, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2, stride=2),
            nn.Conv2d(4, 8, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2, stride=2),
        )
        self.fc = nn.Linear(8 * 2 * 2, 3)
    def forward(self, x):
        x = self.features(x)
        x = torch.flatten(x, start_dim=1)
        return self.fc(x)
```

첫 합성곱은 흑백 채널 1개에서 특징 채널 4개를 냅니다. 다음 합성곱의 입력 채널도 4로 맞춥니다. 둘째 합성곱은 특징 채널 8개를 냅니다. `self.features(x)`를 지난 모양은 `[2, 8, 2, 2]`입니다. 마지막 층은 이미지 하나의 특징 `8 × 2 × 2 = 32`개를 받습니다.

### 같은 인덱스의 이미지와 정답을 돌려줍니다
<!-- facts: F18-42 F18-43 -->

파일의 이미지를 여는 `Image.open`을 사용합니다. 이미지를 연 문맥을 벗어나면 파일을 닫도록 `with` 안에서 읽습니다. `convert("RGB")`는 색 채널을 RGB 3개로 맞춥니다. `ToTensor`는 이 RGB PIL 이미지를 `[3, 8, 8]` 텐서로 바꿉니다. 여기서는 기본 실수 자료형 float32를 사용하며 이미지 값 0~255는 0~1로 바뀝니다.

이 변환을 `transform`이라는 인자로 받아 저장합니다. `PictureData`를 만들 때 실제 경로 목록 `files`, 정수 목록 `labels`, 변환을 전달합니다. 아래에서 `Dataset`과 `DataLoader`는 `torch.utils.data`, `Image`는 PIL, `transforms`는 torchvision에서 가져온 이름입니다.

<!-- skel: S5 직접 읽기 -->
```python
class PictureData(Dataset):
    def __init__(self, files, labels, transform):
        self.files = files
        self.labels = labels
        self.transform = transform
    def __len__(self):
        return len(self.files)
    def __getitem__(self, index):
        with Image.open(self.files[index]) as image:
            x = self.transform(image.convert("RGB"))
        return x, int(self.labels[index])
transform = transforms.ToTensor()
data = PictureData(files, labels, transform)
loader = DataLoader(data, batch_size=2, shuffle=False, drop_last=False, num_workers=0)
```

`self.files[index]`와 `self.labels[index]`는 같은 인덱스를 사용합니다. 변환한 `x`와 파이썬 정수 라벨 하나를 반환합니다. 이미지 변환을 파일 안에서 마친 뒤에는 텐서를 이용하므로 파일을 닫아도 읽은 값을 사용할 수 있습니다. 마지막 줄의 묶기 규칙은 다음 단계에서 확인합니다.

이미 학습한 가중치로 새 분류 문제를 시작하는 전이 학습을 구성합니다. 이번 문제의 전체 클래스는 0·1·2입니다. torchvision의 ResNet-18에서 마지막 분류기는 `fc`이며 그 층이 받는 특징 수는 `model.fc.in_features`로 읽습니다. 모델과 가중치의 선택은 13차시 둘째 단원과 14차시 둘째 단원에서 다뤘습니다.

파라미터의 기울기 계산을 끄는 설정을 동결이라고 합니다. `model.parameters()`는 모델 파라미터를 하나씩 꺼낼 수 있게 합니다. 새 모델의 파라미터를 먼저 동결한 뒤 마지막 층을 교체합니다. 여기서는 이전 기울기나 최적화 객체를 재사용하지 않습니다. `models.ResNet18_Weights.DEFAULT`로 사전학습 가중치를 선택하고 `models.resnet18`에 전달해 모델을 만듭니다.

```python
weights = models.ResNet18_Weights.DEFAULT
model = models.resnet18(weights=weights)
for p in model.parameters():
    p.requires_grad = False
model.fc = nn.Linear(model.fc.in_features, 3)
```

첫 줄은 사용할 가중치를 선택합니다. 둘째 줄은 그 가중치를 읽어 모델을 만듭니다. 반복문은 원래 파라미터의 기울기 계산을 끕니다. 마지막 줄은 원래 분류기의 입력 특징 수를 읽어 출력이 3개인 새 층으로 바꿉니다. 새 층의 파라미터는 기본적으로 `requires_grad=True`로 생깁니다. 교체 뒤에 전체를 다시 동결하면 새 층도 기울기를 계산하지 않습니다.

### 기울기를 계산할 부분을 최적화 대상에도 넣습니다
<!-- facts: F18-49 F18-50 -->


기울기를 계산하는 설정과 최적화 객체에 전달한 목록을 함께 확인합니다. `opt.step()`은 자신이 받은 파라미터를 갱신 대상으로 삼습니다. 본체에서 기울기를 구해도 `opt`가 그 파라미터를 받지 않았다면 이 최적화 객체는 본체를 갱신하지 않습니다.

마지막 분류기만 학습할 때는 `fc`만 전달합니다. 마지막 블록 `layer4`도 학습하려면 그 부분의 기울기 계산을 켜고 파라미터 목록에도 더합니다. `list`는 반복으로 꺼내는 파라미터를 목록으로 모읍니다. 두 목록을 `+`로 이어 layer4와 fc를 함께 전달합니다.

```python
for p in model.layer4.parameters():
    p.requires_grad = True
params = list(model.layer4.parameters()) + list(model.fc.parameters())
opt = optim.SGD(params, lr=0.001)
```

첫 반복은 앞 단계에서 동결한 layer4를 해제합니다. `params`에는 layer4와 새 fc의 파라미터만 모읍니다. 그 뒤에 최적화 객체를 만들어 해제한 부분이 모두 갱신 대상에 들어가게 합니다. 전체를 학습하는 방식에서는 모든 파라미터의 기울기 계산을 켜고 `list(model.parameters())`를 전달합니다.

### 동결한 배치 정규화의 이동 통계도 구별합니다
<!-- facts: F18-51 F18-52 -->

배치 정규화는 파라미터 이외에 이동 평균과 분산을 버퍼로 관리합니다. 기본 `track_running_stats=True`에서는 학습 모드의 순전파마다 이 통계를 갱신합니다. <u>`requires_grad=False`는 이 버퍼의 갱신을 멈추지 않습니다.</u> 버퍼와 파라미터의 차이는 18b의 4단계, 배치 정규화는 5차시 여섯째 단원에서 다뤘습니다.

예를 들어 이동 평균이 0이고 이번 배치 평균은 2라고 놓습니다. 배치 정규화의 `momentum=0.1`을 적용하면 새 이동 평균은 `0.9 × 0 + 0.1 × 2 = 0.2`입니다. 이 층을 평가 모드로 두면 저장한 통계를 사용하고 이동 평균 0을 유지합니다. 이 수치는 동작을 따라 보기 위한 예이며 이 모델의 학습 결과는 아닙니다.

모델 안의 모든 층은 `model.modules()`로 읽습니다. `isinstance`로 배치 정규화 층인지 확인한 뒤 그 층의 파라미터 가운데 기울기를 계산하는 것이 있는지 `any`로 검사합니다. 아래 코드는 기울기 계산을 모두 끈 배치 정규화 층만 평가 모드로 돌립니다.

```python
model.train()
for layer in model.modules():
    if isinstance(layer, nn.BatchNorm2d):
        if not any(p.requires_grad for p in layer.parameters()):
            layer.eval()
```

`model.train()`은 안쪽 층도 학습 모드로 바꿉니다. 그 뒤에 동결한 층의 `eval()`을 다시 적용합니다. 이 순서를 매 에폭에서 지킵니다. 일부 해제판의 layer4 배치 정규화는 파라미터가 학습 대상이어서 이 조건에 들지 않고 학습 모드를 유지합니다. 이 코드는 기본 BatchNorm2d가 있는 ResNet-18에 맞췄으며 모든 모델의 버퍼를 고정하는 함수는 아닙니다.

### 에폭이 시작할 때 모드를 정하고 배치를 학습합니다
<!-- facts: F18-47 F18-48 F18-49 F18-51 -->

마지막 분류기만 학습하는 전체 코드를 연결합니다. `models`, `nn`, `optim`은 torchvision 모델·파이토치 층·최적화 모듈입니다. CPU에서 시작한 새 모델이며 시작할 때 기울기는 없습니다. 비어 있지 않은 `loader`의 각 `x`는 float32 `[2, 3, 224, 224]`, `y`는 0~2의 long `[2]`입니다. `x`와 `y`는 모두 CPU 텐서입니다. 이미지는 선택한 가중치의 `weights.transforms()`와 같은 전처리를 마쳤습니다.

<!-- skel: S6 마지막 층 -->
```python
weights = models.ResNet18_Weights.DEFAULT
model = models.resnet18(weights=weights)
for p in model.parameters():
    p.requires_grad = False
model.fc = nn.Linear(model.fc.in_features, 3)
for p in model.layer4.parameters():
    p.requires_grad = False
model = model.to("cpu")
params = list(model.fc.parameters())
opt = optim.SGD(params, lr=0.001)
criterion = nn.CrossEntropyLoss()
for epoch in range(2):
    model.train()
    for layer in model.modules():
        if isinstance(layer, nn.BatchNorm2d):
            if not any(p.requires_grad for p in layer.parameters()):
                layer.eval()
    for x, y in loader:
        opt.zero_grad()
        out = model(x)
        loss = criterion(out, y)
        loss.backward()
        opt.step()
```

준비 단계에서 파라미터를 고르고 최적화 객체를 만듭니다. 매 에폭에서는 전체 모델의 학습 모드를 켠 뒤 동결한 배치 정규화만 평가 모드로 돌립니다. 다음 배치 반복은 앞 단원 18a의 기울기 비우기·순전파·손실·역전파·갱신 순서를 사용합니다. 이 코드 안에서 다시 `train_one_epoch()`을 호출하지 않습니다. 그 함수가 `model.train()`을 또 부르면 앞에서 정한 배치 정규화 모드를 바꿀 수 있습니다. 평가 함수와 최고 상태 복원은 18b의 3~5단계로 연결합니다.
