### Linear 층 뒤에 시그모이드를 둡니다
<!-- facts: F08-05 F08-06 F08-11 F08-19 F08-76 -->

앞 단계의 꽃 (4.8, 3.4)를 모델에 넣습니다. 다음 모델은 `nn.Linear(2, 1)`로 z = w1 × x1 + w2 × x2 + b를 계산합니다. x1은 꽃받침 길이, x2는 폭입니다. 5차시 첫째 단원에서 본 것처럼 이 층은 입력 2개를 받아 숫자 하나를 냅니다.

z는 음수가 될 수도 있고 1보다 클 수도 있습니다. 이 z를 3차시 여섯째 단원의 시그모이드 σ(z) = 1 ÷ (1 + e^(−z))에 넣으면 0과 1 사이의 값 p가 나옵니다.

```python
class BinaryNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc = nn.Linear(2, 1)          # z = w1·x1 + w2·x2 + b
        self.act = nn.Sigmoid()            # z 를 0 과 1 사이의 p 로
        self.fc.weight.data.fill_(1.0)     # w1, w2 를 1 로
        self.fc.bias.data.fill_(1.0)       # b 를 1 로

    def forward(self, x):
        z = self.fc(x)
        return self.act(z)
```

같은 모델의 층 이름을 `l1`, `sigmoid`로 적을 수도 있습니다. 이 노트는 `fc`, `act`로 적었습니다. `nn.Sigmoid()`는 시그모이드를 계산하는 층입니다. `weight.data.fill_(1.0)`은 가중치의 원소를 모두 1로 채웁니다. 이 예제는 결과를 따라가기 쉽게 처음 값을 1로 정했고 보통은 5차시 셋째 단원처럼 무작위로 정합니다.

Linear 층 뒤에 시그모이드를 둔 이 모델 구조를 <mark>이진 로지스틱 회귀</mark>라고 부릅니다. 7차시의 선형 회귀 모델 끝에 시그모이드 하나를 더한 구조입니다.

```figure
파일: assets/8a-3.gif
캡션: 그림 3. 꽃 (4.8, 3.4)가 Linear 층과 시그모이드를 지나는 흐름. 노란 칸은 입력, 회색 칸은 시그모이드입니다.
프레임:
1. 윗줄은 처음 값 w = [1, 1], b = 1이고 아랫줄은 꽃 분류 예제가 학습을 마친 값입니다. (2000ms)
2. 처음 값으로 z = 4.8 + 3.4 + 1 = 9.2입니다. (2200ms)
3. 시그모이드를 지나면 σ(9.2) ≈ 0.9999입니다. (2200ms)
4. 학습한 값 w = [2.951, −5.115], b = −0.1045로는 z ≈ −3.33입니다. (2200ms)
5. σ(−3.33) ≈ 0.0345입니다. (2200ms)
6. 같은 꽃의 p가 처음 값으로는 0.9999, 학습한 값으로는 0.0345입니다. (2500ms)
```

그림의 학습한 값은 저장된 실행 결과를 사용했습니다. 초기값과 실행 조건을 바꾸면 학습 결과도 달라질 수 있습니다.

> **[보충 설명]** 이름에 회귀가 들어 있지만 로지스틱 회귀는 분류에 쓰는 선형 모델입니다(scikit-learn 사용자 안내서). 시그모이드를 지나기 전의 z는 6차시 셋째 단원의 logit입니다. p에서 z를 거꾸로 구하면 z = ln(p ÷ (1 − p))입니다(PyTorch 문서 torch.special.logit).

### p가 0.5보다 크면 1로 예측합니다
<!-- facts: F08-12 F08-13 F08-14 F08-30 F08-48 -->

앞 단계의 p는 0.9999와 0.0345였습니다. p는 정답이 1일 확률로 읽습니다. 모델은 p가 0.5보다 크면 1, 작으면 0으로 예측합니다. 그래서 처음 값을 쓴 모델은 이 꽃을 1로, 학습한 모델은 0으로 예측합니다. 정답 0을 맞힌 쪽은 학습한 모델입니다.

4차시 여덟째 단원처럼 예측을 0과 1로 가르는 기준값을 임계값(threshold)이라고 부릅니다. 이 모델의 임계값은 0.5입니다.

```figure
파일: assets/8a-4.gif
캡션: 그림 4. 시그모이드 곡선 위를 움직이는 점. 회색 곡선은 시그모이드, 회색 점선은 p = 0.5, 파랑은 0으로 예측하는 점, 주황은 1로 예측하는 점입니다.
프레임:
1. 가로는 z, 세로는 p입니다. z = −3이면 p = 0.0474라 0으로 예측합니다. (1800ms)
2. z = −2이면 p = 0.1192입니다. (1800ms)
3. z = −1이면 p = 0.2689입니다. (1800ms)
4. z = 0이면 p = 0.5로, 0과 1을 가르는 자리입니다. (2200ms)
5. z = 1이면 p = 0.7311이라 1로 예측합니다. (1800ms)
6. z = 2이면 p = 0.8808입니다. (1800ms)
7. z = 3이면 p = 0.9526입니다. (1800ms)
8. z가 0보다 작은 쪽은 p가 0.5보다 작고, 0보다 큰 쪽은 p가 0.5보다 큽니다. (2500ms)
```

σ(0) = 1 ÷ (1 + 1) = 0.5입니다. 시그모이드는 z가 커질수록 늘 커지므로 p > 0.5와 z > 0은 같은 조건입니다. −4부터 4까지 시그모이드 값을 계산해 봅니다. σ(−4) ≈ 0.018, σ(4) ≈ 0.982처럼 z가 0에서 멀어질수록 p는 0이나 1에 가까워지지만 식으로는 0이나 1이 되지 않습니다.

앞 단원의 꽃 (4.8, 3.4) 하나는 학습한 모델이 맞혔습니다. 꽃을 여러 송이 예측하면 맞힌 송이 수를 셉니다. 맞힌 건수를 전체 건수로 나눈 값을 정확도(accuracy)라고 부릅니다. 10송이 가운데 9송이를 맞히면 0.9입니다. 회귀의 MSE는 얼마나 작아야 좋은지 바로 말하기 어렵지만, 정확도는 맞힌 비율이라 0.9를 보고 열에 아홉을 맞혔다고 읽습니다.

학습에 쓴 꽃으로 정확도를 재면 처음 보는 꽃을 얼마나 맞히는지 알 수 없습니다. 2차시와 4차시에서는 학습 데이터에만 맞춰져 새 데이터에서 예측이 나빠지는 현상을 과적합이라고 불렀습니다. 그래서 꽃 100송이를 학습 데이터 70송이와 검증 데이터 30송이로 나눕니다. 과적합을 과학습(overfitting)이라고도 부릅니다.

```python
x_train, x_test, y_train, y_test = train_test_split(x_data, y_data, train_size=70, test_size=30, random_state=42)
# x_train (70, 2), x_test (30, 2), y_train (70,), y_test (30,)
```

`train_test_split`은 5차시 일곱째 단원에서 본 함수입니다. `train_size=70`처럼 정수를 주면 개수로 나눕니다. 이 예제는 x_test와 y_test의 30송이를 학습 중 성능을 점검하는 검증 데이터로 씁니다. 변수 이름에 test가 있어도 묶음의 역할은 실제로 어디에 사용하는지 보고 구별합니다.

데이터를 한 번 나눠 한쪽으로 학습하고 다른 쪽으로 평가하는 방법을 홀드아웃(hold-out)이라고 부릅니다. 4차시 일곱째 단원의 K-Fold 교차 검증은 검증할 덩어리를 바꿔 가며 여러 번 나눴습니다.

### 맞힌 꽃을 세는 두 줄

### 특징이 늘면 경계는 평면, 초평면이 됩니다
<!-- facts: F08-52 F08-25 -->

앞 단계의 경계는 특징이 x1, x2 둘이라 직선이었습니다. 특징이 하나면 w1 × x1 + b = 0을 풀어 x1 = −b ÷ w1이 나옵니다. 이때 경계는 수직선 위의 한 점입니다. 특징이 셋일 때 w1 × x1 + w2 × x2 + w3 × x3 + b = 0을 만족하는 점을 모두 모으면 평면이 됩니다. 특징이 n개이면 경계의 식은 w1 × x1 + w2 × x2 + … + wn × xn + b = 0입니다. 이 식을 줄여 w · x + b = 0으로 적습니다.

```figure
파일: assets/8c-3.png
캡션: 그림 3. 특징 수에 따른 결정 경계. 검은 점과 검은 선은 경계, 회색 면은 특징이 셋일 때의 경계, 파랑 바탕은 z < 0인 쪽, 주황 바탕은 z > 0인 쪽입니다.
내용: 왼쪽은 수직선 위 x1 = 2 의 점과 z = 2·x1 − 4, 가운데는 x1, x2 평면의 직선, 오른쪽은 x1, x2, x3 공간의 평면. 아래 줄에 특징이 n개면 초평면, 직선과 평면도 초평면.
```

특징이 n개인 공간을 w · x + b = 0으로 두 쪽으로 나누는 경계를 초평면(hyperplane)이라고 부릅니다. 직선은 특징이 둘일 때의 초평면이고, 평면은 셋일 때의 초평면입니다. 특징이 넷 이상이면 그림으로 그릴 수 없지만 z > 0인 쪽은 1, z < 0인 쪽은 0으로 예측합니다.

4차시 넷째 단원의 XOR는 1을 낼 두 점과 0을 낼 두 점을 직선 하나로 나눌 수 없었습니다. 이진 로지스틱 회귀 모델 하나의 경계도 직선 하나라 XOR를 맞히지 못합니다.

### 시그모이드를 어디에 두는지가 두 방식을 가릅니다
<!-- facts: F08-27 F08-28 F08-29 F08-18 -->

앞 단원까지 쓴 모델은 Linear 층 뒤에 시그모이드를 두고 확률 p를 `nn.BCELoss()`에 넣었습니다. 다음 코드는 모델에서 시그모이드를 빼고 Linear 층의 출력 z를 그대로 `nn.BCEWithLogitsLoss()`에 넣습니다. 6차시 셋째 단원에서 본 것처럼 시그모이드를 지나기 전의 z가 logit입니다. `nn.BCEWithLogitsLoss()`는 logit을 받아 시그모이드와 BCE를 한 번에 계산합니다.

| | BCELoss 방식 | BCEWithLogitsLoss 방식 |
|---|---|---|
| 모델 끝 | Linear → Sigmoid | Linear |
| 모델 출력 | 확률 p | logit z |
| 손실 줄 | `nn.BCELoss()` | `nn.BCEWithLogitsLoss()` |
| 0과 1을 가르는 기준 | 0.5 | 0.0 |

### 세 층 모델과 pos_weight
<!-- facts: F08-65 F08-35 F08-36 F08-66 F08-37 F08-17 -->

앞 단계의 `X_train_s`와 `X_test_s`를 텐서로 바꿉니다.

```python
X_tr = torch.FloatTensor(X_train_s)                # [8000, 20]
y_tr1 = torch.FloatTensor(y_train).view(-1, 1)     # [8000, 1]
X_te = torch.FloatTensor(X_test_s)                 # [2000, 20]
y_te1 = torch.FloatTensor(y_test).view(-1, 1)      # [2000, 1]
```

`torch.FloatTensor(…)`는 둘째 단원 3단계의 `torch.tensor(…).float()`처럼 32비트 실수 텐서를 만듭니다. `view(-1, 1)`은 둘째 단원 3단계의 `view((-1, 1))`에서 괄호를 한 겹 뺀 꼴입니다. 데이터 수가 N이면 둘 다 [N, 1]을 만듭니다. 이 노트는 [N, 1]로 바꾼 정답의 이름 끝에 1을 붙입니다.

모델은 Linear 층 셋을 쌓습니다.

```python
class FraudNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.h1 = nn.Linear(20, 16)
        self.h2 = nn.Linear(16, 8)
        self.out = nn.Linear(8, 1)
        self.relu = nn.ReLU()

    def forward(self, x):
        x = self.relu(self.h1(x))
        x = self.relu(self.h2(x))
        return self.out(x)                 # 시그모이드 없이 logit
```

마지막 층은 숫자 하나를 내고 그 뒤에 시그모이드가 없으므로 이 모델은 넷째 단원의 BCEWithLogitsLoss 방식입니다. 파라미터는 20 × 16 + 16 = 336, 16 × 8 + 8 = 136, 8 × 1 + 1 = 9를 더해 481개입니다.

4차시 여덟째 단원처럼 찾으려는 사기 거래가 양성이고 정상 거래가 음성입니다. 음성 데이터가 많으면 양성보다 많은 손실 항을 더하지만 실제 손실의 합은 각 예측에도 달려 있습니다. 훈련에 쓸 양성 가중치는 훈련 정답 `y_tr1`에서만 구합니다. 테스트 정답은 이 계산에 넣지 않습니다.

```python
if y_tr1.shape != (X_tr.shape[0], 1) or y_tr1.dtype != torch.float32:
    raise ValueError("훈련 정답은 float32의 [N, 1] 모양으로 맞추세요.")
if not torch.all((y_tr1 == 0) | (y_tr1 == 1)).item():
    raise ValueError("훈련 정답에는 0과 1만 넣으세요.")
n_pos = (y_tr1 == 1).sum().item()
n_neg = (y_tr1 == 0).sum().item()
if n_pos == 0 or n_neg == 0:
    raise ValueError("훈련 데이터에 정상 거래와 사기 거래가 모두 필요합니다.")
pos_weight = torch.tensor([n_neg / n_pos],
                          dtype=y_tr1.dtype, device=y_tr1.device)
criterion = nn.BCEWithLogitsLoss(pos_weight=pos_weight)
```

`n_pos`와 `n_neg`는 각각 훈련 정답에서 센 1과 0의 개수입니다. 분할한 뒤의 훈련 빈도를 사용하므로 전체 데이터의 9,461과 539를 이 코드에 대신 넣지 않습니다. 양성이 0건이면 비율의 분모가 0입니다. 음성이 0건이어도 이진 분류를 훈련할 두 클래스가 없으므로 예제 코드는 중단합니다. 빈 훈련 데이터도 같은 검사에서 중단합니다.

정답 `y_tr1`은 float32의 [N, 1] 텐서이며 원소는 0과 1입니다. 모델 출력도 [N, 1]로 맞춥니다. `pos_weight`는 출력 클래스 하나에 맞춘 [1] 텐서로 만들고 정답과 dtype·device를 맞춥니다. 현재 예제의 입력과 정답은 모두 CPU의 float32 텐서입니다.

`pos_weight`는 `nn.BCEWithLogitsLoss()`의 인자입니다. 정답이 1인 데이터의 손실 항에만 이 수를 곱합니다. 식으로 쓰면 −[pw × y × log σ(z) + (1 − y) × log(1 − σ(z))]이고 pw가 pos_weight입니다(PyTorch 문서 BCEWithLogitsLoss).

별도의 훈련 데이터 예에서 양성이 100개, 음성이 300개이면 pos_weight를 300 ÷ 100 = 3으로 둡니다. 공식 문서도 이 개수로 계산합니다. 현재 훈련 데이터의 빈도를 이 수치로 가정하지 않습니다.

### 학습과 평가를 오가는 루프
<!-- facts: F08-47 F08-20 F08-28 F08-67 -->

앞 단계의 모델, 손실, optimizer로 1,000번 반복합니다. 아래 루프는 반복마다 학습 모드로 한 번 갱신하고, 평가 모드로 바꿔 테스트 데이터의 손실과 정확도를 잽니다.

```python
for epoch in range(1000):
    model.train()                           # 학습 모드
    optimizer.zero_grad()
    loss = criterion(model(X_tr), y_tr1)
    loss.backward()
    optimizer.step()
    model.eval()                            # 평가 모드
    with torch.no_grad():
        z_test = model(X_te)
        pred = (z_test >= 0.0).float()      # BCEWithLogitsLoss 방식이라 기준 0.0
        acc = (pred == y_te1).float().mean()
```

`model.train()`과 `model.eval()`은 5차시 여섯째 단원에서 본 학습 모드와 평가 모드를 고릅니다. 이 모델에는 배치 정규화가 없어서 두 모드의 계산이 같습니다. 나중에 배치 정규화 층을 더해도 평가를 학습 모드로 계산하지 않도록 평가 앞에 `model.eval()`을 둡니다. `torch.no_grad()`는 3차시 일곱째 단원에서 본 계산 기록을 끄는 블록입니다.

### ROC 곡선에는 0과 1이 아니라 점수를 넣습니다
<!-- facts: F08-44 F08-45 F08-46 F08-68 F08-69 F08-79 -->

앞 단계의 임계값을 하나로 정하지 않고 여러 값으로 바꿔 가며 성능을 볼 수도 있습니다. 4차시 여덟째 단원처럼 FPR은 FP ÷ (FP + TN)입니다. TPR은 TP ÷ (TP + FN)이라 재현율과 같습니다. 임계값을 가장 큰 값에서 가장 작은 값까지 내리며 가로에 FPR, 세로에 TPR을 찍어 이은 곡선을 ROC 곡선(ROC curve)이라고 부릅니다. ROC 곡선 아래의 넓이를 AUC(Area Under the Curve)라고 부릅니다. 다음 코드는 logit을 시그모이드로 바꾼 값으로 곡선을 그립니다.

```python
probs = torch.sigmoid(z_test).numpy()
fpr, tpr, thresholds = roc_curve(y_true, probs)
auc = roc_auc_score(y_true, probs)         # 양성 점수로 AUC 계산함
```

`roc_curve`와 `roc_auc_score`의 둘째 인자에는 0과 1로 자른 예측이 아니라 양성일 확률이나 자르기 전 점수를 넣습니다(scikit-learn 문서 roc_auc_score). 임계값을 바꿔 가며 다시 자르려면 자르기 전의 값이 있어야 합니다. AUC의 실제 값은 정답과 점수의 조합에 따라 달라집니다.

### 기록한 검증 손실은 갱신한 뒤의 값입니다
<!-- facts: F08-72 F08-73 F08-20 -->

5차시 일곱째 단원 5단계에서 기록한 손실이 언제 잰 값인지 따져 봤습니다. 여기서도 같은 것을 따져 봅니다. 아래 코드는 둘째 단원 3단계의 `net`, `x_tr`, `y_tr1`을 씁니다. 이 노트는 검증 데이터 30송이의 입력을 `x_val`, [30, 1] 정답을 `y_val1`로 적었습니다.

```python
for epoch in range(10000):
    optimizer.zero_grad()
    p_out = net(x_tr)                        # ① 갱신 전 파라미터로 예측
    loss = criterion(p_out, y_tr1)           # 학습 손실은 갱신 전 값
    loss.backward()
    optimizer.step()                         # ② 여기서 w, b 가 바뀜
    p_val = net(x_val)                       # ③ 갱신 뒤 파라미터로 예측

```
