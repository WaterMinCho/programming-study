### 짧은 변을 기준으로 같은 비율을 곱합니다
<!-- facts: F15-201 F15-202 F15-203 -->

14차시에서 증강의 면적과 한 변을 구분했습니다. <u>검증용 Resize는 정수 하나를 받으면 짧은 변을 그 값으로 맞추고 긴 변에도 같은 비율을 곱합니다.</u>

### 검증에는 같은 변환을 적용합니다
<!-- facts: F15-201 F15-202 F15-203 F15-204 -->

검증에서는 크기 변환과 중앙 자르기의 조건을 고정합니다. 매번 무작위로 자르면 같은 모델도 다른 영역을 보고 평가할 수 있습니다. 고정 크기로 바꾸어도 잘라낸 바깥 내용은 복구하지 못합니다. 대상이 중앙에 없을 때 평가 입력이 무엇을 남기는지도 확인하세요.

짧은 변을 226으로 맞춘 뒤 중앙 224×224를 남기는 설정도 가능합니다. 가로와 세로가 모두 300인 이미지는 Resize(226) 뒤 226×226이 됩니다. CenterCrop(224)는 위아래와 좌우에서 각각 1픽셀씩 버립니다. 앞 단계의 Resize(256)도 중앙 224×224를 남기는 변환과 함께 쓸 수 있습니다. 226은 이 예에서 선택한 값이며 모든 모델에 필요한 고정값은 아닙니다.

```python
val_tf = transforms.Compose([
    transforms.Resize(226),
    transforms.CenterCrop(224),
    transforms.ToTensor(),
    transforms.Normalize((0.5,)*3, (0.5,)*3),
])
```

두 설정 모두 크기를 맞추고 중앙을 자른 다음 텐서로 변환해 정규화합니다. 정규화 상수는 사용하는 가중치와 학습 조건에 맞춥니다. 위 코드는 각 채널에서 0.5를 빼고 0.5로 나누는 예입니다.

### 표본을 읽는 부분만 다른 Dataset으로 감쌉니다
<!-- facts: F15-501 F15-502 F15-503 -->

ImageFolder는 폴더 이름에서 라벨을 찾습니다. 라벨이 표나 목록에 있어도 앞 단원처럼 이미지와 정수 라벨을 한 쌍으로 돌려주면 됩니다. 번호로 표본을 꺼내는 <mark>map-style Dataset</mark>에서는 길이를 __len__, 한 표본 읽기를 __getitem__으로 정의합니다.

아래 예는 Tensor 이미지 목록 images와 라벨 목록 targets가 이미 준비되었다고 가정합니다. 두 목록의 길이는 같습니다. __getitem__은 같은 번호 i의 이미지와 라벨을 함께 꺼냅니다. 실제 파일을 읽거나 개인 자료를 여는 코드는 포함하지 않습니다.

```python
class LabeledImages(Dataset):
    def __init__(self, images, targets):
        self.images, self.targets = images, targets
    def __len__(self):
        return len(self.targets)
    def __getitem__(self, i):
        return self.images[i], int(self.targets[i])
```

### 적은 검증 자료의 한 장 차이를 구분합니다
<!-- facts: F15-501 F15-502 F15-503 -->

검증 자료가 열 장이면 한 장을 더 맞히거나 틀릴 때 정확도는 1÷10×100=10%p 바뀝니다. 이 작은 묶음에서 높은 정확도가 나왔다는 이유만으로 새로운 촬영 환경의 정확도까지 확정하지 않습니다.

훈련과 검증의 수치를 비교할 때는 계산 조건도 읽습니다. 훈련과 검증의 정확도는 서로 다른 모드나 증강 조건에서 계산할 수 있습니다. 검증이 더 높다는 이유만으로 과소적합을 판정하지 않고 자료의 분할과 평가 조건을 먼저 확인합니다.

### 심화 검증 손실이 가장 작았던 상태를 보관합니다
<!-- facts: F15-504 -->

학습이 끝났을 때의 모델이 검증 자료에서도 가장 좋은 것은 아닙니다. 검증 기준으로 고른 시점의 상태를 나중에 복원할 수 있게 보관한 것을 <mark>체크포인트</mark>라고 부릅니다. 설명용 검증 손실이 1~4에폭에서 차례로 0.6, 0.4, 0.5, 0.7이었다면 최솟값은 2에폭의 0.4입니다. 마지막 4에폭의 상태와 구분해 보관합니다.

`model.state_dict()`는 파라미터와 저장 대상으로 등록한 버퍼를 이름에 대응합니다. 이 결과를 변수에 대입만 하면 안의 텐서가 이후 학습으로 바뀔 수 있습니다. <u>`copy.deepcopy(model.state_dict())`로 그 시점의 독립된 사본을 만들고 학습 뒤 `model.load_state_dict(best)`로 복원합니다.</u> 아래 예는 매 에폭에서 학습과 검증을 마친 뒤의 손실을 비교하는 부분입니다.

```python
import copy
best_loss, best = float("inf"), None
for epoch in range(4):
    train_one_epoch(model, train_loader)
    val_loss = validate(model, val_loader)
    if val_loss < best_loss:
        best_loss = val_loss
        best = copy.deepcopy(model.state_dict())
model.load_state_dict(best)
model.eval()
```

`train_one_epoch`는 학습과 갱신을 수행하고 `validate`는 eval 모드와 no_grad에서 검증 손실을 계산한다고 가정합니다. 에폭마다 학습을 다시 시작할 때는 train 모드를 적용합니다. 시험 자료는 선택을 마친 뒤 최종 평가에 쓰며 최적 에폭이나 설정을 고르는 데 쓰지 않습니다. 위 예는 평가할 모델 상태를 보관합니다. 학습을 중단한 자리부터 이어가려면 옵티마이저 상태와 에폭 번호 등도 함께 보관합니다.
