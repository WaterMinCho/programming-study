# 코딩테스트 연습 Lv.2

프로그래머스 Lv.2 수준의 반환값 문제 6개입니다. 퀴즈는 없습니다.
Lv.1 과 다른 점은 "무엇을 세고 무엇을 저장할지"를 먼저 정해야 코드가 써진다는 것입니다.
문제를 읽고 바로 코드를 치기보다, 상태와 규칙과 반환값의 모양을 종이에 적어 본 뒤 시작하세요.

## 문제 분해

문제를 "입력을 받는다 → 상태를 바꾼다 → 답을 만든다" 순서로 나눕니다.

- 상태가 무엇인지 적습니다. 로봇의 위치와 남은 배터리, 지금까지 입력한 글자들, 이름별 누적 금액처럼 **반복이 한 번 돌 때마다 바뀌는 값**이 상태입니다.
- 규칙을 조건문 한 줄씩으로 옮깁니다. "격자 밖이면 무시한다"는 `if row > 0:` 같은 경계 검사가 됩니다.
- 마지막에 요구하는 **자료형과 모양**을 확인합니다. `[행, 열]` 리스트인지, 문자열인지, 정수인지에 따라 `return` 줄을 다르게 씁니다.

## 자료구조 선택

| 필요한 일 | 고르는 것 | 쓰는 메서드 |
|---|---|---|
| 마지막에 넣은 것을 먼저 꺼낸다 (되돌리기) | 리스트를 스택으로 | `append()`, `pop()` |
| 먼저 넣은 것을 먼저 꺼낸다 (대기열) | 리스트를 큐로 | `append()`, `pop(0)` |
| 이름(키)별로 값을 모은다 | 딕셔너리 | `d.get(key)`, `d.keys()` |
| 크기 순으로 줄 세운다 | 리스트 + 정렬 | 8차시 선택 정렬 |
| 중복 없이 모은다 | 세트 | `add()`, `&`, `\|`, `-` |

`d.get(key)` 는 키가 없으면 `None` 을 돌려줍니다. 처음 보는 키인지 `d.get(key) == None` 으로 확인한 뒤 값을 새로 넣거나 기존 값에 더합니다.

딕셔너리는 넣은 순서를 기억합니다. "처음 등장한 순서대로"라는 조건은 딕셔너리를 앞에서부터 돌면 해결됩니다.

## 시간 복잡도 감각

- 반복문 하나가 n 번 돌면 n, 반복문 안에 반복문이 있으면 n × n 입니다. 파이썬은 1초에 대략 천만 번 정도의 간단한 연산을 처리합니다.
- 채점은 문제마다 모든 테스트를 합쳐 5초 안에 끝나야 통과입니다. n 이 1,000 이면 n × n 은 백만이라 이중 반복문도 괜찮습니다. n 이 100,000 이면 이중 반복문은 백억 번이 되어 5초 안에 끝나지 않습니다. 제한 사항의 n 을 보고 어느 쪽인지 먼저 판단하세요.
- 완전탐색은 모든 경우를 다 만들어 보는 방법이므로 경우의 수가 몇 개인지 먼저 셉니다. 네 자리 숫자는 만 가지, 다섯 자리는 십만 가지입니다.
- 그리디는 매 순간 가장 유리한 선택을 하고 한 번 한 선택을 바꾸지 않는 방법입니다. 지금의 선택이 뒤에 고를 수 있는 범위를 줄이지 않는 문제에서만 정답이 됩니다. 충전소 문제에서는 갈 수 있는 가장 먼 충전소에서 충전한 쪽이 가까운 충전소에서 충전한 쪽보다 항상 같거나 더 멀리 닿습니다.

## 문제 구성

| 문제 | 주제 | level |
|---|---|---|
| p01 배달 로봇 | 구현·시뮬레이션 | 2 |
| p02 실행 취소와 다시 실행 | 스택 | 2 |
| p03 단골 고객 | 딕셔너리 | 2 |
| p04 합격선 | 정렬 응용 | 3 |
| p05 다이얼 자물쇠 | 완전탐색 | 3 |
| p06 충전소 | 그리디 | 3 |

p01~p03 은 6점, p04~p06 은 8점입니다. 화면의 '코드 실행'은 문제 본문의 입출력 예만 돌리고, 나머지 테스트는 제출할 때 채점합니다. 숨은 테스트에는 경계값과 큰 입력이 들어 있습니다.
