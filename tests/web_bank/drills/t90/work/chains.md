## 90-A

면접관이 버튼을 눌러도 숫자가 오르지 않는 코드를 보여 줍니다.

```tsx
let count = 0;
export function Counter() {
  return <button onClick={() => { count += 1; }}>{count}</button>;
}
```

### Q1. 버튼을 눌러도 화면의 숫자가 바뀌지 않습니다. 왜 그럴까요?
- [필수] `count`는 바뀌지만 React 는 일반 변수가 바뀐 것을 알지 못해 컴포넌트를 다시 실행하지 않습니다.
- [보충] 컴포넌트 함수를 다시 실행해 화면에 보일 내용을 계산하는 일을 렌더링이라고 합니다.
> 막히면: 숫자가 실제로 바뀌는지와 화면에 반영되는지를 나누어 말해 보세요.

### Q2. 어떻게 고치나요?
- [필수] `useState`로 값을 두고 `setCount`로 바꾸면 React 가 컴포넌트를 다시 실행합니다.
> 막히면: 값을 바꾼 뒤 React 에 "다시 그려 달라"고 알리는 방법이 무엇인지부터 말해 보세요.

### Q3. 다시 그릴 때 DOM 전체를 새로 만드나요?
- [필수] 아닙니다. 새로 계산한 결과를 앞 결과와 비교해 달라진 곳만 DOM 에 반영합니다.
- [보충] 비교한 결과를 DOM 에 반영하는 단계를 커밋이라고 합니다.
> 막히면: 글자 하나가 바뀌었을 때 브라우저가 무엇을 바꾸면 되는지 말해 보세요.

### 약한 답
> "리렌더링이 안 돼서 그렇습니다."

낱말만 말하면 왜 다시 그려지지 않는지가 빠집니다. 일반 변수의 변경을 React 가 모른다는 원인까지 말해야 합니다.

### 이어 말하기
> "count 는 1 이 되지만 React 는 일반 변수가 바뀐 것을 모릅니다. useState 로 두고 setCount 를 부르면 React 가 Counter 를 다시 실행해서 바뀐 숫자를 그립니다."

## 90-B

면접관이 한 번 누르면 2 씩 오르게 하려고 `setCount(count + 1)`을 두 번 적은 코드를 보여 줍니다.

### Q1. 한 번 눌렀는데 1 만 오릅니다. 왜 그럴까요?
- [필수] 두 호출이 같은 렌더의 `count` 값을 써서 둘 다 같은 값을 넣습니다.
> 막히면: 첫 번째 호출이 끝난 직후 `count` 변수의 값이 무엇인지 말해 보세요.

### Q2. 어떻게 고치나요?
- [필수] `setCount((n) => n + 1)`처럼 함수를 넘기면 React 가 가장 최근 값을 넣어 줍니다.
> 막히면: `setCount`에 값 대신 무엇을 넘길 수 있는지 떠올려 보세요.

### 약한 답
> "setCount 를 한 번만 부르고 2 를 더하면 됩니다."

이번 코드는 그렇게 고칠 수 있지만, 같은 값을 두 곳에서 바꾸는 경우에는 쓸 수 없습니다.
